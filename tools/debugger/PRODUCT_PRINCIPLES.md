# Camel Debugger 产品定位与设计原则

图形能力迁移至 OpenCML-Ext 后，不再维护独立浏览器前端。本文约束 debugger 职责，语言语义仍以项目设计原则为准。

## 职责与会话

- LSP 负责源码分析、诊断、导航；camel-db/debug core 负责执行、暂停、断点、步进、帧、值与异常。
- 原生 DAP 管理每个编辑器会话及独立 worker；插件是维护的图形客户端，不另写 HTTP 到 DAP 的适配器，不猜测端口或选取第一个 worker。
- REPL/HTTP 网关保留终端与自动化用途。程序始终在 worker 执行；DAP 对编辑器使用标准输入输出，内部 worker 控制仍为本机 HTTP。
- 网关写请求经 CommandDispatcher 更新状态并回显，再同步到 worker。任务以 id/target 寻址，同一文件可有多个任务；终端可选前台任务，外部按任务客户端应显式给出 target。
- 全局 `/api/state` 与单任务 `/api/task-state` 保持区分。网关维护进程存活状态，debug core 维护暂停状态；失联查询遵循 API 契约，不泄漏 502。
- 停止、重启、断开和 stdin 关闭必须清理 worker。stdout/stderr、诊断和内部断言必须可见；正常语言错误走诊断路径，真正的内部断言保留 fault site 与说明。

## 编译流水线与 GIR

- 编译边界暂停与源码单步是不同操作。边界 0 为初始图，后续编号为某遍返回图后的边界；重复 pass 名有独立编号，消费图或失败的遍不制造遍后图。
- 编译边界使用 Release 也可用的 debug core，不依赖 NDEBUG 专用 hook。最终调度可交接到运行时入口暂停。
- 在执行线程安全边界序列化实际 GIR；历史快照不可变。禁止保留无 GC 根的图指针，或重新编译源码冒充暂停图。
- 插件区分历史查看与执行位置，选择快照不推进执行，返回当前暂停位置只需一个操作。pass 序列和阶段断点通过 launch.json 配置，当前边界清晰显示。
- 使用版本化 JSON 与显式图引用，保留 source/type/origin。详情放在 hover/检查器，循环条件、循环体和函数值有明确的子图入口与返回路线。

## 内存与断点

- 源码、函数、GIR origin、异常和单步由 debug core 管理，Release 也可用；图变换后节点断点按 origin 匹配实际执行图。
- libcamel DebugBreakpoint 的分配钩子专用于 Debug，Release 编译掉 hook 路径；不能把所有调试能力都描述为 NDEBUG 下消失的类型钩子。
- DAP 分配断点在最外层 allocator 返回、锁和共享操作 guard 全部释放后暂停，明确报告 after、空间和大小。不能持有 allocator 锁等待堆检查。嵌套 allocator 只在外层边界通知完成的分配。
- 原 REPL 类型钩子保留；DAP 使用自己的安全分配边界类型，不能偷换两者的暂停语义。
- 堆检查针对选中会话的暂停线程；概览不构造全堆对象数组，字节页最多 4096、对象页最多 200，地址为无损十六进制字符串。错误区域、偏移和生命周期明确报错。
- 初次打开暂停会话可读取一次概览，其余显式刷新。继续、切换会话、到达另一暂停位置和结束会话使旧结果失效，迟到响应不能恢复旧堆。禁止持续轮询全堆。
- 不支持的构建能力必须解释并禁用，不能显示为已启用。

## 界面与验收

- 复用 VS Code 文件、源码、栈、变量、Debug Console、会话选择和重启。执行状态来自后台；视口、展开范围等展示偏好可以本地保存。
- 界面紧凑、跟随编辑器主题，支持中英文、键盘和窄面板。检查内存时后续暂停不能强制用 GIR 标签页覆盖它；图仍在后台更新。
- 旧断言遮罩由 Debug Console、异常信息及可重启会话替代，不新增遮挡编辑器的弹层。
- 接口变动更新 [HTTP 契约](docs/API.md) 或 [技术文档](../../docs/technical/35_debugger.md)，保留 REPL/HTTP/DAP 协议测试。先真实检查行为，再固化测试。
- 验收涵盖多会话、重启/终止、支持与不支持构建、分页边界、迟到响应及中英文窄屏。后台与插件分别提交推送；发布和更新固定运行时副本需用户明确授权。
