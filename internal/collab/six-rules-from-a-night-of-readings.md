# 今晚立下的六条读数规矩（2026-11-27/28）

每条都来自一次真实的错判或一次真实的省时；写成"判据 + 反面例子"，供车道直接引用。

## 1. 分诊按文件头注释与实际期望，不按名字

**判据**：一条用例的名字可能不指向文件，一个文件可能测的是"被拒"。分类前读头注释与 `expect_*`。

**反面例子**：把 `export_loop_for` 当成"计划里写了个不存在的 `.cml`"——它其实是 python 驱动条目（`tool = "python"`，case `ort_loop_node.py`），永远没有 `.cml`；把 `export_loop_carried_array_field.cml` 当成独立导出用例，它的头注释自陈"Refused: … no model file is written"。

**代价**：按名字分类会让整个子批次（G1a）变成空集，白排一轮。

## 2. 甲名单只认读数，不认记忆

**判据**：说"这条已绿/这条在甲里"之前，先贴最近一次全量跑里它的 `[PASS]`/`[FAIL]` 行。

**反面例子**：某轮报告"`pass_export_ctrl_effect_in_callee_json` 不在甲名单（已绿）"，对账后它是 `FAIL`，且**根因与相邻那条不同**（它在程序里还留着 `export_model` 调用，改 range 无用）。

## 3. re-record 的唯一依据是同一跑的 verification 原文

**判据**：位置/文本的期望只能从这次运行的输出里抄，不能按"它应该在几行"推算。

**操作**：贴 `unexpected range {"start":{"line":N,"character":C},…}` 与 `unexpected message: …` 原文，再改那一侧；改完若仍不符，说明拒绝位置真的变了，不是记录问题。

## 4. 测试与二进制必须同树

**判据**：跑计划前先确认"这棵树的尖端就是你要测的尖端"。

**反面例子**："给你一个二进制路径就能跑"——不行：`-NoBuild` 的指纹跟着树的提交走，而且**计划与被测用例都来自树**，在 `bb26b78dda` 的树上跑 onnx 计划，测的不是 `ba5a45e9bf`。

## 5. "待 re-record"与"待修"要分开记账

**判据**：一条红从"旧形态红"变成"新形态但记录没跟上"，按**待 re-record** 记，不按"红"记；提交说明必须写清"case 已经是新语义、只有记录落后一行"，并解释临时出现的计数变化（例如 `pass 115 → 114`）。

**理由**：按红记账会把"已经是新语义"这件事埋掉，下一个人会重查一遍。

## 6. 顺序不是条件

**判据**：需要"B 在 A 之后"时，先问"是先后，还是只在 A 成功时才做 B"。

**实例**：`edit` 块的降级里，`commit` 若排在 `attempt(closure)(draft)` 之后，**故障的体也会提交**；把它放进闭包体末尾，则"先后"与"只在正常路径才提交"变成同一句话（`attempt` 的边界在闭包外，故障 ⇒ 闭包中断、不提交）。
