协调者铁律（插件每小时复读一次；全文在 internal/collab/coordinator.md §0）：
1. 不向负责人提问、不等回复。问句只有一个出口：internal/questions/ 一页一问，带默认建议，同一轮按默认开工。
2. 决策者的派工带 [decision-maker · D-…] 前缀，当轮 oversight_ack（taken 并记进 backlog / declined 写理由 / done 写提交）；主动找他用 oversight_tell。他看不到你的聊天正文。
3. 8 格 = 6 实现 + 1 合并位 + 1 闸门位。develop 只有合并位写；合并不挡派工；合完就推，先推再测，不攒。
4. 分支闸：未合车道分支 > 20 或最落后 > 100 笔 ⇒ 停派新分支，转审计合并。判据看有没有未合内容，不看名字。
5. 会话只做判断；闸门、解冲突、长测试交车道或后台跑，不占住会话。
6. 读不到 ≠ 没变化；查不到就落默认值的代码，要问"失败时它落到哪、那个值会不会刚好看起来对"。
7. 不为让检查变绿而改语义；与设计原则冲突以原则为准，冲突记为缺陷。
8. 生成的表（问题页索引等）合并后先跑只读检查，再重生成，再跑一次只读。
9. 写文件一律绝对路径；派子代理传它自己的工作树 cwd。
10. 读数用 oversight_readings，不自己跑 git 数车道和分支。
11. 不许杀 git 进程，手动命令里也不许。git 正在写索引时被杀，索引会坏——比合并失败糟，
    而且坏得安静：下一次读到的是一份不是任何人的写法的索引。遇到 `index.lock`：
    跑 `node scripts/check-index-lock.mjs --root <检出>` 看谁持有、持了多久；是后台只读程序就等它，
    并查它为什么拿锁（git 面板的补丁是否被覆盖）。合并一律走 `internal/tools/merge-lane.ps1`，
    它只在「锁超过 120 秒**且**没有任何 git 进程」时才删锁；有 git 进程就停下报出来。
