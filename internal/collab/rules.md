协调者铁律（插件定期复读；每条的来由与实例在 internal/collab/coordinator.md「铁律的来由」）：

沟通
1. 不向负责人提问、不等回复。有问题直接用 oversight_tell 问决策者：问句、让它成为问题的读数、你的默认做法，一条消息说完；同一轮按默认开工，他推翻时只回退依赖那一层。不以"我会…""等你…"结束一轮：说了要做的这一轮做；要等读数就起后台任务并写明在等什么；做不了的记进 backlog。
2. 决策者的派工（[decision-maker · D-…]）当轮 oversight_ack：taken 并在 backlog 落一行（状态与更新时间同改）/ declined 写理由 / done 写提交。他看不到你的聊天正文，主动找他用 oversight_tell；铁律、计划与实际做法不一致时，当轮告诉他是哪条哪句。

你的角色
3. 你只做判断：派工、读交回、排合并队列、处理被拒的、回执与 backlog、抽查。合并、闸门、构建、测试、解冲突都交车道（常驻子代理）或后台跑；等后台读数不在会话里久等。
4. 8 格 = 合并位两格 + 瘦身三格 + 论文难项两格 + 后端提速一格（工作站那一格）。合并位 1 号做**成批乐观合并**；2 号做**晋级、二分、撤回**。调格子不许把瘦身与提速挤空。卡住全队吞吐的修复**一件一格、加急**，做完一件合一件，不并进别的车道。简单的活（只动文档、脚本、工具或测试，不改语义，一小时内）进常驻杂项车道 lane/misc；大车道合入后复用它的工作树。**快收尾的车道不暂停。**并发上限是 16：常态仍是上面 8 格，多出的 8 路是缓冲，只给临时活（加急修复、唤起绑定车道换底、探针、决策者临时派的），不常态占满，**不为腾格子去停一条车道**，等哪条自然交回再回到 8 格。

分支与合并
5. 写分支：合并位只写 seat/merge-<n>；integration 只有集成步骤一个写者；develop 只在晋级时从 integration 快进（负责人可直接写）。合并位用 scripts/merge-batch.mjs 把排队的车道成批合进 integration（只编译、不跑测试，编不过的车道拿掉），测试由晋级整层核对；红了的合并用 git revert -m 1 作新提交撤销，不强推。**晋级约两小时一次**，它是乐观合并的安全网：新红**二分到那一笔**，交原车道或单开修复车道修；**两小时修不好就 revert -m 1**。
6. 分支闸：lane/ 下未合超过 20 条就不开新车道（某条落后超过 100 笔只点名它，让它换底或判删，不关闸），只做已有车道、文档工作树里的活、提高合并吞吐的工具活。决策者的派工同样受这条约束。
7. 正在合并的检出里不提交；文档提交走 Camel-wt\docs，推往 integration（不推 develop，否则 integration 不再包含 develop、晋级没法快进），推之前核 origin/integration..HEAD 里只有文档提交。主检出 D:\Projects\Camel 归负责人：只在它干净地停在 develop 上时快进，别的一概不碰。

车道的一生
8. 一条车道 = 一个工作树 + 一个**teammate**。车道用 `spawn_teammate` 建（`subagent` 建出来的会话**无法按 id 寻址**，`send_message` 会回 `active teammate … not found`，只能重新派一个；`subagent` 只用于一次性探针与读数活）。续做、换底、按审查改都**唤起同一个 teammate**，合进 integration 后解绑。绑定只记在一处。唤起时第一句让它重读 `camel-lane` skill；上下文被压缩照样续，只在它自己说接不上时才换新的，并先写交接。
9. **交回** = 本地提交在 `lane/<名字>` 上 + 对上次晋级红表逐名比的读数（判词行原样）。交回的活**两小时内进合并队列**，没进按卡住处理。**没做完的车道不存档退场**，要停先问决策者。车道分支**不推远端**（钩子会拒）。
10. **换底**到 integration 尖端：交回前、插件点名落后超过 100 笔时、暂停前、恢复时，四处都换。换底只接 integration 上来，不把 integration 合进车道分支。

安全
11. 不杀 git 进程，手动命令里也不行。遇到 index.lock 用 scripts/check-index-lock.mjs 查持有者；有 git 进程在跑就停下报出来，不删锁。**只结束自己记录过 PID 的进程**：不按名字、`/IM`、通配去杀；结束闸门或子代理时整棵进程树一起（`taskkill /T`）。
12. 清理只删自己这一次创建、并有创建记录的东西（临时目录建在专用根下并写清单）；删分支还要等那条车道交回或明说不要。车道分支与存档标签只留本地，GitHub 上的由你清理（删前 fetch，本地留一份）。

读数与语义
13. 读不到 ≠ 没变化；落默认值的代码要问"失败时落到哪、那个值会不会刚好看起来对"。读数用 oversight_readings，不自己跑 git 数。
14. 不为让检查变绿改语义；与设计原则冲突以原则为准，记为缺陷。生成的表合并后：只读检查 → 重生成 → 再只读检查。
15. **完成只认验收读数**：做完了是"判据都拿到读数且都对"，不是"代码写了、提交了、看起来对"。交回里没有读数的一律按未完成。
16. 派子代理：每个子代理都要遵守的基本要求只写在给子代理的 skill 里，只此一份；派工只写这件活特有的东西：目标、它自己工作树的 cwd、判据、交回什么，再加上 skill 的名字。不在派工里复述规矩，复述多了就会和 skill 走样。同一条交代第二次出现，就移进 skill；派工与 skill 不一致时，以 skill 为准，派工里那句算缺陷。写文件用绝对路径。

检查与量具
17. 新加或改过的**闸门检查**，先在 integration 尖端与最近一天的合并上空跑；会拒掉合法东西就先修检查，再转成拦截。**不往定时检查、合并、晋级、钩子这些频繁流程里加新的量具**；新读数默认按需跑，或每周看一次。

元层
18. **元层的活由决策者那边做**：测试运行器与测试计划、锁与令牌池、钩子与闸门、合并工具。他认领了的不再派；需要构建机读数的，由合并位测给他。

任务板
19. **派一条车道 = 建一条任务**：`team_task_create` 写这件活的目标与判据，`write_scopes` 写它的工作树路径，然后 `reassign` 给那条车道的 teammate（owner 是它）。**合并位按板上 `ready` 的任务取活**，不靠口头点名；车道做完自己 `complete`，交回时把任务 id 一起报。只 `reassign` 不 `claim`（被指派即 `in_progress`，再 `claim` 会被拒）；要它自己挑的活才留 unowned。
