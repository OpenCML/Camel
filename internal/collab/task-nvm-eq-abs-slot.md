# 卡：`std::nvm` 上 `abs(INT_MIN) == INT_MIN` 判 false，而两边的值与差都对

**发现者**：`lane-misc`（2026-11-28 07:2x，做 `D-1128-55` 的常设用例时）。

## 现象（原始读数）

同一份用例（`test/cases/modules/stdlib/abs_smallest_int.cml`，宽度显式声明）：

```
let smallest_i: i32 = -2147483647 - 1
```

```
std::nvm  0  -2147483648 0 -9223372036854775808 0
std::fvm  0  -2147483648 0 -9223372036854775808 0
std::cpp  0  -2147483648 0 -9223372036854775808 0
std::jit  0  -2147483648 0 -9223372036854775808 0
```

四行依次是 `exit / abs(smallest_i) / abs(smallest_i) - smallest_i / abs(smallest_l) / abs(smallest_l) - smallest_l`。

⇒ **值对、差也对**（`abs(x) - x == 0` 在四后端都成立），但把断言换成 `abs(smallest_i) == smallest_i` 时 **`std::nvm` 答 `false`**，`fvm` / `jit` / `cpp` 都答 `true`。

## 为什么它不是"值不对"

`abs(x) - x` 在 nvm 上也是 `0` ⇒ 算术层面两个值相等；只有 `==` 这一条路给出 `false`。
最可能的方向（**未证实，勿当结论**）：

1. `abs` 回来那个槽的**标签/宽度**与 `smallest_i` 的不一致（例如 nvm 里 `abs` 的结果带 int64 或未定型标签，`==` 按标签比而不是按值提升）；
2. 或 `abs` 的结果槽在 nvm 的寄存器分配里**复用了另一个宽度的槽**，`==` 读到的是不同寄存器视图；
3. 或 `==` 在 nvm 的整数比较里对"最小整数 + 回绕"有分支（符号判断之类）落了默认值 —— 这正是铁律 13 那句"失败时落到哪、那个值会不会刚好看起来对"。

## 判定标准（先只读定因，不改）

- 最小复现：`let m: i32 = -2147483647 - 1; println(abs(m) == m)` 在 `std::nvm` 与 `std::fvm` 各一次；
- 对照组 1：`println((0 - m) == m)`（不走 `abs`，只走回绕取负）—— 若也 false，问题在 `==`/槽，不在 `abs`；
- 对照组 2：`println(abs(m) == -2147483648)` 与 `println(abs(m) == m + 0)`；
- 对照组 3：用 `int` 宽度同一组（排除 i32 特例）；
- 读数要带 `[provenance] tip` 与 `binary built`，并说明临时 `.cml` 放在哪（不进仓库）。

## 边界

- 这是 **nvm 的比较/槽语义**问题，不是 `abs` 的语义问题（`D-1128-54`/`55` 已定：回绕取负、复用 `intAbs`）；
