# 2026-11-26 推送之门的一夜

这一页记录一件事：**从“所有推送都被拒”到“推送恢复”，中间到底修的是哪几层**。
它写给以后遇到“检查明明跑过了，为什么还是推不上去”的人。

## 一句话

那个 gate 不是一条，是**四层**，而且每层都能单独让推送失败；修好其中三层时，读起来和一层都没修一样。

```
① 调用方参数：`check-process-traces` 要求 `--root`，`.husky/pre-push` 不传 ⇒ exit 2（量不了）
② 阈值：检查器默认阈值 0，而树里有 539 条既有痕迹 ⇒ exit 1（红）
③ 守卫是否被 git 调到：`Camel-wt/*` 里 `.husky/_` 不存在 ⇒ 钩子一次都不跑（静默放行）
④ 钩子与检查器是否同源：`develop` 上的钩子不传 `--root`、检查器要求它 ⇒ 装了钩子也只是整齐地全拒
```

## 第一层与第二层：棘轮

`eae6344e8c`（后经合并 `6bb95bc75` 进 integration）把“阈值 0”换成“**这次推送比基线多出来的那部分**”：

```
基线按文件记条数：scripts/process-traces-baseline.json（539 条 / 265 文件，取自发布的尖端 410ca5d02）
任何一笔让某文件条数变少，基线随之下降（`--lower`），且**基线不许回升**——由检查器自己核，不收约定
清到 0 时删掉基线，钩子回到阈值 0
```

判据不是“跑起来没报错”，是同一命令在两棵树上的两种结果：

```
410ca5d02  git hook run pre-push ⇒ exit 1，`process traces in comments: 539 (scanned 6360 files …)`
6bb95bc75  git hook run pre-push ⇒ exit 0，`none beyond the baseline (… 539 trace(s) in 265 file(s) …)`
```

**读法：**棘轮不是把红变绿，是把“继承的债”与“这次新增”分开，并且**把数字打出来**。

## 第三层：每棵树自己的钩子

`.husky/_/.gitignore` 是 `*` ⇒ 这个目录**永远进不了 checkout**，而 `core.hooksPath` 指向它。
于是任何 `Camel-wt/*` 工作树里，git 找不到钩子，推送时**一个检查都不跑**，也一声不响。

`6275fb6958`（`new-worktree.ps1` + `push-hooks-guard.ps1`）改了入口而不是改机器配置：

```
建树即装钩子（`npx --yes husky`），装完**空输入试跑一次**，读到检查器自己的输出才放行
推前 `Test-PushHookGuard`：读不到输出、退出 0 ⇒ 判“这次推送没有守卫” ⇒ 拒，并打印修法
```

判据写成了一句话：**输出为空 + exit 0 = 没有守卫 = 失败，永不判过。**
它已固化成测试第 7 条——因为“空输出恰好退出 0”是所有静默放行的共同形状。

补跑读数（100 棵树）：装上 89、已有 3、跳过 8；**装前 `hook run` 报找不到钩子的 89/89，装后 89/89 找得到**；
`core.hooksPath` 一字节没动。

## 第四层：晋级

装上钩子之后，68 棵树仍然推不动，因为它们是从 `develop` 线开出来的：那里的钩子不传 `--root`，而那里的检查器要求它。
于是拒绝理由是“钩子和检查器拼不上”，不是“树里有痕迹”。

```
⇒ 棘轮管痕迹基线，晋级管钩子与检查器同源。两件缺一，结果都是“看起来有守卫”
```

## 这一夜抓到的两笔债

**已发布的树带着新痕迹。**追溯测量（`git archive` 两棵已发布的树，各跑各的检查器）：

```
基线树（今晚之前的 1b7b986117，同一程序）：1557 条
现在：integration 539、develop 540 ⇒ 净减 1000+，但**夹带 13 条今晚新增**
13 条逐条归因到引入它们的提交：日期 4、commit hash 5、裁决 1、主机名 2、工作项号 1
```

`188d76ad14` 把 13 条改成“它约束的那件事”（不写何时、谁、哪次），基线 `--lower` 到 526/258；
`did not` 仍是 381（394 = 381 条 `did not` + 13 条 `unresolved on purpose`，两拨不是同一个集合；
11 条 ignored 不长这个形状）。这 394 条逐条对**这条文档车道推上去那批改动**的行区间求交 = 0 ——
注意它的取数范围是车道自己的 diff，不是 `188d76ad14` 那一笔的 diff。

**pgl 批自带 9 条新痕迹。**它不是“基过期”一个问题：

```
merge2 树 548 条 vs 基线 539 ⇒ 多 9 条来自 pgl 内容
⇒ 重挂时不能只换基：那 9 条要一起清（`c5115e1cc9`）
⇒ 两个判据指向相反时（“tree 与预览逐字节相同”vs“清掉 9 条”），不折中，分层：重挂一笔 + 清痕迹一笔
```

## 这一夜定型的几句话

```
「技术上能推 ≠ 规矩允许推」——直推一笔单父提交被 D-1124-78 拒：每笔到达都是合并
「空输出 + exit 0 = 没有守卫 = 失败」——写成了测试
「装好钩子只是把静默跳过换成整齐地全拒」——68 棵树
「两个判据指向相反时，不要折中，要分层」——pgl 两笔
「一条红的账本里没有它的尺子」——`units=114` 那次跑动永远查不到，因为检查器不打印它读的 DB
「一条过严的判据与一条过松的判据一样会误事，区别只是没人看得到它挡住了什么」——清分支那趟
「是谁先落，决定谁是那句假话」——onnx 解禁与 loops 文档必须在同一晚按序落，否则页面教错而 git 不报冲突
```
