Design principles 9.8 (`docs/design-principles.cn.md:706`): `main` is an ordinary function, its return
value is the function's own and not the program's result, and the exit code is only what

The 80 new instances are every expectation that had been reading a computed value through the exit
code. This page is the record of putting them back on a channel that still observes the value.

## 3. Why every `-o` script reads the file after asserting the exit code

A run that fails writes no entry result, and a missing file then reads as "the file the test wanted is
missing" rather than "the run failed". Every one of the 21 scripts therefore asserts
`input.exit_code === 0` first, and only then reads the file. The one place this mattered in practice:
the `prl` entry of `order_edges_regions` had its args written as `["-t", "4", ...]`, so the `-o`
prepend that the other four back ends got did not match its shape and silently did not apply; the
first run reported `ENOENT .../entry.txt` and the real finding was "this entry never asked for the
file", not "the prl scheduler cannot write it".

## 6. `contains ["ran"]` was green on a wrong value: a substring needle in a graph dump

The first version of 5.3 used `expect_stdout_contains = ["ran"]` and **stayed green** with the print
changed to `walked`. The reason: `contains` is a substring test over the whole stdout, and
`std::gir` prints the graph first — the dump contains the word `operand`, and ope-**ran**-d contains
`ran`. A three-letter needle inside a several-hundred-line DOT dump is not an assertion about the
program's output at all.

The fix is `expect_stdout_matches = ["^ran$"]`: the runner matches `expect_stdout_matches` patterns
against whole lines (`matchesAnyLine` in `test/tools/run-tests.mjs`), so the assertion now says what
its sentence says. The same deliberate change then turned it red (5.3), and this is the whole content
of `fbd65cb73e`.

The general lesson, worth carrying to other re-pins: **an assertion that passes on a deliberately
wrong value is evidence about the assertion, not about the run** — the wrong-value experiment is the
only thing that separates "the test is green" from "the test checks something".
