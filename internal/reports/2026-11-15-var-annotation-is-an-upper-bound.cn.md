# `var` 的类型标注是上界：这条裁定要落到效应分析上

- 裁定：`c379f9dc3`（`docs/design-principles.cn.md` §3.5 新增一条；`internal/reviews/questions-2026-10-29.md` 末尾同轮追加第 7 项的日期与产物）
- 原文要点：`var f: T = e` 规定这个名字以后绑定的每个值都必须符合 `T`；**调用 `f` 时按它当前绑定的那个值的类型算**（效应更少的函数绑上去，调用就只算更少的效应），因为 `var` 只是值的名字。循环状态在循环里每轮的值不同，按标注（没有标注时按各轮值的类型之并）算。
- 状态：**已裁定，未实现**。这一页只记它落在哪儿、怎么算做到，不是实现。

## 它为什么不是「第 1 项做完就自动有了」

新排第 1 项（`var` 一律化成 SSA）之后，每个绑定都是独立的 SSA 值，**类型天然是「那个值」的类型**。但「SSA 之后类型算得出来」不等于「效应分析会去用得到」：今天按标注算的那条路（拿声明的函数类型去取效应集合）在 SSA 化之后仍然能编译、仍然会给出一个数字，**只是那个数字是上界而不是真相**。所以这一条要单独验，不能靠第 1 项顺带。

## 判据（一条，可测）

一个 `var` 名字绑定到**效应更少**的函数上，调用它的地方必须按**绑定值**算：

```
func pure_fn(x: int): int { return x + 1 }        # 无效应
func main(): int sync {
  var f: () -> int eff ulong = pure_fn             # 标注是上界，比实际宽
  return f(1)                                      # 这里必须算「无效应」，不是 ulong
}
```

- **正例**：上面这段，调用点记的效应集合**为空**（或等于 `pure_fn` 的），不是标注那个更宽的集合。读数：`std::gir` 里调用节点的效应属性，或 `camel inspect` 的效应一栏——两者任一，附原文。
- **反例（同样重要）**：把一个**效应更宽**的函数绑到**更窄**的标注上，必须是**编译错误**，因为标注是上界。「上界」这个词只有在这一方向上可证伪，否则它只是一句好话。
- **循环状态**：循环里每轮绑定的类型不同时，按标注算；没有标注按各轮类型之并。要有一个 `var` 带标注、一个不带的对照。

## 顺序

- 在第 1 项（`var`→SSA）之后做。**不要**在 C1（`test/` 与 `stdlib/` 的机械迁移）里顺手改它：C1 的判据是「每个用例输出逐字节不变」，而这一条**就是要改一个读数**，两者混在一笔里会让「变了的那个数」说不清是谁造成的。
- 落点是效应分析（`src/compile/gir/builder_resources.cpp` 与效应签名一侧），不是调度器。合并位今天刚因为句柄排序改过 `builder_resources.cpp`，注意别把 `handleKeyOf` 的键语义再动一遍。

## 这一页为什么存在

这一类裁定的风险不是「没人实现」，而是**实现了却没人能证伪**：按标注算会给出一个看起来合理的数，而按绑定值算给出一个更小的数——**两个数都「不像错的」**。所以判据必须写成「正例读数必须变小到空集」和「反例必须编译失败」，两条一起才算。

失败模式记一句：如果只有正例没反例，一个「把标注直接当真相」的实现**也会通过**正例（因为它根本没读绑定值，只要标注恰好宽就会显得对）——这正是 §1 里那种「看起来对得上」的读数。
