# 块是作用域：把块体降成普通闭包

负责人 2026-11-27 定：`view`/`edit` 块只是作用域构造，保证两件事——句柄出不了块、进块开草稿走到块尾提交（中途失败整份作废）。编译之后块体是普通闭包，执行时没有特殊对待。规则在设计页 `docs/design/graph-editing/README.cn.md` 第 1、4、5 节与原则第 9 节"图操作只写在三处"那条。

现在的实现是另一套：块体编成一段单独的程序，存在上下文的 `BlockPrograms` 里，外层图里只有一个按块体规范形式命名的算子节点，由专门的内核去跑。这一套整体换掉。

排在 C5 的重落（`lane/abort-fix`）合入之后，在 C5 这一格里做。

## 第 0 步：先测前提，不改代码

块的降低方式要靠一条已有规则：块内新建、出不了块的资源在块出口按效应遮蔽消失（原则 3.4，`sync` 块的时间线就是这样）。先实测今天的效应分析对"函数体里新建的局部资源"是否已经这样遮蔽：写一个函数，体内新建一个局部资源、对它读写、不交出去，看这个函数推出来的效应里有没有它。报原文；没有遮蔽就先报，不往下做。

## 第 1 步：降低方式

- `view d = f { B }`：块体 `B` 编成一个闭包，参数是 `f` 的只读图句柄与捕获的值；块就是对它的一次调用，值是 `B` 的值。
- `edit d = f { B }`：`open(f)` 开草稿；以 `attempt` 的方式调用块体闭包（参数是草稿句柄与捕获的值）；结果是错误就交出这个错误，否则 `commit(d)`。`edit` 的值类型照第 2 节，由块外的期望类型给出。
- 标签只在类型检查里：句柄外逃照旧在编译期报出；类型检查之后标签不进图。
- 草稿作为局部资源在块边界被遮蔽，`edit` 对外是纯的。

## 第 2 步：运行时

- 草稿在 `commit` 之后、或块体失败之后关闭。对已关闭的草稿做任何读写都带位置产生故障 `DraftClosed`；草稿是回收器管理的对象，关闭不等于释放。
- `open`、`commit` 与查询、编辑算子都是内核里的普通算子，按它们读写的资源（`graph`、`spelling`、草稿）声明访问。

## 第 3 步：删掉旧的那一套

`BlockPrograms`（`src/kernel/include/camel/runtime/block_programs.h` 及其实现与上下文里的持有）、块的规范形式命名（`block_form.h/.cpp`，若别处不用）、块的专门内核、测试入口 `src/stdlib/test/block_body.cpp` 的脚手架，以及 C++ 导出器里拒绝块算子的那段（`src/stdlib/std/cpp/function_emitter.cpp:1126` 前后）。删的东西不留指向新做法的诊断或说明。

## 验收

- `git grep -n "BlockPrograms\|blockPrograms" -- src` 为 0。
- 设计页第 2 节的四个示例逐字编译、跑出结果。
- 嵌套四条（`edit` 里套 `view`、`edit` 里套 `edit`、内层读外层句柄、内层把自己的节点交给外层应在类型检查报错）各有用例。
- 块体能被 `std::cxx::inline` 内联、被 `std::opt` 优化，结果不变（各一条用例）。
- 同一个带块的程序在 `std::nvm`、`std::fvm`、`std::jit` 上结果相同。
- 一条 `DraftClosed` 的用例（用测试模块的 C++ 遍把草稿句柄挪出块再用）。
- 英文原则与设计页同步；新增红 0。
