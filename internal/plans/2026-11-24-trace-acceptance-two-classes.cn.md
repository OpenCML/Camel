# 痕迹检查的验收口径：叙述性为 0，地址与格式样例单列

状态：已定（2026-11-24）。执行：`scripts/check-process-traces.mjs` 下一次改动。

## 为什么要分两类

一个模式抓到的东西里，总有一部分是**同一个词、另一个领域**。已经发生过三次：
`/*` 在 shell 注释里是 glob、`lane-1` 在路径里是占位符、`2026-11-24T02:40:00` 在 manifest
格式样例里是数据。

三次的错法是同一个动作：**一个只看文本的东西，去猜它看到的那段文本属于哪种结构**。
所以两类不靠"看上下文"来分，靠**这条模式抓的是名字还是地址**来分。

## 口径

1. **叙述性痕迹 = 0**。派工编号、裁定日期、角色、车道名、"待审"、"this lane"、"iron rule N"
   出现在说明性文字里，都是叙述性。
2. **地址与格式样例 = N**，按文件逐个列出（`<文件>: N`）。N 只允许在有人**新加**了路径或格式
   样例时增长，增长必须写进提交信息。
3. 检查器输出一行：`traces: 0 narrative, N address-or-format (see the per-file list)`。

"0"不再是一个数，是一句话：叙述性痕迹为零；地址与样例有 N 处，名字在清单里。

## 哪些进 N

- 主机与运行目录的路径（`~/camel-work/...`）、主机名、本机路径；
- 格式样例里的字面量：TSV/JSON 样例行、时间戳、示例 sha；
- 判断脚本能否动手所依据的那个路径本身（拒绝条件是"在 root 之外"，那个路径就是条件）。

## 哪些不进 N

- 任何"为什么这样做"的句子里的编号、日期、人名、车道字号；
- 被写成理由的"某次事故"里的**编号**（事故本身可以讲，编号是坐标）。

## 判据一句话

**代码里的路径可以留，散文里的名字不能留**——前者是**地址**，后者是**坐标**。

## 测试

一份故意同时含三类的临时文件，检查器要报 `0 narrative, N address-or-format`，并断言 N 等于
该文件里地址与样例的处数。这条测试存在的理由：新口径第一次被下一个改模式的人打破时，会
以"叙述性也进了 N"的形式出现，而那与今天所有缺陷同形。
