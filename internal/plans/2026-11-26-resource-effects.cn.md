# 资源效应系统：按等式落实

设计见 `docs/design/effects/README.cn.md`（负责人 2026-11-26 定），原则第 3 节已改。目标：遍能对一次访问做什么，只由资源声明里的等式决定；修饰词齐全；实现与原则的几处偏差一并收掉。读数依据是两份审计（编译器与运行时、标准库声明）。

## 一、资源记录带上等式

1. `resource` 声明接受 `unordered`、`idempotent`、`overwriting`、`readonly`、`observed`，可以叠加；C++ 一侧登记资源的接口给出同样的五个标志（一个资源一条记录，两个入口平等，两边都写必须一致）。
2. 矛盾组合在声明处报错，各一条诊断：`unordered` 与 `overwriting`；`readonly` 与任何写的修饰词；`observed` 与 `readonly`。`overwriting` 与 `idempotent` 同写不报错。
3. 从资源记录与访问的读写，算出这次访问满足的四条等式（丢弃、复制、交换、擦除），只在一处算，所有读者问这一处。

## 二、读者改问等式

- 建图时的排序（`builder_resources.cpp` 的 `orderEffectsOnOneResource`）与运行时的冲突判定（`resources.cpp` 的冲突查询）都改问"这对访问满足交换吗"。顺带：读与读不再排序（今天建图器排、运行时不排，两边不一致）。
- `unordered` 只让写与写交换，读与写照常排序；核对现有 `unordered` 资源（`test_support::rendezvous_point`）有没有读，有就看它依赖的是哪一种。
- 死代码消除只删满足丢弃的访问，合并重复计算只合并满足复制的访问（C++ 的 `std::cxx::dce`、`std::cxx::cse` 与 `opt.cml` 的 `dce`、`cse` 都改问它；`opt.cml` 经图模块的查询拿到）。
- 新增：被 `overwriting` 的写覆盖、中间没有读的写可删（死存储消除），先只在 `std::cxx::dce` 里做，`opt.cml` 的 `dce` 同步。
- 调度：并行调度器对 `idempotent` 的写允许重做；先只加标志与查询，不改调度策略。

## 三、`observed` 与调试观察

1. `observed` 资源：不进推断出的资源集，不影响 `pure` 与 `uses` 检查，不进特化键；不加任何顺序边与同步边；节点必须保留（丢弃与复制在实现层禁止）。
2. 读 `observed` 资源的操作在调用处报错（新诊断）。
3. prelude 加命名空间 `debug`：资源 `debug::channel observed`；`debug::print::<T>(x: T, ...rest) => T` 与 `debug::print<fmt>`，C++ 内核写标准错误，前缀 `[文件:行]`（位置由编译器在调用处填，与 `error(...)` 同一机制），交回 `x`。
4. 变换：求导规则是恒等（导数穿过，打印原值）；批处理打印整批。
5. 遍 `std::strip_debug` 删除全部调试节点；ONNX 与 C++ 导出把它当恒等。
6. 后端差分工具把以 `[文件:行]` 前缀开头的调试行排除在比较外。

## 四、程序输出交回 `void`

`print`、`println`、`eprintln` 等交回 `void`（C++ 登记与 prelude 声明同改）。全仓里把它们的返回值接着用的地方（`x->println->f` 一类，以及把 `println(...)` 当值的位置）改成 `debug::print` 或拆成单独的语句；`git grep` 列出全部位置，迁移一笔做完。

## 五、审计查出的偏差

1. `console` 合成一个资源、三条通道，写标准错误、读标准输入前先刷出标准输出——已在 `task-87` 做，这里只列入验收。
2. 读时钟按写算：`time::now`、`process::sleep` 今天登记成读 `clock`，改成写，并核对单独一行 `sleep(x)` 不再可能被丢掉（新用例）。
3. 导出函数推出的资源发生变化时给警告（原则 3.3 写了，未实现）。
4. 闭包的类型提到它每个捕获物里握着的全部句柄，一层层往里取（今天捕获物里套着的闭包所握的句柄没往外传）。
5. `pure` 允许读：今天按"资源集为空"检查，比原则严；改成"没有写"，用例：读 `Ref` 与读外部资源的函数能声明 `pure`。
6. 没写资源的原生操作是"全局"效应：运行时已按全局处理，建图器也改成与一切效应排序，两边一致。

## 顺序与验收

一 → 二 → 三 → 四；五各条独立，可与前面并行（各自一格）。

- 一：五个修饰词各一条正例、三种矛盾组合各一条负例。
- 二：同一资源上的写与写，`unordered` 时图上无顺序边、默认时有；读与读无顺序边（建图器与运行时一致）；`overwriting` 的被覆盖写在 `std::cxx::dce` 后消失；`opt/camel_passes` 与 `opt/cxx_isolation` 保持全绿。
- 三：纯函数里写 `debug::print` 能通过 `pure` 检查、函数类型不变；两次相同的 `debug::print` 都打印；`std::strip_debug` 之后输出里没有调试行；读 `debug::channel` 报错；`grad` 与 `vmap` 下各一条用例。
- 四：迁移前后快层逐名比新增红 0，标准输出只在原先依赖返回值的用例处变化（逐个列名）。
- 五：每条一条能区分改前改后的用例。
