# `std::default` 指向 `std::fvm`

依据：设计原则 9.2（负责人 2026-11-24）。fvm 承担性能，默认用它；此前指向 nvm，是早期 fvm 不稳定时临时改回的。nvm 是实现的标准参照，其他后端与它比对。

## 先量，再改

默认一换，所有靠默认执行的用例都改由 fvm 来跑。fvm 与 nvm 结果不同的地方，就是 fvm 偏离了参照，这正是要找出来的东西，不能让它们混在迁移里变成"新红"。

1. **量**：在 integration 尖端，把 `std::default` 临时指向 `std::fvm`（只在测量用的工作树里改，不提交），整层跑快层，按名字和 nvm 默认下的红表逐条比。报三个数：fvm 下新红多少、新绿多少、红法变了多少；新红按失败的第一条期望分组。
2. **判**：读数回来我按分组定，每组归两类之一：
   - fvm 的缺陷：fvm 与 nvm 不一致，nvm 是对的。记进 backlog 修 fvm，不改用例的期望。
   - 用例本身依赖 nvm 的特有行为：比如钉着 nvm 的调试输出。这类用例显式写 `std::nvm`。
3. **改**：`src/kernel/execute/pass.cpp:116` 的 `{"std::default", "std::nvm"}` 改成指向 `std::fvm`；`docs/cli.cn.md:157`、`docs/cli.md:169` 的"它是 `std::nodevm` 的别名"一并改；`AGENTS.md` 里"`std::nvm` is the fallback pass"改成 `std::fvm`。
4. **合**：fvm 的缺陷修完之前，默认切换不合进 integration。如果某一组短期修不完，报给我决定：是先修，还是先合、把这组用例临时标成已知失败（写明主人和结束条件）。

## 差分测试

nvm 是参照这一点，要有一个计划按它落实：同一批用例在 fvm 与 nvm 上各跑一次、比结果。测试重构里已有类似的计划就用它，没有就补一个。默认换成 fvm 以后，这个计划是 nvm 唯一的常规用途。
