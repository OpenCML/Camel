# camel-oversight 改插件不再重启 DSH

负责人 2026-11-24：停掉 DSH 再重启代价大（正在干活的 agent 全停）；手动强制刷新一次网页可以接受。

## 目标

| 改了什么 | 怎么生效 |
|---|---|
| `rules.js`、`measure.js`、铁律文本、阈值 | 已做：插件下一次测量时从 `origin/develop` 重新载入（`b99879d46`），不用任何操作 |
| `index.js`（路由、工具、会话接线） | DSH 的单插件热重载（`dsh-hmr`），不重启进程、不断会话 |
| `client.js`（横带） | 负责人刷新一次网页 |

## 做法

1. **插件从一个只放已推送内容的目录加载**，例如 `D:\Projects\camel-oversight-live\`。主检出的工作区里有合并中途和车道半成品的内容，热重载监视那里会载入没过闸的代码；`dsh-hmr` 载入失败不回退，插件会直接停。
2. **同步由合并位在推送成功之后做**（`merge-lane.ps1` 末尾，或单独一个脚本由它调用）：
   - 从 `origin/develop` 取出 `internal/tools/camel-oversight/` 到一个临时目录（`git archive` 或逐个 `git show`，不建工作树）；
   - 对每个 `.js` 跑 `node --check`，有一个不过就不同步，报出来；
   - 过了就整目录替换 live 目录（先写临时目录再改名，不留半新半旧）；
   - 只有插件文件真的变了才替换，免得每次推送都触发一次重载。
3. **DSH 配置改两处**（这一步要重启一次，之后不再需要）：
   - 插件的加载路径指向 live 目录；
   - `dsh-base` 的 `cordis.patch.yml` 里 `hmr` 一项的 `config.root` 设为 live 目录（现在是 `[]`，只监视配置文件）。
   改配置由协调者准备好改动并写明文件与行，负责人挑车道少的时候确认并重启。
4. **横带**：先实测一次——改 `client.js` 里一处无害的文字，推送、同步后刷新网页，看横带是否换成新的；若刷新不够（宿主缓存了旧版），把实测结果写在这页，再定办法。

## 验收

- 同步脚本：推一个坏的 `index.js`（在临时分支上模拟），同步拒绝、live 目录不变；推一个好的，live 目录换新。
- 重启一次之后：改 `index.js` 里一句提醒文案并走完合并，DSH 不重启、协调者会话不断，新文案生效（`/oversee/state` 或下一条提醒可见）。
- 横带：刷新网页后看到新版，或这页写明刷新不够的实测结果。
