# `main` 是普通函数，程序只产出效应

负责人 2026-11-26 定（设计原则 9.8 已改）：`main` 的返回值只是这个函数的值，不论类型都是同一个意思；运行时由驱动程序把它写出，这是边界上的一次输出效应；退出码由显式效应 `exit(code)` 表达，不借返回值；命令行参数可以重新设计，不计兼容。

## 要改掉的

`docs/cli.md`「Programs whose `main` takes parameters or returns a value」一节按类型分两义：`main` 返回 `int`、`bool`、`byte` 是退出码、不打印；返回其他类型是程序结果，打印或写进 `-o`。这条按类型分义整个删掉。

## 新规则

1. **返回值**：`main` 声明了非 `void` 的返回类型时，运行结束后驱动程序把返回值按 `println` 的写法写到标准输出（`int` 也一样写出）。`main` 不声明返回类型或声明 `void`，什么都不写。`-o` 改成"把返回值写到这个文件而不是标准输出"，它就是输出去处的选择，不再和退出码相关；命令行的整体重新设计另做，这一步只去掉按类型分义。
2. **退出码**：用标准库已有的 `process::exit(code: int) => never uses var process`（`src/stdlib/process.cml`）：写出缓冲的输出、释放外部资源之后结束程序，之后写的都不执行，类型是底类型 `never`（设计原则 3.9）。不新增函数。没调用就是 0；没被处理的错误值到达 `main` 出口、故障终止时照现在给非零。
3. **`main` 返回 `T!`**：错误值照现在作为 `UnhandledError` 写到标准错误、退出码 1；成功的值按第 1 条写出。

## 迁移

全仓 `func main() => int` 有 3853 个文件，绝大多数是 `return 0`。机械迁移，写成一个一次性脚本跑完、脚本不进树：

- `func main() => int ... { ...; return 0 }`：去掉返回类型与末尾的 `return 0`（`sync` 等修饰保留）。
- 返回非零字面量或变量的（约 290 处）：改成 `process::exit(n)`（文件里补 `import process` 或写全限定名），再去掉返回类型；用例期望的退出码不变。
- 期望里用到"返回值即退出码"的计划条目照迁移后的程序核对：退出码应完全不变，标准输出不应多出一行。
- 有意返回 `int` 作为结果、期望里本来就读退出码之外的东西的，逐个看，按新规则改期望并在提交说明里列名。

## 验收

- `docs/cli.md` 那一节按新规则重写（不留旧规则的说明）。
- 新用例：返回 `int` 的 `main` 打印那个数、退出码 0；`process::exit(3)` 退出码 3、标准输出只有它之前程序自己的输出、它之后的语句不执行。
- 迁移后快层与合并闸门对比迁移前：退出码逐条相同，标准输出除新规则要求的写出外逐字相同；逐名比新增红 0。
- `git grep -n -E 'func main\(\)\s*=>\s*int' -- '*.cml'` 只剩有意返回结果的那些（逐个列名）。
