# 重复在图上原生：`EACH` 节点，库函数用 Camel 写

负责人 2026-11-28 定了两件事：

- 每一轮各算各的重复，在图上有自己的节点 `EACH`。
- 库里的函数式算子全部用 Camel 写，没有内置的重复算子。

设计见 [`docs/design/repetition/README.cn.md`](../../docs/design/repetition/README.cn.md)，规则见设计原则 3.6 与 3.10，本页只讲施工。它取代 `2026-11-28-refactor-not-patch.cn.md` 第四件"map 是循环"的第二刀；第一刀（推导式的元素函数从位置取类型）照旧有效。

## 要做成的样子

- **图上**：两种重复各一种节点。`EACH` 有迭代空间、体区域与两种汇合方式（按位置收集、按位置保留），`LOOP` 照旧。
- **语言**：推导式 `[e for x in xs if c]` 直接降成一个 `EACH`。`loop` 的循环头状态可以不写，`loop for x in xs do e` 的值是 `void`。
- **库**：全部用推导式、`loop` 与递归写成：

  | 库函数 | 写法 |
  |---|---|
  | `map`、`filter` | 推导式 |
  | `fold`、`foreach`、`find`、`any`、`all` | `loop` |
  | `reduce(xs, op, unit)`、`scan` | 二分递归 |

- **删掉的**：
  - 所有重复相关的内置算子：`:mark/map_arr`、`:mark/filter_arr`、`:mark/reduce_arr`、`:mark/foreach_arr`、`:mark/unordered_foreach_arr`、`:mark/unordered_reduce_arr`。
  - 它们在每个后端里的内核：`fvm` 的元素调用与 `callElement`，`prl` 的 `mark_map_arr`，`nvm` 与 `jit` 的对应实现，内核 `frame.h` 里对 `map_arr` 的引用。
  - 为它们单写的求导、融合、批处理规则。
  - `para.cml` 里的 `unordered_` 一族。

## 施工顺序

每一步单独成一笔，每一笔都有读数。

1. **节点与体区域**：图模型、编码与 `std::jgir` 规范形。体区域由"拥有区域的节点"编辑原语建造；提交检查把各轮当作没有先后。用例：体里写共享资源被拒，带位置；体里给外面的 `var` 赋值是编译错误。
2. **`nvm` 执行**：两种汇合方式各一条用例；故障报下标最小的那个。
3. **推导式降成 `EACH`**：推导式不再是对 `filter`、`map` 两次调用的糖，而是直接降成一个节点。判据：推导式的三条基线逐字节不变；图上一个 `EACH`，没有对标记算子的调用。
4. **`fvm` 与 `jit`**：字节码生成把 `EACH` 降成循环，体内联。判据：
   - 输出与 `nvm` 逐字节相同。
   - 在工作站净场窗口量每元素耗时：`fvm` 与 `nvm` 同一量级，`jit` 更快。这一条等 `fvm` 调用路径的回归修好后再量。
5. **`prl`**：按节点切块并发，粒度按相对代价定。判据：输出与 `nvm` 逐字节相同；`git grep mark_map_arr` 零命中。
6. **`loop` 的状态可选，库改用 Camel 写**：
   - 写法按上一节那张表。
   - 删掉上面列出的内置算子、内核与 `unordered_` 一族。
   - `map`、`filter` 的元素函数补上 `pure`。

   迁移：
   - 今天的 `reduce` 是从左到右折叠，用法改写为 `fold`。
   - `unordered_foreach` 改写为 `foreach`，`unordered_reduce` 改写为 `reduce` 并补上 `unit`。
   - 旧名一律删除，不留别名，也不留指向新名的诊断。

   判据：
   - `git grep ':mark/.*_arr'` 零命中，整层新增红为空。
   - `reduce` 对浮点数，三个后端逐位相同。
   - `find` 带一条"命中之后的元素会故障"的用例，证明后面那个故障不报。
7. **`LOOP` 改写成 `EACH` 的遍**：放在 `std::opt` 里。不带状态、各轮足迹互不冲突的 `LOOP`，改写成 `EACH`。判据：一条可改写、一条不可改写（各轮都往控制台打印）的用例；改写前后输出相同。
8. **变换**：
   - `EACH` 上的求导结构规则：反向是对体求反向的 `EACH`，共享输入的余切用 `reduce` 那棵树相加。
   - `EACH` 套 `EACH` 的融合，用 Camel 写成一个遍。

   判据：与 `with_grad` 数值一致；融合前后输出相同。
9. **性能验收**：`benchmarks/parallel/cases/merge_sort.cml` 改写成纯 Camel：递归到小块，合并也用 `loop` 写，不再调 `array::sort`、`merge_sorted`。判据：在工作站净场窗口，`prl` 相对 `nvm` 有加速；递归版 `reduce` 的耗时与 `fold` 同一量级。不够快就由优化遍处理（小叶子展开成循环时，保持同一棵合并树），不改回内置算子。
