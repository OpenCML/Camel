# 元组当值流进了算子实参

**日期**：2026-11-19
**提出者**：车道 N（`lane-ssa`，基线 `3df2b3b27`）
**状态**：待裁（本页写死一条默认建议）
**触发**：按作者 2026-11-19 的路 B 打包 `var` 形参的出口类型后，`linear` 113 红里抽样到一条**不是文字错**的类型错。

## 1. 是什么（一句）

一个带 `var` 形参的调用，值成了**元组**；这个值被当成「声明的结果类型」用在算子实参的位置时，算子看到的是元组：

```
test/cases/linear/byref/var_rule_subpasses.cml:60:43:
No matching function found for argument types: <> ((int, int), int);
operator '*' is not defined for these operand types
```

## 2. 最小用例

`var_rule_subpasses.cml`（第 54–60 行，逐字）：

```
    let f = bump
    let r1 = f(c, 2)          // bump(var x: int) —— 声明的结果是 void
    let r2 = f(c, 2)
    return a * 10000 + b * 100 + c + r1 * 0 + r2 * 0
```

`bump` 的结果是 `void`，所以 `r1` 在这个程序里**本来没有值**；打包之后它有了一个元组，于是 `r1 * 0` 拿到 `((int, int), int)`——**一个 `void` 调用变成了有值的调用**，这是这一类最锋利的形态：不只是类型名被读错，是**值本身多出来了**。

## 3. 与「53 条泛型」的关系：同一个根，不是同一处读者

- **泛型那 53 条**：读者是「一个**函数值**的签名」（算子按「有 `var` 形参就要给变量」检查实参）。
- **这一条**：读者是「一个**调用值**的类型」（运算符 `*` 的实参）。
- **共同的根**：两者都把**图的出口类型**当成了**语言类型**。所以它不是新的一类原因，是同一个原因在第三个读者上的表现。
- 它此前被算进 `var_rule_subpasses` 的 20 条里、并被记为「泛型」，**那个归法是错的**：20 条里至少这条与泛型无关。

## 4. 默认建议（写死）

**不给这一类加第二个例外，也不在算子实参处再解一次包。** 算子该读的是**表达式的类型**：有结果时是结果的类型，声明为 `void` 时**就是没有值**——按「`void` 调用没有值」去拒，而不是按元组去拒。理由与前两页同一条：打包是图的事，读类型的地方要读类型；在第二个地方解包等于把「调用交出什么」写两遍，也修不掉 `void` 那一半。

**范围**：在本页定下来之前，这一类的红不动、不 `--update-golden`、不改进诊断文字掩盖它。它要的读者与 53 条泛型是同一族的第三处，改那一族时一起过。
## 6. 更正（2026-11-19，本页第 2、5 节的前提是错的）

**更正一句**：本页第 2 节说「`bump` 声明 `void`」，**这是错的**。`var_rule_subpasses.cml:7` 是

```
func bump(var c: int, by: int): int sync {
```

`bump` 声明的结果是 **`int`**，不是 `void`。于是：

- 那个元组 `(int, int)` 是**结果 + `var` 形参**，属于**正常打包**，不是「没有值的调用凭空有了值」；
- 本页第 5 节「`void` 调用有了值」**不成立**；我在 `handBackVariableParameters` 里加的那条 `void` 守卫对这条用例**不生效**，实测也是不生效（失败文字一字未变）；
- 真正的形态是：`let f = bump` 之后 **`r1 = f(c, 2)` 是一次经由函数值的调用**，它的值没有被取第 0 份，于是 `r1 * 0` 拿到元组。**这仍然是「读者读错层」，但读者在「经由函数值的调用」那一处，不是 `void` 那一支。**

**留下的**：`void` 守卫本身是对的（声明 `void` 的体不该造值），只是它不是这条用例的原因；本页关于「打包把声明盖掉」的判断（第 2、5 节的机制描述）仍然站得住，错的是**我把它安在了一个声明 `int` 的函数上**。

## 决策者答（2026-11-23）：被重构取代

页 §6 已更正，问题出在"经函数值的调用没取结果"，取值应是声明的结果。这些页出自同一个根子：GIR 建图器在一个阶段里同时定类型和建图，并用 cell、打包位、就地改开放签名来表达 `var` 形参。核心抽象第 8 节定了前端分阶段：类型检查阶段"函数类型在这里定下来，此后不再改"；建图"只做机械的翻译……`var` 只降低成 SSA（原则 3.5），`Ref` 是唯一的单元"；第 5 节定了"函数类型有唯一的主人"，第 17 节定了"'开放类型'随前端重构消失"。于是本页问的机制在新前端里不存在：调用表达式的值永远是声明的结果，`var` 形参的终值是调用的另一份输出，由调用处重绑。lane-ssa 分支不合，归档。

带进 前端分阶段 的验收输入：`var_rule_subpasses.cml:54-60`（`let f = bump; f(c, 2)`）、`var_params.cml:52`（`bump_then`）
