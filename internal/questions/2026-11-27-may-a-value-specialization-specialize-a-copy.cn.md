# 值特化能不能专门化一张副本（“副本的副本”）

**状态**：等负责人回答（默认见末节：不允许，按“记账断口”修，不把嵌套当特性）

## 问句

运行期的**值**特化，允许以“一张已经特化出来的副本”作为 base 再造一张副本吗？
现状是**允许**：`std::cxx::specialize` 每回合扫程序里每张图的每个 `Func` 节点，
上一回合副本把调用点的 callee 改指自己之后，下一回合就**以这张副本为 base** 再造一层，
于是出现 `walk$spec0$spec11`、`walk$spec25$spec58` 这种**两层后缀**的名字。

设计页对这件事**没写**：
- §5.11 只讲**类型**特化的键与“递归不动点”（`:503-504`），并给类型特化记了“根”（`setTypeSpecializationRoot`）；
- §5.2:383 说函数值没有身份 ⇒ 副本的个数不算语义；
- **运行期值特化表**本身、以及“副本的副本”允许不允许，都没有一句。

## 读数（判“记账坏了”的部分不需要设计页）

```
23 = 13 张平铺 + 10 张嵌套（`walk$*` 共 23 张，名字前缀可直接读出）
16 = 表的项数（`src/stdlib/std/stats/stats.cpp:102`：`program.specializations().size()`）
⇒ 差 7：`draft_session.cpp:2108-2115` 的 keep 谓词按 **base 的 revision** 保项
   （`programKeyOf` `:1308-1315` 的键里带 baseRevision）
   平铺副本的 base 是 `walk`（用例的常量就是挑来让 `walk` 不被改写的）⇒ 13 项全在；
   嵌套副本的 base 是**副本**，那些 base 副本后续被再特化/改写 ⇒ revision 失配 ⇒ 项被丢、**图还在**
危害（不是审美）：`specializations.h:119-142` 的头注释写死 "a later session that needs that binding
makes the specialization again … one need costs one copy, not one per round"；
7 张副本没有表项 ⇒ 下一回合同一 (副本, 值) 请求不再命中，会再造一张、编号继续涨。
```

**判“这不是设计句过时”的硬证据**：同一个 plan、同一个文件里的 `simplify_growth_budget.table_is_not_an_owner`
断言**同样两件事**（名字集合精确 + `specializations === 副本数`），在**当前基上 PASS**
⇒ 同一句设计在隔壁用例上还成立 ⇒ 是这条路上行为坏了。

## 两边的理由

**不允许（记账断口该修）**
```
· 设计 §5.11:504「沿当前调用环，同一个函数以相同的键再次被实例化，**复用**环上已有的实例」——
  表项被丢之后同键再造副本，与这条相反
· 类型特化已经有“根”（`draft_inline.cpp:761-765`）；值特化没有对应物，这个不对称更像漏掉而不是设计
· 表的存在意义就是“一次需要的代价是一张副本、不是每回合一张”
```
**允许（嵌套是特性）**
```
· 副本的 base 被改写后，它的绑定确实变了 —— 从“当前 base 的现状”出发再造一张，语义上并非不可解释
· 但那就必须让表项跟着走（键不能只钉 baseRevision），否则表的承诺与实现不一致
```

## 默认（不等回答也照这个）

**按“不允许”修，且只修记账那一半**：
```
① 键不再只钉 base 的 revision：值特化照类型特化的形状记一个**根**，键用「根 + 累计绑定」，
   或（治标）keep 谓词接受“base 改了但副本仍被程序持有”
② 修完的验收：目标用例绿 + 兄弟用例 `table_is_not_an_owner` 仍绿 + 该计划其他红不增加
③ **不把“副本的副本”写成设计事实**：嵌套是否允许，仍等负责人一句；在定案前它只是“记账不该丢”的副作用
```

**可被推翻的条件**：负责人裁定“值特化可以套副本，且表项应当跟着 base 的改动重键”——那就不是断口，而是表要按“当前 base”重键。

## 影响面

- 1 条红（`opt.generic/specialization_survives_the_round.copy_is_reused_in_a_later_round`），不阻塞 `develop`。
- 修的是 `src/kernel/runtime/{draft_inline,draft_session,specializations}.*`（运行期特化表），属语义邻近改动，需要反控用例。
## 答复（决策者）

同意默认：不允许嵌套。值特化与类型特化一样有根：副本记下它的根函数，对副本再请求值特化时，按（根，合并后的值绑定）查表、在根上造。表的键不随副本的改写失效，"一次需要一张副本"的承诺因此成立，名字也只有一层后缀。用例按这条修。
