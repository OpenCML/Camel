# 一个 native 声明能不能带编译期参数

**一句话**：卷积的步长和填充是普通 `int` 参数，而语言的 extents 只许读维名或 `constas`；native 声明又不许带 `constas`。
**⇒ 于是 `conv2d ::<T>` 这样的声明，今天写不出来。**

## 卡在哪

```
**① 形状检查要读 `stride`/`padding`/`kernel` 这几个值**
⇒ **⇒ ② `docs/design-principles.cn.md` 409:**extents 里只许出现**维名**或 **`constas`**
⇒ **⇒ ③ 而 body-less 的 native 声明**不许带 `constas`**
   —— **⇒ 编译器当场拒:`ConstasInNativeDeclaration`(`0x0300019A`)**
```

**⇒ 三条各自都对，合起来就没有出路：要检查形状，就得让这几个参数进入 extents；要让它们进入 extents，就得是 `constas`；而声明里不许写 `constas`。** **

## 两条路，各自放弃什么

### (a) 声明里不写形状，让结果退成 `T[n,o,?,?]`

```
**⇒ 换来:`::<T>` 写得出来、能编译、调用处真的检查元素类型**
⇒ **⇒ 放弃:卷积/pooling 的输出**边长不再从参数算** —— 而今天 `conv2dInfer` 是算得出来的**
   （`(n + 2p - k)/s + 1`），**⇒ 所以这是把已经知道的事丢掉**
```

**⇒ 这一条与今天的主题相冲：今天一整天在做的，都是**把某一层已经知道的事交出去**。这一条是反过来的。** **

### (b) 允许 native 声明带 `constas`，把 `stride`/`padding`/`kernel` 变成编译期参数

```
**⇒ 换来:形状照样算,而且算在**类型里**,不靠一条 C++ 的 `infer`**
⇒ **⇒ 放弃:`stride`/`padding` 只能是**编译期常量**;今天它们可以是运行时表达式**
   —— **⇒ 而 conv 的 stride 写成运行时变量**有没有人真在用**?这是这一条的关键,我没查**
```

## 还有第三条，而它不在上面两条里

**⇒ 保留一条 C++ 的 `infer`，只让它**读自己的参数**，不手写第二份形状算术。** **

```
**⇒ 即:声明写 `T[n,o,?,?]`（(a) 的形状），而 `?` 由那个算子在**求值前**填上,
   填的时候读的是声明里已经写了的那些参数**
⇒ **⇒ 好处:形状不丢,`::<T>` 写得出来,`stride` 仍是运行时值**
⇒ **⇒ 代价:**类型层看到的仍是不完整的形状**,直到求值前那一刻 —— 而那是今天
   `tensor:shape` 丢掉列表长度那条缺陷的**同一种形状**（一个层把形状填晚了一步）**
```

## 我按默认走哪一条

**⇒ (b)。而支撑它的那一条我量过了：今天没有一处调用把这三个参数写成运行时值。**

```
**签名是 `stride?: int` / `padding?: int`(`src/stdlib/nn/signatures/nn.cml:37`、`:64`)**
⇒ **⇒ 而调用点两种:**
   ① **省略**（`conv2d(x, kernel(), bias())`,`nn_grad_check.cml:48` —— 走默认 1 和 0）
   ② **字面量**（`conv2d(input, kernel, bias, 1, 0)`,签名页自己的 `@example`）
⇒ **⇒ 全语料里把 stride/padding/kernel 写成变量再传进去的:** 0 处**
```

**⇒ 所以 (b) 今天**不破任何东西**，而它换来的是：**

```
**形状算在**类型里**,不靠 C++ 的 `infer`**
⇒ **⇒ 而那 15 个 `infer` 就可以删 —— 包括今天刚被按类型实例化的那十个
   `conv2dIn`/`pool2dIn`/`batchNormIn`/… 的形状那半边**
```

**⇒ 而若将来有人真要运行时的 stride，那时它是一个**新问题**（要不要为它保留一条不求形状的入口），而不是今天这个循环的解。** **

**⇒ 一个限定：**这条只量了 `test/cases`、`examples`、`src/stdlib` 三处**。若仓库外有人按 `stride` 是运行时值来写，那这次改动对他是**从能编变成不能编**，而这需要作者判断值不值。** **

## 而在定下来之前

**⇒ `nn-kernels` 那一笔已经让 **f64 真的算得出**（内核按类型实例化），也把导出侧的元素类型改成了随调用。** **

```
**⇒ 只剩「声明里的 `::<T>`」这一件,而它卡在上面那个循环里**
⇒ **⇒ 所以这不是一条车道没做完,是一个语言问题暴露在了车道尽头**
```

## 负责人裁决（2026-11-25）

选默认的 **(b)**：没有函数体的原生声明可以带编译期参数（`constas`），卷积、池化的 `stride`、`padding`、核大小成为编译期参数，输出形状在类型里算出。已写进设计原则"新的原语"一条之后，并记入日志。诊断 `ConstasInNativeDeclaration` 随之删除。
