# 块的名字不必先给语句定序

## 这件事是什么

块身份哈希把**区域内语句的先后**算进名字：两具只在“区域内两个写谁先谁后”上不同、而依赖结构相同的块体，会得到两个名字。名字不同本身不是错 —— 错的是同一份东西存了两份，少去一次重复。

今天修掉的是另一件事：**撞名**（两具真不同的块体共用一个名字 ⇒ `BlockPrograms::add` 只留第一个 ⇒ 静默跑错程序）。撞名已修，并有用例钉住（`test/cases/runtime/block_identity/*`）。**顺序这一条不跑错程序**，所以不急。

## 方向（先记下来，免得以后有人去“定一个规范化次序”）

名字**不必**靠排序得到。做法的方向是：**按依赖结构自下而上算哈希**。

```
每个节点的哈希 = 算子 + 各输入端口上的哈希（按端口序）
区域与块的哈希 = 从它交出的值和效应链往回算
```

依赖结构相同的两具块体，不论构造先后如何，这样算出来**自然同名** —— 不需要先给语句定序、不需要任何“次序规则”。这也是它比“定一个次序再按次序走”更对的原因：次序是**构造过程**的性质，而名字要读的是**程序**的性质。

## 代价与时机

```
· 现在的代价：同一个块偶尔存两份、少去一次重；**不会跑错程序**
· 撞名（会跑错程序）那条已修，所以这一条按“不急”处理
· 真要做的时候，判据是：两具只差构造先后、依赖结构相同的块体 **同名**（改前两个名字、改后一个名字）；
  以及现存的块名用例全部不变（逐字比），`BlockPrograms` 的条目数下降
```
