# `__iter__` 写不出来，于是那条查找要替它承担

**一句话**：作者①要「一个 `__iter__`」，而今天的编译器**不许声明 `__x__` 这种名字**（`gct/builder_internal.h:302` 的 `validateIdent`，只有 `func operator +` 那条语法能拿保留名）。所以 `Range` 的流落成了 `prelude.cml` 里的 `iter(r: Range) => int.. sync`，由「按类型的**声明模块**找同名函数」那条路命中。

## 这件事暴露了一个更早的缺陷

**⇒ 而 `range-ri` 量出来的是：那条路**对 `prelude` 里的类型一直没命中过**。**

```
**`moduleNamed` 只比 `Module::name()`（文件名给的名字）**
⇒ **⇒ 类型声明里记的是 `declaredName`（设计原则 10.1）**
⇒ **⇒ 两个名字对 `prelude` 不是一个字符串 ⇒ 5.7 那条查找**从来没成功过**,不只是 `Range`**
```

**⇒ 修是两个名字都认（`e93a627d9d`）。而它的后果是：`range-rn` 早上那个「`map`/`len` 非得绕到算子表」的坑，**不是设计选择，是被这个缺陷逼出来的**。** **

## 要作者定的只有一件

```
**`iter` 这个名字该不该是 `Range` 的成员表里那一个,还是该有一个保留名**
```

**⇒ 三条路，各自放弃什么：**

**(a) 保持现状：`for` 先问算子组 `__iter__`，没有成员就在声明模块找同名函数**

```
**⇒ 不新造语法,用的是 5.7 已有的查找**
⇒ **⇒ 放弃:`iter` 与 `map`/`len` 一样是**普通名字**,用户自己写一个 `iter(r: Range)` 就能盖掉它**
```

**(b) 让 `validateIdent` 放行声明里的 `__x__`，把 `__iter__` 写成真成员**

```
**⇒ 换来:名字不可盖、诊断统一**
⇒ **⇒ 放弃:`__x__` 从「只有算子语法能造」变成「谁都能声明」—— 那今天靠它护着的
   「内核保留名」就不再是保留的**
```

**(c) 只给 `__iter__` 开一个例外（一个白名单条目）**

```
**⇒ 换来:(b) 的好处而没有 (b) 的敞口**
⇒ **⇒ 放弃:白名单本身 —— 而下一个要保留名的东西会问「为什么它不在名单里」**
```

## 已答：三条都不取，`for` 是一个可重载运算符

```
**作者裁定（`D-1123-49`,`fsh-dev` 的 `09c805e8d`）：**
⇒ **⇒ 迭代钩子就是**运算符重载**,和 `operator []` 是**同一机制**,落到算子组 `__iter__`**
⇒ **⇒ 于是写成 `func operator for(r: Range): int..`**
⇒ **⇒ 不动 `validateIdent`;不按名字找普通函数 ——(a) 正是早上那页否掉的乙**
⇒ **⇒ `prelude` 里的 `iter` 普通函数换成 `operator for`;语言参考 7.4.5 的可重载列表加 `for`**
⇒ **⇒ 两条用例:用户类型写 `operator for` 能被遍历;同名普通函数 `iter` 不改变 `for` 的走向**
```

**⇒ 这条裁定比我下面的 (a) 好在哪，值得写下来：**

**⇒ 我把 `operator []` 当**先例**提了一句。而裁定说的是**它们同一机制**。** **

```
**「先例」仍然可商量 —— 先例可以被下一次例外推翻**
⇒ **⇒ 「同一机制」不可商量 —— 而一条规则是哪种,取决于它**有没有兄弟****
```

**⇒ `operator []` 就是 `for` 的兄弟。所以这不是「给 `for` 开一个口子」，是**把 `for` 补进那张早就存在的表**。而 (c) 的白名单之所以不好，正是因为它**造了一个没有兄弟的名字**。** **

## 决策者答（2026-11-23 22:10）

**三条都不取，用第四条：`func operator for(r: Range): int..`。** 迭代钩子就是一个运算符重载，和 `func operator [](v: Vec, i: int)` 同一个机制：`for` 是它重载的那个语言构造，声明落到算子组 `__iter__`（内核里字符串、映射的那几条本来就在这个组里）。

- 不动 `validateIdent`：保留名照旧只有运算符语法能造，`__iter__` 不会变成"谁都能声明"的名字，也不需要白名单。
- 不按名字找普通函数：(a) 正是早上 `how-a-named-type-says-it-converts-to-a-stream` 那页答复里否掉的乙；用户写一个 `iter(r: Range)` 也盖不掉它。
- 随类型走：命名类型的运算符在它声明所在模块导出的重载里找（原则 5.2），`Range` 的 `operator for` 跟着 `Range` 走，不用导入。
- 只交流：`operator for` 的返回类型必须是 `T..`，否则报错（与①的"只交 `T..`"一致）。

改动：语言参考 7.4.5 的"可以重载的"一句加上 `for`（被遍历的值，返回 `T..`）；解析器接受 `func operator for`；`for` 的建图对数组以外的值解析 `__iter__` 组。`prelude.cml` 里现在的 `iter` 普通函数删掉，换成 `operator for`。补一条用例：用户自己的命名类型写 `operator for`，`for` 能遍历它；再写一个同名普通函数 `iter`，确认它不改变 `for` 的走向。

另：`e93a627d9d` 的"两个名字都认"已按原则 10.1（模块名只有文件名这一个来源）返工，见派工 D-1123-48；查找修好后，`range-rn` 绕到算子表的那处随之撤掉。

## 更正：上面「两个名字」那一格是误诊（2026-11-23 晚，`lane/range-ri`）

`Module::declaredName()` 的写入方 `setDeclaredName` 从来没有调用者，所以它对每个模块都答 `""`——「`declaredName` 与 `name` 不是一个字符串」并不成立，5.7 那条查找也从来不是因为名字不同才没命中。真正没命中的是**搜索的集合**：它只问当前单元和 Camel 写的模块，而 prelude 两者都不是；`558819d0fa` 把 prelude 加进集合，判据随即由 0 变 1。

`declaredName_` 连它的访问器已在 D-1123-52② 里删除（原则 10.1：一个模块一个名字，就是文件给它的那个）。类型声明现在直接记**它声明的那个模块**（原则 5.2）：`declaringModulesOf` 交出的是模块对象，`moduleNamed` 与它搜的四个集合一并撤掉。本文第 11–13 行保留原文，因为否掉的是一条具体的推理。
