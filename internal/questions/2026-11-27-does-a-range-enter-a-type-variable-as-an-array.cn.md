# 一个范围能进入**类型变量**并绑成数组吗？

- 时间：2026-11-27
- 缘起：`task-153`（`Range` 按期望类型转 `int[]`，依据设计 §415）落地后，写明了 `int[]`/`T[]` 的位置都能物化；但 14 条 `WhenConditionUnmet` 不在覆盖内。
- 相关：`docs/design-principles.cn.md:415`（范围是值，按期望类型转 `int[]`）、§9.3（参数类型决定怎么读）

## 读数

```
14 条的形态：`f32(0 .. 24)` 这类 —— 形参是**类型变量**（`f32::<A>(x: A)` 一类），不是写明的数组
失败原文：`No candidate of 'f32' applies to (<> (Range))`、`WhenConditionUnmet`
机制：范围绑 `A = Range`，而 `is_compact_array::<A>()` 对 `Range` 为假 ⇒ 约束不满足
```

## 问句

**调用实参是 `Range`、形参是类型变量时，范围该绑成 `int[]` 吗？**

- 甲（默认）：**不该**。类型转换由**期望类型**驱动；类型变量没有期望形状，所以没有可驱动的转换。
  要传数组就写 `to_array(...)`。这条与 §415 不冲突：§415 讲的是“位置期望数组时如何物化”，不是“任何位置都物化成数组”。
- 乙：该。“没候选时把 `Range` 实参当 `int[]` 再试一次”—— 但这**不是转换**，是**改候选选择**：
  它会让“同一个调用在候选失败的第二次尝试里得到不同的实参类型”，并且要回答“重试只做一次还是递归”“重试失败后报哪个诊断”。
  设计页没有这条规则，落地前必须先写清。

## 默认做法（未裁定前）

按 **甲**：转换只在**写明了数组形状**的位置发生（`let x: int[] = 0 .. 3`、`f(0 .. 3)` 里 `f` 的形参是 `int[]`/`T[]`、
`return 0 .. 3` 而返回类型是数组）。类型变量与其它位置一律 `Range` 保持是值。
那 14 条按**用例侧**处理（写 `to_array(...)`），与“`Range` 传给非数组位置仍按原样拒绝”分开记账。

## 验收（按甲时要能证明）

```
① 写明了数组的位置：`let`/实参/返回 三处都物化，且 `Range` 未被当成数组（`len`/`print`/`map` 在 Range 上的行为不变）
② 类型变量位置：`f32(0 .. 24)` 仍报 `WhenConditionUnmet`（这是甲要的结果，不是遗漏）
③ 反控：`Range` 传给非数组位置的用例仍按原样拒绝
```
## 答复（决策者）

甲。原则写的是"按期望类型转"，转换由写明的数组形状驱动；类型变量没有期望的形状，范围绑成 `Range` 本身，这是"范围是值"的直接结果，不是遗漏。乙会让候选选择依赖一次重试，同一个调用的实参类型随重试改变，不加。那 14 条用例写 `to_array(...)`。验收照页上三条。
