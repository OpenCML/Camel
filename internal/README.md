# 内部协作

本目录是决策者与施工方之间的全部协作记录，公开发布时整体删除。`docs/` 只放公开文档。设计结论写在设计原则（`docs/design-principles.cn.md`）与设计稿（`docs/design/`）里，不只留在本目录。

## 每样东西一个位置

| 位置 | 谁写 | 内容 |
|---|---|---|
| `inbox.md` | 决策者写，协调者接手一条删一条 | 待接手的派工，滚动 |
| `backlog.md` | 协调者 | 手上的全部工作，一条一行 |
| `lanes.md` | 协调者 | 当前车道，一条一行 |
| `questions/` | 施工方提问，决策者答 | 一题一页；`questions/README.md` 是待答表（脚本生成） |
| `plans/` | 决策者 | 施工计划 |
| `reports/` | 施工方 | 读数与报告 |
| `reviews/` | — | 历次裁定与审查（只读；`questions-2026-10-29.md` 是封存的旧长页） |
| `archive/` | — | 只读：旧批次任务书、m2–m5 笔记、旧的待做清单、标准库笔记等 |
| `tools/` | — | 内部脚本 |

## 流转

1. 决策者在 `inbox.md` 写一条派工，编号 `D-日期-序号`，两三行：做什么、完成标志、细节在哪个计划或报告。
2. 协调者接手：从 `inbox.md` 删掉这一条，在 `backlog.md` 以同一编号加一行，提交说明写"接手 D-…"。inbox 只是中转，删了不丢。
3. 协调者自己发现的活（红基线、闸门欠账、`known_fail`、搁置的分支、问题页答复带出的跟进）以 `C-日期-序号` 进 `backlog.md`。
4. 开车道时在 `lanes.md` 加一行，写明在做 backlog 的哪几条；合入、卡住、收车道时当场改那一行。
5. 完成的 backlog 条目写上提交哈希，保留一周后删除；历史以 git 为准。

## 格式

`backlog.md`：`| 编号 | 来源 | 内容（一句话 + 指向） | 车道 | 状态 | 更新时间 | 完成提交 |`，状态只有 `待做`、`在做`、`卡住（原因）`、`完成`。

`lanes.md`：`| 分支 | 在做 backlog 的哪几条 | 分支读数 | develop 读数 | 下一笔预计 | 更新时间 |`。

每条 `在做` 的 backlog 条目都要能在某条车道上找到；超过两小时没更新的行算停滞。决策者每次检查读 inbox 里未接手的条目、backlog 里卡住和停滞的条目、车道表的在跑数（目标 6–8 条）。
