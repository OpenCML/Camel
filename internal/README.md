# 内部协作

本目录是决策者与施工方之间的全部协作记录，公开发布时整体删除。`docs/` 只放公开文档。设计结论写在设计原则（`docs/design-principles.cn.md`）与设计稿（`docs/design/`）里，不只留在本目录。

## 两种东西，两个地方

即时的东西走通道：派工、接手、回执、催办、车道在不在跑。它们几分钟就过时，放进要靠合并才能同步的文件，只会慢、会漏、会过时。要长期留下的东西进仓库：待办清单、计划、问题页上的推理、报告。

| 位置 | 谁写 | 内容 |
|---|---|---|
| 决策者通道（`tools/camel-oversight/`） | 双方 | 派工与回执、协调者的主动消息、车道与会话的实时状态；日志在协调者机器上 |
| `backlog.md` | 协调者 | 手上的全部工作，一条一行 |
| `questions/` | 施工方提问，决策者答 | 一题一页；`questions/README.md` 是待答表（脚本生成） |
| `plans/` | 决策者 | 施工计划 |
| `reports/` | 施工方 | 读数与报告 |
| `reviews/` | — | 历次裁定与审查（只读；`questions-2026-10-29.md` 是封存的旧长页） |
| `archive/` | — | 只读：旧批次任务书、m2–m5 笔记、旧的待做清单、标准库笔记等 |
| `tools/` | — | 内部脚本与 DSH 插件（`camel-oversight/` 是通道，`camel-lanes/` 把分支闸门放到代理面前） |
| `coordinator/` | 协调者 | 协调者自己的操作说明（`SKILL.md`，兼作运行时装载的那份技能）：分工、机器、路径、流程、坑 |

## 流转

1. **派工**：决策者经通道发一条，编号 `D-日期-序号`，消息自成一体（做什么、完成标志）；细节长的写进 `plans/`，消息里给路径。
2. **接手**：协调者当轮用 `oversight_ack` 回执 `taken`，并在 `backlog.md` 以同一编号加一行；不做就回 `declined` 写理由；做完回 `done` 写合入的提交。
3. **自己发现的活**（红基线、闸门欠账、`known_fail`、搁置的分支、问题页答复带出的跟进）以 `C-日期-序号` 进 `backlog.md`。
4. **车道**：开车道就是派子代理。车道在跑与否由通道实时读出（协调者会话的活子代理），不手写表；每条车道的读数（改了什么、测试数字）写进它的合并提交说明。
5. **提问**：写好 `questions/` 的一页后，用 `oversight_tell` 告诉决策者页名；决策者当轮答在页上，原则与语义类转负责人。
6. **主动找决策者**：卡住、出现他必须马上看到的读数、某个结果会改变他接下来派什么，用 `oversight_tell`。
7. 完成的 backlog 条目写上提交哈希，保留一周后删除；历史以 git 为准。

通道不通时（协调者没认领、决策者那边离线），派工由决策者存着待发，通了再发；不另开第二条路。

## 格式

`backlog.md`：`| 编号 | 来源 | 内容（一句话 + 指向） | 车道 | 状态 | 更新时间 | 完成提交 |`，状态只有 `待做`、`在做`、`卡住（原因）`、`完成`。

决策者每次检查读：通道上的车道在跑数（目标 6–8 条）与未回执的派工、backlog 里卡住和停滞（`在做` 超过两小时没更新）的条目。
