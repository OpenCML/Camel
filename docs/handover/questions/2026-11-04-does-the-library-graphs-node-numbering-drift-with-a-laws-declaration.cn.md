# 库自己图的节点下标，会随一条律的声明而平移——这算黄金漂移吗？

**状态**：待裁；我方默认见第 3 节，**按默认做，不停工**。

## 1. 问题

`stdlib/rulesets/transpose.cml` 里的律是**图**：一条律的参数表就是它的端口，端口是节点。所以

- 一条律**少一个参数**（把"多出来的 extents 端口"换成 `extent_of::<X>()` 之后，`sum_from_type_t` 等四条律各少一个），
- 库自己的图就**少一个节点**，而**其后所有节点的下标平移一格**。

于是 `std::jgir` 的导出里出现两种差异行：

```
"origin": 37871  →  "origin": 37875      （下标 +4）
"line":     868  →  "line":     872      （源码行号 +4）
```

**节点数两侧相等**（`erf_gradient_both_legs` 两边都是 120 个 `"origin"`），**结构、类型、边、调度零变化**。

## 2. 两条路

**甲：为了不漂，保留一个不生效的端口**——律照旧声明那个 `at`，只是右边不读它。**代价**：一个端口写在声明里、没有任何人读，是"为了让黄金不响"而留在图里的空位；下一个人读到它，会以为它有用。

**乙（默认）：认这是可接受的漂移，把成因写进提交正文**——因为它可算（少 N 个参数 ⇒ 少 N 个节点 ⇒ 下标平移 N），并且能同时证明"除它之外别处没变"（`grep -v '"origin"'` 之后只剩 `line` 一种行；节点数相等）。

## 3. 默认（照此做，除非被推翻）

**走乙。三条落法：**

1. **重建基线，并在提交正文写清**「这不是数值变化，是四条律各少一个参数端口带来的节点下标平移，节点数两侧相等」；
2. **正文里写 `grep -v '"origin"'` 之后剩下的行数**（今天这一笔是"只剩 `"line"`，也是 +4"），用它证明除下标外无其他差异；
3. **一页一问就是本页**，并把甲（哑端口）写成"被否决的替代"。

## 4. 为什么这是对的

黄金的职责是**发现"不该变的变化"**。当一处变化的成因可算、且能同时证明"除了它别处没变"时，**重建黄金并对原因留证，比让黄金一直红着强**——一直红着的黄金等于没有黄金，那和今晚"总在响的守卫"是同一个病：**守卫一直响，就没人再读它**。

## 5. 与别的裁定连着的两处

- 同一条道理今晚已经用过一次：`known failures` 从 14 掉到 2 **不是进展**，是"换了一种红"——**数字变化必须配一句解释，否则与"修好了"无法区分**；
- 本页的反面（甲的代价）与"不许为了过测试而改语义"（`docs/design-principles.cn.md`）一致：**为了让基线不动而留一个不生效的端口，是为测试改结构**。
