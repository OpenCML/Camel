# 和类型与有序集合：三个目标上不存在的值类型，是缺口还是边界？

**问题一句**：`std::cpp` 要给 `Json`、`Set<T>` 和 `Map<K, V>` 的表示，需要三个目标上不存在的值类型
（自描述和类型、有序集合、有序映射）；这算缺口（该修）还是目标不具备（该拒）？

## 三个形状，各自量过

`Json`（`modules/json/value.h`）：一个 kind 加一格载荷，载荷的类型随 kind 变——`Null` / `Bool`(bool) /
`Int`(int) / `Float`(float) / `String`(string) / `Array`(`Json[]`) / `Object`(`Map<string, Json>`)。
它是**自描述的和类型**：值自己带着"我现在是哪一种"，程序在运行到才知道。目标现有的拼法（数字、串、
数组、元组、结构体）里没有"一个字段的类型取决于另一个字段的值"这一形。

`Set<T>`（`include/camel/core/rtdata/collection.h`）：不是数组，是**持久 B+ 树的 Table**——叶子按 key
升序放元素，打印 `{a, b}`，`items`/`reduce` 也按升序走。

`Map<K, V>`：同一棵树的 Map 形态——叶子按 key 升序放键，值跟着键排，打印 `{k: v, k2: v2}`，
`keys`/`items`/`reduce` 都按 key 升序。

三个都不是"缺一条规则"：`ProgramValues::type` 里没有它们的位置（`Map`/`Set` 是运行时注册的
`CollectionType`，`Json` 是 `json` 模块注册的 `OtherType`，都落到"没有"），而 `include/camel/standalone/`
里也没有任何一个对应的值类型可以拿来拼——数组的文本是 `[..]`，集合和映射的文本是 `{..}`，
和类型要一个变体。三者都要**新增一个值类型**，而这一轮 worker 的边界是"表示只走既有那几条
（数字/串/数组/元组/结构体）"。

## 两种回答，各自的代价

**修**：目标要多三个值类型（一个变体、一个有序集合、一个有序映射），`T[..]` 只有一种表示这条规矩
要跟着扩写成"数组一种、集合一种、映射一种、变体一种"，以及每种类型的文本、比较、迭代顺序和
`items` 的形状都要与解释器逐字节对齐；三个类型的算子（`Json` 的 `kind`/`get`/`as_*`，`Set` 的
`add`/`remove`/`contains`/`union`/`intersect`/`difference`/`items`，`Map` 的 `get`/`insert`/`remove`/
`keys`/`items`）也都要一条条写出来。

**拒**：这三族 **38 条**（`Json` 11、`Set` 5、`Map` 22）从此记在"目标不具备"，语言侧写着这几个类型
存在、目标侧写着它们没有表示；以后再遇到读它们的程序，拒绝的原话就是"目标不具备"，不再是"写的人
还没有拼法"。

## 一句判据（进页）

两个类型撞在同一条边界上，就不是两次缺拼法，是一次边界问句——先问，别各修一半。
