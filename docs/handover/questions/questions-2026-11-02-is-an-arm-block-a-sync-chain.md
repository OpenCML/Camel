# 更正记录：`sync` 函数里 `if` 的臂块**不是**同步链（我们那条"默认 B"被推翻，不收）

**问题**：`func f(c: bool): int sync { if c then { println(1); println(2) }; return 0 }` 在 `c=true` 时该打印什么？

**答案（原则 3.4，`docs/design-principles.cn.md:171`）**：**只打印 `2`**。同步块不向内继承——它只管自己直接写着的语句；写在里面的臂、循环体与嵌套块按自己的写法执行，要同步就在那里写 `sync`。`if` 在同步链上、它的值是臂的结果 `println(2)`，所以 `println(2)` 执行、`println(1)` 不执行。要两句都打印，写 `if c then sync { … }`。

## 那么 P0-1 到底修了什么

**修的不是读数，是机制**：`computeExecutionOrder` 的收尾循环原来是 `if ((live[n] || isMember(n)) && …)`，即"区域里有它就排它"。3.1 说一个节点执行当且仅当**它所在区域里一个要执行的节点用到它**，3.4 说同步块不向内继承——两条合起来：**成员关系只决定"何时"，不决定"是否"**。现在收尾只按 `live[n]` 排。

**"被用到"怎么进臂**：经过臂的**值**。`arm_true.cml` 的图里，`N04(:io/println) -> N01(JOIN) [WITH]` 是臂的值进 JOIN 的端口，`N01(JOIN) -> N06(GATE) [SYNC]` 是执行者沿同步链到达 JOIN 的路。**所以这笔删的是一个取种，不是加一条边**；也**不是**"把臂当成同步块"——两件事：同步块不向内继承（3.4），而"被用到"可以经数据端口和同步边传进去（3.1）。

**A/B 实测：两版读数逐格相同**（旧收尾 vs 只按存活，24 格全同；全量 `8332 / 0 fail` 两版都绿）。**结论：那个取种在今天的图上已经是惰性的**——前端在计划之前就把"没人用到"的效应删掉了，所以不存在"live 没到、但还在区域里"的节点。这笔按"规则"收下，不按"读数"收下，提交信息里也是这么写的。

## 附：另设一个算子是第二套机制（原则 2.3 的正面判例）

负责人 2026-11-02 的裁定收回了他 10-31 写进原则 3.3 的那半句：**`:op/keep` 删掉，保活交给 `GATE`**。理由是他自己的话：

> **`GATE` 已经表达了这个意思**——一个数据端口读值、一个同步前驱，同步边传递"被用到"（`edges.cn.md` 第 5 节第 3 条）；`keep(x, v)` 就是值 `v`、同步前驱 `x` 的 `GATE`。**另设一个算子是第二套机制，违反原则 2.3。**

以后谁想加一个算子去解决"这个值要活到某一点"，**先问 `GATE` 能不能表达它**；能，就不要再添一个名字。判据是"同一件事在图上是否已经有一条边能说"，不是"这个算子好不好实现"。
