# 四个格从「编译错」变成「算错」之后，E9 该把它算一个缺陷还是两个

## 事实

2026-11-17 的 E9 全跑（树 `3d9b177ec`，`wrong 7 refused 3 crashed 12`）里，seed 429 的一个类换了边。

修之前，它的 4 个 `std::cpp` 格是 `CPP_COMPILE_ERROR`：writer 给一条 arm 发 `v1_branch = ;`，clang 说
`expected expression`。修之后那 4 格是 `MISMATCH`，而且**它们和同一程序本来就已经错的 95 格印出同一段错输出**。
数字上正好对得上：`cells_wrong` 272 → 276（+4），`cells_crashed` 71 → 67（−4），程序总数不变。

那段错输出是：

```
expected: q20 12, L3 3.0 1, L5 (31, 1), q20 5, L4 1 1 1, q20 31, null, L6 -7, L7 1, L8 false
got:      q20 12, L3 3.0 1, L5 (31, 1),               L4 1 1 1, q20 31, null, ...
```

第 4 行该是 `q20 5`，来自程序第 137 行：

```cml
q20(if false then v53 else 5, false);
```

**这一行整个没有打印**——不是印错值，是这次调用没发生。同一次运行里 9 个格（两台收集器 × 11 条管线之外
的 `std::cpp`）都一样，所以差异不在后端，也不在那次修法。

## 于是「这一类」有两种数法

**数法 A：一个缺陷。** 一个程序的 99 个格讲的是同一个程序的同一件事；`CPP_COMPILE_ERROR` 只是**让 E9 看不见**
那 95 格的错值——崩溃比错值先被分类。修掉编译错误之后，程序落到它本来就在的类里（`MISMATCH`），
所以 `crashed −1 / wrong +1`，程序总数不变，**这是分类变准，不是变出新缺陷**。

**数法 B：两个缺陷。** 编译错误（writer 发 `= ;`）与被丢掉的 `q20(...)` 调用是两处独立的错，
一次修法只关掉前一处；后一处今天没有任何类名——它藏在 `MISMATCH` 这个兜底类里，和另外六个数
据无关的错值混在一起（`wrong 7` 里 292/303/313/361/388/453 各自的错法都不同）。

**两种数法的差别不是学术的**：若按 A，seed 429 现在算「已修到它本该在的类」，E9 的三个数就是
`12/7/3`；若按 B，它算「compile error 已修、错值待查」，那么这一类要拆成两笔、并且 `MISMATCH`
需要能分得出「同一个程序的同一个错」与「另一处错」。

## 问的只有一件事

**一个 `CPP_COMPILE_ERROR` 被修好、程序落进 `MISMATCH` 时，E9 的类计数把它算作「同一个程序的一个缺陷」
（数法 A），还是「两个缺陷、需要拆类」（数法 B）？**

## 我的默认（若无答复，按此开工）

**按 A 数，并把 B 的那一半记成一笔待查的缺陷，不拆类。**

1. E9 的类今天按**程序**数（`programs_crashed` / `programs_wrong`），一个程序在同一轮里只进一个类，
   而选哪个类由「最坏的格」决定。这条规则本身是对的：**编译错误会掩盖同一程序里更轻的错**，
   而掩盖的方向是「少报」，不是「多报」。
2. 拆类需要 E9 能回答「这 95 格和那 4 格是同一个错吗」，而它今天只有 `MISMATCH` 一个名字——
   **拆不出来**。要拆，得先有「错值按第一次分歧的行归类」这种东西，那是一件工具活，不是一类修法。
3. 而**被丢掉的 `q20(...)` 调用是一件真事**，值得独自成页追踪：它是「调用没发生」，
   与「值算错」不同类。本页只把它写成事实与数字，不把它塞进某一类。

**代价要说清**：按 A 数，`MISMATCH` 这个类会继续同时装「值算错」与「调用没发生」两种东西，
`wrong 7` 会一直是「7 个程序，原因各不相同」。**这是今天的账，不是这一页造成的**；这一页只是把它写明。

## 这一页不改变的事

不改 E9 的类规则，不改基线，也不把这 4 格算成回归。它只说明：**那 4 格换类是因为它们并进了本来就在错的
95 格——`CPP_COMPILE_ERROR` 曾经让一个错值不被看见。**
