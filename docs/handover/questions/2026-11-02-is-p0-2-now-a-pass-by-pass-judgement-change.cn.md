# P0-2 的范围要不要按实测改？

**问：实测之后，P0-2 是否改成「先给依赖控制边的 pass 换判据」？默认建议：甲。**

## 实测（一次性分支，`Ctrl→Sync`，`-Tier fast`）

`total: 8447, pass: 4245, fail: 4192, skip: 10`；前 5 个族：`fault` 172、`attempt` 146、`stdlib` 144、`limit` 140、`rules` 129。

**为什么探 `Ctrl→Sync` 而不是 `Ctrl→Data`**：终局是"等待由 sync 链承担"，前者直接探终局；后者测的是把等待降级成数据依赖，红表不可解释。

**为什么只跑 fast**：行为类（`fault`/`limit`/`stream`/`entering`）都红了，记账类只会红一小撮快照 ⇒ fast 已足够。

## 两条路

- **甲（默认建议，并按甲开工）**：P0-2 的范围改成"给依赖控制边的 pass 换判据"，第一步选红数最大的族 **`fault` 172 条**，读数是红数下降多少。
- **乙**：P0-2 拆成批次，先只做"等待由 sync 链承担"的最小一片，其余等待排期。

**甲的理由**：4192 条红说明控制边在承重，删边不动 pass 不会变绿；**乙的风险**：最小一片做完也仍然红 4192 条，账上看不出进展。
