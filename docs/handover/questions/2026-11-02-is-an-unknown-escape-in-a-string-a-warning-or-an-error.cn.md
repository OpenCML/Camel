# 字符串里的未知转义是警告还是错误？

## 问的是什么

`LexicalDiag::InvalidEscapeSequence`（`0x100000`）今天**只是警告**：`diagnostics/registry.tsv` 那一行是
`warn`、`Fix` 一列写 `none: choice: the text to write instead is the writer's`，`docs/language/02_lexical.md`
的转义表把它写成规格——「**未知转义**：反斜杠与那个字符原样保留，并报 `LexicalDiag::InvalidEscapeSequence`
警告」。行为、码、消息都定死了，**没定的是"为什么不是错误"**：`docs/diagnostics.md` 里这一节只有
Fix/Message/Help 三栏，没有一句理由。

要你裁的就是这一点：**这条"只是警告"要不要一直这样。**

## 今晚撞上这条线的那条红（它不是实现错了）

Windows 腿上 `interpreter_first_use` 红在 `both plot calls wrote their image`，根因是夹具把平台路径
原样写进了 Camel 源码字符串：`plot([1.0, 2.0, 3.0], "D:\temp\run-1/twice-1.svg")`。于是

- `\t`、`\r` **是合法转义** ⇒ 路径里落进制表符与回车，`"D:␉emp␍un-1"` 根本不是路径；
- `\C`、`\m`、`\i` **是未知转义** ⇒ 原样保留，并各报一条 `InvalidEscapeSequence` 警告。

**所以那条红是"合法转义恰好撞上 Windows 路径"，不是诊断级别的问题**：把未知转义升成错误，那三条警告
会变成编译失败（更容易看见），但 `\t`/`\r` 那两处**依旧静默**——真正让图片没写出来的那一步，升级也
不覆盖。这一点是这一页最该记下来的东西，比结论重要。

## 两个默认

**(i) 保持警告（我方默认）**

- 理由：与 `\t`、`\n`、`\r` 这类合法转义并列时，用户最容易写错的是 `\C`、`\m`、`\i`——正是 Windows 路径
  上一定会出现的那些；它们已经各有一条警告，而单拿起一条警告去搜"哪个路径写错了"并不难。
- 代价：一个写错的字符串会**静默变成别的东西**（除非用户看警告），今晚这一条就是例子。

**(ii) 升为错误**

- 理由：一个静默变成别的东西的字符串，比一个拒绝编译的字符串更贵。`\C` 编译不过，用户两秒就知道；
  现在他要读警告、或者等到图片没写出来才发现。
- 代价：语言参考 2.5.4 的这条规格要改判；`diagnostics/registry.tsv`、`docs/diagnostics.md`、
  `test/cases/compile/escapes/plain.cml` 一起改；且**今天把 Windows 路径写进源码字符串的用例都会编译不过**
  （今晚这一条是夹具，改成正斜杠即可，但别处也许还有）。
- 另外要说清：升级**不覆盖** `\t`/`\r` 那一半，所以它不是"今晚这条红的修法"。

## 我方默认与往下怎么做

**按 (i)：不改判据，保持警告。** 今晚这条红按夹具修掉——路径用 `/`，已经在 `1f2a36558` 里改完，
同机同目录改前 exit 1 / 改后 `PASS`、Linux 计划 2/2。

若你选 (ii)，那是**一次语言判据的改动**，请连同"`\t`/`\r` 这一半怎么办"一起裁：只升级未知转义，
今晚这类红会从"静默写错路径"变成"多三条错误"，而真正那两处仍然静默。

## 一句话

**这条红的教训不在诊断级别上，而在"路径要写成 `/`"。** 这一页留着，是为了让下一个人知道：那三条
警告不是缺陷，是**合法转义与未知转义在一条 Windows 路径上同时出现**的样子。
