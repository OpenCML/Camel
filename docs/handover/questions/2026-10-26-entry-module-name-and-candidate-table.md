# 入口模块名：文件名还是文件里声明的名字？（外加：候选名表去留）

（一个模块解析收口后，只剩这两处要你定。实现在 develop 上已绿、`MG/R2`/`R3`/`R4` 都有红→绿读数。）

## 一、入口名不一致

文件是入口时，现在的行为是**两套名字并存**：

- **tag** 按**文件名**：`decl.cml` 里写了 `module tags_decl` 时，tag 打印成 `decl::kernel`；
- **自限定与诊断名**仍按**文件里声明的名字**（`tags_decl::…`）。

⇒ 同一个模块有两个名字，读起来会打架。请裁其中之一：

1. **一律取文件名**（那样文件里的 `module` 声明不再影响命名，甚至可以去掉/忽略）；
2. **一律取声明名**（文件名只是找到它的方式）；
3. 其它（例如"声明名与文件名不一致时报错"，或按你正在做的"删掉 `module` 声明"一并处理）。

## 二、候选名表（`MG/R15`）去留

导入时按**候选名**逐个试（`level.helper.foo` 这类点分展开）这套逻辑现在**原样保留**，并已用用例钉住它当前的行为（不是我们新加的语义）。你的选项：

1. **删掉**（只认写出来的那个名字）——我们就删，并把两条用例改成"找不到即报错"；
2. **写进设计原则**（承认候选名是语言的一部分）——那我们补文档并把行为固化；
3. 其它。

在你定之前，我们没有改它的行为（两个用例都绿）。
