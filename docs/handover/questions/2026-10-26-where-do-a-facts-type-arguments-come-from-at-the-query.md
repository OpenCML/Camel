# `fact` 的类型实参在查询点从哪里来？

**问谁**：语言作者（负责人）
**问什么**：`fact range::<T>(v: T)` 里那个 `T`，在**查询点**（`range(x)`）应当**由实参推出**、**由外层实例同名取**、还是**必须显式写出**（`range::<int>(x)`）？您给这项的验收是"**设计稿 7.5 的 `range` 例子要能编译并跑通**"，而 7.5 的例子按"推得出来"写（`case x + y => range(x) + range(y)`、`rule abs_nonneg(x: T) when range(x).lo >= 0`），实现上今天推不出来。请定取值口径，并把 7.5 的例子按定下来的口径改到可跑（例子本身另有两处问题，见下）。

## 量到的事实

1. **前端把查询建成的函数，形参类型被擦成 `Node`**：`src/parse/ast/builder.cpp` 的 `visitFactDecl` 里 `queryParams` 一律 `refType("Node")`——**头形参的声明类型没有保留**（只有 `const` case 的 fact 函数形参带 `T`）。所以查询点**永远推不出** `T`：`range(x)` 里的 `x` 静态类型就是 `Node`。
2. **唯一"知道 `T`"的地方**是外层实例的类型绑定（`instantiateRuleTemplates` 按 `entry.typeParams` 的名字绑定）。
3. **设计稿 7.5 的例子本身还有两处问题**（无论取值口径怎么定都要改）：`rule abs_nonneg(x: T) when range(x).lo >= 0` **没有声明 `::<T>`**（5.9 要求写出）；`Interval::of_type` **库里没有**（要么补进库，要么按现成库改写成 9.5 那种 `hull`/`intersect` 形态）。
4. **`fact` 的 `with` 形式已经实现**（上一批由五条用例钉住），所以这里只差"类型实参"这一半。

## 候选

- **甲（显式写出）**：查询处必须写 `range::<T>(x)` 或 `range::<int>(x)`（5.9 第二层的显式形式）；推不出时诊断**提示写出**。不新增表面规则，实践上最省事；**但设计稿 7.5 的例子要加 `::<T>`**，也就是您那句"7.5 例子能编译跑通"的验收要按加了 `::<T>` 的版本算。
- **乙（外层实例同名取）**：不写，按事实声明的类型形参**与外层实例的类型形参同名**匹配。7.5 的例子照原样能过；代价是引入"两个无关声明的 `T` 同名就相连"，`rule abs_nonneg::<U>(x: U) when range(x)` 这种**取不到**（名字不同）。
- **丙（按被查询节点的值类型取）**：要求把规则/事实形参的**声明类型**保留到 GIR（现在条件函数形参一律 `Node`）；改动最大，而且**在"只拿到 `Node`"的遍里仍然只能写显式**——等于甲的一个超集。
