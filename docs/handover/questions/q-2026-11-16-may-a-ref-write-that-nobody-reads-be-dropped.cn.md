# 没人读的 `Ref` 写，可以删掉吗？

（2026-11-16，协调位提出，等作者裁定。这一条的默认做法已在同轮开工。）

## 事由

原则 3.3 写着：**「对 `Ref` 的写由之后的读者用到（3.1）」**。实现里**这句话没有任何机制**：

```camel
func p(): int {                  // 非 sync 体
    let c = state::ref(0)
    state::set(c, 1)             // warning: EffectNotExecuted
    return state::get(c)         // 印 0
}
```

`std::gir` 显示 `state:set` **节点根本不在图里**——写被删掉了，不是「跑而不生效」。而同文件里 `println(...)` 照常执行（外部写是区域的根），`let v = state::set(c,7)` 也照常执行（`set` 的**值**被读）。

**中间那一档——「盒子被之后读、但写的值没人要」——没有任何机制实现。** 图里 `set` 与 `get` 之间只有 `ORDER` 边，而 liveness 与死写判定都不看 order。

## 默认做法（本轮按此开工，除非作者另有裁定）

**把「写一个句柄资源」也算作被所在区域用到**：`OperatorSemantics::writesOutside` 从「`writes && reachesOutside(cls)`」放宽到「`writes && (reachesOutside(cls) || cls == Handle)`」。`Variable` 类**留在谓词外**（11-15 已裁定：给 `var` 赋值不是效应）。

**为什么不能用更保守的「本图里有读者才保活」**：图内读者判不出来。三个形状证明它两头都错——
- 盒子经 `return` **逃逸**、读者在调用方（`R6`）；
- 盒子被**闭包带走**、读者是之后那次调用（`R7`）；
- 两个同类型句柄名**可能指一个盒子**（`R8`，3.3 明说访问按书写顺序除非能证明是不同值）。

这三条的读者都不在本图里，却必须执行；而「真没人读」的那条本图里也没有读者。**条件式保活会把这三条判成可删。**

## 代价（作者要认的就是这一句）

**`R4`（真没人读的自写）会从「删掉」变成「执行一次」。** 也就是说：

> **用「死写可删」换「句柄写一律执行」。**

- 它**不可观察**（句柄只经 `get`/`update`/`set` 观察，没人读就没有观察点）；
- 但在意它的是两处：**调试器的行断点**（`feat/tools/debugger` 有「一条从不执行的行不是停点」的用例）与**耗时**；
- 若作者要保住死写删除，那就得接受 `R6`/`R7`/`R8` **继续不执行**——**即继续违反 3.3**。两者不可兼得，因为判据缺的是一条数据边，而补数据边是语义重构（`get`/`update` 要加版本操作数，句柄这边今天没有 `:var/after` 那样的版本节点）。

## 验收用哪六条

修完之后这六条必须**执行并印出**：

| 形状 | 今天 | 修后应为 |
|---|---|---|
