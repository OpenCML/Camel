# （A）不必要：割点对「结果含函数」也是**类型可算**的

**问句（一句）**：让 `split` 割「结果含函数」的提升图时，前向半要不要**在图在手时**才被拓宽（(A)：替身在图在手的洞里换掉）？

**答（本页的结论）：不要。** 割点（前向半拿什么、答案是什么）对「结果含函数」是**纯类型**的函数——就是 `Lift<T>` 本身——所以它**不需要**「图在手」那个洞，解析器**能**自己算出来。

## 一、为什么不是 (A)：那条硬约束会把它自己的目标挡死

按 (A)，前向半的参数表要按**图**拓宽（多一个它读到的切向端口）。而那条硬约束说：**图不在手的调用点必须拒，并说出「这里没有图」。**

**⇒ 二阶的目标恰恰是「图不在手时用前向半」**：`vjp` 的体是 `let (value, lin) = forward(w)` —— 这句在**源程序里**、在割存在之前就被类型化（按 `Split<F>` 的替身）。割无论如何拓宽图里的那一半，这个调用点都只按替身配实参。

```
所以 (A) + 硬约束 在二阶上只能**把墙改名**：从「值半读切向端口」变成「这里没有图」
⇒ 而 rename 不是进展，是记录
```

**⇒ 这不是「(A) 做错了」，是 (A) 的适用面：它适合「答案的宽度只有图知道」的形状（残差正是这样）。而这一格的宽度**不是**只有图知道。**

## 二、这一格的宽度是类型算的：割点按**分量**，不按位置

`split.h` 开头对它自己的判据写得很清楚（逐字）：

> `split` cuts that function in two **along the pair, not along a position**

裁定给的提升形状是逐分量的：

```
Lift<(float, (float) => float)>  =  ( (float, float) , Lift<(float) => float> )
                                      ↑ 值分量提升为它自己的 pair   ↑ 函数分量提升为提升后的函数
```

于是「沿 pair 割」在逐分量形状上**有唯一的答案**，而且是**类型算的**：

```
结果 (T0...Tn)，每个分量：
   Ti 有切平面      ⇒ 前向半拿 Ti 的值，反向半拿 Ti 的切向
   Ti 是函数        ⇒ **前一 半拿它的提升**（提升后的函数是一个值，不是切向），反向半拿不到东西
   Ti 两边都没有    ⇒ 这一格没有提升形状（法则整条弃答，另案）
```

对那对 `(float, (float)=>float)`：前向半答 `(float, Lift<(float)=>float>)`，反向半只答 `float` 的切向。

**⇒ 关键：这个决定只读 `liftedShapeOf`，一个字都不读图。** 所以解析器（只有类型）和割（有图）**算的是同一条法则的两个输出**，替身不再是替身 —— `Split<F>` 的答案类型按法则变宽，但**是可算的**，没有洞。

## 三、**撤回**：这一节原来的断言是错的（同一个方向数不出来）

原来这里写的是：「那半逐分量割开后，值半答 `((float,float), Lift<F'>)`，里面的 `Lift<F'>` 是**值**（闭包捕获是残差，全是值）⇒ **不需要 `dw`**」。

**这句话是错的，撤回。** 追一遍实参就看得见：

```
`Lift<F'>` 是「在 (w, dw) 处的提升闭包」——它是一个**具体的**线性映射，
它的体里读 `dw`（`dw` 是 `first_with_as_param(F)` 的参数 `w` 的切向，**是 `Lift<F'>` 那个体的参数/捕获**）
⇒ 谁要建出 `Lift<F'>` 这个值，谁就要有 `dw`
⇒ 值半若只拿「值的那半」，它建不出 `Lift<F'>`
```
而「值半改成不是照抄、而是调用被调者的**一阶前向半**」也救不了：那个前向半的答案里同样带着 `Lift<F'>`，它自己也要 `dw` ⇒ 它自己的割就会拒（逐字就是现在那句 `the value half reads the tangent of parameter 0`）。**递归到底只有一句话：一个「依赖方向」的函数分量，一个没有方向的值半交不出来。**

**⇒ 所以第二阶的方向必须从**某个**调用点进来，而今天唯一可用的那个调用点（`vjp` 的体 `let (value, lin) = forward(w)`）没有方向。** 这已经不是割的法则，是**「提升后的闭包把方向当参数还是当捕获」**。

## 三之二、撤回后：`Lift<F'>` 是**族**（作者裁定，写死）

**问句（一句）**：`Lift<F'>` 是一个**族**（方向作**参数**收），还是一个**点值**（把 `dw` **捕获**进去）？

**默认：族。** 依据是裁定的**写法本身**：

```
裁定逐字：`Lift<A ⇒ B> = Lift<A> ⇒ Lift<B>`
⇒ 右边 `Lift<A> ⇒ Lift<B>` 里，`Lift<A>` 在**箭头的左边** —— 箭头左边是**参数**
⇒ 若方向是**捕获**，写法会长成 `Lift_{da}(F)` 一类，即**一个带下标的点值**；
  而裁定给的是**类型到类型**的等式，**没有下标**
```

**反支的代价（写死）**：若作者裁「点值」⇒ `vjp` / `grad` 的**写法**必须把方向带进来，**割点不是瓶颈**，这一格的全部工作要重排。

**它给出的二阶形状是「两次喂」，不是「一次捕获」**：

```
`forward` 收到 `(w, dw)` 后答 `(float, Lift<F'>)`；`lin` 是那个**族**，**再喂一次 `(x, dx)` 才得到二阶方向**
⇒ 于是三件事同时成立：
   ① 割点成立：前向半答 `(float, Lift<(float)=>float>)`，那个 `Lift<F'>` 是**值**（一个等 `(a, da)` 的函数），不需要 `dw`
   ② `vjp` 的体不用改（`let (value, lin) = forward(w)` 仍按替身类型化，而替身现在**算得对**）
   ③ `Lift<F'>` 拿到的是**一个提升后的参数**（`(a, da)`），不是切向量
```

**⇒ 红线在这支下仍然成立**：**若你的实现让函数拿到了一个切向量，那你实现错了东西。**

## 四、落地形状（按「族」落地）

```
一处：`modules/transforms/split.cpp#splitHalvesWith` —— 出口按 `liftedShapeOf` 逐分量割，
      前向半的答案 = 「值分量 + 函数分量的提升」，反向半 = 「有切平面的分量的切向」
零处：解析器不用改（它调的就是 `splitHalvesWith`），`Split<F>` 的声明不用改（它是 `<>` 泛型）
阳性对照：feat/transforms/split 30/30/0 必须逐字不变（今天的 pair 结果逐分量割开与今天逐字相同）
阴性臂（与上面同一次提交）：
      ① 结果里有「两边都没有」的分量（如 `bool` 与函数同处） ⇒ 法则弃答 ⇒ `split` 拒，拒句点名那一格；
      ② 反向半要一个函数分量的切向（源程序真的读它） ⇒ 拒，拒句点名「函数分量没有切向」。
      **两条的拒句必须是新句子，不是改前那句**——否则证不了松的是哪一类。
```
**⇒ 这一节按「族」落地；「点值」那一支下割点不是瓶颈，`vjp` 的写法才是。**

### 四之二、落地前必须先有的那一条：`Lift` 的**解码**（同一个头的第二个函数）

割点要回答「该答案的第 i 个分量，是值还是要切向」，而它手里只有 `Lift<R>`，没有 `R`。**没有 `R` 就判不出**，除非把 `Lift` 反过来读一次——而这是可算的，判据就在法则本身：

```
对非 pair 的 `Y = Lift<R>`，它的每个成员 m 都是某个源成员 ti 的 `Lift<ti>`：
  · m 是函数            ⇒ ti = 反解 liftSignature(m)（参数取前半、答案反解一层），前向拿 m 本身
  · m 是二元 tuple (a,b) ⇒ 这是 `Lift<ti> = (ti, Tangent<ti>)` ⇒ ti = a，前向拿 a，反向拿 b
  · 其它                ⇒ 法则不答（这一格没有提升形状），拒
```
**为什么不会误读**：一个**真正的**二元 tuple 分量 `(x, y)` 在 `Y` 里出现时会**翻倍**成 `((x,y), (x,y))`，与 `Lift<ti>` 的 `(ti, Tangent<ti>)` 形状可区分；而 `Lift<(float,float)> = ((f,f),(f,f))` 被读成 `ti = (f,f)` 也一致。**⇒ 解码是唯一确定的。**

**⇒ 所以落地的第一笔不是 `split.cpp`，是 `lift.h` 里的 `liftDecodeOf`**（`Lift` 的逆，同一头、同一条法则的第二个函数），`splitHalvesWith` 再读它。**我把这一笔留在这里而不是先写一半**：解码不先立起来就改割点，等于用「猜这个二元 tuple 是不是 pair」去判语义——那正是本章第一节撤回的那类错误。
