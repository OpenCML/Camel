# 生成器状态按值传递时，「还没写过的局部」用什么表示？

> 一页一问。**默认建议写死在下面，本轮按默认开工，不另等。**

## 这一页要的答复

作者第 ④ 条要「生成器跨 `yield` 的状态按值在拉取之间传递」。我按这条把机器改成：步进函数
`(S) -> (elem, stream)?`，`S` 是一个值元组；每次拉取的值 = 一个把当次 `S` **按值**带住的闭包；步进体开头
把 `S` 解开成自己的局部，`yield` 处把局部打回 `S'`。这一步会同时拿掉两样东西：机器对格子的捕获口
（`capture_ports_generator` 归零），和程序闭包在生成器体里被机器答案粘住的那条链——`62` 页记的类型分叉
随之消失。

**卡住的地方只有一个，而且它是每个局部都会遇到的，不是边角情形：**

```
visitGeneratorBody 里，程序写的每个局部都是「有类型、没有值」的格子：
  addCellOfType(name, typeOfPlaceholder(expr))   -- 类型来自 typeof，值在语句那里才写
对应算子 :var/new/empty，注释原文：
  「A cell with no value in it yet, of the type its single `with` argument names.
    What a local of a generator body becomes; its value is written where the statement stands」
只有 pc / halt 是 addCell（int 字面值，创建时就有值）。
```

一个值元组**没有「这个槽还没有值」的写法**：每个槽从创建那一刻起就必须是一个 `T` 的值。而 `T` 是任意类型
（结构体、泛型、函数），机器造不出「空 `T`」；算子表里只有 `:op/tag_is_null`、`:op/tag_null_value`，
**没有把 `T?` 拆回 `T` 的算子**（`include/camel/core/operator_table.h`）。

**⇒ 问题是：生成器里「还没执行到声明」的那个局部，状态值里占的那个槽用什么值填？**

## 默认建议（按此开工，不另等）

**槽的类型写成 `T?`，机器在读到它时直接拆开，并为此加一个算子（`assume`/`unwrap` 一类，语义是
「这个值已知不是 null，拆它不检查」）。**

依据：

- **拆开不会失败，所以不该在现场检查**：一个局部的读如果排在它的声明之前，是名字先用后声明，GCT 那一关
  已经拒了；机器能读到的槽一定已经写过。所以这是一个**机器不变量**，不是程序要付的检查。
- **不加拒绝、不改成语言限制**：另一条路是「生成器的局部必须在第一个 `yield` 之前写过」，那是一条新的
  语言限制，会拒掉今天合法的程序（`reading()` 的 `var x = 0` 在第一个 `yield` 之前，算是合法；但
  `yield` 之后再声明局部是今天允许的形状），会连带动用例与文档，范围比一个算子大。
- **也不做按 `pc` 的和类型**：那要给每个生成器造一个带 N 个变体的枚举类型并在每次拉取上判 `pc`，
  是比一个算子重得多的机器。

**因此本轮的做法**：`S` 的每个程序局部槽是 `T?`，创建时全 `null`；步进体开头用新算子把槽拆成局部；
`yield` 处把局部（以及 `pc`/`halt` 这两个 `int`）打回 `S'`。新算子只由编译器发，不写进任何一个 `.cml`。
