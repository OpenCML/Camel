# 问题：启动/声明成本这道闸量什么、天花板在哪（H177，note ⟨83d65581⟩）

## 问题
两件，都来自同一次重测：(a) H142 给的四条启动命令天花板（40 / 45 / 100 / 90 ms）保不住
"负载 215 下仍成立"这条保证——H142 自己的负载倍数把今天的安静中位数推成约 127 / 113 ms；
(b) 30% 的声明共享率这条线已经抓不住它当初要抓的东西（H177 量到 4.6 ms 的回归只读到 24.5%）。
H177 的任务只许动天花板，所以把数字交上来；两条都改变"计划量什么"。

## 选项与代价
| 选项 | 代价 |
|---|---|
| (a) 不改（现状） / 抬到 150 / 140 ms | 抬：恢复 H142 那条保证，但要先做一次**负载 200 的实测**确认（H177 自己的规则：不拿外推改数字）；不改：安静主机上仍绿，但 2026-10-23 在负载 106–130 下 `imports_all` 已经报红（92.8 / 101.4 ms 对 90），保证事实上只剩"安静时成立" |
| (b) 选项 1：按模块自身时间计一次 | 比例会远高于 30%，要重新定基线，等于换一把尺子 |
| (b) 选项 2：直接闸绝对总量（如 `total_ms` ≤ 9 ms） | 简单可比；一条新数字要按主机标定，换机器要重播 |
| (b) 选项 3：加结构断言"每个 (阶段, 模块) 每轮恰好出现一次" | 确定性，抓"编译两遍"不依赖比例；抓不到"单次变慢"这一类 |

## 倾向
(a) **先做负载 200 的实测再决定 150 / 140**，并把"负载下红不算回归"的口径写进计划（否则每次
共享主机忙起来都是一次假红）；(b) 选 **3 + 2** 的组合：结构断言管确定性的重复编译，绝对总量管
整体变慢，30% 这条线退休。**判断在决策者**（量什么属于检查口径）；若 (a) 要恢复的正是负责人
当时要的保证，数字由负责人点头。
