# 少给名字的解构：一个四值 `loop` 写成 `let (a, b) =` 该拒绝，还是该按位置取前两个

> **少给名字 = 静默丢值 = 静默算错数。而语言已经拒绝写 `_` 来表示"这个不要"，却允许用"少写名字"做同一件事。**

日期：2026-10-31　车道：`lane-mcts`

**要作者答的一句**：多值 `loop`（以及元组）的解构，**名字少于值**的时候应该**拒绝**（诊断），还是**按位置取前几个**（今天的实现）？

## 怎么撞上的

`showcase/d4-mcts/selfplay.cml` 的第二个循环带四个状态（模型、优化器状态、至今的 loss 数组、步数），
我写成 `let (losses, trained) = loop m = …, opt = …, ls = …, s = 0 …`。**编译不报错**：`losses`
拿到的是第一个状态（`Net`），`trained` 拿到第二个（优化器状态），数组和步数被无声丢掉。第一次
被看见，是它当成数组去格式化的时候：

```
error[SemanticDiag::DeclaredTypeMismatch]: This value has type 'Net', which is not the declared type 'int'.
```

也就是说：**错不在解构，错在"后面正好有个类型不匹配"才被发现**。如果丢掉的槽和留下的槽同型（两个
`float` 状态的循环），这一步连错都不会报，程序会安静地算下去——这就是"静默算错数"，不是风格问题。

## 最小程序（探针实测，三个读数）

主程序：

```cml
func main(): int sync {
    let (x, y) = loop a = 1, b = 2, c = 3, d = 4 while a < 2 do {
        return (a + 1, b + 1, c + 1, d + 1)
    }
    `four-valued loop, two names: x=${x} y=${y}`->println
    return 0
}
```

读数：`four-valued loop, two names: x=2 y=3`，exit 0，**没有诊断**（`c`、`d` 消失）。

同一个探头上的另外两点：

- **名字多于值**会报错，但位置没用：`SemanticDiag::InvalidAccessIndex: Invalid access index: '2'.`，
  箭头指的是 `func main(): int sync {` 的 `func`（1:1），读者看不出这是"解构少了值"。
- **`_` 写不出来**：`let (x, _) = …` 是 `SyntaxDiag::UnexpectedToken: Unexpected '_'; expected a name.`
  （2:13，位置准确）。所以语言在**明说**"这个不要"时拒绝，在**不明说**时放行。
- **不只是 `loop`**：`let (x, y) = (1, 2, 3)` 同样打印 `x=1 y=2`。所以这是**元组解构**的形状，
  `loop` 只是我撞上的入口（循环体返回的正是元组）。

## 两条路

**(A) 拒绝**：名字数与值数不一致就报诊断，位置指在解构上（与"名字多于值"共用一条，但把位置改对）。
- 理由：静默丢弃是算错数的入口；`_` 已被拒，说明语言本意是"忽略要明说"。
- 代价：今天若有程序靠少写名字丢值，会转红；先按 `let (` 扫一遍即可知道有多少。

**(B) 允许**：钉住今天的语义（按位置取前缀），写进语言参考，并把"名字多于值"的诊断位置也改对。
- 理由：不改语义，`let (x, y) = loop …` 在"只关心前两个"时省事。
- 代价：与 `_` 被拒自相矛盾；丢掉的可能是**循环状态**，读代码的人看不出少了哪个槽，只能回数
  循环头有几项。

## 我方倾向

**A**。`_` 被拒是这条判据的另一半：语言已经表态"忽略要明说"，那么"少写名字"这条更含糊的忽略就不该
通过。B 若保留，就得把"少给名字是合法的部分解构、`_` 不是"写进文档当规范，读者才不用试出来。

## 堵着谁

没有明天就堵的活：`mcts` 这条车道已经绕开（四个名字全写全，并在 `selfplay.cml` 的注释里写明"所以
下面的四个名字必须是四个")。它堵的是**下一个多状态循环**——两个同型状态就足以让它安静地算错。
