# 一条转置律没被一阶走查读到，算不算"律已经补上"？

## 问什么

D1（"删掉引擎的 pullback"）的账是按**算子**记的：一个算子要么有转置律，要么没有。但量下来存在第三种情况——
**律写了、也对了，而一阶 `vjp` 的走查根本没读到它**，数字却仍然和引擎逐位相同。于是"补上了"这句话有两个意思：

* (a) 族里有了这个算子的律（`stdlib/rulesets/transpose.cml` 的 `export rule`）；
* (b) 某条程序真的把它读到了（`TRANSPOSE … rhs=…` 那行里有它）。

这一页问的是：D1 的清单按哪个记。

## 测到的情形（2026-11-04，`tranche` 树 = `origin/develop` 545b24d92 + 本车道改动，8 条全绿）

`rhs=` 是走查自己列出的、它读过的律；`same=true` 是库层 `vjp` 与引擎 `grad` 逐位相同。

| 算子 | 引擎读数 | 走查 `rhs=` | 它的律被读到吗 |
| --- | --- | --- | --- |
| `neg` | `[-1.0, -1.0, -1.0]` | `sum_t,neg_tensor_t` | 读到 |
| `abs` | `[-1.0, 1.0, 1.0, -1.0]` | `sum_t,mul_tensor_t` | **没读到** |
| `sqrt` | `[0.25, 0.3333333333333333, 1.0]` | `sum_t,divide_t,mul_tensor_t,sqrt_t` | 读到 |
| `log` | `[1.0, 0.5, 0.25]` | `sum_t,divide_t` | **没读到** |
| `rsqrt` | `[-0.0625, -0.5, -4.0]` | `sum_t,mul_tensor_t,rsqrt_t` | 读到 |
| `maximum` | `dx [0.0, 1.0, 1.0, 0.0]` `dw [1.0, 0.0, 0.0, 1.0]` | `sum_t,add_tensor_t,mul_tensor_t,subtract_t` | **没读到** |
| `minimum` | `dx [1.0, 1.0, 0.0, 1.0]` `dw [0.0, 0.0, 1.0, 0.0]` | 同上 | **没读到** |
| `divide` | `dx [0.5, 0.25, 0.125]` `dw [-1.5, 0.1875, -0.015625]` | `sum_t,subtract_t,divide_t,mul_tensor_t` | 读到 |

## 为什么分成两半

走查是**按线性半边的节点**要律的。非线性算子的前向律把斜率写成 mask 或乘积（`abs` 的两个 mask、`maximum` 的
`where` 与 `1 - where`、`log` 的 `dx / x`），算子本身不进线性半边，所以它的转置律没有人问。反过来，
`sqrt`/`rsqrt` 的前向律要**重算**算子（`sqrt(x)`、`rsqrt(x)`），cut 把这次重算当残差带进后向半边，
走查就会在那个重算节点上问律——于是它们被读到。`neg`/`divide` 则是算子真的落在了一条线性值上
（`-dx`、`dx / w`）。

这不是缺陷，是同一条边界的两侧：律问的是"这个**算子**的余切是什么"，而不是"这条程序会不会路过"。

## 两个答案

**(a) 按算子记（本文默认）**：律在族里就算有。理由：族是给未来问的——二阶走查、手写的以该算子为算子的线性函数、
以及将来某条把算子放进线性半边的前向律；而 D1 要删的是引擎的 `setVjp` 表，删得掉的前提是"库里对任何一个方向都能答"，
不是"今天这条程序走过"。

**(b) 按读到记**：没被一阶读到的律算未完成。理由很硬：一条没人执行到的律，写错了没有任何测试会红——
今天 `abs_t`、`log_t`、`maximum_t`、`minimum_t` 四条的正确性**只有"和引擎是同一个公式"这个论证，没有运行时证据**
（它们的读数之所以绿，是因为数字由 mask 那条路算出，和律无关）。

## 默认与代价

默认按 (a) 记账，并且加两条要求，缺一不可：

1. **没被读到的律必须写明没被读到**。本车道 8 条已经在
   `test/plans/feat/compile/transforms.plan.toml` 的读数表里逐条写出 `rhs=`，注释里也说了哪四条没被读到、为什么。
2. **欠账要写在账上**：今天没有任何一条用例能读到 `abs_t`/`log_t`/`maximum_t`/`minimum_t`。补证据的路有两条，
   都是独立的一块工作——一条二阶 `vjp` 程序（对 `abs` 节点再求一次导），或者一个手写的、以该算子为算子的线性函数
   交给 `transpose`。两条今天都不在本车道的范围内。

代价：如果作者选 (b)，上面四条要降级成"待证"，D1 的清单会把它们记成未完成；如果选 (a)，清单可以前进，
但必须留着这句"它们的正确性目前是论证而不是测量"。
