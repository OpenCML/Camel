# 负责人这个名字，要不要对一张名册？

**状态**：待裁；我方默认见第 3 节（**甲：先不管名册，名字是自由文本**）。
**缘起**：作者 2026-11-03 00:30 的裁定要求每条 `known_fail` 带「标记 + 负责人 + 原因」三样，这一轮把
它做成了闸门（`test/tools/run-tests.mjs#checkKnownFailMark`）：缺负责人、缺原因、负责人写占位词、
原因写空话或说不清卡在哪，计划一加载就被拒。**但"负责人"这一格今天只检查"不是占位词、不是空"**，
它不检查这个名字是不是一个真的存在、而且答应了这件事的车道或人。

## 1. 读数（今天的闸门能证明什么、不能证明什么）

1. **能证明**：16 条 `known_fail`（展开 22 条 known failures）现在**全部**带齐两样，缺任一样即拒；
   `test/tools/selftest/knownfail/` 五份夹具给出四种缺法的读数（缺负责人 / 缺原因 / 原因写「待修」/
   原因说不清卡在哪），加一份三样齐的对照组。
2. **不能证明**：`known_fail_owner = "lane-fwdclosure"` 与 `known_fail_owner = "lane-nobody"` 在闸门
   眼里**完全一样**。全树 16 条里出现的负责人只有三处：`lane-fwdclosure` 9 条、`lane-transforms` 5 条、
   `lane-order-region (batch item 9)` 2 条——**其中 `lane-order-region` 这条在 `origin` 上已经查不到
   分支**（`git ls-remote --heads origin lane-order-region` 空），批表里它的最新提交是 `—`。也就是说
   "名字填得出来"和"有人在负责"仍然是两件事，只是第二件今天由人读，不由闸门判。

## 2. 两条路

| 路 | 做法 | 代价 |
| --- | --- | --- |
| **甲：名字仍是自由文本** | 闸门只管"填了、不是占位词"，谁存在、谁答应由派工的人核对；负责人在每条 `[XFAIL]` 下面打印出来，读到的人当场能发现名字不对 | 上面第 1 节第 2 条的缺口保留：一个不存在的车道名照样过闸。好处是零维护，且**改车道名不用改闸门** |
| **乙：对一张名册** | 新增 `test/owners.json`（车道名 / 人名 → 在不在、管什么），闸门按名册校验，写不在册的名字即拒 | 名册本身要维护：车道开张、合并、撤销都要改一处，否则**闸门会用"名册过期"把一条好计划拒掉**——这正是"用默认值糊过去"的镜像错误。而且它只证明名字在册，仍不证明那个人答应了这条用例 |

## 3. 我方默认

**甲。** 理由：这一天要的是"**不许靠记忆**"，甲已经把这条做到了——条目、负责人、原因三样在文件里，
缺一样就红，读闸门的人还能在 `[XFAIL]` 行下直接看到负责人。乙多买到的是"名字存在"，代价是名册与
现实漂移时闸门开始说谎，而漂移是这张树的常态（本轮就撞上 `lane-order-region` 已不在 `origin`）。

**若作者裁乙**：名册只登记"车道在不在"这一位，不做权限；漂移的处理写死一条——**名册里没有的名字
报"不在册"，但闸门仍然通过并在 `[XFAIL]` 行下打印 `owner-not-in-roster`**，让漂移可见而不是变成一次
拒绝。也就是说乙只加读数，不加拒绝，拒绝仍留给"缺字段"那一种。
