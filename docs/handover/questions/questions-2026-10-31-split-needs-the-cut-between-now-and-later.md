# `split` 的"现在就有"和"以后才有"在哪一刀切开？

**问题一句**：4.2 写 `func split::<F>(f: F): Split<F>`，但 `Split<F>` 在 4.2 和 §2 的类型清表里都没有定义；
而"后一个接残差与其余输入"里的**"其余"**是一个类型级的事实——**输入里哪几个是"现在就有"、哪几个是"以后才有"，
在签名里没有写法**。这一刀怎么切？

## 4.2 原文的三条规则（照抄，供核对）

- **循环**：每一轮的残差作为收集输出保存，是值不是闭包（原则 9.9 现有规定），后一个函数里循环按同样的轮数执行，逐轮取残差。
- **分支**：条件是残差，后一个函数按同一个条件选臂。
- **调用**：被调函数各自拆分，残差按调用嵌套。

直线代码（这一档先做的）不在三条里，是他们的底座：函数体只有一串算子应用时，"前一半算出能算的一切、
后一半接残差"就是按程序顺序把每个值归到一侧。

## 两种写法与各自的代价

**甲（默认建议）**：切口就是**函数的 `with` 参数**——`Split<F>` 定义为

```camel
type Split<F> = ((..ParamsOf<F>) => (ResultOf<F>, ResidualsOf<F>), (ResidualsOf<F>, ..WithOf<F>) => ResultOf<F>)
```

前一半吃普通参数、回结果与残差；后一半吃残差与 `with` 参数。代价：`reinterp<jvp>` 的切向量要放进 `with`
（`jvp` 的既有写法不是这样），`ParamsOf`/`WithOf` 已经要靠 §2 的包展开才存在；好处是签名里不用切参数包，
`..ParamsOf<F>` 与 `..WithOf<F>` 都是现成的两个包。

**乙**：切口是显式的一个类型——`split::<F, Now>(f: F)`，`Now` 是"现在就有"的那几个参数的类型（元组），
其余是"以后才有"。代价：要把 `ParamsOf<F>` 减去 `Now` 才对得出"其余"，**参数包的减法**语言里还没有
（§2 只写了逐成员展开，没有删成员）。

## 残差的形状与命名（甲乙都一样）

直线代码的残差是**一个值**（不是闭包），形状是"后一半要用的那些中间值，按它们在程序里出现的顺序"：

- 前一半按原顺序算；一个值只被前一半用，就不是残差；被后一半用到，就是残差的一项。
- 残差**按项编号**（`r0`, `r1`, …），项的顺序就是程序顺序——这样后一半的代码与原来的代码逐行对应，
  读数才能和原函数逐字节对。
- 带名字的中间值（`let y = …`）在残差里仍用 `r<序号>`，不另起名字：残差是**后一半的输入**，
  它的名字不该依赖前一半的局部名字，否则拆分改一次名字就改一次接口。

## 这一页的默认建议，以及按它往下做的第一步

按**甲**做：`split` 的签名写成 `func split::<F>(f: F): Split<F>`，`Split<F>` 用上面的两半定义；
直线代码的第一版只处理"普通参数里没有依赖 `with` 的"情形（依赖 `with` 的值也归到"以后才有"）。
若作者选**乙**，回退的是那一层签名与切口的取法，前一半/后一半的走法不变。
