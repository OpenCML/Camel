# 三件待定：`attempt` 的调用写法、`never` 的重载、`if` 里出现 `error` 的类型

（错误系统那一批做完了，只剩这三件没有已决定的规则；另外附一条我们自己记下的缺陷。）

## 一、`attempt`

现在是 `attempt(f, x)` 这种**调用形态**。要改成"函数变换"就得先定三件：
1. 调用写法是什么（`attempt(f)(x)`？还是别的）；
2. 结果类型是什么形状（成功/失败两臂各是什么）；
3. 旧的 `attempt(f, x)` 写法报什么诊断，还是继续接受。

现在的实测：`consistency.fail_never` **11/11 绿**，`attempt` 能隔离 `fail`、值无人要时不执行；但**不能**把 `attempt(f)` 当函数传来传去。

## 二、`never` 的重载

一个 `never` 实参与别的重载同时匹配时选谁——**今天没有已决定的规则**。其余六项语义都有用例（签名可写、报告打印 `never`、可赋任何类型、分支合并取另一臂、泛型推断、不能有值），只有这一项没覆盖。

## 三、`return if c then error("…") else v`

被判 `BranchReturnTypeMismatch`。我们的读法是：`error` 值**只在声明 `T!` 的位置**成为失败那一臂，所以两臂在没有 `!` 的地方合并就是类型错误。
语言参考 7.3 的示例已改成**臂内** `return error(...)`（在主机上跑过，输出与文档一致）。
若你要的是"`if` 的 `error` 臂把整个表达式变成 `T!`"，说一声我们改回来。

## 四、另记一条缺陷（不属上三条，供你知悉）

单独的 `fail` 语句被"结果未使用"规则拒，措辞是 `…changes nothing`——对故障不合适。
