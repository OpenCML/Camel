# `gc_soak` 的那一跳不是 `!=` 改 `!(==)` 造成的 —— 作者 12:10 的机制假设被读数证伪，预算怎么办

## 问的是什么

12:10 的裁定把 `gc_soak_long.generational` 的 1.9× 归到一条机制上：`!=` 在图上建 `!(==)`，而 `1de967a2a` 删掉了 `eq_*`/`ne_*` 的 URI 表项。按裁定把窥孔做进 fastvm 后端（`f2c1f313a`，图不动）之后，读数说**这条机制不是那一跳的原因**。要你裁的是：**预算怎么办**。

## 为什么这四条足以证伪那条机制

1. **用例里没有那个形状。** `gc_soak.cml` 的条件是 `left == 0`，全文没有一次 `!=`；它的字节码改前改后都是 1 条 `LEQ`、0 条 `:op/not`。窥孔在这个用例上**无事可做**，1.9× 不可能是它造成的——也不可能是"它被删掉"造成的。
2. **`1de967a2a` 删的东西没人查。** 那次提交删的是 `eq_*`/`ne_*` 的 URI 表项，而 `INE`/`LNE`/`FNE`/`DNE` 四个 opcode 从未被删：`gotovm.cpp`、`casevm.cpp`、`jit/backend/x64/x64_backend.cpp` 一直还在执行它们。删表项时没有任何地方按那两个 URI 查表，所以它不可能让谁变慢。
3. **窥孔本身是对的**，而且在形状真正出现的地方很大：−16.4%（fvm）、−18.4%（jit），图 sha256 不变。所以它**不该因为治不好 `gc_soak` 回退**——它没有让任何读数变差。
4. **那一跳落在别处。** 本目录另一页的 profile 已经把它点名：`:op/atos` 52.6% + `:op/add_s` 41.8% = 94% 的算子时间，就是每步构造 48 个字符串的活；收集器暂停合计 0.26%。比较指令碰不到那 94%。

## 顺带纠正一处算术（`f2c1f313a` 的提交信息里的）

那条信息写「prelude 声明 11.22 + compile 10.96 = 22.2/24.1 ms，×3200 ≈ +77 s」。**这两处都错了**：`parse prelude` / `gct prelude` / `declare prelude` 是 `compile` 的**子阶段**（`--time-phases` 里 depth=1），加不得；而两行的 "total" 是**墙钟**，HEAD 那次撞上了别的套件（30.12 wall 对 17.09 CPU）。按 CPU（装载无关的那一半）重算：

| 命令 | e7629168b | 0bcd59bab | 涨 |
|---|---|---|---|
| `imports_nothing` | 5.60 ms | 17.09 ms | **+11.49**，其中 `compile` 0.70→11.66，而 prelude 的三个子阶段 3.24+4.76+3.22 = **11.22（占 98%）** |
| `inspect --ops`（27 模块） | 39.75 ms | 100.75 ms | +61.0，其中 prelude 自己的 parse/gct/declare 12.67、`gir` 0.30→12.94 |
| `imports_all` | 40.92 ms | 95.16 ms | +54.2，其中 `compile` 35.81→87.42 |

正确的结论比原来那条更干净：**每个进程把 `prelude` 重编一遍（parse+gct+declare 11.22 ms、随后的图编译在同一个 `compile` 里）就是 `imports_nothing` 的全部增长**；`collfuzz.many_small` 的 +70.8 s 里，按每进程 +11.49 ms × 3200 ≈ **+37 s 能由这条解释**（一个进程若导入整份标准库则付 +54 ms，即 +173 s），所以那一跳落在"声明缓存"能覆盖的区间里——这是另一本账，与 `gc_soak` 无关。

## 我们的默认

- **(i) 预算不动；把 `gc_soak` 的真实热路径（`:op/atos` / `:op/add_s` 的字符串构造）作为下一条性能任务。** 我们按这条往下做。
- **(ii) 认为「1.6」这个目标本身要重定价。** **我们不支持**：按你的口径，只有「测量基线被证明有错」才改预算；这里错的是**目标所依据的机制**，不是基线——基线（`1.605`）仍然能测出来，只是它不是 `!=` 这条路能到的。

要你裁的是：**同意 (i)（预算不动、转向字符串构造）、还是你另有判断。** 在你回话之前，预算一条不动，窥孔留在树上。
