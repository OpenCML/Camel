# 一个编辑算子，该保证「落地」，还是只保证「写进草稿」？

**状态**：待裁。从 `opt::cse` 那条红上发现。

## 1. 事实

为了让用 `graph` 模块写的遍也能把「折掉的持位节点」的位置交给后继，本轮给模块加了
`set_sync_predecessor(t, n, pred)`（`stdlib/graph.cml`、`modules/graph/txn.cpp`），它落到
`GraphDraft::setSyncPredecessor`（`src/runtime/draft.cpp:2132`），后者只是一句
`setSyncInputs(id, only)`。

实测（临时读数，未提交）：

```
[probe] graph=227 ref=8 refKind=11 pred=4 predKind=11 syncBefore=0 predHasUser=0
[probe] wrote=1 syncAfter=1          ← 草稿里读得到这条边
after %8 Oper :op/assn_l : var int sync_in=0    ← 提交后的图里没有
result 27 27                          ← commit 没有报错，也没有走回退
```

于是：**算子报成功、草稿里确实有、`commit` 也成功，图里没有。** 三个「成功」叠在一起，
调用方没有任何返回值可以判断「我写的那条边还在不在」。

## 2. 问题

一个编辑算子（`replace`、`erase`、`set_sync_predecessor`、以后可能的每一个）**承诺的是什么**：

- 承诺「写进了草稿」，交付出去有没有它不负责？
- 还是承诺「写完的图里一定有它」？

今天的模块只有前者，而使用者（一个遍）需要的是后者：遍的判据写在图上，判据说「这里该有一条
sync 边」，那么遍结束时这条边不在，遍的判据就是假的，而它拿不到任何信号。

## 3. 默认（本页写死）

**编辑算子必须保证落地，或返回「未落地」；只写进草稿不算成功。**

具体到本模块：`commit` 之后，算子（或 `commit` 自己）核对这次编辑留下的东西还在不在，
不在就返回「未落地」——对 Camel 侧就是 `throw`/`error`，而不是静默返回成功。

理由：

1. 「编辑的成功」与「图的状态」是两件事，而调用方只能观察后者（遍的判据都写在图上）。
   不给出这个信号，任何用模块写的遍都只能靠「另写一段代码自己核对」，那等于把不变式
   复制到每个调用点。
2. 今晚已经出现过同族的第二个例子：`closeChainOver` 在没有前驱可交时**静默放弃**，
   那正是 `fold` 一条红的来源。两者的差别只是「没返回值」与「返回值没说清承诺了什么」，
   修法却是同一个问题的两面：**编辑必须能报告「没做成」**。
3. 反过来（只承诺草稿）也不是不能成立，但它要求调用方每次都用「读回来的图」验算一遍，
   而遍在运行期**读不到自己刚写的东西**（读算子读的是冻结图，草稿没有读入口）——
   于是那条路今天根本走不通。

## 4. 一句可以带走的话

> **不是「不可判」，是「判错了」——它判的是草稿，而交付的是图。**
