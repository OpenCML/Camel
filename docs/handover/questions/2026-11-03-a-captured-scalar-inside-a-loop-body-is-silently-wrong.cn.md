# 一个被循环体捕获的标量，抬升后静默算错

## 问什么

`jvp` 抬升一个体内读到外部值的循环时，**不拒绝、不诊断，给错数**。这页记下四条读数（含基线复现），把"错数"这件事从聊天记录里搬成不可丢的东西；成因还没找到，§5 明说拼不出自洽的机制。

## 1 纸面与实测

两条程序的形状一样，都是递推 `x ← x·c + k`，`k = 1, 10`，`s = 1`；差别只在"体里怎么读那个外部值"。

```cml
// A：捕获一个标量，体里直接读它
func f(s: float, c: float): float {
    return loop x = s for k in [1.0, 10.0] do x * c + k
}
// B：捕获一个结构体，体里通过成员投影读它
type Pair = { a: float, b: float }
func k(s: float, c: Pair): float {
    return loop x = s for kk in [1.0, 10.0] do x * c.a + c.b * kk
}
```

纸面：A `f(1,2) = (1·2+1)·2+10 = 16`，`∂/∂s = c² = 4`，`∂/∂c = 2cs+1 = 5`；B 取 `c = {a:2, b:1}` 也是 16，`∂/∂s = a² = 4`，`∂/∂a = 2sa+b = 5`，`∂/∂b = a+10 = 12`。

| 程序 | 纸面 | 实测 |
|---|---|---|
| **A 捕获标量，直接读** | 16 / 4 / 5 | **12.0 / 2.0 / 1.0** ✗ |
| B 捕获结构体，投影读 | 16 / 4 / 5 / 12 | 16.0 / 4.0 / 5.0 / 12.0 ✓ |
| 对照 `g`：把捕获换成常量（`x * 2.0 + k`） | 16 / 4 | 16.0 / 4.0 ✓ |
| 对照 `h`：`let d = c;` 再读 `d` | 16 / 4 | 12.0 / 2.0 ✗ |

读数原文（`std::nvm`）：
```
A v=  12.0 / A d1= 2.0 / A d2= 1.0
B v=  16.0  d1= 4.0 / B d2= 5.0 / B d3= 12.0
g v=  16.0   d= 4.0        h v=  12.0   d= 2.0
```
A 那条**没有任何诊断**：`REINTERP jvp function=f … tangent=computed source=ruleset rules=jvp_mul,jvp_add`，没有 `skip=`，没有 `diagnostic`。它不是"红"，它是错。

## 2 不是这两笔提交弄坏的（基线复现）

把 `modules/transforms/jvp.cpp` 换回 `542ba0dda`（develop）自带的那一份，同一个程序重跑：`g` 仍是 **16.0 / 4.0** ✓，`h` 仍是 **12.0 / 2.0** ✗。所以错数在基线就存在（`542ba0dda` 时它所在的形状还没人量过），与本支行 `7544e9221`（数组态）`e1b00e8af`（结构体态）两笔无关。

## 3 边界：标量直接读会错，结构体投影读不会

同一具身体、同一组数，只有"体里怎么读那个外部值"不同：

- 外部值是**浮点标量**、体里**直接**当操作数读 ⇒ 错（A、h）。
- 外部值是**结构体**、体里通过 `c.a` / `c.b`（`GCAccsKind::StructKey` 投影）读 ⇒ 四个数全对（B）。
- 根本没有外部值、把捕获换成**常量** ⇒ 对（g）。

所以接错的不是"capture"这个大类，是"体里对外部**已被配对**的标量节点的直接读"这一条。

## 4 探针：循环本身的接线是对的

```
PROBE loop ref=7 index=1 stateStart=1 inKind=1 inRegion=0 inType=float paired=1
```
（`kind=1` 是 Port，`inRegion=0` 在体外，`paired=1` 说明它有对。）控制变量下 `g` 打印的是同一行 —— **两条程序的循环接线一模一样**：一个 iterable、一个配对的状态输入，`capture` **不在**循环的 norm input 里（它是跨区读）。所以问题不在循环的输入表，在体里那几个节点的接线。

## 5 三个读数拼不出一个自洽的机制

把 iterable 换掉，A 的读数不收敛：

| iterable | 纸面 | 实测 |
|---|---|---|
| `[1.0, 10.0]` | 16 | 12.0 |
| `[1.0]` | 3 | **1.0** |
| `[10.0]` | 12 | **10.0** |

`12 = 1·2+10` 像是"状态没接回 `s`"；但 `[1.0]` 给 1.0（= `s`）、`[10.0]` 给 10.0（= `k`），这两条与"状态不接回"或"只跑一轮"都不合。**我拼不出一个能同时覆盖这三条的机制**，所以这页只把事实钉住，不猜成因；成因要等抬升后的图打出来再写。

## 6 抬升后的图：接线是对的，错在运行期

把 `draft` 里抬升完的图整张打出来（`h`，全部 22 个节点；`kind` 0=Data 1=Port 4=Fill 5=Accs 10=Func 11=Oper 15=Loop）：

```
node reg kind di type           norm        with
0    0   1    1  float          -           -       s 的值端口
1    0   1    2  float          -           -       ds
2    0   1    3  float          -           -       c 的值端口   ← 体直接读它
3    0   1    4  float          -           -       dc
4    0   1    5  float          -           -       轮次元素 k
5    0   0    -  float          -           -       k 的零切线
6    0   1    6  (float,float)  -           -       体里的状态对端口
7    1   5    7  float          6           -       状态的值半边 .0
8    1   5    8  float          6           -       状态的切线半边 .1
9    0   0    -  float[]        -           -       iterable
10   1  11    9  float          7,2         -       mul_d(值半边, c)
11   1  10   10  float          7,2,8,3     -       mul_d 的切线调用 (x,y,dx,dy)
12   1  11   11  float          10,4        -       add_d(mul, k)
13   1  10   12  float          10,4,11,5   -       add_d 的切线调用
14   0  15   13  (float,float)  9,21        19,17   循环：输入 [iterable, 初始对]，体结果是 19
15   0   5   14  float          14          -       循环结果 .0
16   0   5   15  float          14          -       循环结果 .1
17   0   1   16  int            -           -       轮次序号
18   0   0    -  (float,float)  -           -       体结果的模板
19   1   4   17  (float,float)  18          12,13   体结果对（值 12，切线 13）
20   0   0    -  (float,float)  -           -       初始状态的模板
21   0   4   18  (float,float)  20          0,1     初始对 (s, ds)
```

这张图**照纸面算就该是 16 / 4 / 5**：状态从 `.0` 读值、`.1` 读切线；`mul_d` 的两个操作数是"状态的值半边"和 `c` 的值端口；两个切线调用拿的是 `7,2,8,3` 与 `10,4,11,5`，与 `x·c + k` 的规则参数一一对应；循环的输入是 `[iterable, 初始对]`，体结果是那个 `(值, 切线)` 对。

它和 `g`（常量）唯一的差别是**第二个操作数**：`g` 是 `norm=5,8`，`8` 是区 0 的 **Data**（常量 `2.0`）；`h` 是 `norm=7,2`，`2` 是区 0 的 **Port**（`c` 的值端口，`di=3`）。同一形状，Data 算对、Port 算错。

所以判据里的那一问："错在值半边、整对、还是第三样" —— **第三样**：体里读捕获既不是取半边也不是取整对，而是把**体外那个端口本身**接进了体（`valueOf` 对参数端口无效，于是走了 `copyOf` 兜底，把端口原样递过去）。接线位置是对的；错在**运行期对"体内读体外端口"的取值**，而常量（Data）那条路不走这个取值。这也解释了为什么 §5 三条读数拼不出机制：它们量的是症状，机制在另一层。
