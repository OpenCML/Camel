# 去掉打包位与从声明算，互为前提

**日期**：2026-11-19
**提出者**：车道 N（`lane-ssa`，基线 `775ecc12b`）
**状态**：**给作者的问题页**（本页写死一条默认建议，并写清它替代的是哪一种读法）
**触发**：按作者 `11148d2fe` 的「打包后的出口由声明算出来、打包位去掉」，先把最靠近的一处读者（`builder.cpp:155/167`）从「读 `funcType()->exitType()`」改成「读 `graphExitTypeOf(funcType())`」后实测。

## 1. 现象（可验）

只改那两处读，`feat/compile`：

```
before:  total 2635, pass 2619, fail 0, known 16
after:   total 2635, pass 2614, fail 5, known 16      killed 0, timeout 0
```

失败从 `Error: unexpected output: (0, 1)` 起（两条同形）。一个**纯读法替换**改掉了五条用例 ⇒ 那个「现算」不等于原来那个类型。

## 2. 差在哪（本页核心）

`graphExitTypeOf` 对**已打包**的输入逐字幂等——`src/compile/gir/builder_helpers.h:113` 第一支：

```cpp
if (exit != nullptr && exit->code() == TypeCode::Tuple) {
    return exit;
}
```

所以差别不在「已打包的输入」上。差别在它回答的问题：

- **`funcType()->exitType()`** 回答「**这个图**交出的出口是什么」；
- **`graphExitTypeOf(funcType)`** 回答「**按这个签名建出来的图**会交出什么」。

喂后者一个**没有打包**的声明（入口图，签名声明 `int`、带 `var` 形参），它就按规则造出 `(int, int)`——**多包一层**，而那个图从来没有打包。**「算」于是把一个从没发生的打包算给了它。**

## 3. `(0, 1)` 的出处

`test/plans/compile/effects_syntax` 的 `var_parameter.write_outside_sync.nvm`。`(0, 1)` 是「声明 `int` 的入口被当成交出 `(int, int)`」之后的输出形状；**本该是一个 `int`**。

## 4. 要问作者的一件事（是一对，不是一个）

- **(甲)** 那个位**保留但改名**（例如「这个图是不是入口／打没打包」），让「算」有一个可问的东西——**位回答「打没打包」，不回答「出口是什么」**。
- **(乙)** 「算」不该在**这些读者**处发生，而应在**建图时一次定死**——但那就是**另一个字段**，正是作者 `6b733b8ae` 否掉的形状。

**⇒ 这两条正是作者否「第二字段」时没有说的那一半：**「算出来」需要知道**该不该算**，而那个知识目前只有位带着。

## 5. 默认（写死：甲）

**默认甲：位保留、改名、注释写清它回答的是「这个图打没打包」，不是「出口是什么」。** 理由：乙就是已被否的「第二字段」；甲只是把**同一个位**换个诚实的名字，不新增状态、不新增读者规则，而它让「从声明算」有一个可问的前提。

**若作者否甲**，那说明他要的是一条更长的路——「该不该打包」在建图时就消掉，读者端根本不需要问。**那这条页就是那条路的入口**，而它需要作者先定：一个图的出口**是否**被打包，能不能在建图时被彻底消掉，而不是换一个地方存着。
