# 开秩数组上的 `t[0]`：取元素，还是取"去掉那一维的行"？

**问谁**：语言作者（负责人）
**问什么**：核心取位置按您的裁定带轴落地后（`t[i]` 就是轴 0、写位置的那维从结果里去掉），**开秩**（`f32[..]`）上的 `t[0]` 该给什么类型？今天的行为是**元素**（`f32`），而按设计原则 5.4"什么秩都是同一套规则"也可以推成 **`f32[..]`**。

## 量到的事实

- **今天的读数**：开秩 `f32[..]` 上 `t[0]` ⇒ **`f32`**（元素）。
- **谁靠它**：`export_branch`、`ort_branch`、`ort_dynamic_batch`、`pass_export_equals_export_model` 四个 ONNX 用例靠这个读法写出 `t[0] > 0.5`（导出时输入是开秩/动态 batch）。**若改成 `f32[..]`，这四个用例要改写**。
- **闭秩侧已按裁定**：`m[:, 0]` ⇒ `f32[2]`、`m[1, 2]` ⇒ `f32`、秩 3 混合 `c[:, 1, 2:4]` ⇒ `f32[2,2]`、`c[:, idx, 2:4]` ⇒ `f32[2,2,2]`（`idx` 含重复下标，重复保留）、`m[:, [1,1,0]]` ⇒ `f32[2,3]`；伴随沿该轴 scatter（`m[:, 0]` 梯度 2.0、`m[:, [1,1]]` 重复累加 8.0）。这些都是新落的、有红→绿用例。
- 设计原则 5.4 现在的写法（逐字要点）：每一维写**一个位置 `i`**、一个范围 `a:b`（可带步长）或一个整数数组 `idx`；**后面没写到的维整维保留**；**写位置的那一维从结果里去掉**；不支持负数下标；越界是故障。

## 候选

- **甲：保留今天的读法（开秩 `t[0]` ⇒ 元素 `f32`）**。**好处**：行为不变、四个 ONNX 用例不动；**问题**：与"什么秩都是同一套规则"不一致（闭秩 `m[0]` 给的是去掉第一维的行）。
- **乙：按 5.4 统一（开秩 `t[0]` ⇒ `f32[..]`，即去掉那一维、秩仍未知）**。**好处**：一条规则管所有秩；**代价**：那四个 ONNX 用例要改写（先取元素再比较，或写成别的形态）。
- **丙：别的划法**（例如"开秩上写位置必须先写范围/数组"、或"开秩写位置给元素，闭秩给行，并在 5.4 写明这条差别"）。

我们倾向**乙**（与您刚重写的 5.4 一致），但那会动四个 ONNX 用例，所以不自己定。
