# 问题：哪些结构体形状可以做循环状态（H71，note ⟨1eb82db9⟩）

## 问题
两处 `loop` 状态的形状设计原则没有覆盖：(a) 状态本身是空结构体
`loop s = {} ... do {}`——状态不携带任何信息，循环只能靠条件退出，它是不是一个有意义的循环；
(b) 携带的结构体里带 `int[]` 字段（`shape` 那样的定长小数组），导出时被拒绝，要不要把它拆开携带。

## 选项与代价
| 选项 | 代价 |
|---|---|
| (a) 允许空结构体状态，不加规则 | 零改动（它就是"按叶子拆分量"的 0 叶子退化情形）；代价是默默接受一个多半是笔误的程序 |
| (a) 语义上拒绝 | 要一条新诊断与用例；而空结构体在别处（作结构体字段、作 `Loop` 的 carried）已有定义，规则要多一处例外 |
| (b) 定长小数组拆成标量携带 | 要定"多小算小"（4 个元素？阈值？）以及"拆了以后与程序里对数组的写法怎么对应"；动态长度仍拒绝，于是同一种写法两种命运 |
| (b) 保持拒绝（现状） | 零改动；导出的 carried 集合继续只有张量与数值/布尔标量，而核心一侧不逃逸的结构体状态已经按分量拆开（H69 裁定 + H71 实现），两条路对"数组字段"不一致 |

## 倾向
(a) **允许**，它是既有拆分规则的退化情形，不值得一条新规则；(b) **保持拒绝**，等 H17 第 2、4 项
（原生多维数组 `T[维度]`）把元素类型与形状的说法定下来，再考虑定长数组的拆分。
**判断在负责人**（这是语义），决策者转呈。
