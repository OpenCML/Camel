# 内联把体搬进调用者图之后，那张图多出来的环境资源归谁

**状态**：等作者裁。**一问**。

## 一、问题

遍边界的第一条不变量（"一个遍不许改变程序碰到的环境资源集合"）已经立住，量在整树上是 **0 处**。它的第二类——**把同一个集合从整程序收到单张图**——试过一版，**量出来 9 红，全部同一种形状**，于是撤回，只留下这一问。

**要裁的是**：**内联把一个体搬进调用者图，调用者图因此多出一项环境资源（比如 `stdout`），这一项归谁？**

1. **归调用者**：那张图从此就是"会写 `stdout` 的图"，调用它的人按这一项算账；
2. **归原来的体**：多出来的那项只是替身，图上记的仍应是原来那个体的资源；
3. **谁内联谁负责，并在区域记录里登记**：内联时把"这一项是从哪个体搬进来的"写进区域记录，读的人据此把它扣掉。

## 二、9 条读数（`lane-effects2`，`22bae9a11`）

逐图比的那一版，整树量出：

```
[FAIL] callback.write_through_parameter_opt.nvm / .fvm / .jit / .prl
[FAIL] callback.two_references_write_one_object_opt.nvm / .fvm / .jit / .prl
[FAIL] pass_boundary.resources_kept
```

报文同一种形状：

```
Pass 'std::opt' changed the ambient resources ... before graph 1 (one graph), after nothing
```

**读法**：`std::opt` 把效应搬出去或删掉（图 1 从 `{stdout}` 变 `{}`）；把判据收成"只许增不许减"之后**还是这 9 条**——它们的形状是"从 nothing 增出来"，正是内联搬进来的那一类，而按内联区域计数的豁免没接住（**区域记录没说清这个遍干了什么**）。

## 三、为什么这不是"树错了"

**这 9 处没有一处的输出变了**：`callback.*_opt` 的四个后端都照旧打印同样的东西。**变的是"哪张图碰了什么"**，不是"程序做了什么"。所以它不是缺陷清单，是**模型缺一个口径**：内联之后，一张图的资源里，哪些是它自己的、哪些是替别人拿着的，今天没有话说。

## 四、裁与不裁的代价

- **裁"归调用者"**：逐图这条尺子立刻可用（9 红就是 9 个待改的点），代价是调用者图的名字从此背着被内联体的效应；
- **裁"归原来的体"**：需要在图上多存一份"扣除"，区域记录要能回答"这一项从哪来"；
- **裁"谁内联谁登记"**：区域记录扩一项，内联的每一处都要写，写的成本落在内联这个遍上。
