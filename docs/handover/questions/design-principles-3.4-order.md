# 设计原则 3.4 的首句与同节的 F17 相互矛盾

## 问题

`docs/design-principles.cn.md` 3.4（143 行附近）首句写「块内一切（跨资源的、纯计算的）都按书写顺序」，
而同一节两行之后的 F17 裁定（2026-10-23，由 H241 第 5 项落地）写：同步块**不向内继承**——
`func f(c: bool): int sync { if c then { println(1); println(2) }; return 0 }` 里只有 `println(2)` 执行。

两句直接冲突：首句说块内一切按书写顺序（即 `println(1)` 也在同步链上），F17 说块内嵌套的块自成一块、
不在同步链上。设计原则是**规范文件**，实现者读到的是首句，因此它今天会把人带错。
`docs/design-principles-log.cn.md:658` 有同一句的 2026-10-19 记录——那是历史记录，不必改。

另有一处相邻但不属于 F17：`docs/technical/18_sync_control_semantics.md` 2.5 的未决问题（非同步体里嵌套
一个 `sync { … }` 而没人用它的值）按 **F1（用到才执行）**已有答案，已转给 H241 第 1–3 项的实现者。

## 选项

- **A（建议）**：改写 3.4 首句，只保留与 F17 一致的部分——把「块内一切按书写顺序」限定为
  「**同步块自身范围内**、且不在内层块里的语句按书写顺序」，并指向 F17 的向内不继承。
  代价：改一行，不动任何实现、测试或生成文件（没有测试钉这句话）。
- **B**：保留首句，在旁加一条「与 F17 冲突，以 F17 为准」的批注。代价：规范文件里留着一句
  自己知道是错的话，读的人仍然会先读到它。
- **C**：不改，由作者另行处理。代价：与 A 相同，只是走流程。

## 建议

A。这是措辞更正，不是语义裁定：F17 已经定下语义，首句只是还没来得及跟上。
