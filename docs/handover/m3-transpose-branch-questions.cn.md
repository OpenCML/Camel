# 分支上的转置：要裁的一件事，和按默认建议做下来的样子

`transpose` 现在能转过带分支的线性函数（`f(x) = if x > 0 then 2*x else 3*x`，余切 `1.0` 在 `x>0` 时给 `2.0`、`x<0` 时给 `3.0`）。直线那一批里有一个决定是所有分支都继承的，这一页把它写清楚：**转置后的函数多拿了 `f` 的参数。**

## 一、为什么绕不开

转置要回答「余切 `1.0` 拉回到参数是多少」，可是**走哪条臂是值决定的**：`x > 0` 是一个值算出来的判断。直线函数里没有它——`2*x + 3*x` 的余切只跟常数有关，参数本身用不着。分支函数里，没有 `x` 就不知道当时走的是哪条臂，也就谈不上「那条臂的余切」。

同一个理由在循环上更明显（设计页 §4.3 说的「逐轮取 split 留下的残差」）：一轮一轮的余切要靠那一轮的值才认得出来。

所以转置后的函数签名不是 `(ct) => (ct_x)`，而是：

```
(..ParamsOf<F>, ct: Tangent<ResultOf<F>>) => (..Tangent<ParamsOf<F>>)
```

一个参数时就写成 `transpose(f)(x, 1.0)`——**读作「在 x 这个点上，把 1.0 拉回来」**。

## 二、两个可选的路，和为什么选了现在这条

| 走法 | 形状 | 代价 |
|---|---|---|
| **A（现在的默认）参数当残差一起给** | `(x, ct) => (ct_x)`，对所有 `f` 一个形状 | 直线函数的那一版也要多一个用不上的端口（`back(2.0, 1.0)`）；已经 gated 的那条用例跟着改 |
| **B 由 `split` 提供残差** | `(ct) => (ct_x)`，形状跟 `jvp` 对称 | 得先有 `split` 与残差容器，那是设计页 §5 的事，不属于这一笔；在 `split` 之前，分支根本转不了 |

选 A 的理由只有一条：**C 里的形状在能转的那个子集里是统一的**——读者不用先知道函数有没有分支才写得对调用。B 更漂亮，但它把这一笔绑在了还没到的 §5 上。

**这是要裁的一件事**：`Transpose<F>` 最终该是 A 还是 B。若裁成 B，这一笔要改的是签名、操作符的 `signature()`、两条用例的调用形状，以及三个模块接口里跟 `split` 相连的那一段（现在没碰）。

## 三、按 A 做下来，这一笔落成了什么

- **条件按原样读**：转置出来的图里有一个新的 `BRCH`，它的条件是从原图**正向复制**过来的（同一个 `:op/gt_d`、同一个常数、入口的那个端口）。复制而不是转置，因为判断不是线性的东西，没有余切可言。
- **每条臂在自己的区域里倒着走**：`addRegion(Arm, ...)` + `setInsertRegion`，臂的链走完把结果交给区域；两条臂都建出来，`JOIN` 挑一条——这正是运行时既有语义，不是新发明。
- **臂内的 k 份相加照旧**：`2*x + 5*x` 在一臂内给 7；**两条臂的余切是「接」不是「加」**——只有跑过的那条贡献了余切。这一点和直线里的「k 份相加」看起来相反，其实是同一件事的两面：相加发生在「一个值被同一段路径用了 k 次」，接发生在「两段路径只有一段跑」。
- **`transposeRuleOf` 的调用者数：1 → 2**（直线走的那个循环一处，臂区域的走法一处；都还在 `modules/transforms/transpose.cpp` 里，没有外溢）。
- **拒绝仍然按名字**：臂里有非线性的东西（`x*x` 这类要残差的）、臂外有残差、条件链复制不了，各给一个 `skip=` 词，绝不答一个错余切。

## 四、这一笔的数

`pick`：`transpose(pick)` 读数 `nodes=9 arms=2 rules=mul_t`，`x=1.0` 给 `2.0`，`x=-1.0` 给 `3.0`。
`merged`（一臂 `2*x + 5*x`、另一臂 `4*x`）：`nodes=12 arms=2 rules=add_t,mul_t`，给 `7.0` 与 `4.0`。

手算：`pick` 的两臂斜率 2 与 3；`merged` 正侧 `2+5=7`、负侧 `4`。两处都跟输出逐位一致。
