负责人给了 72 小时。目标只有一个：**AI 栈的形状定下来**，即求导与变换是 Camel 的库，不是 C++ 里的一段代码。设计稿是 `docs/design/program-transforms/README.cn.md`：局部规则，加 `reinterp`、`split`、`transpose` 三个算子。主线优先，细节以后再磨。

## 一、八路怎么分

主线六路，每路一个子代理，人手先满足它们：

| 路 | 做什么 | 依据 |
|---|---|---|
| **M1 `reinterp` 收尾** | 调用（同一个被调函数配同一个 `H` 只生成一份）；初值切向量沿链提升；"按调用跑每轮"的循环形式；效应原语（前向规则集让效应原样执行、切向量为零）；验收 2（缺规则的诊断在编译期、落在原语的 `file:line` 上）和验收 3 | 4.1 |
| **M2 `split`** | 一个函数拆成"现在就有的输入"和"以后才有的输入"两半，残差作为前一半的输出。先做直线代码，再做分支（条件就是残差），最后做循环（每轮的残差作为收集输出，按轮倒序取） | 4.2 |
| **M3 `transpose`** | 线性函数的转置。`rulesets/transpose.cml` 里已有的规则按左边建索引，与 `jvp` 同一套机制；先做直线代码，再做分支和循环 | 4.3 |
| **M4 库层 `vjp`/`grad`** | `vjp = transpose ∘ split ∘ reinterp<jvp>`，写在库里，`grad`、`with_grad` 是它的包装。M2、M3 的直线代码一通就开工。先把现有 autodiff 用例按"库层能不能过"分好类（`test/plans/feat/modules/autodiff.plan.toml`，115 个用例），逐类迁过去；最后一笔让 `modules/autodiff` 的 `buildGradientGraph` 退役 | 4.4 |
| **M5 `vmap` 向量化** | 新建规则集 `rulesets/vmap.cml`，`Lift<T> = RowsOf<T>`，给逐元素、`matmul`、归约、`reshape` 写批处理规则。`vmap(f) = reinterp<vmap>(f)`，结果与今天的逐行 `map` 逐位一致 | 4.1，第 14 条 |
| **M6 组合与 `remat`** | JAX 那几组组合：`grad(vmap(f))`、`vmap(grad(f))`、`jvp(vjp(f))`，数值与解析导数或有限差分对照；`remat`（反向时把一段子图重算一遍，不保存残差），数值不变、残差数下降 | J8、J14 |

支撑两路，保持推进，但**不许改 `modules/transforms`、`modules/autodiff`、`stdlib/rulesets` 的接口**（避免 10-30 那种车道互相踩）：

| 路 | 做什么 |
|---|---|
| **S1 执行器按区域排计划 + 删控制边** | 12:30 的裁定：活性的种子是每个区域的结果，臂的范围是区域的成员；然后按清单删 ctrl 边。这一路关系到语义正确，主线的分支和循环用例也要靠它 |
| **S2 一个端到端训练示例** | 拿 `c2-mlp-mnist` 或 `i2-diffusion-step` 改成用**库层 `grad`** 训练。M4 一能用就接上，到 72 小时时它就是演示；顺带记一组和 PyTorch 的同机耗时对照（只记，不追） |

**本冲刺暂停的**：`std::cpp` 补齐、断言改检查、环境变量开关清理、`GraphDraft` b6、复数张量、窄浮点上设备、报告和账页。报告只在一笔代码需要时写，一页够用。

**M7 补充（负责人 2026-11-01 19:10 澄清，原则 2.5 已据此改写）**：往返要的只是不丢语义，不要求可读，名字、可读性都不计，判定上以规范化后同构为充分条件，内联部分摊平。由此：
- 图只有一种，不分"程序层/执行层"。任何合法的图写不回来，就是语言的缺口。
- 标注分两种：只用于编译期计算、作用已经体现在图结构里的（如 `#op`）不必进图；后面的遍或后端要读的（`#strict`、`#jvp(rule)`、`#remat`、节点属性）必须在图上，并能写回源码。第 5 步里的"标签进图"照此做。
- 每个算子节点都打印成对它声明的调用。没有声明的算子（如 `:op/keep`）补一个声明，写法不追求好看。
- 顺序边不需要源码表示：按 `edges.cn.md` 第 1 节与 4.6，顺序边只出现在同一资源的效应之间、同一 `var` 的写之间、内联展开的同步链上，打印时按拓扑序排语句就能重新推出来。遍不得产生这三类以外的顺序边，提交时的结构检查要覆盖这一条。
- 大常量照原样打印成字面量，不再拒绝（`CmlBigConstant` 删掉）。编译器生成的图名由打印器按固定规则起名。

依据：原则 3.1"效应不静默消失"、3.3（读是依赖、内部与外部资源、`uses` 的读写、`pure`、冲突的访问）、3.4"同步块可以当值"、3.5"可变实参的别名"、3.6 `map`/`filter`、3.9"故障沿依赖传播"、9.7。

0. **效应与资源的推断写成一个独立的分析**（2026-11-13 架构审计，见第十节）：有写明的输入与输出，取代现在分在解析器、GCT、GIR 三处的做法；本节各条都在这一个分析里实现，不在三个建图器里各改一遍。
1. **读写进类型。** 推断出的资源集分读与写，打印与诊断都带读写。`uses` 只列外部资源与句柄形参（`uses fs` 读、`uses var fs` 写），变量写进 `uses` 报错；对外部资源是读是写由算子定义声明（负责人 2026-11-14）。
2. **`pure` 改为"没有写入"**：读什么都可以（变量、外部资源），不能写活得比调用长的变量，不能写外部资源（负责人 2026-11-14）。合并重复计算照旧按图上的输入比较。**效应遮蔽**：只写自己局部变量的函数（包括经不逃出的闭包写）是纯的；现在 `func total(x: int): int { var acc = 0; let add = (k: int): int => sync { acc = acc + k; acc }; ...; return b }` 传给 `pure` 形参被拒，改后要能通过；闭包返回出去时仍按写效应处理。规则引擎的 `protect_effects` 对外部访问与活得更长的变量的最终写入不再起作用，可以删，`protect_faults` 保留。
3. **冲突按资源与读写判断**：读与读不排序；读之后的写要等读完成（这条顺序边现已存在，`b72d59535` 上实测，保持）。提交时的顺序检查、别名特化、并行执行器都用同一个冲突定义。
4. **外部访问由所在区域用到**：
   - 非同步函数体里的裸语句 `println(x)`、臂里的打印、循环体里的打印，区域运行就执行；不报编译错误。
   - 对变量的写：活得比函数长的由出口用到，执行；`func f(var p: int): int { p = 3; return 0 }` 调用者读到 3。被覆盖或之后没人读的局部写不执行、不报。
   - `EffectNotExecuted`、`IgnoredSideEffect` 两条警告删掉，相应用例改期望。
   - "用到"由区域的结果承担，顺序边不兼任。
5. **控制台合成一个资源**：`stdout`、`stderr`、`stdin` 改为资源 `console` 的三条通道，按书写顺序；写标准错误、读标准输入之前先刷出标准输出。验收：`print("name? "); let n = readline()` 先出提示；`println(1); eprintln(2); println(3)` 在 `2>&1` 下依次是 1、2、3。
6. **`map`、`filter` 要求 `pure`**：声明改为 `with <f: (item: T) => U pure>`；带效应的元素函数报编译错误，诊断点出它写了什么。新增 `para::unordered_map`。`stdlib/opt.cml` 里在 `map` 中改事务的那处改成 `foreach` 或循环。只读外部变量的元素函数照常并行。
7. **故障沿依赖传播**：出故障的节点交出故障；依赖它的节点不执行，故障往下传；不依赖它的照常执行，包括外部访问；到出口时带位置终止，到 `attempt` 边界时变成错误值；几个故障时报规范顺序里的第一个。四个调度器（`nvm`、`fvm`、`jit`、`taskflow`）行为一致。验收：`func f(z: int): int { let a = println(7); let r = 50 / z; return r + a }` 与把 `r + a` 换成 `a + r` 的版本，`f(0)` 都先打印 7 再报除零；`sync { let r = 5 / z; println("after") }` 在 `z` 为零时不打印 `after`。
8. **同步块当值、块里点名算用到**：`let r = sync { ... }` 现在是语法错误，要改；`a;` 这种语句要接上同步链。验收：`let q = a / b; sync { q; println("checked") }` 在 `b` 为零时不打印。
9. **图接口**：外部访问只能用专门删效应的操作删除，`erase`、`replace`、`graft` 都删不掉；"没人用的外部访问"是不变式，在图的校验里断言，不作为提交时的一项检查。R1 的 `GATE` 只用于可能出故障的计算，外部访问不需要。
10. **别名**：现行为已符合 3.5。把 `bump(inc, n)`（闭包与 `var` 实参是同一变量）收进用例，各后端打印 202、之后 101。
11. **迁移**：测试、`stdlib`、`examples`、`docs/tutorial` 按新规则改写法；期望输出变了的逐条列出交决策者，不许为了通过而改期望。
- **验收**：上面每条各有正例与反例，进快层；四个调度器同一组输出。

**R4 图接口默认看不见写法**（负责人 2026-11-13 定 D3 为"乙加丙"；R1–R3 合入之后开）

依据：原则 9.5"图接口默认看不见写法"。
1. **规范顺序与编号**：从出口出发，沿数据边与同步边按端口顺序深度优先，每个节点只访问一次；臂与循环体按所属节点的端口顺序进入。开销线性，按图的版本缓存。到不了出口的节点不在默认查询里。
2. **默认查询**：`nodes` 等按规范顺序返回；`id` 返回规范编号；图与节点的 `==` 比结构。
3. **读写法的查询单列**：创建编号与顺序、名字、源码位置、`show`、句柄同一性、报错信息的内容。
4. **能力声明**：读写法是类型里声明的一种能力，与效应声明同一套机制。没有这种能力的规则、`when` 条件、遍调用上面这些查询时报编译错误；用没有这种能力的规则拼出的遍自动没有。
5. **迁移**：标准库的遍与测试里按名字挑函数的，改为把函数值交给变换；诊断与调试声明这种能力。
- **验收**：交换两条无关语句前后，`nodes`、`id`、`==` 的结果相同（ECOOP 的探针 p1 收成用例）；并列取最小表要对整个程序取，不能每张图先各自定死（原则 9.5）：被绑图有交换两个捕获口的自同构时，两份交换了键的同构绑定 `==` 为真、结构哈希相同（ECOOP 规格第三版 §6.4 的例子收成用例）；没有声明能力的规则条件读 `id(n)` 报编译错误；规范顺序在最大的测试图上的开销与节点数成线性（报一行读数）。
