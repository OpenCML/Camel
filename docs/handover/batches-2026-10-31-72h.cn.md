# 72 小时冲刺：程序变换写成库（2026-10-31 15:00 → 11-03 15:00）

负责人给了 72 小时。目标只有一个：**AI 栈的形状定下来**，即求导与变换是 Camel 的库，不是 C++ 里的一段代码。设计稿是 `docs/design/program-transforms/README.cn.md`：局部规则，加 `reinterp`、`split`、`transpose` 三个算子。主线优先，细节以后再磨。

## 一、八路怎么分

主线六路，每路一个子代理，人手先满足它们：

| 路 | 做什么 | 依据 |
|---|---|---|
| **M1 `reinterp` 收尾** | 调用（同一个被调函数配同一个 `H` 只生成一份）；初值切向量沿链提升；"按调用跑每轮"的循环形式；效应原语（前向规则集让效应原样执行、切向量为零）；验收 2（缺规则的诊断在编译期、落在原语的 `file:line` 上）和验收 3 | 4.1 |
| **M2 `split`** | 一个函数拆成"现在就有的输入"和"以后才有的输入"两半，残差作为前一半的输出。先做直线代码，再做分支（条件就是残差），最后做循环（每轮的残差作为收集输出，按轮倒序取） | 4.2 |
| **M3 `transpose`** | 线性函数的转置。`rulesets/transpose.cml` 里已有的规则按左边建索引，与 `jvp` 同一套机制；先做直线代码，再做分支和循环 | 4.3 |
| **M4 库层 `vjp`/`grad`** | `vjp = transpose ∘ split ∘ reinterp<jvp>`，写在库里，`grad`、`with_grad` 是它的包装。M2、M3 的直线代码一通就开工。先把现有 autodiff 用例按"库层能不能过"分好类（`test/plans/feat/modules/autodiff.plan.toml`，115 个用例），逐类迁过去；最后一笔让 `modules/autodiff` 的 `buildGradientGraph` 退役 | 4.4 |
| **M5 `vmap` 向量化** | 新建规则集 `rulesets/vmap.cml`，`Lift<T> = RowsOf<T>`，给逐元素、`matmul`、归约、`reshape` 写批处理规则。`vmap(f) = reinterp<vmap>(f)`，结果与今天的逐行 `map` 逐位一致 | 4.1，第 14 条 |
| **M6 组合与 `remat`** | JAX 那几组组合：`grad(vmap(f))`、`vmap(grad(f))`、`jvp(vjp(f))`，数值与解析导数或有限差分对照；`remat`（反向时把一段子图重算一遍，不保存残差），数值不变、残差数下降 | J8、J14 |

支撑两路，保持推进，但**不许改 `modules/transforms`、`modules/autodiff`、`stdlib/rulesets` 的接口**（避免 10-30 那种车道互相踩）：

| 路 | 做什么 |
|---|---|
| **S1 执行器按区域排计划 + 删控制边** | 12:30 的裁定：活性的种子是每个区域的结果，臂的范围是区域的成员；然后按清单删 ctrl 边。这一路关系到语义正确，主线的分支和循环用例也要靠它 |
| **S2 一个端到端训练示例** | 拿 `c2-mlp-mnist` 或 `i2-diffusion-step` 改成用**库层 `grad`** 训练。M4 一能用就接上，到 72 小时时它就是演示；顺带记一组和 PyTorch 的同机耗时对照（只记，不追） |

**本冲刺暂停的**：`std::cpp` 补齐、断言改检查、环境变量开关清理、`GraphDraft` b6、复数张量、窄浮点上设备、报告和账页。报告只在一笔代码需要时写，一页够用。

**暂停不是半路切走**（负责人 2026-10-31 补充：要有过渡，不留技术债）。每条要暂停的路，先把**手上这一步做到一个自洽、可合入的落点**，合进 develop，再把子代理调到主线。落点的判据只有一条：**develop 上不留新旧并存、只做了一半、或"有声明没有实现"的状态**。逐路的落点如下：

| 路 | 落点（做到这里再停） |
|---|---|
| `std::cpp` | 手上那个算子或那类缺陷做完、对照通过；张量从 `Foreign` 改回 `rt::Array`（07:30）如果已经开了头，就做完，不留两种表示并存 |
| 断言改检查 | 手上那一族收完，计数写进账；没开始的族不碰 |
| 环境变量开关 | 手上那一个改完，账页更新；剩下的留在账里 |
| `GraphDraft` b6 | 手上那一片做完，账上的数只降不升，快层检查绿 |
| 复数张量 | `f2e6b1009` 已让张量模块认得 `c64`/`c128`，但还没有内核，这正是"有声明没有实现"。二选一：把 `zeros`/`ones`/打印这一小段做完，让 `zeros::<c64>([2])` 真能跑；或者把这一笔撤回，等冲刺之后整条线一起做。不许停在只认类型、没有实现的中间态 |
| 窄浮点上设备 | 五步原定在车道上做完再一次合入（03:50）。已经进 develop 的部分（`DType` 五种、类型门读窄元素并点名缺的内核）如果自成一体，就停在这里；有只加了枚举、没有消费方的地方，补上消费方或撤回 |
| 报告和账页 | 写到一半的写完，然后不再开新页 |

每条暂停的路在状态表上写一行：停在哪一笔、下一步是什么，冲刺之后直接接上。

## 三、加速的规矩

1. **问题不停工**：主线一路遇到要裁的问题，照常写进 `questions/`，同时**先按页里的默认建议在车道上往下做**。决策者每 20 分钟一轮，当轮必答；默认建议被推翻，就回退那一段。不要停下来等。
2. **选项与已有裁定一致，就直接做，不问**（10-30 起的规矩，重申）。
3. **每路每 1–2 小时合一笔进 develop**。车道上做完的不要攒，攒着既看不见，也容易冲突。
4. **设计稿就是规格**：`reinterp`/`split`/`transpose` 的每一句都写在 4.1–4.4 里，照着做；设计稿没写到的，才算问题。
5. **验收只认数**：每一笔的提交信息第一行之后，贴一行能复现的读数（命令和输出），不写"应该可以"。
