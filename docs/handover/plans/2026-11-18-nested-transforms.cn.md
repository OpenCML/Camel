## 甲：库的形状（设计稿 2.1，先做）

**（2026-11-18 13:40 修订，与 ECOOP 演算 GNC 统一，原"残差作显式参数"作废）** 残差不能作值层面的显式参数：`x+x` 没有残差、`x·x` 的残差是 `x`，同一输入类型前向的类型却不同，库里 `let (y, r) = fwd(x)` 没有静态类型。所以采用 GNC 的形状：
1. `split(f)` 只做一次（在 `grad(f)`/`vjp(f)` 求值时），交出前向 `fwd: x ↦ (y, pb)`：`pb` 是一个闭包，它的**代码是一张静态的图**（线性一半，以残差为参数），捕获这次调用的残差。`split` 结果的类型里不出现残差。要点不是"残差显式"，而是**闭包的代码在 `split` 时就建好、只建一次**，不再每次调用时由 `split` 现场造。
2. `transpose` 作用在这个闭包上：它的代码已知，转置静态地做一次（按代码缓存），捕获的残差照常传入。
3. `stdlib/vjp.cml`：`vjp(f)`、`grad(f)` 在求值时算出 `fwd`，交出的函数只调用它和转置后的反传；`with` 值照今天的规则传给 `fwd`。
4. 读数：训练案例（`examples/case-study/train.cml`）每步不再调用 `split`、`transpose`（`--trace transforms` 读出变换次数：只在 `grad(f)` 求值时各一次）；六计划逐名比较。

## 乙：变换递归进闭包（设计稿 2.2）

1. `reinterp`（`jvp`）、`split`、`transpose`、`vmap` 遇到闭包（函数体里的 lambda、捕获了函数值的闭包）时：代码已知就递归变换，捕获的数值照常提升，捕获的函数值随之变换；同一被调函数配同一规则集只生成一份。
2. **函数值按类型提升**（与 GNC 一致，2026-11-18 13:40 修订）：函数类型的值，不论经形参、调用结果、元组、分支哪条路来，都按类型提升（`Lift<A ⇒ B>` 是 `Lift<A> ⇒ Lift<B>`）；程序里每处造闭包的地方（lambda、具名函数）都有它提升后的版本，所以"按数据在已知函数之间选一个"是支持的。删除按来历的拒绝。
3. **拒绝的判据**（取代原"变换时未知的函数一律拒绝"）：只拒绝**类型会变的函数值进出非惰性算子**——交给一个块或变换算子、写进资源（如 `Ref`）、交给 C++ 不透明算子。诊断写明是哪个算子、哪个值。
4. **展开（unfold）**：函数体里出现变换节点（如 `(x) => x * grad((y) => x + y)(1)` 里的内层 `grad`），它的操作数是代码已知、捕获里不含函数的闭包时，在建图之后（或 `std::macro` 阶段）把这个变换节点就地展开成变换后的代码，捕获的值作为输入。展开之后外层变换看到的是普通代码。这对应 GNC 里"对 FN 节点与捕获里不含函数的 BIND，reinterp 可以静态替换"那条等式。扰动混淆的经典例子就按这个内层写法验收，不改写法。
