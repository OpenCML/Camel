# 不终止与故障同等对待；保证本身的代价（施工计划）

> 决策者 2026-11-18，负责人同日定（经 ECOOP 会话转达）。原则 3.4 已改：可自由安排的计算是"纯、不会出故障且已知会终止"的计算。

## 甲：一个谓词，加上"已知会终止"

1. 原则 3.4 说这个分类是**一个谓词**，处处同用：离开同步链、移出循环体或臂（下沉、提出循环）、被改写丢掉（9.7，`protect_faults`）、内联后不连顺序边、抽取时提前。先核对编译器里这几处是否真的调用同一个函数（今天的候选：`may_be_rearranged`、`mayBeRecomputed`、`nodeMayFault`、`carriesOrdering` 等），不是就收成一个；然后在这个函数里加"已知会终止"。
2. "已知会终止"的判定：循环按次数有界的（`for` 遍历一个已知长度的序列、计数循环）算会终止；`while` 一类条件循环、调用了可能递归的函数，判断不了就算"可能不终止"，与"可能出故障"同样处理。规则删除保护 `protect_faults` 同样覆盖它（一个可能不终止的计算不能因改写失去读者而被丢掉）。
3. 用例：一个可能不终止的纯循环只被一条臂读到，另一条臂被选中——优化前后都不结束（用超时判定），不被下沉进那条臂；一个有界的纯循环照常下沉。

## 甲的补充（2026-11-18 18:50，GNC rev26 分支与循环部分证明时查出）

"可自由安排"这一个谓词还要管下面三处，今天它们可能各自判断或根本不判：
1. **展开（unfold）与投影化简**：`π_i(mk(ū)) → u_i` 会让其他分量失去读者；只有被丢掉的分量都可自由安排时才化简，否则保留（用 `GATE` 接住它们的用处，或不化简）。
2. **内联**：内联时不能丢掉被调函数出口 `GATE` 的依赖端口（尾随的写与依赖）；可自由安排的才可以不接。
3. **`split` 切分分支或循环**：切分后原值部分不再等切值部分；只有切值部分可自由安排时才切分，否则拒绝（诊断写明是哪个分支或循环、为何切值部分不可自由安排）。`cutBranchGraph` 在臂里重算条件与参数的做法，只在被重算的部分可自由安排时成立，同一个谓词判。
用例：每处一条反例（被丢掉的分量是一个可能不终止的循环 / 会出故障的除法 / 一次打印），优化或变换前后可观察行为相同。

## 乙的补充（2026-11-18 19:10，负责人定：实现尽量用最先进的算法，补实测）

**实现**（现状不是这样就改；改不了的在报告里写明现状与原因）：
1. **合并互模拟的函数图（Merge）**：划分细化（Paige–Tarjan，O(m log n)）；端口有序的图按带标号的转移系统处理。
2. **规范编号（Number）**：利用端口有序，做有根有序图的规范标号，不在遍历选择上做组合搜索；无序的部分（区域出口 `GATE` 的尾随写、`unordered` 资源上的访问）按已有的并列组处理。
3. **冲突检查**：按资源分组，沿每个资源的写者链检查；可达性用位集合或拓扑序上的区间。"只需检查相邻写者、读者只需与前后两个写者比较"若被 ECOOP 一侧证明，就按它简化，并在报告里引用。
4. **作用域**：区域树做进出编号，祖先判断常数时间。
5. **规范形式按需计算**：执行不需要它；只在读图、结构比较、按代码缓存时算，算过就缓存在图（不可变值）上。
6. **按定理省掉检查**：内核变换（`reinterp`、`split`、`transpose` 及其上的 `grad`、`vjp`、`vmap`）与不新增访问的编辑，按已证的定理省掉对应的检查——照 11-15 的分档：发行构建省，调试构建与测试照查，用来核对定理。

**测量分开报**：
- 规范形式各步（Saturate、Prune、Direct、Merge、Number）的耗时分解；
- 六项检查各自的耗时；
- 增量检查对全图检查；
- 内核变换省掉检查对不省；
- 规范形式按需计算对每次都算。
目的是说明开销集中在哪一步、简化之后剩下多少。节点数覆盖 10³–10⁵，交替多次运行报中位数与区间，附环境与原始输出。

## 乙的补充二（2026-11-18 19:50，ECOOP 一侧证明了代价的界，归档 `ECOOP2027/handoff/cost/` `9740a1219`；以此为准，取代上一节相应的条目）

1. **冲突检查**：取一个线性扩展（必须是线性扩展，任意顺序不成立），只比较相邻的写者，每个读者只和它前后两个写者比较；按资源沿序做，O(s·ρ)（或位向量 O(s·a/w)）。
2. **顺序边按资源存成写者链**：规范形式里的顺序边恰是"冲突对按某个线性扩展定向"，按资源存链 O(sρ)，不存全部两两边（k 个连续打印的两两边是 k(k−1)/2 条）。核对今天图上的顺序边是链还是两两，是两两就改成链。
3. **Merge**：互模拟 = 按各位置的局部表与目标的最粗划分，每个引用位置加一个元素，归约到 Paige–Tarjan，O(s + (k+k_ref) log(k+k_ref))。
4. **Number**：在化简后的代码上一次深度优先遍历，O(s)；"在所有遍历顺序里取最小"在这里不会遇到选择点。
5. **总的界**：提交 O(sρ + T + (k+k_ref) log(k+k_ref))，资源集固定、类型有界时 O(s log s)。
6. **增量检查**：出口位置只在区域 0 被碰过时查；作用域、端口、效应只看碰过的区域；无环与冲突连同全部祖先区域查，在没碰过的祖先区域里只查涉及"包含被碰区域的所属节点"的环与冲突对。
7. **各编辑会破坏哪些检查**（一串编辑只查各自会破坏的项的并集）：`erase`、草稿上的 `outline`：都不会；`order`：只有无环；`replace`：无环、作用域、端口；只复制惰性节点的 `inline`：出口、无环、作用域、端口；复制带访问节点的 `inline`：后五项；经检查的规则、受支持的 `reinterp`：都不会。按 11-15 的分档，发行构建按此省，调试构建与测试照查全部六项。
8. **更正"规范形式按需计算"**：Prune（剪掉没用的节点）与第二次 Saturate 是执行必需的（不剪，没人读的打印会经顺序边卡住别的节点；不重补顺序边，留下的边会让一个打印永远等一个不终止的循环），每次提交都做；只有 Merge 与 Number 按需做——块头、`inline` 与 `reinterp` 的函数实参、原语的函数实参、按代码缓存时才算。按需之后，造闭包是 O(1)。
**测量按这个划分报**：化简（Saturate、Prune、DirectCalls）每次提交都做，Merge 与 Number 按需做，分别计时；其余照上一节。

## 甲的补充二（2026-11-18 20:40，与 GNC 合并稿 `a9335f444` 对齐）

"可自由安排"的判定按结构定义，与 GNC 同一个（不靠启发式）：节点不访问资源，并且是下列之一——
1. 绑定、常量、函数值节点，或算子表里声明为**全函数**的算子（结构算子、选择算子算；取首、取尾、`map` 这类可能失败或调用未知函数的不算）——算子表加一个"全函数"声明位，由算子作者声明；
2. 被调函数已知、且其图全部可自由安排的调用或 `map`；
3. 各区域里只有可自由安排节点的分支；
4. **结构上有界的循环**：(a) 遍历一个列表或数组、每轮取下一个元素、以"取完"为条件（GNC 的记录带循环）；(b) 计数循环：状态里有一个计数器，条件是"计数器 < 一个循环里不变的上界"，每轮计数器加一个正常量。其余的循环、可能递归的调用，一律算可能不终止。
(b) 是 Lang 的 `for` 计数形式；GNC 目前只认 (a)，已请 ECOOP 一侧把 (b) 也纳入全函数类（"GNC 不窄于实现"），在那之前实现照 (a)(b) 做、报告里写明 (b) 待 GNC 补。
**计数循环与回绕**（2026-11-18 20:55，ECOOP 一侧指出）：Camel 的整数加减乘溢出时回绕（原则 4.x"整数加减乘的溢出……保持回绕"），所以 `c + k` 可能溢出成负数、`c < N` 又成立，循环永不结束。(b) 的判定按保守写法：上界 `N` 与步长 `k` 都在编译期已知（常量或可证明的范围），且 `N ≤ 类型最大值 − k + 1`；判断不了的算可能不终止。GNC 采用哪种条件，等它的证明出来再对齐。
**计数循环的判定（2026-11-18 21:10，取代上一条的保守写法，与 GNC merged-defs (4a) 一致）**：条件必须写成 `c < N`（`c ≤ N` 不算：`k = 1`、`N` 为最大值时永远为真），计数器每轮加正常量 `k`：
- `k = 1`：`N` 可以是任何在循环里不变的值（外部节点、常量，或原样传递的状态）——常见的 `i < n; i += 1` 都算会终止；
- `k ≥ 2`：`N` 必须是常量，且 `N ≤ 类型最大值 − k + 1`（反例：`k = 2`、`N` 为最大值、从 0 开始，回绕后一直是偶数，永不结束）。
其余一律算可能不终止。三条各收一个用例（含这个反例）。
