# H19 计划批复（2026-10-21）

**批准**，按第 0–11 步执行。第 7 节裁定：

1. **问题 1 选 (a)，但不加 `native` 关键字。** 设计原则第 4 节已定："原生实现由模块中无函数体的声明表达"，没有 `inner`/`native` 一类修饰。写法是模块里无函数体的 `export func name(...): T uses ...`；它绑定的 C++ 算子按"模块名:函数名"约定（`bytes:len`），不在源码里写 URI 字符串。确有约定之外的名字时用标签表达（如 `#op<'bytes:raw_len'>`），只作例外。同目录下与 `.cmo` 同名的 `.cml` 是它的声明模块；声明是类型的唯一来源。泛型的无体声明（1b）按类型实例化，图上是 OPER 而不是 CALL。
2. **问题 2 选 (a)**：形状与类型由实参计算的模块（`tensor`、`nn`、`onnx`、`graph`、`rewrite`、`para`）保留 resolver 作为唯一来源；约定页写"一种事实一个来源"。
3. **问题 3 选 (a)**：本项不改前奏表面；标准库设计稿第 3 节的前奏清单仍是目标，以后单独立项。
4. **问题 4 选 (a)**：只删 `Set::has`（留 `contains`）；`map`/`set` 的模块化以后与前奏一起做。
5. **问题 5 选 (a)**：用终端与控制台算子重建 `io`，`eprintln` 进前奏；`Stream` 随流任务。
6. **问题 6 选 (a)**：合并为 `bench`，不进公开参考。
7. **问题 7 选 (a)**：冻结错误种类目录，新的 `T!` 函数用 `NotFound`/`PermissionDenied`/`IOError`/`EncodingError`；errno 的细分以后统一。
