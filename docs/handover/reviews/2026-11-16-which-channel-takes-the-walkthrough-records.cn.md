# 走查记录该进哪条通道：作者说「诊断通道」，而诊断通道按设计装不下它

## 事实

作者 2026-11-16 对 `break_rate` 那条要求的第二项是：

> 那 1988 行 `TRANSPOSE` / `REINTERP` 记录是**产品路径上的调试输出**，要**移到诊断通道**，golden 逐字节不变。

`modules/transforms/` 里的走查记录今天走 `readings()`：它打到 stderr，产品运行时也打，1988 行。
一个车道先把它做成环境开关 `CAMEL_TRANSFORMS_READINGS`，被 `registry.no_env_switches` 挡回：

```
[FAIL] registry.no_env_switches  modules/transforms/readings.h: reads 'CAMEL_TRANSFORMS_READINGS'
       from the environment and no ledger line allows it
```

设计原则 9.3 与 `test/tools/check-env-switches.mjs` 的原话是「一次运行的行为由程序、命令行、构建选项决定，不由环境决定」，且 ledger 只能缩短。**那条守卫是对的，那个开关撤掉了。**

## 于是「诊断通道」有两条合法的读法，而它们不是一回事

**读法 A（按字面：进 `diagnostics/registry.tsv`）**——今天装不下，四条都硬：

1. `registry.tsv` 是**修复目录**：299 条全部 `severity = 0 (Error)`，每条带一句解释与一个 fix 类别（`edit` / `none: internal…`）。逐节点走查**没有 repair 可写**。
2. 诊断带 `range`（文件行列）。走查说的是**图节点**，不是源码位置；落成记录会是一串 `modulePath` 为空的条目。
3. 诊断是 **raise 即打印**。目录里没有「默认静默」这个类，而作者要的正是**默认不打印**。
4. `expect_diagnostics` 在 `test/` 里**零命中**——runner 没有这个字段。今天钉诊断是靠 `expect_output_contains` 里的 `[Error] …` 文本。

**读法 B（按设计：走查本来就不该有码）**——这棵树已经把两件事分开了：

```
src/passes/transforms/transpose_operator.cpp#transposeKernel
  语言有规则的成因      → RuntimeDiag::TransposeNeedsParameterShape   （有码、有修复、有行列、立刻打印）
  同一处 why.str()      → readings()                                  （无码、无修复、默认打）
```

「拒绝 → 码，走查 → 读数」是设计。而 1988 行**全在走查一侧**——正好是没有码、没有 fix 的那一侧。

**这一条比它看起来重要**：今晚另一处证据说明「有码」是有分量的标记。`3773eed5c` 留下的三族红里，最危险的一族是「既不产生节点、也不产生诊断」的 `dead_write.*`（9 条，静默错值）。**把走查记录也标上码，等于把「这不是错误」标成「这是错误」。**

## 问的只有一件事

**读法 A 要的是「非错误、默认静默、以图节点为对象」的一个新诊断类**，那是 9.3 领地的设计变更（诊断目录的语义、runner 的字段、golden 的形态都要跟着变），不是一个车道能自己开的。**是现在就开这个类，还是这一步先按「pass 参数」做？**

## 我的默认（若无答复，按此开工）

**先按 pass 参数做：`readings=on`（默认 off）。** 理由：

1. 它不碰 9.3、不碰 ledger、不碰诊断目录语义——**合法**；
2. 产品路径同样安静（默认 off），**作者要的那件事达成了**；
3. golden 逐字节不变（条目加实参，输出不变），**可验**；
4. 若将来真需要「非错误、默认静默」的诊断类，那一类可以单独设计，而这个参数随时能退场——**它不欠债**。

**代价要说清**：约 130 余条钉读数的条目要各加一个实参。而**名单不能靠 grep 得到**——`feat/compile/stated_extents` 用 `expect_stderr_contains = ["rhs=sum_stated_t"]` 钉的是一句话的碎片，前缀搜不到。**正确做法是把开关置 off 跑一遍，红的那批就是名单**，那一跑本身要留着（它是「关掉之后有多少条依赖它」的唯一读数）。

## 这一页不改变的事

本页不请求开新诊断类，也不请求例外。它只说明：**「移到诊断通道」这句话在今天的树上没有直接可落的地方**，并把两条合法读法的差别与代价写清，让答复可以是一个词。
## 决策者答复（2026-11-16）

**读法 B，我那句"诊断通道"说得不准：走查本来就不该有码。** 拒绝走诊断（有码、有修复、有位置、立刻打印），走查走读数（无码、默认不打印）。环境开关撤得对。

但不按每个遍各开一个 `readings=on` 参数：同类的走查读数今天还有好几处（`PLAN_REF_SITES`、效应包含的汇总、折叠的调试计数），每处各开一个参数就是同一件事好几种开法。改成**命令行上一个跟踪选项，按区域选**，例如 `--trace transforms`、`--trace plan`、`--trace effects`（名字由你们定），原则 9.3 允许命令行决定运行行为。默认全关；钉读数的条目在 `args` 里加这个选项。读数的写法与去处（stderr、前缀）只在一处实现，各区域只登记自己的名字。上面那几处一并迁过来，环境变量与"测量时手工翻的常量"随之删除。约 130 条钉读数的条目要加实参：用"开关关掉后哪些条目变红"来得到名单，不靠 grep。
