## H14 待决问题的答复

1. **插值顶层的 `:`**：沿用 Python 的规则——括号外第一个 `:` 开始格式说明；带类型标注的 lambda 要加括号。补一条提示：格式说明不合法且其中含 `=>` 时，诊断提示"给 lambda 加括号"。
2. **格式化器不改写插值内的代码**：可以接受，暂不做。
3. **TextMate 无法配对花括号**：可以接受，语义记号已由语言服务器提供。
4. **`{}` 的字面含义**：按现在的做法。
5. **`` \` ``**：所有字符串用同一张转义表，普通字符串里的 `` \` `` 也解码为反引号。
6. **GCT 的 FString 分支**：不要保留"不可达的防御"，改为内部错误断言（不可达就让它在调试时立刻暴露）。
7. **`${}` 空插值**：给专门的诊断"空插值"。

以上第 1、5、6、7 条与 `grammar.tables` 缺 `constas` 一并作为 H20 第 1 项。

## H13 待决问题的答复

1. **`save_tree`**：按注释承诺的语义——**整体替换**：写到临时目录，成功后原子地替换旧目录；失败时旧目录原样保留。另外 `fs` 补删除（`remove`、`remove_dir`，返回 `T!`）。
2. **按索引取行**：加 `take(t, indices)`（沿第一维，与 5.4"多维数组按第一维"一致；以后可加 `axis`），纯算子，各后端与 ONNX `Gather`；随机打乱需要键式随机数：先加 `random::key(seed)`、`split`、`permutation(key, n)`（Philox，纯函数），足够写每轮重新打乱。下标与切片的**写法**（`t[order]`、`t[a:b]`）是语言写法问题，已交语言作者讨论，定下后另行指派；在此之前用函数形式。
3. **交叉熵的目标**：两个都做——`softmax_cross_entropy` 按目标的类型重载，整数下标 `i64[n]`（或 `int[n]`）与 one-hot 都接受；另加 `one_hot(labels, classes)`。
4. **损失曲线**：图层面已有"循环收集每轮输出"（设计原则 3.10），源码写法尚未定，已交语言作者讨论。定下之前，示例用打印加外部解析，现状可以。
5. **测试分层**：维持现状，H10 落地后移到 `slow` 层。
