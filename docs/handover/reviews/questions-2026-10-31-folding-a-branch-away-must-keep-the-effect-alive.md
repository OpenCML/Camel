# 把分支折掉之后，被整条臂用到的效应怎么保活？

**问题一句**：原则 3.3 写「去掉一个效应的最后一个用处时，它由指向后继的顺序边保活（9.7）」，F2 写「顺序边只排序，不传递被用到」——**两句冲突**，而作者给的例子里也根本没有后继效应可接顺序边。这一条该按哪句改？

**读数（同一棵树，两个后端）**：

```camel
func main(): int {
    let a = println(1)
    return if 1 > 2 then a else 0
}
```

- `std::nvm` → 打印 `1`；
- `std::opt std::nvm` → **什么也不打印**。

按 3.1，`a` 被分支整体用到，建图时就定了它要执行；3.3 写明遍不得改变"用到"。`fold` 把常量条件折成 `0` 之后，`println(1)` 失去最后一个用处，执行器便不再执行它。B、C、D 三组和 `g(false)` 都与模型一致，只剩这一组。

**三条路与代价**

- **甲（默认建议）**：**保活落在数据边上**——加一个普通算子 `:op/keep(x, v) : V`，结果是 `v`，`x` 经数据边被用到（与 `:var/after` 同一种做法）；`fold` 折掉一条臂时，把那条臂从外面读过的受约束节点经 `:op/keep` 接到 `v` 上。**3.3 那句加限定语**：顺序边保活只适用于"有后继效应"的情形。**代价**：原则 3.3 要加一句；**收益**：与 F2 不冲突，且没有后继效应的情形也有解（就是这个例子）。
- **乙**：**保留 3.3 原话**，允许顺序边保活，**F2 改成「顺序边只排序，但可保活」**。**代价**：没有后继效应的情形仍无解，这个例子还得另想办法。
- **丙**：**两句都改**——删掉 3.3 的顺序边保活，保活只认数据边。**代价**：要复查 9.7 现有的顺序边保活用例是否都靠数据边也成立。

**按默认建议（甲）已开工的部分**：无。这一笔只写页；`fold` 那处等这一句定了再动。

**归属**：这一项不在冲刺主线上；S1（执行器按区域排计划）做完手上的事再接。

**用例（落地后要绿的）**：上面这个程序，四个后端在 `std::opt` 前后都打印 `1`。
