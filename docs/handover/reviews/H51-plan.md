# H51 计划批复（2026-10-21）

**批准**，按 15 步执行。第 7 节裁定如下（依据设计稿 [泛型按结构展开](../../design/generic-structure/README.cn.md) 与设计原则第 1、5 节）。

1. **Q1 选 (a)**：函数类型的参数可以接受泛型函数或重载集合，作为**编译期可调用绑定**——实例内联时（Q3），每个调用处按实参类型解析；实例不内联、需要把它当作值物化时，只有能定为一个具体函数的才行，否则在调用处报错。不新增语法。这是设计稿 3.1.1 的直接读法，写进语言参考。
2. **Q2 选 (a)**：`constas name: T` 值参数与无类型的 rest 参数 `..ts`（调用处是编译期元组，必须展开）都属第一期。
3. **Q3 选 (a)**：含 `match type`、`static for`、`static loop` 或 rest 参数的实例一律内联，不写标注；编译期成本用节点与深度预算约束。
4. **Q4 选 (c)**：不要求诊断与旧实现逐字节相同；`static error` 第一期只接受字面量，编译器把当前静态路径作为相关标签；测试断言路径与关键字。
5. **Q5**：第一期只接受 `(n, F)`；`(n, F, tags)` 第二期随标签反射一起做，现在写出来报"第二期"。两棵树按字段**名**对应，字段声明顺序不同不报错（结果按第一棵树的顺序）。不加索引绑定。
6. **Q6 选 (a)**：`static` 保留；`fields`、`struct`、`tuple`、`error` 是上下文关键字。
7. **Q7**：C++ 内建模块改名 `ckpt`，`save`/`load` 只在 `ckpt` 里；`tree` 成为纯 Camel 库，不放包装，调用处改为从 `ckpt` 导入（不考虑兼容）。
8. **Q8 选 (b)**：删除 `nn` 的优化器（C++ 与包装都删），所有调用处改用 `optim`。ONNX 训练导出**不识别优化器**，直接导出 `optim` 展开后的逐元素节点；删除 `lowering_grad.cpp` 中对 `nn:sgd`/`nn:adam` 的识别。融合由 Tiles 负责（H50）。
9. **Q9 选 (a)**：先按计划试写；不行就把 `tree_unzip` 暂留 C++，在报告中记为例外与技术债，第二期类型位置落地时改写。不为它提前做类型函数。
10. **Q10 选 (a)**：未选分支仍做名字解析，不建图、不做类型检查；语言参考写明。
11. **Q11 选 (a)**：验收用图结构与行为对照；训练步时间只记录在 H48 的基线里，不作门槛。
12. **Q12 选 (a)**：`load_tree` 的一次校验单独立项（之后安排）；H51 文档写明设计稿第 11 条未在本项完成。
