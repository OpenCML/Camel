# 已答：循环体**计算**下一个状态，状态**类型**由循环头声明 —— 不是二选一

## 答案

两件事各归各位，所以（甲）与（乙）都不是完整的答案：

- **状态类型**由循环头声明（`loop s = 0 …` 里的初始值给出类型，今天如此，且必须如此 —— 抬升、拆分、转置都要在编译期知道状态类型）。
- **下一个状态的值**由**体计算**，不是一个"声明"：体构造一个新值，那个值成为下一轮的状态。这一点今晚有三条实测。

## 三条实测证据

1. **`std::gir`**：循环状态在图上就是状态类型（如 `(float, float)`），体里写的 `{ a: …, b: … }` 被降成一个 **FILL** 节点 —— 即"按类型构造一个新值"，而不是一段声明。
2. **三种状态都能被抬升**（`jvp_loop.*`、`array_state_is_lifted`、结构体态六个数对上纸面）：抬升逐状态做，正是"体算出一份新状态、抬升也算出它的一阶部分"这个前提成立才有意义。
3. **逐轮映射来自体的表达式**：`swap(s) = loop x = s for k in [1.0, 10.0] do { a: x.b, b: x.a + x.b * k }` 的逐轮矩阵是 `[[0,1],[1,k]]`，两轮后 `M = M₁₀ M₁` —— 矩阵的每一行都是体里那两句算出来的，头的声明只给了类型。

## 仍然成立的那一半（本页原判据）

原页的读数 `[loop-probe] bodyType=int void=0 assignable=1` 仍然有效，它说的是**另一个**缺陷：`builder_control.cpp` 里 `stateType->assignableFrom(bodyType)` 因为"臂的出口类型按构造就等于状态类型"而**恒真**，于是 `loop s = 0 for i in [0,1,2] do { println(s) }` 静默跑出 `0 0 0`。那是"体的值没有被绑定到末句"这件事缺一条诊断，**不是**"下一个状态由谁给出"的问题 —— 前者是缺陷，后者已由上面三条回答。

## 结论怎么用

后续要补的是**诊断**（体没有给出状态值时拒绝，而不是静默沿用初始值），不是改"下一状态由体算"这条语义 —— 语义今天已经是"体算"，只是缺一条拒绝。
