# 已答：循环体**计算**下一个状态，状态**类型**由循环头声明 —— 不是二选一

## 答案

两件事各归各位，所以（甲）与（乙）都不是完整的答案：

- **状态类型**由循环头声明（`loop s = 0 …` 里的初始值给出类型，今天如此，且必须如此 —— 抬升、拆分、转置都要在编译期知道状态类型）。
- **下一个状态的值**由**体计算**，不是一个"声明"：体构造一个新值，那个值成为下一轮的状态。这一点今晚有三条实测。

## 三条实测证据

1. **`std::gir`**：循环状态在图上就是状态类型（如 `(float, float)`），体里写的 `{ a: …, b: … }` 被降成一个 **FILL** 节点 —— 即"按类型构造一个新值"，而不是一段声明。
2. **三种状态都能被抬升**（`jvp_loop.*`、`array_state_is_lifted`、结构体态六个数对上纸面）：抬升逐状态做，正是"体算出一份新状态、抬升也算出它的一阶部分"这个前提成立才有意义。
3. **逐轮映射来自体的表达式**：`swap(s) = loop x = s for k in [1.0, 10.0] do { a: x.b, b: x.a + x.b * k }` 的逐轮矩阵是 `[[0,1],[1,k]]`，两轮后 `M = M₁₀ M₁` —— 矩阵的每一行都是体里那两句算出来的，头的声明只给了类型。

## 原页那条读数的归宿（2026-11-03 复测后改写，不成墙）

原页的读数 `[loop-probe] bodyType=int void=0 assignable=1` 仍然是真的：`builder_control.cpp` 里 `stateType->assignableFrom(bodyType)` 因为"臂的出口类型按构造就等于状态类型"而**恒真**。但我按它去验"静默给错数"，三次实测都说**这个恒真今天没有牙齿**：

- `loop s = 0 for i in [0,1,2] do { s + 1 }` ⇒ **3** —— 体的值确实驱动状态，完好；
- `loop s = 0 for i in [0,1,2] do { println(s) }` ⇒ `0 0 0`，末值 0 —— **这是对的**：`println` 的值是 `int` 0，体每轮给出 0，状态就是 0，正是"体的值成为下一状态"这条规则的结果，不是静默错数；
- `loop s = 0 ... do { "x" }`（int 状态、字符串体）⇒ **被拒**，诊断原话："The initial state fixes the state type. Return that type after 'do', or change the initial value …"。

所以：**这不是墙**。恒真的比较确实在代码里，但体这一侧的普通类型检查把它该抓的都抓到了，没有观察到错数或静默接受。留在这里当一条"这个恒真目前无害"的记录；哪天体的值类型能与状态类型不同而仍被放行，这条记录就是重新检查的入口。
