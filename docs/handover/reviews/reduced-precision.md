# 裁定：bf16 / f16 的标量地位（决策者 2026-10-23，答 reports/reduced-precision-question.md）

问题清单写得好：四问分开、每个选项的代价与未知都列清了。裁定依据设计原则 7.2/7.3 的本义与"同一类事同一条规则"：**`bf16`/`f16` 是和 `f32`/`float` 同等的浮点类型**，只是更窄；`f32` 有的，它们都有，规则相同。

**先更正一处我自己的错**：H238 任务书写了"`bf16`/`f16` 的计算按 `change_precision` 许可"，并据此让张量 `cast` 写入 bf16 时要求许可。这是误读：`change_precision` 是**编译器**以低于写下的精度计算时要的许可（7.3 表中"以较低精度（TF32、BF16 等）计算"）。用户**写下**的转换、写下的类型，就是用户要的精度，不是编译器改变精度——与今天 `f32(x)` 收窄一个 `float` 不需要许可完全同理。

1. **(a) 字面量：a1。** `let x: bf16 = 0.1` 合法，取离写下的十进制数最近的 bf16（与 `f32`/`float` 同一规则，5.1）；越界与下溢的诊断与 `f32` 同一套，各用自己的范围。打印按 11.5 的浮点文本规则。
2. **(b) 标量运算：b1。** 算术与比较都有；规则是"在 f32 里算、结果舍入一次到元素类型"，与张量内核（`dtype.h` 的唯一算术路径）相同；**不需要许可**（运算的类型就是写下的类型）。各后端经通用算子退路即可，翻译与导出按 URI 认识新后缀；`math::min`/`max`/`abs` 等补 bf16/f16（按 H228 的"一个算子、按类型的执行器"）。
3. **(c) 转换：存在，不需要许可。** `bf16(x)`、`f16(x)`、`x as bf16` 与张量 `cast` 一致：写下即是要求，收窄按"就近、平局取偶"舍入一次。**张量 `cast` 写入 bf16/f16 时的许可检查删除**（同上更正）。编译器自行引入的低精度计算（例如把 f32 的矩阵乘换成 bf16 计算）仍然要 `change_precision`——这才是许可管的事。
4. **(d) 归约：返回元素类型，浮点在 f64 中累加、舍入一次。** 与张量的轴 `sum` 同一规则（`reduce.cpp`：double 累加、存回时舍入一次），并且**对 `f32` 数组也一样**——今天 `array::sum` 对 `f32` 在 `f32` 里逐次累加，与张量 `sum` 不一致，同批改正。定义体写出这条语义（例如 `T(xs->reduce<(a, x) => a + float(x), 0.0>)`，整数保持在 `T` 里回绕），数值数组配 `#impl` 内核（10.4）。这样 (d) 不再依赖 bf16 的零字面量。
5. **自动微分**：bf16/f16 值的切线类型是它自己（与"梯度保持所属值的元素类型"一致）；登记切空间与 `add`/`mul` 等的规则，不悄悄丢梯度。
6. 文档里"没有字面量、没有标量运算"的句子（`base.h`、`half.h`、`types.cml`、诊断帮助）随之改写。

这是数值语义的裁定，记入设计原则 7.3 的说明，可由负责人推翻。
