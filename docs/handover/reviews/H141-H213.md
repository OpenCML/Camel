## 追加：`when` 的第二轮（决策者 2026-10-22）

通过：`when` 里可以调用任意编译期 Camel 谓词（用户写的 `is_compound::<T>()`、`has_field::<T>('w')`），只在函数头出现的类型参数也算泛型。

剩下的缺口由报告点明："`match type` 只按形状匹配，写不出 `int` 与 `float` 的区别"，所以七个标准谓词仍在编译器里。这是 `match type` 的缺口，补上：**`case` 可以写具体的类型与类型的并**——
```camel
func is_integer::<T>(): bool { return match type T { case i8 | i16 | i32 | int | u8 | u16 | u32 | u64 => true; case _ => false } }
func is_numeric::<T>(): bool { return is_integer::<T>() || is_float::<T>() || is_complex::<T>() }
```
（与值的 `match` 中 `case 1 | 2 =>` 同一种写法。）补上后七个标准谓词搬进标准库，编译器里的内建删除。

## 答：遍参数的字符串与 `#impl` 的跨模块内核（决策者 2026-10-23，答 `pass-param-and-impl-kernel-questions.md`）

**Q1：按原则改实现。** 命令行上，声明为 `string` 的遍参数取那个词的原文：`out=model.onnx` 合法；`bool`/`int`/`float` 仍按常量表达式解析。这不构成两种写法：`out="model.onnx"` 里的引号由 shell 去掉，到 `camel` 手里还是同一个词；值里有空格时用 shell 的引号，与任何命令行工具一样。`docs/cli.md`、`AGENTS.md` 改回不带内层引号的写法，守卫的豁免随之删除。
