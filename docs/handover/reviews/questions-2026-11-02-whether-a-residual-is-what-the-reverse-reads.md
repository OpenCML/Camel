# 残差集该由"反向实际读了什么"决定，还是由"前向建图时顺手记了什么"决定？

**状态：`lane-m4b` 实测逼出来的，等作者裁；今天按默认建议停在这里，`split` 侧一行未改（改过、实测红了、已回退）。**
问的起因是 `grad`/`vjp` 对一个数组参数的函数做不到。三处转置落点已经改完（成员签名 `(float[], int, float) => (float[],)`，不变量从 8 条降到 6 条），剩下 6 条同一个根：**反向要读原数组，残差里却没有它**。

## 三条读数

- 今天 `jvp(g)` 的残差是 `(int, float, int, float)`（`REINTERP split function=jvp_of_g … residuals=4`，用例 `grad_of_an_array_parameter` 的前身，`nvm`）：**不含数组**。`xs` 只被前向半读，切线半读的是 `dxs`；按今天"跨切线 = 前向半算过 且 切线半读"的判据，`dxs` 是**切线参数**、不跨切线，所以不记。
- `T[]` 的长度**不在类型里**（`float[]` 只写元素类型），所以 `zeros_like(xs)` 的形状推不出来，只能由值给——这是"必须记"的正当理由，不是省事。
- 把"切线半读到的参数"加进残差集后，`split` **具名拒绝**：`skip=residual (the forward half does not compute a value the cut carries)`，21 条既有用例当场红（`[SUMMARY] total: 78, pass: 48, fail: 21, skip: 9`）。机器自己说：**残差是"前向半算出来的值"，参数不是。**

## 两条路

- **A：残差记参数本身。** 由"反向实际读了什么"决定，所以补上数组。代价：`split` 的残差契约要放宽（前向半可以把入参原样交出），上面那条拒绝文案的判据要改，16 条断言（`transforms`/`split`/`remat`/`compositions`）跟着动。
- **B：残差记由参数算出的东西（长度）。** 前向半算 `len(xs)` 记进残差，转置侧按长度造零数组。代价：`stdlib/rulesets/transpose.cml` 的 `idx_arr_t` 与一个造零算子要改，但**不动** `split` 的契约。
- （已被否）`Transpose<F>` 对残差形也收原参数：窗口在 `vjp` 有、`jvp`/`split` 不一定有，一处能用三处不能用，不是机制。

## 默认（照它开工）

**A——由"反向实际读了什么"决定，补上数组。** 落地时同时改 `split` 的残差契约（"前向半可以交出一个参数"），并接受 16 条读数跟着变。
若作者认为"残差只能是前向半算出来的值"是一条硬线，则退 **B**（记长度），那时改的是转置规则与造零算子，不是残差契约。

## 作者的裁定与实测的反证（2026-11-02 05:40 之后补）

作者裁：**「残差不含参数，不是遗漏，是契约；需要的值应由前向半算出。」** 走 B（让前向半把长度算出来），判据之一是"残差集一字不改、16 条断言不动"。

实测三条反证：

- **B 在建图期到不了。** 一个值成为残差要同时满足"前向半算得出它"和"切线半读它"（`split.cpp#residualsOf` 的两个条件）。`len(xs)` 两条都不满足：只在前向半算、没人读 ⇒ 不跨切；只在切线半读 ⇒ 它不在 `beforeCut` 里、被当切线链重算。要让它在两侧都出现过，得有一条"反向需要它"的通道——那正是残差契约本身。**所以"让前向半补算"落在规则展开上是空的，要改的就是残差契约或算子签名。**
- **"残差集不动"与任何残差改动矛盾**：B 记长度同样会让 `residuals=N` 变，16 条断言同样要动。这条判据对 A 和 B 都不可满足。
- **"不是遗漏"有两处相反证据**：`split.cpp` 残差那段自己的注释写着 "A parameter's value is one of them when the backward half reads it"，分支成员（`forward.portOf[parameter * 2]`）已经按它兜底，普通成员缺同一句。把参数放进残差集后，**6 条不变量确实归 0**（`residuals=5`、`(float[], int, float, int, float)`、内层成员 `(float[], int, float) => (float[],)` 与 `contribution=0 … space=none` 都保住），但 **15 条红、核心梯度算错**（`vjp_api.analytic_gradient` 的 `df/dx=0.0` 应为 12.0；`split_two_params` 的 `tangent dx=54.0` 应为 12.0；`split_identity_pipeline` 的 `residuals` 从 0 变 1）——因为 `transpose` 取参数值走的是**按位次**的 `残差 i-1`，残差集一进参数就整体错位。

**下一步要动的两处（未做，等点名）**：`forward(port i)` 改成按 `Residual::parameter` 认身份而不是按位次；转置侧数组余切的零改由残差 `zeros_like` 给（今天是 `skip=unread-parameter port=1 type=float[]`）。

## 本节两条裁定已作废（2026-11-02 06:15）

- **作废一：「残差不含参数，不是遗漏，是契约。」** 反证：注释原话 + 分支成员已有兜底（见上）。
- **作废二：「判据：残差契约一字不改、16 条断言不动。」** 反证：B 记长度同样让 `residuals` 变、16 条断言同样要动；这条对 A 和 B 都不可满足，是把"A 的代价"错记成"B 的好处"。
- **同时作废「A / B 二选一」这个框架**：真因是普通成员缺对称，不是路线之争。

## 第三条反证：切线参数在前向半没有端口（2026-11-02 06:15，实测后补）

`split.cpp` 建前向半时只建**偶数端口**（`for (size_t i = 0; i < sourcePorts.size(); i += 2)`），注释把这件事写成设计：**"The forward half: the value of every parameter in, (result, residuals) out."** ⇒ 前向半只有**值**参数的端口，**切线参数没有端口可以交出来**。

于是：

- "把切线参数记为残差"这一手，前向半交不出值；唯一能兜底的 `forward.portOf[parameter * 2]` 取的是**值**端口，把 `x` 的值放进 `dx` 的位置 ⇒ 实测 `split_two_params` 的 `tangent dx = 54.0`（应 12.0）、`vjp_api.analytic_gradient` 的 `df/dx = 0.0`（应 12.0）。**15 条红的根在这里，不在"按位次映射"**——把映射改成认身份也换不来正确的值。
- "让前向半补算长度"（B）也没有通道：前向半算出的值只有被切线半读到才跨切，而切线半没有任何理由读它。

**所以再往下走要动签名级的东西**：前向半多一个切线参数的端口（"the value of every parameter in" 要变成"值与其切线"），或 `Transpose<F>` 的残差形多收一个原参数。两者都超出现有落点，等作者裁。
