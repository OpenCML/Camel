## 事实：三行，都是读数

1. **整轴 `argmax` 的答案是行优先展开后的位置，不是逐轴的位置。** `argmax([[4.0, 1.0, 6.0], [3.0, 2.0, 5.0]])`
   答 `2`（6.0 是第三个元素），沿轴形式 `argmax<1>` 对同一行答 `[2, 2]`（每行里各自的位置）。
   一行 `float[2, 3]` 的整轴答案是 `5`，不是 `[1, 2]` —— 两个数不是一个东西，所以「折掉行的一个轴」
   得到的逐轴位置**不等于**整轴位置。

2. **批规则要读一行就得有这一行的扁平视图，而 `reshape` 的形状只能写在尖括号里。**
   实测原文（想把 `float[2, 3]` 的那一行在运行期摊成一条线）：

   ```
   No matching function found for argument types: <> (float[2, 3], int[]); 'reshape' takes
   '[s[0], numel(b) / s[0]]' in angle brackets, not in the parentheses: write reshape<...
   ```

   也就是说摊平所需的形状必须是**编译期常量**，而批出的行各轴长度是**值的**、不是类型的
   （`T[..]` 只说「一个张量」，从不说几条轴、每条多长）。

3. **今天的拒绝已经是读数，不是「大概不行」。** 在 `test/plans/feat/compile/rulesets.plan.toml`
   钉着（`vmap_whole_argmax_is_refused_by_name`，四后端跑）：

   ```
   REINTERP vmap function=row_argmax skip=body construct=- uri=tensor:argmaxasked=1 found=0 missing=1
   transforms: vmap has no rule for `tensor:argmax` (the operator has no batching rule key bound at all)
   ```

   `argmin` 同形（`uri=tensor:argmin`，同一句诊断）。诊断分得清「没键」与「有键缺规则」：这里是前者，
   因为写不出规则就没有可绑的键。

## 三条路，各写代价与判据

### A——`reshape` 收运行期形状

- **改什么**：形状从 `with` 参数变成普通参数（`reshape(t, shape)` 与 `reshape<[6]>(t)` 并存或只留前者）。
- **代价**：运行期形状的校验时机要定（今天「元素数对不上」「秩与常量形状冲突」在编译期就查；换成运行期后，
  哪些还在编译期查、哪些变成运行期故障、故障种类是什么）；`reshape` 的 infer 在形状不是常量时得放弃
  秩信息，`float[2, 3]` 这样的精确类型会退化成 `float[..]`，那是类型精度的一次性损失；仓里所有
  `reshape<...>` 的写法要不要跟着改。
- **判据**：`reshape` 的声明仍是一句话（一个名字、两行声明，靠实参区分），且 `vmap_argmax` / `vmap_argmin`
  各一条规则就能写出来——摊平成 `[行数, 每行元素数]` 后沿最后一个轴 `argmax_axis` 就是行优先位置。

### B——加一个 kernel 级的「扁平位置」原语

- **改什么**：诸如 `tensor:argmax_flat` 的原语，答案直接是整份张量的行优先位置（或按行的一条）。
- **代价**：`tensor:*` 多第五个名字，与「同一个名字之下、由 `with` 区分」的口径相抵；OpDef、kernel、infer、
  `vjp`（无梯度）、签名、文档、`--verify-ops` 各一遍。它存在的唯一理由是一条批规则。
- **判据**：能删掉规则集里的折法，代价是原语表里多一个**只为批而生**的名字——若作者认为「扁平位置」本身是
  一个有独立价值的原语（例如未来 `flatten` 语义也归它），这条就成立。

### C——让规则集能写扫描或取对角

- **改什么**：规则集缺的是两种能力之一：沿轴累积（`cumsum`/`scan`）或按位置取对角（`gather` 的对角形式）。
  有前者，位置可以写成「掩码前缀和 + 第一个 1 的位置」；有后者，可以逐轴取对角把逐轴位置合成整轴位置。
- **代价**：比 A、B 都大（新原语、语义要定、四个后端的 kernel 各一遍），但它不是「为一条批规则加的」，
  而是补语言里本来缺的两种形状；这两样东西迟早有别的东西要用。
- **判据**：新增的原语在**至少两处**有独立用途（今天已知：整轴位置；`cumsum` 在掩码类代码里也要），
  否则它就是为了这一条规则加的，不如 A。

**裁定之后补量的一步（「写不出来」必须试，不许推）**：`reshape` 的尖括号里到底能写什么，四种写法各跑一次，
原文各一行（`b: float[2, 3]`，`n = shape(b)[0]`）：

| 写法 | 读数 |
|---|---|
| `reshape<[n, -1]>(b)` | `shape` = `[2, 3]` |
| `reshape<[shape(b)[0], -1]>(b)` | `shape` = `[2, 3]`（不先 `let` 也行） |
| `reshape<[-1]>(b)` | `shape` = `[6]`（一条线） |
| `reshape<[n, shape(b)[1]]>(b)` | `shape` = `[2, 3]`（用另一轴的长度代替 `-1`） |

`argmax_axis(reshape<[n, -1]>(b), 1, false)` 得 `[2, 2]`——这就是那条批规则的全部内容。
