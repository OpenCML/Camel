# 问：`sync` 函数里 `if` 的臂块，是同步链吗？

**问题**：`func f(c: bool): int sync { if c then { println(1); println(2) }; return 0 }` 在 `c=true` 时，臂里那两条 `println` 该不该执行？

**默认建议（本页按此往下做）**：**是。臂块是同步链**，所以 `c=true` 时两行都打印。

## 为什么它是个问题

原则 3.1 第一条："同步块之外、结果没有被使用的带效应的调用不会执行……是合法的预期行为。"

这句话有两种读法，差别只在"臂块算不算同步块"：

- **读法 A（臂块不是同步链）**：`sync` 只覆盖函数体的顶层链；`if` 的臂是另一块，里面没有同步链，所以臂里的效应是"没人用到、也不在链上"，不执行。今天前端就是这么判的：上面那段程序在今天的两棵树上都打出 `SemanticDiag::EffectNotExecuted`（`--> arm_true.cml:4:17`，`c=true` 与 `c=false` 各一次），两次都 `exit 0`、一行不打印。
- **读法 B（臂块是同步链，默认）**：`sync` 声明的是"这块代码按书写顺序执行"，`if` 的臂是它的一部分；臂里的语句因此连成一条链，链上相邻语句互为"被用到"，链尾由臂的结果（JOIN 的 with 端口 / 块的值）用到。

## 裁 B 的理由

1. **A 让作者自己写下的验收读数永远不可能成立**。2026-11-01 的架构审查（`docs/handover/reports/code-review-2026-11-01.md`，P0-1）给的读数是"`c=true` 时按原则 3.1 的例子输出"。在 A 下这段程序**在任何实现上都打印不出东西**，那条读数就是笔误；验收读数不该是笔误。
2. **A 与 3.1 的"区域只决定何时"冲突**。区域成员关系只决定"何时"，不决定"是否"；把臂块判成"没有同步链"，等于说 `if` 里的语句**永远不能被同步**——那正是"成员关系决定是否"的另一副面孔。
3. **B 才让"臂里的语句被臂外节点用到"这件事有意义**。在 A 下臂里的效应是死的，讨论"被臂外用到的臂内语句执不执行"没有对象；B 下它是一条正常的链，用不用由数据边和同步边决定。

## A 的代价（选 A 要付什么）

- 任何想"在 `if` 里按顺序做几件有副作用的事"的写法，都得再套一层 `sync { }`，语言多一条必须记住的规矩。
- 前端要一直保留 `EffectNotExecuted` 的这个分支判定，与"`sync` 声明的是顺序"的说法并存，读代码的人每次都要想"这一层算不算"。

## 附：P0-1 的真红，找到了

按"臂里的语句被**臂外**节点用到，或 `std::opt` 之后臂被重写"去找，第二类**找到了**，而且是可复现的行为差：

```
$ camel tmp/p0/arm_true.cml std::nvm            # 前端判它们"不执行"
exit=0                                          # 什么都不打印

$ camel tmp/p0/arm_true.cml std::opt std::nvm   # 加一个优化遍
2                                               # 打印了
exit=0
```

**同一个程序、同一个后端，加一遍 `std::opt` 就从"不打印"变成"打印"**——按 3.1「遍不把效应或可能出故障的计算移进或移出分支与循环」，这是一条真红：遍改变了效应**是否执行**。它也与 P0-1 描述的形状一致：执行计划按 `live[n] || isMember(n)` 排，臂的成员被当作"要执行"，而 `std::opt` 重写分支后这条成员关系把语句带进了执行。**修法就是审查给的那条**：计划只按存活排，臂里语句的"被用到"经同步链传到臂结果。

第一类（臂里语句被臂外节点用到）**没找到**：能构造出的形状里，臂外的读者看到的都是臂的**结果**，而不是臂里某条语句本身；前端的 `EffectNotExecuted` 会先把"没人用到的语句"判死，所以在今天的树上构造不出"臂内语句被臂外直接用到而它仍被判死"的例子。
