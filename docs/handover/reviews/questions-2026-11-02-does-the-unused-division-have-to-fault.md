# 作者 20:30 那条读数在今天不产生除零：按规则删，还是按读数据删？

**2026-11-02。** 提出问题的是负责人在 20:30 打回 P0-1 时给的那条读数；下面是我们照它量出来的事实，与我们的默认处理。**默认我们照它开工**，作者只在我们判断错的那一处需要改口。

## 事实三行

1. **程序**
   ```camel
   func f(c: bool): int sync {
       if c then { let z = 1 / 0; println(2) }
       return 0
   }
   ```
   `c=true`，四个后端 × `std::opt` 开/关，**A 版（`live[n] || isMember(n)`）与 B 版（只按 `live[n]`）都是 `2`，`DivisionByZero` 一次都没出现**。
2. **`std::gir` 里没有那个除零节点**：`let z = 1 / 0` 的 `z` 没人用、臂也不是同步块（3.4），**前端在编译期就把它判为不执行并删除**，它没走到计划这一层。
3. **计划层计数已经能分辨机制**：在 `computeExecutionOrder` 末尾数"被排进计划、但 `live[n]==false`"的节点——A 版 0、B 版 0（三个程序；`var_read_before_region` 两版都是 1，那一个是图结果本身，与判据无关）。**即：这个状态在今天能构造的图上不出现。**

## 问题

**"作者那条读数复现不出红"要按哪种方式处理？**

- **按规则删**：`z` 无人用 ⇒ 该删（3.1 的"当且仅当"），读数不红是因为**没有东西要被删**，不是判据错；
- **按读数据删**：如果作者认为"这条读数本该红"，那说明**前端不该在编译期删掉它**（臂里无人用的计算该留到计划层再判），改的是前端那一层，不是计划。

## 我们的默认（照它开工）

**按规则删。** 理由：3.1 说节点执行当且仅当被用到，`let z` 不被用到，前端删它是**正确**的；读数不红正是"没有多余的东西被执行"。**机制证据改用计划层计数**（上面第 3 行）：它直接数"有没有人不被用到却被排进去"，不依赖前端是否保留某个节点——**这个数今天是 0/0，说明 B 版每次改动都是"删掉一个没人使用的入口"，而不是"改变了谁执行"**。

若作者认为该"按读数据删"，我们改前端那一层（让臂内无人用的计算留到计划层），再量同一条读数。
