# 诊断的位置行打印哪个路径形式

**问题（一句）**：一条诊断的位置行 `--> <路径>:行:列` 里，那个路径该是**调用方写在命令行上的那个写法**，
还是编译器解析出来的绝对路径？

## 让它是问句的读数

同一个目录、同一份 `fault.cml`（下标越界故障），只换命令行上的写法，位置行逐字跟着变：

| 命令行 | 位置行原文 |
| --- | --- |
| `camel fault.cml` | `  --> fault.cml:4:15` |
| `camel .\fault.cml` | `  --> .\fault.cml:4:15` |
| `camel ./fault.cml` | `  --> ./fault.cml:4:15` |
| `camel sub\fault.cml` | `  --> sub\fault.cml:4:15` |
| `camel D:\Temp\snippetprobe1\fault.cml` | `  --> D:\Temp\snippetprobe1\fault.cml:4:15` |

编译期诊断同一形状（一份 `let x = 1 / return y` 的 `bad.cml`：`camel bad.cml` 打 `bad.cml:3:12`，
给它绝对路径就打绝对路径）。**所以绝对路径不是编译器算出来的，是调用方递进来的：工具现在是「原样回显」。**

三件事让这成了一个问句，而不是一个可以照着文档改掉的错：

1. 两页语言参考的例子写的是 `fault.cml:4:15`（`docs/language/04_execution_model.md` 与
   `docs/language/en/04_execution_model.md` 的 4.6 节），正是读者照页面敲 `camel fault.cml` 会看到的那一行，
   与上表第一行一致——**文档这一侧没有写错**。
2. 但 `docs.snippets_compile` 在 Windows 上是红的：那份检查把自己的临时文件路径**按绝对路径**交给编译器，
   而比较时只擦掉盘符之后那一段（旧模式 `(?:[^\s:()]*[\\/])?` 的字符类里没有 `:`，跨不过盘符的冒号），
   于是同一页在 Linux 上读作 `<file>:4:15`、在 Windows 上读作 `D:<file>:4:15`。红的原文：

   ```
   docs/language/04_execution_model.md:227: output differs from the text block: line 3:
     page says "  --> <file>:4:15", program printed "  --> D:<file>:4:15"
   docs/language/en/04_execution_model.md:271: output differs from the text block: line 3:
     page says "  --> <file>:4:15", program printed "  --> D:<file>:4:15"
   ```

   注意这不是「诊断本身在 Windows 上不同」：诊断换台机器逐字相同，**不同是检查报出来的读数**——
   一条检查在两台机器上给出两个判决，这正是要定下来的地方。
3. `docs/design-principles.cn.md` 没有规定这件事：3.9 只要求故障带位置，10.x 只要求名字完整，
   没有一句说那个位置里的路径取哪种写法。**没规定就是未决，不是文档写错了。**

## 三条路，各带代价

- **甲（默认建议）：位置行原样回显命令行上的写法，永不换成绝对路径。**
  代价：同一份程序从不同目录、用不同写法启动，前缀不同（`fault.cml`、`.\fault.cml`、绝对路径），
  读者 grep 报告时要按自己写的形式找；收益：同一份源码在哪台机器上都给出同一段诊断，读者能把自己敲的那行
  命令与诊断逐字对上，而文档里的例子因此与机器无关。
- **乙：一律打印相对当前目录的规范路径**（`.\`、`./` 归一成一种，去掉 `..`，分隔符统一）。
  代价：多一条路径归一规则和它自己的读数（至少 `fault.cml`、`.\fault.cml`、`sub\..\fault.cml`、绝对路径、
  跨盘路径、符号链接六种），并且 Windows 上分隔符要不要写成 `/` 又是一个新问句；收益：同一棵树里输出稳定。
- **丙：一律打印绝对路径。**
  代价最大：每一段诊断都带上构建机与用户名，跨机器不可比，语言参考里五处 `--> ` 例子全部要改成机器相关的样子，
  检查只能靠归一化比较；收益是「路径总能直接拿去打开」。

## 默认建议（写死；本轮就按它开工，不等回复）

> 诊断打印用户传入时写的那个路径形式，不打印绝对路径，因为同一份源码在两台机器上应当给出同一段诊断；
> 若做不到，就在检查里把盘符归一后比较，并在文档里写明归一规则。

按这条，工具侧不动（它已经是「原样回显」，上表就是证据），本轮做两件事：

1. **检查里归一**：`scripts/check-doc-snippets.mjs` 的比较把整条路径——Windows 盘符与它的冒号也算路径的一部分——
   归一成 `<file>`，于是 `D:\x\fault.cml:4:15`、`/tmp/x/fault.cml:4:15`、`.\fault.cml:4:15` 与
   `fault.cml:4:15` 是同一个读数；归一规则写在那个函数的注释与它的出处（`parseExpected` 上方）里。
2. **文档里写明规则**：语言参考 4.6 两页各加一句「位置行里的路径就是写在命令行上的那个写法」，
   这句话不依赖机器、也不含任何盘符——它是甲这条规则本身，而不是某一台机器上的样子。

丙要推翻这条时，回退面只有两处：那句文档，与 `compareText` 的归一模式。
## 决策者答复（2026-11-15）

甲：原样回显命令行上的写法，不换成绝对路径。这与 rustc、gcc 的做法相同，读者能把自己敲的命令与诊断逐字对上，文档里的例子与机器无关。检查那一侧按 `e9c4a2b02` 的修法读路径（盘符也归一），归一规则写在检查自己的说明里，不写进语言文档。
