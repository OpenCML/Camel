# 一个接受不止 `void` 的版本口：`:var/after` 的第二个实参比裁定宽

**已裁定（2026-10-31 23:50，选 A，而且比我们主张的更宽）。原句：**

> 接受任意值，包括 `void`。22:50 那句"它的值可以是 `void`"说的是"`void` 也行"，不是"只能是 `void`"。这个算子不读第二个实参，它只表示"这次调用之后的版本"，所以调用返回什么类型都一样。今天的实现是对的，把签名写成 `(var T, any) => var T`，语言参考写同一句。

**要作者答的一句**：`:var/after` 的第二个实参应该**只接受 `void`**（按 22:50 裁定的字面），还是**接受任意值**（今天的实现，因为第二个实参不被读）？

## 裁定怎么写的

`reviews/questions-2026-10-29.md` 的 22:50 节：

> **`:var/after(cell, call) : var T`**：第一个实参是变量单元，第二个实参是那次调用，它的值可以是 `void`；结果就是这个单元本身，类型 `var T`。读写成 `:var/get(:var/after(cell, call))`。
>
> 这个算子唯一需要类型系统让步的地方，是第二个实参接受 `void`。把它写进算子的签名，其他算子不受影响。

## 实现时发现（`edges` 的读数）

`var_param` 那一族里，写变量的调用**自己有返回值**（`int`），不是 `void`——只允许 `void` 会让该族直接编译失败。第一版实测的诊断原文（`src/compile/gir/builder_expr.cpp:1528` 的格式串产出）：

```
a variable after a call rejected its operands: the variable is var int and the call is int
```

今天的做法是第二个实参**接受任意值**：`src/compile/gir/builder_expr.cpp:673-676` 的注释写明"调用的值可以是 `void`——**这个算子不读它**"；`src/compile/gir/builder_expr.cpp:1518-1521` 同样写"第二个实参是那次调用，它的值可以是 `void` 且不被读取——是这条边让调用在读到这个版本时执行（3.1、3.5）"；`src/builtin/executors/builtin.cpp:671` 只把 `:var/after` 标成 `stateOnly`。

## 两条路

**(A) 接受任意值（今天已在跑）。**
- 理由：它对这个算子**什么都不读**——第二个实参只用来把"这次调用"接进图里，3.1 的"用到"沿数据边传到调用；宽在这里不放松任何检查。
- 代价：签名比裁定字面宽；`var T` 的结果与第二实参类型无关，读者可能误以为"任何值都有意义"。

**(B) 接受 `void`，另给 `var_param` 族一条替代写法。**
- 更窄，但**要动那一族**：`var_param` 的写调用有返回值，要么换一种形状表达"这次调用之后"，要么在那一族里绕开 `:var/after`。
- 代价：`var_param` 的读写形状要重新对一遍；`twice` / `return counter` 那条验收（打印 `3`）要从新形状重跑。

## 我方倾向

**A**。宽在这里不放松任何检查，因为第二个实参不被读取；而 **B 会把一条已在跑的形状**（`var_param` 写调用有返回值）**堵死**。

## 堵着谁

**`edges` 的 ② 保守写者集合那一步**：② 要按这个算子写 `:var/after(counter, f(v))`，而 `f(v)` 有返回值。签名若钉成 `void`，② 落地前就得先给 `var_param` 族找替代写法。
