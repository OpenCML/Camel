# `:op/ne_*` 那 11 个名字、22 行规则，命名不到任何东西

这不是"建议删除"，是一条**可核对的事实**，摆给作者：它是一次删除的候选，但删不删由作者定。

## 事实

1. **`!=` 没有自己的符号**。编译器判的，原话：

   ```
   error: '!=' cannot be overloaded: it follows an overload of '==': 'a != b' is '!(a == b)'
   with that overload, so the two cannot disagree.
   ```

   所以任何声明都命名不到 `:op/ne_*`——`operator !=` 写不出来，这是语法层的封闭，不是我们偷懒。

2. **这 11 个名字各占 2 行注册**（`eq`/`ne` 都是每个名字两行：`inspect --ops` 里 `:op/ne_d` 出现两次，都是 `with=0 norm=2`）。22 行 = 11 名 × 2 行。

3. **删掉它们之后可核对的结果**：

   | 量 | 现在 | 删掉 22 行后 |
   |---|---|---|
   | `inspect --ops` 的 `OPERATOR` 行数 | **655** | **633** |
   | 三栏表的"已覆盖 / 真缺 / 签名表达不了" | 435 / 145 / 75 | **435 / 145 / 75**（不动：它们本来就在"签名表达不了"这一栏） |
   | `--verify-ops` | 报 559、agree | 声明没变，仍 559、agree |
   | 全量 | `8359/8347/0` | 删完必须仍是 `8359/8347/0`；若掉，说明有地方直接调了 `:op/ne_*` 而不是写 `!=`，那就不是候选。 |

4. **为什么它们是候选而不是垃圾**：`a != b` 是 `!(a == b)`，所以 `ne_*` 与 `eq_*` 实现同一个事实的两份。这与 19:50 那条"同键多规则按类型选"要删 `mul_tensor` 是同一个判断：**同一个事实不要两份实现**。

## 问题

这 11 个名字（`:op/ne_` 加 `b/bf/bytes/c/d/f/f6/i/l/s/z`）该不该删？

- **A. 删**：`!=` 由 `==` 推出，规则多余；删掉是"同一事实一份实现"。
- **B. 留**：它们也许被优化器直接点名（按 URI 匹配规则），删了会让某条规则失效——那要先查有没有按 URI 引用。
- **C. 别的**：例如保留但标注"不可达"。
