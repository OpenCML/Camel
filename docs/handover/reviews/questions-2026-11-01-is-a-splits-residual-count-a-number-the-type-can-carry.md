# `split` 的残差项数，是不是一个类型能携带的数？

> **问什么**：作者 2026-11-01 09:35 的裁定写的是"调用点的静态类型给出 **0/1/3 项残差**"。今天量到的是
> **任意 N**——`f(x, y) = x*x*y*y` 是 **4** 项。若那句话指"三档"（0、1、3），类型层可以用三个刚性形状承载；
> 若指"按图走的计数"，类型只有在**图也在编译期**时才拿得到。**两种读法给出两种工程**，需要一句话拍定。
> **今天堵着谁**：**谁也不堵**（`test/cases/` 里 0 个用例能观察到占位项数，见 §现象 3）。它挡的是两个
> *决定*：M4 之后要不要把 `jvp` 挪进编译期；以及"残差元组能不能被程序拆开"这个对外可观察的形状。
> **为什么我不自己定**：它决定 `Split<F>` 的残差位是"有项数的类型"还是"没项数的占位"，以及占位要不要
> 变成一条成文的类型规则——那是语言类型层的决定，不是写法选择。

## 现象（全部是本轮在 `develop` 上量的，读数逐字）

**1. 项数是任意 N，不是三档。** 同一台构建、同一个探针形状（`split(jvp(f))` 走 `std::nvm`）：

```
f(x,y)= x*x*y*y  →  REINTERP split function=jvp_of_f type=(float, float) => (float, (float, float, float, float)) pure residuals=4
```

`reviews/questions-2026-11-01-the-residual-slot-has-no-type-until-execution.md` 那张表里还有 0、1、2、3 四行
（恒等 `x` 是 0，`x*x` 是 1，`x*x*x` 是 2，`x*x*x*x` 是 3）。**连起来看就是一个随体长大的计数**，没有上界；
所以任何"给 0/1/3 各铸一个形状"的写法都不成立，除非另配一条"超过三个就拒绝"的规矩——那是一条新裁。

**2. `split` 这个名字在 `stdlib/**/*.cml` 里是四个函数。** 上一轮报的"102 处拼写"（我复数量到 105/132）是
`jvp|split|transpose` 三个名字合起来数的，不能当工作量：

| 数法 | 数 |
|---|---|
| `\bsplit\b` 在 `stdlib/**/*.cml` | **36 处 / 35 行** |
| 其中真是 `transforms` 的 `split` | **19 处 / 18 行**（`autodiff.cml:20,24`、`signatures/transforms.cml:32,46,63,64,65,66,104,106,114`、`vjp.cml:7,11,41,49,67`、`signatures/autodiff.cml:50`） |
| 其中**真正的调用点** | **2 处**：`stdlib/vjp.cml:49`、`:67`，都是 `split(jvp(f))` |
| 声明 | 1 处：`stdlib/signatures/transforms.cml:66` |
| 另一个函数 | **17 处**：`str::split`（9/8）、`random::split`（3）、`re::split`（2）、`tensor.cml` 散文（3） |

**3. 今天 0 个用例能观察到占位项数。** 树里没有任何用例把残差元组**拆开**（`vjp_split_halves.cml:15-17` 是
`let (value, residuals) = forward(3.0)` 之后整块传给 `backward`），而 `transpose` 消费的是**形参个数**
——那是精确的，不受占位影响（`transpose` 的余切元组按参数给，不按残差给）。唯一可观察的是诊断里的
`residuals=`，那是图算的。

**4. 占位被问 3 次，其中一次在运行期，而且它给返回值定类型。** `splitHalvesOf`（`modules/transforms/split.cpp:516`，
替身分支 `:561-567`）：

| 位置 | 何时 | 用途 |
|---|---|---|
| `modules/transforms/split_operator.cpp:58` | 编译期（GIR 建图） | 调用点的静态类型 |
| `:95` | 编译期 | 拒绝正文 |
| `:151` | **运行期**（`splitKernel`） | 给返回的 `(forward, backward)` 元组定类型（`:165-166` 的 `pair->set<slot_t>(…, halves.pair)`） |

第三行是这条问题唯一"落地"的地方：**值本身带着一个比它的图窄的类型**。

**5. 那个窄类型会静默丢值，这一笔把它钉住了。** 新增用例
`test/cases/compile/transforms/split_residuals_destructured.cml`（计划条目 `split_residuals_destructured`）：
`f(x, y) = x*x*y*y` 在 (3, 2)，图给四项，程序只拆两个名字——

```
REINTERP split function=jvp_of_f ... type=(float, float) => (float, (float, float, float, float)) pure residuals=4
value= 36.0
r0= 3.0          // x，不是 x*x = 9.0
r1= 2.0          // y，不是 y*y = 4.0
tangent= (24.0, 36.0)
```

两个乘积**从未交到程序手上**，而反传仍然对——**元组是完整的，只有它的类型短了一截**。用例注释与计划注释都写明
"这条钉的是错误行为，修法见页"，并加了 `not_contains = ["r0= 9.0", "r1= 4.0"]`，让半个修法不能悄悄通过。

## 两条路的代价

### A——项数当图的属性：把 `jvp` 挪进编译期，`split` 跟着走

- **代价**：单位不是 `split`，是整条抬升。`jvp` 的抬升发生在内核里（`buildJvpGraph`），要让它和
  `residualsOf`（`split.cpp:394-515`，122 行）在建图期就能跑，等于把 **623 行内核 + 3039 行构图**搬进编译阶段；
  `stdlib/vjp.cml` 的 `split(jvp(f))` 值级组合要换写法（那是设计 4.4 的正文，不是实现细节）。
  另有一条更便宜但**被册子新判据否掉**的近路：只用 `f` 的图在类型层"象征地"走一遍残差——
  那是 `reinterp<jvp>` 抬升律的第二种写法，**同一部法的第二种写法迟早会说出不同的话**（上一笔刚因此删了
  `explainRejection` 里的旧法）。
- **好处**：`splitHalvesOf` 的替身退成"两图自己的类型"，删掉 **~15-20 行**（`:561-567` + 说明 `:555-560`、
  `:516` 与 `split.h:70-73,78-81`、`residuals=` 读数）；**返回值类型 = 图类型**，拆开不再丢值；
  `residuals=` 从运行期读数变成编译期事实。

### B——承认它是任意 N，放在 M4 之后，只在诊断里可观察

- **代价**：占位留着，静态类型继续比图窄一个数；**任何"拆开残差元组"的程序静默丢值**（今天钉在用例里）。
  若将来 `ResidualsOf<F>` 要进签名，这条还是一次性重写。
- **好处**：**今天 0 行改动、0 个用例受影响**（§现象 3）；诊断 `residuals=` 已经如实报出图里的项数，
  读数不撒谎——撒谎的只有类型。

## 判据（三种收益各一句）

- **能删几行**：A 删 **~15–20 行**（全是替身与它的读数，`residualsOf`/`copyHalf` 一行不动——它们产**列表**，
  不产数）；**B 一行删不动**。
- **消掉哪个显式点**：A 消掉**替身** `splitHalvesOf`，它今天在 3 处兼职"项数是几"，其中 `:151` 是运行期；
  B 不消。
- **消掉哪条生存期漏洞**：**两条路都没有**。缺陷是**类型说谎**（值的静态类型比图窄），不是悬空；
  图与元组都活在 `context_` 里（`GraphDraftGroup` 的 `program_ = context_->reserveProgram()`），
  没有任何指针活过它的所有者。

## 默认建议：B

理由只有一条，但它是实测的：**今天 0 个用例能观察到这个数**，而 A 的代价是 623 行内核 + 3039 行构图一起动。
在这个前提下把 A 排在 M4 之前，等于为一个看不见的差数先付全部成本。B 期间唯一的损失是"拆开残差元组会丢值"，
而它现在被一条用例钉着——修的时候会在 diff 里看见。

**要作者答的一句**：`Split<F>` 的残差位取哪一条——**A**（带上项数，`jvp`/`split` 挪进编译期，`vjp.cml` 的组合写法跟着改），
还是 **B**（维持今天：项数由图定、静态类型只给占位，并在类型文档里写明；若选 B，请确认"任意 N"进文档，
而不是"0/1/3"）？两条都能照字面执行；页上三种收益与今天谁被堵都已写明。
