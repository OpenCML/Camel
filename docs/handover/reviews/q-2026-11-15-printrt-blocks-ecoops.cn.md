# 打印往返丢端口，算不算「挡住 ECOOP 的缺陷」

**问题（一句）**：打印再编译**丢一个普通参数端口**这件事，属不属于「挡住 ECOOP 论文的缺陷」，
可以由决策者点名**插队**到「优先级一的三件」之前？

## 让它是问句的读数

同一个程序，打印（`std::cml`）后重新编译，得到 `DIFFERENT`，原文：

```
a structural class has 1 vertex/vertices on the left and 0 on the right --
{"id": "n0", "inputs": [], "kind": "PORT", "param": {"index": 0, "kind": "normal"}}
```

左侧 1 个、右侧 0 个：**重编译后的文档里，那个 `kind:"normal"` 的参数端口没了。**

三件让这成了问句，而不是一个可以直接派活的缺陷：

1. **它与 `#macro` 无关**。三条对照——有标签 / 无标签 / `stdlib` 退回 `025d645db`——失败一字不差，
   所以「改期望值」没有依据（`23fec87f4` 的正文）。
2. **它可能与另一条车道的折叠同源**。`ssa2` 在**不含其折叠**的树（`701388712`）上量到该条 `print_and_recompile` **PASS**、
   `trans.cml` 3/3 绿；在含折叠（`faccf38b9`）的树上红在同一句 `structural class` 上。**两处读数都成立，
   成因尚未收敛到一处。** 谁先动手都可能修错对象，而今晚「归因错」已经发生过两次。
3. **它恰好挡在 ECOOP 的验收仪器上**。验收原文是「导函数子图**在 `inspect` 与 `std::jgir canonical=true` 里看得到**」。
   若 `inspect` / `std::jgir` 与 `std::cml` 共用会丢端口的那段打印代码，则**验收仪器本身不可信**——
   它会给出绿的验收。而 `std::jgir` 是否也丢，**没有量过**。

## 三条路，各带代价

- **甲（默认建议）：不插队；先量一件事，量完自动改判。**
  代价：若 `std::jgir` 也丢端口，那么在量出来之前，ECOOP 的验收一直在用一把可能有问题的尺子，
  而这段时间里它读起来是绿的；收益：三件照原序推进，且**判据先于决定**——不必等人。
- **乙：立刻插队，先把打印往返修好。**
  代价：三件各推迟；而且**成因还没收敛到一处**（打印器与 `faccf38b9` 两处读数），先修可能修错对象。
  今晚已经有两次「两条红长得一样、成因不同」，第三次的代价是一条改错地方的修复加一次误归因。
- **丙：不插队，把这两条标成 `known_fail`，等三件做完再看。**
  代价：`known_fail` 会把它藏起来，而它与验收仪器同源；且今晚刚定过**不许把「设计如此」当红留着**。
  收益最小，不建议。

## 默认建议（写死；本轮就按它开工，不等回复）

> **不插队。** 三件（`var` 化成 SSA、计数做准、E9 的错值）照原序推进，`print_and_recompile` 作为普通红记在账上。
> **但先量一件事**：用 `std::jgir` 打同一个丢端口的程序，看那个 `kind:"normal"` 的 PORT 在不在 JSON 文档里。

- **不在**（`std::jgir` 也丢） ⇒ **自动升级为插队**，因为 ECOOP 的验收仪器坏了，理由不必再问；
- **在**（只有 `std::cml` 丢） ⇒ 维持不插队，本页转成一条普通待办。

按这条，本轮做一件事：**取那一次读数**（一条命令、一个程序、两行输出）。
它不需要作者在场，也不阻塞任何车道——**它是把「要不要问」变成「量一下就知道」的那一次测量。**

## 示例：把「要不要问」变成「量一下」的形状

```
camel cases/linear.cml std::jgir      # 数一数 JSON 里 kind":"PORT" 且 param.kind":"normal" 的条目
camel cases/linear.cml std::cml       # 打印，再编译，比较两份 jgir
```

前一行的条目数若与源程序一致，甲成立；少一个，乙自动生效。
