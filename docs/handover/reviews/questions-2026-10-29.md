## 补一条缺陷（第 21 条，归"优化保效应"或前端那一路，空出来的先接）

**经函数类型的形参调用、写了捕获 `var` 的回调，调用处没有记成对该变量的写**（原则 2.6："函数通过捕获……写入一个 var，与通过 var 参数写入一样，调用处应当记为对该变量的一次写入"）。
- **现象**：未写资源子句的函数值，资源签名是 `Generic`；实例化时，实参的资源集没有带进实例。所以 `apply(f)` 里调用 `f(1)` 不取结果时，`EffectNotExecuted` 看不到这次调用有效应，一点诊断都没有（ICPC 研究的 R38，及决策者 10-26 的体验记录）。
- **修法**：函数类型的形参在实例化时接过实参的资源集，调用处按"对这些变量的写"处理；`pure` 函数调用资源泛型的形参要被拒。
- **验收**：R38 一类的程序得到诊断；`func applyPure(f: (x: int) => int): int pure { return f(1) }` 被拒。

## 裁定（2026-10-31 15:30，冲刺主线 M2）：`split` 在哪一刀切开——甲、乙都不选，切在每个形参的两个分量之间

**甲不选**：切向量是每次调用都要给的参数，不是函子的配置。按 `with` 参数的判断依据（`with` 放的是"这个函数是谁"，每次调用的值放普通参数），切向量不该进 `with`。**乙不选**：它要参数包的减法，为一个切口另造一套类型运算，不值得。

`split` 在冲刺里的唯一用途是线性化：`split(reinterp<jvp>(f))`。`reinterp<jvp>(f)` 的每个形参都是 `Lift<T> = (T, Tangent<T>)` 一对，所以切口天然就在这里：**每个形参的第一分量（值）现在就有，第二分量（切向量）以后才有**。这正是 JAX `linearize` 的切法。

```camel
type Split<F> = (
    (..ParamsOf<F>) => (ResultOf<F>, ResidualsOf<F>),                   // 前一半：原值进，结果与残差出
    (ResidualsOf<F>, ..Tangent<ParamsOf<F>>) => Tangent<ResultOf<F>>   // 后一半：残差与切向量进，输出切向量
)
func split::<F>(f: F): Split<F>   // F 是 reinterp<jvp>(g) 的结果，形参都是 Lift 的一对
```

- 这里 `F` 指原函数 `g` 的签名。`ResidualsOf<F>` 是编译器算出的类型函数，不是用户写的，每个函数各有一个，与 `Tangent` 同类。它的值是一个元组，按你们页里写的：项按程序顺序编号，不借用前一半的局部名，这条照做。
- **后一半对切向量是线性的**，这正是 `transpose`（M3）的输入条件；`vjp = transpose ∘ split ∘ reinterp<jvp>` 就这样接上了。
- 通用的"任意一部分输入现在就有"（对任意形参子集做部分求值），等真有用户需要再做，不在这一笔里留半个口子。设计稿 4.2 的签名按上面改写，第 7 节"待定"里 `split` 这一项同时清掉。
- 直线代码先做：值节点归前一半；凡是读到切向量的节点归后一半；前一半里被后一半读到的值，记为残差。然后做分支（条件是残差）和循环（每轮残差收集成数组），照 4.2。
