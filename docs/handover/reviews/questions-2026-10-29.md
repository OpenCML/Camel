## 补一条缺陷（第 21 条，归"优化保效应"或前端那一路，空出来的先接）

**经函数类型的形参调用、写了捕获 `var` 的回调，调用处没有记成对该变量的写**（原则 2.6："函数通过捕获……写入一个 var，与通过 var 参数写入一样，调用处应当记为对该变量的一次写入"）。
- **现象**：未写资源子句的函数值，资源签名是 `Generic`；实例化时，实参的资源集没有带进实例。所以 `apply(f)` 里调用 `f(1)` 不取结果时，`EffectNotExecuted` 看不到这次调用有效应，一点诊断都没有（ICPC 研究的 R38，及决策者 10-26 的体验记录）。
- **修法**：函数类型的形参在实例化时接过实参的资源集，调用处按"对这些变量的写"处理；`pure` 函数调用资源泛型的形参要被拒。
- **验收**：R38 一类的程序得到诊断；`func applyPure(f: (x: int) => int): int pure { return f(1) }` 被拒。
