# 出口门要等的"链上最后一站"，这个服务归谁？

日期：2026-11-03　状态：**默认按 ①(a) 落地**

## 问题

autodiff 重建一张图之后，要把"新结果"顶替旧出口，而旧出口可能等过一些语句（打印之类）。
今天的写法是手造一个 `GATE`，把旧出口写成它的**控制输入**（`modules/autodiff/pullback.cpp#setResult`，
378–391 行；同类还有 3022 的臂结果、4756 的体结果、4844 的梯度门）。

`GATE` 的等待按 `docs/design/effects/edges.cn.md` 5.3 是**同步前驱**，不是控制输入。建图器在链首
造位门时，旁边那条控制边让它蒙混过关；本分支按 P0-2 不再造链首位门，它就只剩一条不算等待的
控制边，封印检查（`src/runtime/graph.cpp#validateRuntimeGraphPayloadImpl`）于是打中：`Runtime graph 'jvp_of_g' has GATE
node 8 without a wait`。

实测过"照建图器的方式等"这条路（把旧节点的同步前驱与 ctrl 输入接成门的同步前驱）：
**`old` 身上没有可继承的等待**——那个 9 节点纯数学图的旧出口本来就没有等过任何东西。所以问题的
真身不是"autodiff 少写一条 wait"，而是：**"这个值在链上的最后一站"这个答案，今天只有建图器有，
pass 拿不到。这个服务归谁？**

## 三条路与代价

1. **`GraphDraft` 给出这个答案**（谁写的谁记，不现算）。代价：draft 要记"每个区域的链尾/最后一个
   作用于语句"，建图器与 inline splice 都要在收尾时写进去；好处是 pass 能问，且不必知道建图器。
2. **`Builder` 持有**（正路）。代价：`Builder::chainPlaceForNode` 在 `compile/gir` 里，一个 pass
   够不到；除非建图器在收尾时把结论写进 draft —— 那就等于第 1 条。
3. **让 autodiff 走建图器重建**（最正）。代价：那是整条 autodiff 建图路径的迁移，不是一笔。

## 默认建议：①，并且顺带把判据说准

**出口门只在"图里真有作用于语句"时才造，并且它等那条语句；图里没有效果语句就不造门。**

理由：`jvp_of_g` 这种纯数学图拿一个门去等"没有的东西"，本身就是造一个没人消费的位——P0-2 要删的
正是这种位。所以这一处的正确处理是"没有作用语句 ⇒ 不造门"，而不是"给门补一条等待"。

## 落地

`modules/autodiff/pullback.cpp`：新增 `afterTheSameStatements(transaction, value, old)` ——
取 `old` 的同步前驱（再并上它的控制输入，去重），没有可等的东西就**原样返回 `value`**（不造门）；
有就把它们写成新门的**同步前驱**。四处改用它：

| 位置 | 改前等什么 | 改后等什么 / 为什么不造门 |
| --- | --- | --- |
| `setResult` 出口门 | 一条控制边指向旧出口 | 旧出口的等待（同步前驱）；没有就不造门，值直接当返回 |
| 3022 臂结果门 | 一条控制边指向旧的臂结果 | 同上 |
| 4756 体结果门 | 一条控制边指向旧的体结果 | 同上 |
| 4844 梯度门 | 一条控制边指向函数返回的那条链 | 同上（`hasOrdering` 守门不变） |

封印检查一个字没动：仍然拒绝"手造控制边当等待"的门。
