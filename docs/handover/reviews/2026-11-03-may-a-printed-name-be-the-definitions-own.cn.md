# 打印器可以把 `sum<0, false>(m)` 写成 `sum_axis(m, 0, false)` 吗

**问题**：一个算子的"写名"和它"边界在哪"是两件事；当两个算子共用一个写名时，打印器只能知道其中一件。是否允许打印件用一个**与源不同、但唯一**的名字？

## 形状

`tensor:sum` 是整表归约，源里写 `sum(m)`；`tensor:sum_axis` 是带轴的形式，源里写 `sum<0, false>(m)`。两个算子的定义都 export `sum` —— **一个写名，两个算子**，区别只在 `<>` 里那两个数。

打印器拿到的是节点：两者都是**三个普通输入、零个 `with` 输入**。也就是说：

- `OpDef` 知道边界（`withAfterNorm`、`ordinaryParams`）；
- 节点不知道，这份知识没有随节点走；
- 打印器只能二选一：猜边界，或者不印。

"猜"这条路试过（把末尾若干个值搬进 `<>`），结果不是把这一类印对，而是**连带把已经印对的程序变坏** —— 同一张表里别的算子（打印族的格式串、`concat`、轴归约）也带 `<>`，而它们的 `<>` 值在节点里不总是常量，搬错就把参数放进了括号。逐次的读数在提交信息里。所以打印器现在**不给这类算子形状**，它们被按名拒绝。

## 两条路

**A. 让边界随节点记录。** 节点上记下"这次调用把后 N 个值写在 `<>` 里"，打印器照抄。

- 代价：改动在**节点/图的记录**（构建侧），不在打印器；还要决定这个事实属于每个节点还是每个算子实例。
- 好处：打印件与源逐字一致，`sum<0, false>(m)` 原样回来。
- 风险：给节点加字段是语义面的改动，要走设计原则的流程。

**B. 承认"印出来的名字可以不是源里的写名"。** 用定义自己的名字写限定名：`tensor::sum_axis(m, 0, false)`、`tensor::mean_axis(...)`。

- 代价：与"打印件要像源"这个直觉冲突；读者要相信"两个写法是同一个算子"。
- 好处：**不需要知道边界**。名字唯一确定算子，这正是已定的判据（"打印出来的名字必须解析回同一个算子"）。
- 已验：`tensor::sum_axis(m, 0, false)` 能编译，且输出与源逐行相同。

## 默认

**按 B 往下走**，除非作者说"print 必须复现源里的 `<>` 写法"。

理由：B 落在一条已经定过的判据上，改动只在打印器一侧；A 是给节点加事实，属另一类改动。

**已按 B 做成的部分**：无 `<>`、无 `::<T>` 的算子已按 `module::name` 印（`tensor::tanh(x)`、`tensor::matmul(a, b)`）。带 `<>` 的一族（`sum`、`mean`、`concat`、`argmax` 的轴形式）与带 `::<T>` 的一族（`zeros::<f32>`、`from_bytes::<...>`）暂按名拒绝，等这一页的裁定。
