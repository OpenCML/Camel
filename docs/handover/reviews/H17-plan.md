## 必须修改（结构）

1. **小数组内联，不为每个数字数组单独分配缓冲区。** 按现计划，每个 `int[]`、`float[]` 都多一次缓冲区分配、一次可终结登记与原子计数，`alloc_small`、`map_chain` 这类小型逻辑程序会变慢——这是红线（设计原则 10.5）。改为：数据不超过一个阈值（建议 256 字节，作为常量写在一处，以基线校准）时，数字直接内联在 GC 对象里（随对象移动，无计数、无终结器，与今天相同）；超过阈值才用 `Buffer`。内联数组在**被导出（DLPack）或产生视图时提升**为 `Buffer`（复制一次，此后稳定）。"缓冲区只放数字"的红线不受影响。提交 3 之后立即跑一次基线的三个小程序，作为门槛。
2. **缓冲区的字节数计入 GC 的触发。** 缓冲区不在 GC 堆里，若 GC 只看堆内字节，大张量反复产生垃圾时 GC 迟迟不触发、缓冲区释放不了，进程会先耗尽内存（.NET 的 `AddMemoryPressure`、V8 的外部内存计数解决的就是这个）。要求：活着的缓冲区字节数参与年轻代与全量收集的触发判断；自检加一条"循环中反复产生大张量，峰值内存有上界"。
3. **元素总数与第一维用 64 位。** `size_`、`numel_` 改为 64 位（形状本来就是 `int64_t`）。数据管线中一维数组超过 2³² 个元素是现实情形（分词后的语料）。槽存储的容量可以保持 32 位。
4. **原地更新的判据 1 覆盖循环状态。** 设计原则 3.10 刚定"收集每轮的值用状态数组追加"，依赖它不复制：`LOOP` 的状态在下一轮开始时旧值不可见（未被捕获时），要和 `t = t->relu` 一样标为"不共享"。用 `loop xs = [] for … do xs + [v]` 的分配计数断言覆盖。
5. **临时值的原地更新留给使用者索引**：`relu(exp(x))` 中 `exp` 的结果只有一个使用者，按设计也应原地；这需要图上的使用者计数，属于协调者一方的图存储重构。H17 只做重绑写法与循环状态，在 `OperatorTable::reusesOperand` 处留好接口即可，报告中列出。
