# 生成器的 `halt` 位已经没有读者了：状态元组要不要从 2 元组收成 1 元组

- 日期：2026-11-18
- 提出：`lane-genstate`（作者 2026-11-17 每日审查第 6 条落地过程中查出）
- 问题一句：**`halt` 在两份状态收成一份之后没有任何读者，要不要把它从状态元组里删掉？**

## 1. 实测事实（不是推理）

```
`git grep -n 'pcName\|haltName'` 整树 **0 处**（按名比较已经删掉，不是换成读另一个名字）
`feat/compile` 2627 / 2600 / **10 fail / 17 known**，逐名与基线相同（**新增 0、消失 0**）
`generators.cml` 的 `std::jgir` 删除前后都是 **647 节点**，
  唯一结构差异 `__gen_touch__2` → `__gen_touch__0`（两张死单元退出编号表）
```

`halt` 的读写点：

```
6336 / 6421  写 1
7001         写 0
6284         **唯一的读** —— 但它只是把状态打包出去，不是在判什么
循环停判      读的是**轮状态第 1 位**，不是 `halt`
```

⇒ **所以：`halt` 被写了四次、被读了一次，而那次读不产生任何分支。**
⇒ **今天的状态元组是 `S = (pc, halt)`，其中 `halt` 是纯负重。**

## 2. 两条路，各自的代价写清

**路 A：删掉 `halt`，状态收成 1 元组 `S = (pc)`**

```
· 好处：真正只剩一份、一个字段；「状态是恢复点」这句话第一次字面成立
· 代价：`slots` 全空时 `S` 变成 1 元组 —— 而 `docs/design-principles.cn.md` 5.4 写的是
        「S 只列恢复点」，1 元组仍然符合；
        但 **11-16 的报告写的是 `S = (pc, halt)`**，那条已被引用过
· 风险：`halt` 目前被写 4 次；删它要同时删掉那 4 处写，**它们是「生成器停在这里」的唯一记号吗？**
        ⇒ **必须先证明「停」只有一处记（轮状态第 1 位），否则删掉会丢掉停机信息**
```

**路 B：留着 `halt`，但在注释里写清「它是导出用的，不是判据」**

```
· 好处：不动已引用的形状（11-16 报告、5.4 的讨论）
· 代价：一个被写 4 次、不被判任何分支的字段留在「恢复点」里 —— 下一个人会再问一次
· 风险：它看起来像状态的一部分，于是**别人会以为「停」有两条真相**
```

## 3. 默认建议（按此开工，不必等回）

**走路 B，且只写注释，不动形状。**

理由三条，按分量排：

```
① **删 `halt` 是「改语义」，不是「改表示」。** 作者第八条说的是「语义变了就改表示」，
   而这里语义**没变** —— 变的是我们发现一个字段没有读者。
   ⇒ **「发现一个字段没用」的正确出口是记录，不是当场删。**
② **证据还不够。** 「唯一那次读不产生分支」是静态读出来的，
   而「停」是否只由轮状态第 1 位记，**没有一条判据钉过**。
   ⇒ **在拿不到判据的地方动手，等于用一个猜测替换另一个猜测。**
③ **它不挡任何事。** 这 5 条 `stream.generator*` 的红根因已确认是
   「Ref 参数在步进里不再是引用」（最小复现：`state.set` 的值不是引用），**不是状态形状。**
   ⇒ **删 `halt` 不会让任何一条红变绿。**
```

**所以要做的只有一件**：在 `halt` 的写入点附近写一句注释——

> `halt` 目前只有导出读者（`6284` 打包），不判任何分支；循环停判读的是轮状态第 1 位。
> 它是否该留在状态里，见 `docs/handover/questions/2026-11-18-generator-halt-has-no-reader.cn.md`。

**什么时候改判为路 A**：当有人能给出一条判据，证明「停」在状态里只有一处记 —— 那时删 `halt` 是清理，不是赌博。

## 4. 这条为什么值得留一页

作者第 6 条的原话是「**生成器状态按 11-16 的答复做成按值传递的一份状态**」。
`lane-genstate` 做到了：按名比较 0 处、三张同名表并成一张、`std::find` 全没、两份拷贝里的死那份的读者是 0。

**⇒ 但「一份」这个词有歧义：一份拷贝，还是一份**字段**？**
**⇒ 这份页钉的是后者。而按默认（路 B），「一份」指前者 —— 今天已经成立。**
## 决策者答复（2026-11-18）

**走路 A：删掉 `halt`。** 默认（路 B，只写注释）不采纳。
- "停"已经由轮状态第 1 位回答，循环的停判读的就是它；`halt` 被写 4 次、没有一次读决定任何事，它是"停"的第二份记录。留着它正是页里自己说的风险——"别人会以为停有两条真相"；注释挡不住第二份真相，删掉才挡得住。
- "11-16 报告写过 `S = (pc, halt)`"不是理由：内测不计兼容，报告记的是当时的形状，不是承诺。5.4 "S 只列恢复点"，1 元组正合。
- 页里的前提照做：删之前先确认"停"只有轮状态第 1 位这一处记（`git grep` 加上生成器全部用例：提前结束、`yield` 之后结束、空生成器、嵌套生成器）。确认之后连同 4 处写一起删，读数按逐名比较 `[FAIL]` 集合报。
