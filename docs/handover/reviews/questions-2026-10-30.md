## 1. 一个跨 `yield` 的值，状态里怎么放？（三选一）

**先更正问法**：状态不是"结构体里的格"。状态就是 `__gen_pc__`、`__gen_halt__` 与那些单元本身（`7637a71b7` 已定：GCT 里单元是节点身份，从结构体里取出来的值不再是单元）。所以真问题是"它成为下一个单元、**类型与初值从哪来**"——今天的 `addCell` 必须带初值，GCT 没有"某类型的占位值"（`src/` 与 `include/` 里 `Data::null()` 一共 11 处，没有一处是给单元当无值初值用的）。5.4 里"状态 `S` 是……结构体"那句因此也要改，与 7.3.1 的"状态机还没有"一并留在最后一笔。

三种写法，代价不同：

- **A 单元"带类型、暂不赋值"**：`vari` 的 ref 只带类型，第一次写之前读是编译错误（数据流证明）。最贴 5.4"活过 yield 的局部都是单元"，但要给 GIR 加一种"已声明未赋值"的单元形状；顺带修掉 `UnresolvedReference`。
- **B 单元可空**：初值 `null as T?`、读时拆。不加新形状，但图里多一步可空，"读在写之前"退化成运行期 null 而非编译错误。
- **C 只做 match**：把**被 match 的主语**放进单元（主语在 match 处就有值，初值天然在），臂绑定仍由 CASE 绑，恢复臂从主语单元重取载荷。一个 match 一个单元；代价是恢复臂要重做模式提取（`case v` 上多一次非空拆），且"绑定"与"局部"成两套机制。

各自的落点：

| | 新增的 GIR 形状 | "读在写之前" | 局部与绑定 |
|---|---|---|---|
| A | 一种"已声明未赋值"的单元 | 编译期错 | 同一套 |
| B | 无 | 运行期 null | 同一套 |
| C | 无 | 编译期错（载荷重取） | 两套 |

**⑥ 循环里的 `yield` 落在同一处，不是另一个问题。** 查过了：把循环开起来，要先把循环拆成臂（入口、条件、体、步进），因为臂是各自独立的图，跨得过去的只有单元（`src/compile/gct/builder.cpp:5733` 建臂、`5917` 起按 `pc` 选臂）；而单元建在生成器**被创建**时跑的那段体里（`5685` 的 `addCell`、`5951`、`5955`），所以单元的初值在创建那一刻就定了。可循环的初值与序列是"在循环所在处求值一次"（`3365`–`3408`，注释在 `3383`）——拆成臂之后，那就是某一臂，而不是创建时。

- 单层 `while`、累加器初值是常量（`loop i = 0 while i < n do { … yield … }`）：把它变成单元时 `addCell(i, visitData(0))` 在创建时求值，与在循环处求值同值（常量无副作用、不看任何单元），**不需要本条**。
- 作者点名的 `pairs(n)` 是双层：内层的起点从外层当前值算（5.4 的例子 `docs/design-principles.cn.md:393` 写 `func pairs(n: int): (int, int).. { … yield (i, j) … }`），创建时外层还是 0，拿它当初值只能得到错的值；`for v in xs` 的迭代器同理（序列在循环处求值，不是创建时）。

也就是说，循环的某个形状第一次拉取时**还不该有值**——正是 A/B/C 要定的那一件事（A 让它"暂时没有值"，B 让它"先是 null"）。所以 ⑥ 等这一条，不再另开一问；裁定之后，`pairs(n)` 与常量初值的单层循环可以一起落。

## 2. `return` 不带值：改解析器还是改文档？

语言参考 7.3.1 写"`return` 结束流，不带值"，7.3 写"不带值的 `return`、`return null` 用于没有值的块"，5.4 写"要交出错误元素写 `yield error(...)` 然后 `return`"。**但今天 bare `return` 解析不过**：

- `func g(): int.. sync { yield 1; return }` → `Unexpected '}'`，`expected an expression`；
- `return null` 可以（读数：`1`，流结束）；
- 语法是 `retStmt : ('return' | 'yield') dataList`（`src/parse/syntax/parser.cpp:1250`），`dataList` 至少一个表达式。

所以要么解析器接受 bare `return`（文档现写法），要么文档改成"不交值写 `return null`"（解析器现行为）。本格没有动它。

## 3. 出错之后，元素还继续产出吗？

5.x 里**没有明文**。查到的相关三句：

- 5.4："要交出错误元素写 `yield error(...)` 然后 `return`"——像建议写法，不像"错误元素自己终止流"的规则；
- 3.9："错误值就是一个值……不展开调用栈，没有'传播'与'捕获'"；
- 7.3.1："故障发生在产生那个元素的那次拉取处（**故障不是值**），之前已经交出的元素不受影响"。

照字面，错误元素只是一个值，流该继续就继续（`return`/体到尾才结束）。但这份读法没有判据，`ab25942d7` 的用例体在错误元素后就结束了，**区分不了"可续"与"立即止"**。请裁：**可续**（错误元素之后照常产出，除非体里 `return`）还是**立即止**（交出错误元素即结束流，写不写 `return` 都一样）。裁定后加一条能区分两者的用例（错误元素之后还有元素/效应，看它们出不出现）。
