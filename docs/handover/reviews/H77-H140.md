# H77–H140 批复（2026-10-22）

这一段合入的 H77–H140 全部通过（泛型第一期步骤 5–6 的一部分、H19 第 0–11 步的大部分、规则库替换 `algebra.cpp`、`--devices`、`#macro`/`#vjp` 改为标签、下标切片等）。下面只答各报告的待决问题；没有列出的报告无待决。凡标"可推翻"的，是协调者按原则推出、但涉及语言表面的裁定。

**H77**：1 `#strict` 存在节点的属性集，满足"清空有效许可、不新增许可位"，接受。2 闭包规则不做，`#vjp(rule)` 的规则是静态函数。3 `vjp` 是 `autodiff` 的模块标签（设计原则 6.2 的示例本来就是模块标签），写 `#vjp` 的模块须导入 `autodiff`，接受。4 跨进程缓存以后随持久化一起定。

**H85**（`#independent`）：1 消费点是并行调度器（`std::prl`）对用户函数的元素调用路径，与算子的元素调用同一条路。2 它声明"元素之间没有依赖、不共享可写状态"，因此**既许可重排也许可并行**（设计原则 3.6"并行来自声明的性质"）。3 已由 H95 移到 `std::opt::ctrl`。4 故障语义沿用并行 `map`：已开始的跑完、未开始的不开始、报最小下标。

**H86 / H96**（`static loop`、`indices`）：
- `static loop` 写成语句时按普通表达式语句处理（纯的、值被丢弃即按现有规则拒绝），不另设规则。
- 展开出的绑定可以遮蔽外层，与普通 `let` 一致，不加诊断。
- `indices` 只接受元组（结构体用 `fields`）；**允许 `(j, F)`**，第二个名字绑定元素类型，与 `fields` 的 `(n, F)` 对称。
- `indices` 的操作数只用于取类型；`StaticTuple` 落地后不再建值节点。
- `constas` 值参数**已裁定属于第一期**（reviews/H51-plan.md 第 2 条），按计划做，连同 rest 参数与 `StaticTuple`。

**H89**（转义）：**可推翻**——取消八进制转义：只保留 `\0`、`\xHH`、`\u{...}` 与具名转义（与 Rust 相同），`\101` 这类写法是未知转义。三种字符串一致。4 的文档措辞接受。

**H91**（常量与捕获）：1 建图时**不**折叠全常量的纯节点（图反映源码，折叠是 `std::opt` 的事）；2 `externalInputs` 不做纯度分析，这类节点仍是输入，`std::opt::fold` 之后自然成为常量；3 函数常量（`let f = inc`）是常量，不是捕获。

**H92**（lambda 参数推断，设计原则 5.9）：lambda 在期望函数类型的位置时，先由其他实参与期望类型定下能定的类型变量，再按此降低 lambda——**参数类型定得下来就推**，返回类型由 lambda 体得出，不要求整个期望类型事先确定。实现顺序随之改为"其余实参先实例化、lambda 后降低"。参数类型定不下来时报错要求标注。5.9 的例子 `tree_reduce<(count, leaf) => count + numel(leaf)>(model, 0)` 是验收用例。

**H95 / H98**（声明是否进同步链）：**可推翻**——**不进**，H98 草稿不实施。字面量构造的分配不是语言层面可观察的效应，按依赖求值（设计原则 3.1）不为它排序；测量分配窗口的测试改为让测量与被测值有数据依赖。

**H97**（`#macro`）：1 不带参数。2 宏的值可以是函数值（静态函数或捕获都是常量的闭包），作为常量。3 宏产生新的宏时继续展开到不动点，展开轮数由 `std::macro` 的遍参数限制（默认给一个上限，超出报错）。4 不支持写在 lambda 上。5 无体声明上的 `#macro` 报"标签不能用在这里"。6 不提示。

**H102**：融合记为图上的组属性、CPU 暂不省中间张量，接受；CPU 的融合内核以后读 `tensor.fusion`（GPU 设计稿 G6）。`linear` 保持规范 GEMM。

**H108**（`load_tree` 需要静态类型的文本）：选**选项 1 的库函数形式**——`type_spec<T>()`（或同类名字）是在编译期按类型展开、折叠为常量的库函数，产出与 manifest 的 `dtype` 与 `shape` 对应的结构化值；不实现 `typeof`，不给内核开 5.5 的例外。之后按设计稿写 `load_tree`。

**H110 / H118**（交换律）：整数张量的 `add`/`multiply` 在整数（回绕）语义下精确可交换——由 `tensor` 内核契约声明 `BinaryLaw`。双向规则不走交换退路，接受。`float_fold` 需要 `no_infs`，正确。

**H134**（资源名）：1 `io:terminal` 并入 `stdin`（终端模式与读输入必须互相有序）。2 `eprintln` 按 H19 批复（问题 5）进前奏，补上。3 不加 `inspect --resources`。

**H16**（Json）：1、2 保持；3 Json 的错误种类进 H19 第 7c 步的错误种类目录；4 **`CAMEL_JSON_MAX_DEPTH` 是环境变量开关，删除**，深度上限暂为固定常量（以后作为 `decode` 的可选参数开放，设计原则 11.2）。
