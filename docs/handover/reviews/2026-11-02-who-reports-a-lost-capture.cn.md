# 捕获被丢掉时，谁该报错？

**这一页问的是 high-2 返工里**剩下的那一半**。方向作者已经裁了："被变换函数的捕获值，就是那个函数值的一部分，变换照抄它，不许丢，也不许回到拒绝"。照抄这一半已经落地（见下"已落地的默认路"）。没裁的是：**照抄不了的时候**（捕获的类型没有批量形式，或者调用链上根本拿不到那个值），**该由谁、在哪一层报错**。

## 现象：改前读数

两个程序同一个形状——`make(3.0)` 返回 `(x: float) => x + c`，`c = 3.0` 是捕获，`xs = [1.0, 2.0, 3.0]`：

| 程序 | 改前打印 | 手算 |
| --- | --- | --- |
| `vmap(make(3.0))(xs)` | `[2.0, 4.0, 6.0]` | `[4.0, 5.0, 6.0]` |
| `remat(make(3.0))(1.0)` | `1.0` | `4.0` |
| `vmap(remat(make(3.0)))(xs)` | `[2.0, 4.0, 6.0]` | `[4.0, 5.0, 6.0]` |

根因两处，都是"捕捉没被带上"，不是算术错：

- `modules/transforms/vmap.cpp` 的体构建（`buildVmapGraph` 的 walk）：源图的**每一个** `Port` 都接到批量参数上（`copyOf[ref] = port`），捕获口也在内。`x + c` 于是读成 `x + x`，`[1,2,3] + [1,2,3]` 就是 `[2.0, 4.0, 6.0]`。它读的是 `GCGraph::closureNodes()`（`include/camel/runtime/graph.h`），那里明明把捕获列了出来。
- `modules/transforms/remat_operator.cpp` 的拷贝：只把 `cloned.normPorts` 和 `cloned.withPorts` 装回草稿，`cloned.closureNodes` 没装。生成的图因此声明"我不捕获"，调用时没有任何一处去绑，捕获口读到自己槽位的零 ⇒ 体算的是 `x + 0`。

## 已落地的默认路（这一半不用裁）

**变换自己补常量端口**：捕获按一个常量进产出的图。

- `vmap`：`buildVmapGraph` 从**函数值**（不是图）拿 closure tuple，按源图的捕获顺序，把每个捕获 lift 成"一行批量"的静态值（和体内写死的常量走同一条 `liftConstant`），体里读捕获就读那个值。产出的图不再声明捕获，所以值的 closure 是空的，调用侧按位置绑定不会错位。
- `remat`：拷贝把 `closureNodes` 与 closure 布局一起装上，标记后的值仍然捕获它捕获的东西。

改后读数：`[4.0, 5.0, 6.0]`、`4.0`、`[4.0, 5.0, 6.0]`，两个后端（`nvm`、`fvm`）同值。两条用例进了 `test/plans/feat/compile/rulesets.plan.toml`，不带 `skip_unless`。

## 两条路（要裁的这一半）

- **A 变换按名字拒绝**：捕获 lift 不出来时，`buildVmapGraph` 就在那个捕获口处停下，按 9.9 的口径说"这一层没有它的批量形式"，指名那个构造。代价：每个会拷贝体的变换都得自己写一次"我抄不动这个捕获"。
- **B 加一条与变换无关的一致性检查**：值声称的 closure 布局与它图的 `closureNodes` 必须对得上（remat 那条正是这里漏的：值有 1 个捕获、图声明 0 个）。检查在图定型之前跑一次，所有变换共享。代价：今天没有任何一处检查这个不变量，新开它要决定它在流水线的哪一点、以及"不匹配"算编译期诊断还是运行期故障；而且它只能挡住"图声明得少"，挡不住"图声明得对、值里那个捕获是错的值"。

## 已否掉的选项（作者明令不许）

- **回到调用处的拒绝**："`vmap` takes a function without `with` parameters: … a captured value has no port to enter it by"。那句话在 `modules/transforms/vmap_operator.cpp` 的 `explainRejection` 里，2026-11-02 之前是挡板；作者当天裁的是"返工：修到算对"，并写明"错数比拒绝更坏"，但**拒绝也不是答案**。这一版没有把它放回去，只把第二句改成了实话（拒绝的是调用处要传进来的 `with` 值，而捕获会作为常量被抄进去）。

## 要作者答的一句

**「捕获照抄不了的时候，该由变换按名字拒绝（A），还是由一条与变换无关的"值与其图的捕获对得上"检查来报（B）？」**

**我方默认：A**，因为 `vmap` 今天已经是这个口径（拒绝按名字、指到那个构造，9.9），而 B 需要一条目前不存在的检查，且它挡不住"声明对、值错"那一类。
