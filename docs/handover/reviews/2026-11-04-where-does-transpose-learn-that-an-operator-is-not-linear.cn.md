# 裸 `transpose` 拒绝非线性算子：那个「不是线性的」事实写在哪？

2026-11-04，`lane-powzero`。作者在 `d79408e45`（06:55）裁定：`abs_t`、`log_t`、`maximum_t`、
`minimum_t` 四条律该删，裸 `transpose` 遇到非线性算子作用在线性输入上要**按语言规则拒绝**，
句子点名算子：`tensor:log` 对它的操作数不是线性的；`transpose` 只用于线性函数，求梯度用 `vjp`。

删律本身是一处改动。**难的是这句话从哪里知道「`tensor:log` 是非线性的」。**

## 三种可能的依据，各有代价

**甲、走查里挂一张非线性算子的表。** 一行一个 uri。代价：这张表是**第二份真相**——作者删这
四条律的理由正是「每个算子另写一份反向规则」；再加一张「哪些算子非线性」的表，同一个病换个地方
长回来。加了 `tensor:erf` 的人不会记得回来改这张表，而漏改的后果是**静默算错**，正是这次要
消灭的东西。

**乙、结构判定：这个算子有前向规则（`jvp_*`），但没有 `_t` 律。** 有前向规则 ⇒ 它可微；没有
`_t` 律 ⇒ 它的转置不存在 ⇒ 它非线性。走查本来就查两张规则表，这个判断不需要新数据、不需要
人维护，且**与作者的模型一致**：`_t` 律的存在就是「这个算子是线性的」的声明。风险在反例：一个
线性算子暂时没写 `_t` 律，会被判成非线性并给出一句错话（今天有这种算子吗？`_t` 律覆盖到的
是 `add_t`、`mul_t`、`matmul_t`、`reshape_t` 等，`docs/stdlib-reference.md` 列得全，但**我没有
逐条查过**，这是这个方案的唯一风险，也是它可被证伪的地方）。

**丙、在算子的声明上加 `linear` / `nonlinear` 标记。** 最干净、最不重复：声明是既有的事实源
（`stdlib/signatures/*.cml`），`transpose` 读它。代价是**动签名格式**——那是一份跨全库的契约，
且今天没有任何消费者，会先长出「标记了但没人读」的空字段。

## 我这一轮的默认（下一轮就照这个做，不再问）

**走乙**，理由：它不新增事实源、不新增维护负担、与作者的模型同构，且它的失败模式是**说出错
话**（把「暂时没写律」说成「非线性」）而不是**静默错数**——而这次整件事的动机就是把静默错数换成
明确拒绝。乙的失败模式可以被一条用例钉住：拿一个**确实有 `_t` 律**的线性算子跑一遍，它必须照旧
答数；再拿 `abs`/`log`/`maximum`/`minimum` 跑，必须拒绝并点名。

**如果作者要的是丙**（声明里的标记），那是签名格式的一次扩张，应该由声明那条线一次做完，
