# 问题：一张提升图（`(..Lift<P>) => Lift<R>`）是"另一种图"，还是"同一张图带着一段来历"？

状态：**等作者裁**（2026-11-02）。这一页只放两个读数与默认做法，不替作者选。

## 为什么问

`include/camel/runtime/graph.h#graph` 有一个引用角色：

```cpp
kGraphRefLiftedFrom = 1 << 4, // the graph a lift of this one took its body from (`jvp`)
```

它记的**不是图的内容**，是图的**来历**（"我是从哪张图提出来的"）。裁定 ② 要删它；删之前逐点核过（`docs/handover/reviews/graph-ref-lifted-from-inventory.cn.md`），**十处里八处随字段走，两处不走**。

## 两个读数

**(a) 按原则 2.5"图只有一种"，它该是"同一张图带着一段来历"。**
同一个数据结构、同一套节点、同一种求值——提升图不是新种类，它只是由 `jvp` 造出来的图。若成立，字段该留，而且它的名字要说清楚它只是来历。

**(b) 但今天有两处只有"来历"能回答，内容不能。**

1. **`split.cpp:296` `retargets()`**：判断"这个被调用的图是不是提升图"。**签名形状不能代替身份**——`(..Lift<P>) => Lift<R>` 的形状，用户完全可以自己写一张出来；用形状判定，**会把"用户写的、恰好成对的图"误接受成提升图**，于是值半边去调一个不存在的原函数。**这是把拒绝变成误接受，方向错了。**
2. **`transpose.cpp:794`**：需要**原函数的图 id**，才能把"提升调用"转置成"原函数的转置成员"。**提升图里没有任何一处记着它**——不是没读到，是它不在内容里。

## 默认做法（我们照它开工，等作者说"提升图是一种图"再谈删）

1. **字段保留，改名成它真正的意思**：`kGraphRefLiftedFrom` → 名字里出现"来历 / provenance"（具体名字随改动定），`liftedFrom()` 保留但注释写明**"这是来历，不是种类判据"**；
2. **只给这两处读**（`split::retargets`、`transpose` 的调用处理），并在头文件写清：**任何"这张图是不是提升图"的判断都不许用它做种类**，它是"这张图若由 `jvp` 造出，造它的原图是哪张"的记录；
3. **`#remat` 标签与 `split` 的"值半边从提升图取"都不依赖它**——两条线各自成立，不受这条未决问题阻塞。

## 与裁定 ② 的关系

裁定 ② 说"`split` 的前一半从提升图本身得到（只留值那一路输出，切线计算由 DCE 去掉），不再去调'来源图'"。**这话对 `split` 的值路径成立**：值路径不再需要原图 id，因为它改为调提升图再取 `.0`。**但它不回答上面的问题**，因为 `split::retargets` 仍要知道"这个 callee 是不是提升图"（否则不知道要不要取 `.0`），而 `transpose` 仍要原图 id。

**换句话说：裁定 ② 能削掉两处读点中的"取原图 id 来调用"那一半，削不掉"你是不是提升图"与"transpose 要转置谁"这两问。** 这两问的答案，要么是"提升图是一种图"（于是需要一种身份，而不是一个来历字段），要么是"来历就是它能有的全部"（于是字段改名保留，且不许当种类用）。

## 附：`split` 值半边改"调提升图取 `.0`"时撞到的一件事实

这一步（清单里的 #7）实现时需要一个决定：**提升调用要传全部参数（值 + 切线），而前向半边手上只有值**。

- 切线那一路的输出**会被 DCE 掉**，所以切线**传什么都对结果无影响**；
- 但"传什么"仍要选：给每个切线参数造一个**零常量**（最便宜，且如实表达"这里不用切线"），还是让前向半边**多接一组切线端口**（那等于把切又变成两路，与"只留值那一路"矛盾）。

**默认取零常量**，并在读数里写明"前向半边对提升调用的切线实参是零，仅用于满足调用的形状，其输出由 DCE 去掉"。这条与上面的问题不冲突：它不需要原图，只需要提升图的签名。
