# `split` 的"一套遍历"：形状表（待做，2026-11-02）

**来源**：`docs/handover/reports/code-review-2026-11-01.md` 的 **P1-14**——`split` 只认"整个函数就是一个
分支"，碰到循环和效应边一律拒绝；修法是**按区域递归，直线体、分支、循环用同一套遍历**。嵌套分支的裁定
照此执行。

**这一页只定形状，不改代码。** 下面三栏是"今天"与"目标"的对照，最后一段是**待删清单**——删掉的东西
比新增的更重要：如果目标实现之后 `split` 里还留着"分支一支、循环一支"，那就是**同一个事实写两遍**。

## 1. 今天的形状（`modules/transforms/split.cpp`）

| 位置 | 今天做什么 | 问题 |
|---|---|---|
| `buildSplitGraph`（1071） | 读出口：`withInputsOf(exit)` 是两元 `Fill` → 直线体；是 `Join` → 分派到"分支"或"循环" | **出口决定走法**，而不是**区域决定走法** |
| 直线体 | `makeCopy`（566 一带的 `walkHalf`）沿 `halfInputsOf` 反向复制，跨切的值变成残差投影 | 只走 region 0 |
| `Join` 且有一只 `Brch` 认领（1331） | `cutBranchGraph`（888）→ `buildHalfBranch`（829）分半建图 | **"整个函数就是一个分支"的特判**；臂里的体只按"整只臂"复制 |
| `Join` 而无人认领（1340） | `skip=loop exit=Join` | 循环直接拒绝 |
| 效应边 | 反向复制时遇到 `Dref`/`Call` 等按边拒绝 | 没有"效应是体的一部分"的读法 |

**关键一句**：今天"分支"是一条**独立的建图路径**（`cutBranchGraph`），不是"遍历中的一个区域"。所以嵌套
分支要么被那只特判漏掉，要么按"整只臂"整块复制——上一轮读到的
`skip=forward … why=the value half reads the tangent of parameter 0` 就是后者：臂的出口是那个 `Tuple`，
整块复制就把切线也复制进值半。

## 2. 目标的形状（一套遍历）

**一个递归入口**，参数是 `(区域, 半边)`：

```
cutRegion(region, half):
    enter(region, half)         // 半边在这一层要什么（值 / 切线 / 两者）
    for node in region:
        cutNode(node, half)     // 复制、规则、调用，跨切 → 残差投影
    exit(region, half)          // 这一层交出的结果（值、切线、或两者）
```

三种体**只有 `enter`/`exit` 里的三个分支**，遍历本身（`for node` / `cutNode` / 跨切）**一份**：

| 体 | `enter` | `exit` |
|---|---|---|
| 直线体（region 0 的体） | 取参数（值半取值，切线半取切线） | 交出的就是出口那个 `Fill` 的两元 |
| 分支（`GCRegionKind::Arm`，owner 是某只 `Brch`） | 条件**不**参与微分（它是选择，不是值）；每只臂按同一套 `cutRegion(arm, half)` 递归 | 臂交出 `(值, 切线)`；**值半只取 `.0`，切线半只取 `.1`**，两条都从臂的区域里取，**不整块复制臂** |
| 循环（`GCRegionKind::LoopBody` / `LoopCond`） | 携带状态切成 `(初值, 切线)` 对；条件区域按同一个 `cutRegion` 走 | 体交出的对就是下一轮的携带状态；循环的残差是"一轮交给下一轮"的那份（设计 4.2） |

**三条不变量**（比形状更重要，写在这里免得实现时走偏）：

1. **区域进出只有一处**：`enter`/`exit` 是**一处代码**，三个体是它的三种情况——不是三条路径。
2. **半边的粒度到节点**：一只臂里的每个节点都按 `half` 决定"要不要、要值的还是切线的"，**不许**"整只臂
   复制"这种粒度（那正是切线泄漏进值半的入口）。
3. **拒绝仍然逐条具名**：遍历走不到的地方报 `refuseAt(node, why)`，**不静默**；但拒绝的理由从"这个图
   不是分支"变成"这个节点/这只区域，这一半边读不到"。

## 4. 为什么这张表要先写

因为 P1-14 的修法**不是"给分支加一条规则"**：如果实现时把嵌套分支当成 `cutBranchGraph` 的一个新分支，
那就又写了一遍"区域怎么进、怎么出"。表里第 1 条不变量就是为了防这个：**进出只有一处，三种体是它的
三种情况**。上一轮 (b) 撞墙（臂的出口是 `Tuple`，切线必然跟着进值半）正是"按整只臂复制"这个粒度的
后果，换粒度就换掉了它——不需要在 `split` 里加第二套区域筛选。
