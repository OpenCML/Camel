# `match type` 里能不能用类型函数做守卫

**判据一句话**：`match type` 没有守卫位置——`case … when …` 只属于值的 `match`；`[?]` 与 `[..]` 都只匹配秩 1。所以"一条臂覆盖任意秩张量"今天在 `match type` 里没有任何写法，只能按形状枚举。

## 现象到符号

- 规则集要一条臂覆盖任意秩浮点张量：`stdlib/rulesets/jvp.cml#zero_tangent` 的零切向量，对 `f32[2, 3]`、`f32[2, 3, 4]` 都该是"同形状零张量"。作者给的写法是 `case _ when is_float::<ElementOf<T>>() => zeros_like(x)`。
- **这条写法解析不了**：`git grep "case _ when" -- stdlib` 只有值匹配的用法，`test/cases/parse/constructs/match_guard.cml` 里守卫属于值的 `match`；在 `match type` 里写 `case _ when …` 报 `Expected '=>' before 'when'`（实测）。
- **按形状枚举也不成立**：`case f32[?]` 与 `case f32[..]` 都只匹配秩 1，`f32[2, 3]` 与 `f32[2, 3, 4]` 都落到 `case _`（实测，`Return type '()' does not match … 'f32[2, 3]'`）。所以这不是"还没试对写法"，是**语法里没有这个位置**。

## 为什么不能自己定

"任意秩"要么给 `match type` 加一个守卫位置（新语法），要么改 `[..]` 这个**既有构造**的含义（改动既有语义），要么认下"按元素类型枚举"。三条路各自由谁拍板不同：第一条是语言形状，第二条会动到今天已有的规则，第三条与"按判定而不是枚举"那句话直接相悖。

## 选项

- **① 给 `match type` 的 `case` 加守卫**：`case _ when is_float::<ElementOf<T>>() => …`。**要多造**：`match type` 的 `case` 接受 `when`，守卫里求值类型函数（`is_float`/`ElementOf` 在类型层已可用），并为"守卫为真但不匹配"的次序写清规则。**会不会改变已有语义**：不改变——只是一个新位置，今天写不出这种程序。代价是类型匹配多一个分支形式，文档与黄金都要跟。
- **② 把 `[..]` 从"秩 1"放宽成"任意秩"**：`case f32[..]` 一条覆盖所有秩。**要多造**：`[..]` 的匹配语义改成任意秩，并核对 `stdlib/rules.cml` 里 `T[..]` 的既有用法（那些规则今天靠它匹配秩 1）。**会不会改变已有语义**：**会**——这是改一个既有构造的含义，凡是依赖 `T[..]` 只匹配秩 1 的规则都受影响，必须逐条核对，不是加一个位置。
- **③ 认下枚举**：按元素类型四族各一条 `[..]`（`f16`/`bf16`/`f32`/`float`）。**要多造**：四条臂 + 各自用例；仍是**形状枚举**，只是枚举得少一点。**会不会改变已有语义**：不改变，但与"按判定而不是枚举"那句话相悖，须作者认。

**默认建议：①**。它不加新形状、也不动既有构造；②的风险最大（改既有语义）；③是把作者自己否掉的写法换个规模再用一次。

裁定之前 `stdlib/rulesets/jvp.cml` 的 `zero_tangent` 只覆盖浮点标量，张量与聚合体一律**被类型拒绝**，不会拿到一个错的零。
