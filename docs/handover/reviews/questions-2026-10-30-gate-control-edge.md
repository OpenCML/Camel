# `GATE` 的控制入边：两份文档口径冲突（2026-10-30）

> 已由作者裁定（第 2 条）：`GATE` 只认同步前驱，代码侧归第 9 条收口。

## 现象

同一个节点，两份文档的定义不同：

- `docs/technical/05_graph_ir.md` 4.1（4.8 同口径）：`GATE` 是"数据-控制聚合门控"，**至少一条 `Norm` 入边、至少一条 `Ctrl` 入边**，缺一即构图错误。
- `docs/design/effects/edges.cn.md` 5.3（决策者 2026-10-24）：`GATE` 是纯传值节点，"**不再有控制输入**（控制边已不存在）"，它的等待是同步链的链尾（同步前驱）。

代码两种都接受：运行图的封存检查读 `GATE` 的等待，同步前驱与控制入边**任一**即可（`src/runtime/graph.cpp:561` 的注释、`:568` 的判定）。也就是说，今天写 `Norm + Ctrl` 的图和写 `Norm + Sync` 的图都能编码入库。

## 这是真矛盾，不是笔误

不是同一句话的两种措辞：05 的 4.1 描述的是控制边还在时 `GATE` 的用法（把"值出口"与"控制完成点"会合），5.3 描述的是删掉控制边、把顺序交给同步边之后的模型。两者对 `GATE` 的**定义**不同——一个要求双入边，一个禁止控制输入。只改任一处的措辞都会让另一处变错，所以不能在本车道顺手改。

## 两条路

1. **改 5.3，恢复 `Ctrl` 入边**：`GATE` 继续做"值 + 控制"会合点，05 的 4.1/4.8 不动。
   代价：控制边正在被删（H242），5.3 的前提不再成立；内联的同步链要在同一个 `GATE` 上同时写同步边与 `Ctrl`，两条边说同一件事。
2. **改 4.1，按 5.3 写**：`GATE` 是纯传值节点，要求 `Norm>=1`，等待是同步前驱（或旧图遗留的 `Ctrl` 入边），不再是"双门控"。
   代价：05 的 4.1 与 4.8 要重写，`GATE` 的"聚合"定位作废。

**默认建议：走第 2 条。** 理由：5.3 是决策者 2026-10-24 对 `SYNC` / `GATE` 的现行裁定，代码已按它实现（`writeSyncStatement` 写同步边，`graph.cpp:561` 的注释直接写"it has no control input there at all"），而 05 的 4.1 写于控制边还在的时候。除非裁定恢复控制边，否则 4.1 应跟着 5.3 与代码改。
