# 一页一问：`sync` 块里两条副作用语句之间，该不该有一条链边？

## 实测（今天这棵树，探针输出原文）

程序：

```cml
func g(x: int): int { return x }
func main() {
    sync {
        g(1);
        g(2);
    }
}
```

`std::gir` 的边（`N02` 是 `g(1)`、`N04` 是 `g(2)` 所在的执行节点）：

```
N01 -> N02 [type="NORM"]
N03 -> N04 [type="NORM"]
N02 -> N04 [type="CTRL"]     ← 两条副作用调用之间：只有 CTRL
N04 -> N05 [type="NORM"]
N04 -> N05 [type="CTRL"]
```

**零条 `[SYNC]`。** 两条语句都是调用、都有外部效应。

按 `docs/edges.cn.md`：(1) 链是语句的**顺序**；(5.3) 一个块的语句是**一条链**。按这两条读，`g(1)` 与 `g(2)` 之间**应当**有一条 `SYNC`；按今天的构建器，只有 `CTRL`。

同样的形状在 `docs/edges.cn.md` 之外还有两处被依赖着：封口检查 `graph_edges.cpp` 会拒绝"sync edge 从一个不是 sync 块写的节点出发"，而 `generic.cpp#joinBlockFragments` 挑"链头"时读的正是"这个节点被构建器挂上过链"这个标记 —— **若块里本该有链边而没写，这两处的读数都不是它的本意。**

## 问题

**(甲)** 块里两条副作用语句**应当**有链边 ⇒ 这是建图的缺陷，修在写链边那一处；修完后 `generic.cpp:342` 那个标记可望由形状推导出来（"块内无 sync 前驱"就是链头）。

**(乙)** 块里**只**需要 `CTRL`，`SYNC` 只用于别的情形（例如显式的求值顺序约束）⇒ 那么 `edges.cn.md` 1 与 5.3 的措辞需要收紧，并且 `generic.cpp:342` 那个标记**应当进例外清单**（它编码的是"构建器做过什么"，不是形状）。

## 我方默认

**按 (甲)**：**块里应当有链边**，缺的那条是建图缺陷，修在写链边的地方（作者 2026-11-02 23:30 那条"删掉标记后图断了，就说明只有标记没有链边，那是建图/校验的缺陷，在那里修"指向同一件事）。
