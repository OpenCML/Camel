# 一页一问：`loop` 的下一个状态是"体算出来的"，还是"臂声明的"？

## 实测事实（`lane-resid` 树，一行日志）

```
[loop-probe] bodyType=int void=0 assignable=1        ← 程序：loop s = 0 for i in [0,1,2] do { println(s) }
```

`builder_control.cpp:3274` 的判断是 `Type *bodyType = bodyPart->exitType(); if (!stateType->assignableFrom(bodyType)) …`
而 `bodyPart` 的出口类型**按构造就等于状态类型**（循环臂先按状态类型声明出口）⇒ **这个比较恒真**。

后果：

- `loop s = 0 for i in [0,1,2] do { println(s) }` **静默跑完**，输出 `0 0 0`，状态停在初始值，**没有任何诊断**；
- 连 `LoopBodyTypeMismatch` 也抓不到 —— 它同样恒假（即体值类型永远"对"）；
- 设计原则 3.10 说"体的值是下一个状态"，而实现里**体的值这个位置并没有被绑定到末句**。

## 问题是

`loop` 的下一个状态应该：

- **(甲)** 由**体的末句**推导（3.10 的字面意思：体有一个值，它成为下一个状态）；或
- **(乙)** 由**状态类型**声明，体只是"确保把它写进去"（今天的实现）。

## 我方默认（已按它暂停这条线）

**按 (甲)。** 理由：3.10 是规范性文本，且今天是 (乙)，后果是"体不写下一状态"这种程序**静默跑出错误结果**——这是比拒绝更坏的一档。

**但在没有裁定前不动 `loop` 语义**：这是语义改动，不是接一个诊断。
