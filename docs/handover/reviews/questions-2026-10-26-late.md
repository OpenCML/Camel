# 2026-10-26 晚间问题的裁定

## a-void-arm-and-a-cell-typed-arm-collide

**单元格（cell）不是值，任何取值的位置都先读出它的值。** 定为 (a)，再加一条：
1. **不取值的位置，汇合处不取值、丢掉臂的值**，与"没写 `else` 的 `if` 汇合处不取值"是同一条规则。`void` 函数里的 `return if … then null else (x = x + 1)` 就属于这种位置：两臂的效应照常发生，没有值要汇合。
2. **取值的位置，单元格先读出它的值再参与汇合**。一臂是单元格 `var T` 时，按 `T` 汇合，`void` 臂照原则给 `null`，得到 `T?`。单元格类型永远不进入汇合、实参值或绑定。
   - 这两条一起修掉 `coerceArmExit` 的段错误。
   - Release 下被编掉的那条断言，改成一条带位置的内部错误，不能再静默变成空指针。
3. **写捕获的调用交出的版本只在被读取处物化**（即 (c)）。它们是图上的状态边，不是用户可见的值类型，所以不和 (1)、(2) 冲突。
4. **Debug 下 `Node::ruleBinding` 被用在 DECL 上的断言是真缺陷**，你们修：`isGenericHere` 对 DECL 不该走 rule 绑定。

## holed-composite-literals-do-not-take-the-expected-type

**期望类型在参数位置、声明位置、箭头接收者位置走同一条路传进复合字面量的每个元素，包括含洞的字面量。**
- **字面量元素**取期望类型。
- **计算出来的元素（洞）**不做转换，只检查它是否已经是这个类型。
- 所以 `[1.0, float(n)]` 放在 `f32[]` 的位置，报 `ElementTypeMismatch` 是对的：`float(n)` 是 `float`。但三处必须报同一条诊断，指向那个洞，而不是"找不到匹配的函数"。
- 正例是 `[1.0, f32(n)]`，在三种位置都要通过。

照这个改 `compositeEntersIn`，复用 `compositeWithHolesInType`。§15 的 `entering-operator-args` 就按这一条结案。

## 决策者这边 `math` 接入时定下的三条

1. **C++ 提供的值，在声明模块里写成不带右边的 `export let`**：`export let inf: float`。这与不写函数体的 `func`、不写右边的 `type` 是同一条规则（原则 6.4）。草稿里 `// value ...` 的注释写法删掉（`math` 的 `inf`、`nan`，`rewrite` 的 `coverage_table`）。浮点除以零是故障，所以 `inf` 不能写成 `1.0 / 0.0`。
2. **只有 `when` 不同的同名声明是不同的重载，不是重复声明**（原则 306：条件不成立时这个重载不适用，选择去试其他候选）。实例化时多于一个适用，在调用处报歧义，列出各自的条件。
3. **一个模块的导入从不解析到它自己**：入口文件叫 `math.cml` 时，`import math` 找的是搜索顺序里下一个 `math`（标准库），而不是它本身。自己导入自己没有意义，Python 里脚本名遮住标准库的那种陷阱不出现。

## four-model-level-questions-from-the-control-edge-retirement

1. **可自由安排的节点不等待任何东西，哪种边都不接**。不回退到控制边。
   - `edges.cn.md` 4.6 与第 7 条已经写明：顺序边的两端都是效应节点或可能出故障的节点，内联时只给函数体里的效应节点和可能出故障的节点连顺序边。
   - `rules::combineSameSign<f32>` 那条顺序边是内联器违反了第 7 条：`f32` 的加法既无效应也不会出故障，不该有边。
   - 修内联器：用"可自由安排"那一个谓词（C1 正把它收成一个，`nodeIsFreelySchedulable`，即将合入）判断一个节点是否接边。
   - "纯但可能出故障"的节点留在原位，接顺序边，这是 4.6 允许的。所以不存在"纯节点要等待却没有边可用"的情况。
2. **环按并集判，混用两种边是允许的**：控制边与顺序边都表达"先于"，并存期两种写法语义相同，并集上的环就是真的环。
   - 出现旧模型里没有的环，说明改写时把一个方向写反了，是那次改写的缺陷，去找写出这条边的站点。
   - 不要求同一对节点只能用一种边。
3. **统一成溶解**：没有任何等待、只有数据使用者的 `GATE` 就是纯转发，运行时提交与前端冻结都把它溶解掉。
   - 效应有没有丢，由效应可达性检查（`reportDroppedEffects`）负责，不靠这条结构错误兜底。
   - 报出诊断之后进程崩溃，本身是另一个缺陷：诊断之后不得再用失效的指针。照"内部错误带位置、不崩"修。
4. **照边的种类原样复制**：把一个节点的等待转交给另一个节点的站点，读并集，每条边按它自己的种类写到新节点上。
   - 不能只读要写的那一种，那会丢掉另一种边表达的顺序。
   - 不能把种类合并成一种，那会改变写入端的语义。

**附二（今天就能复现的误编译）：决策者这边修，你们不用动。**
