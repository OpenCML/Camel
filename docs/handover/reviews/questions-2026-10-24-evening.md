## python-host-contract（H253）

端到端通了、零拷贝有地址证据、wheel 不设 `CAMEL_HOME` 也能跑——好。

1. **泛型 `export func`**：支持，**按实参类型实例化**——这就是设计原则 5.5 在宿主边界上的样子：Python 一侧传进来的数组与标量类型就是调用点的具体类型，按它们实例化并缓存实例。只有类型变量只出现在返回类型里、实参推不出时，才需要显式写（`f.instantiate(T="f32")` 一类，形式由施工方定）。不要求库作者写具体类型的包装。
2. **模块根**：被加载文件所在的目录算模块根——与语言参考 5.x"模块的 `import` 先在模块自己的目录里找"同一条规则，命令行与宿主一致。
3. **错误值**：确认"统一的 `FaultError` + `name`"就是契约；不把错误值里的字符串提升成宿主的类名（错误在 Camel 里是值）。
4. **类型不匹配**：数组按元素类型，**不转换**（5.1：已取好类型的值不隐式转换；也保住零拷贝）。宿主的**标量**（Python 的 `int`、`float`）按**字面量**处理：它们没有 Camel 的固定宽度，进入形参时按形参类型取类型、放不下报错（同"字面量放不下"）——所以 Python `0.1` 可以进 `f32` 形参，一次舍入。
5. **未导出的函数**：消息写明"外部只能调用 `export func`"；三种情况（没有这个名字、有但没导出、模块找不到）都进诊断注册表各给一个码——报出来的错误都有码（规则统一），`e.code` 不再为空。
6. **GIL**：执行 Camel 期间**释放 GIL**（Camel 运行时不碰 Python 对象，NumPy 的长运算也这样做）；Camel 回调 Python 时再取得。
7. 长期持有 Camel 值留到以后，按 §6.2 的边界。

## h426-interval-step-form（带步长的整数序列）

两参数 `range` 删除、142 个文件迁移、`for i in 0..n` 融合——好。

1. **选 (a)，补上 `range(a, b, step): int[]`**，语义照 Python（AI 与人都熟悉，不另立规则）：`step > 0` 时是 `a, a+step, …` 中 `< b` 的那些；`step < 0` 时是 `> b` 的那些（方向反过来的半开区间）；`step == 0` 是故障，常量时编译期报错。`for i in range(a, b, step)` 与 `a..b` 一样融合、不物化。一件事一种写法：单位步长只写 `a..b`，带步长才写 `range`。
2. **张量模块的 `range`**：P4 之后它也返回整数数组，与核心的 `range` 是同一件事，按"一件事一种写法"在 P4 里删除——`range(n)` 写成 `0..n`，带步长写核心的 `range(a, b, step)`。
3. **"内建赢"是缺陷**：语言参考 5.x 的名字查找顺序是"局部 > 本模块 > 按名字导入的 > `using` > 内建"，`import { range } from tensor` 之后应当解析到导入的那个。修名字查找，不改用例。
4. **语言参考里 `range(a, b)` 的旧句子**（`06_expressions.md` 两处等）：授权协调者按 `a..b` 机械改写。

### reduced-element-epsilon-and-rounding

**选 B：epsilon 一律是机器 epsilon（相邻两值的相对间距，`2^(1−p)`，即 C 的 `FLT_EPSILON`、NumPy 的 `finfo.eps`）**：bf16 `2^-7`、f16 `2^-10`、f32 `2^-23`、f64 `2^-52`。f32 与 f64 的读数一条不动（今天比较用的就是这两个数）。

**这是我上一条裁定写错了**：我给的"bf16 `2^-8`、f16 `2^-10`"混用了两种约定——`2^-8` 是 bf16 的 unit roundoff，`2^-10` 是 f16 的机器 epsilon。现在统一。`elementEpsilon` 与 `checkEpsilon` 合成一个定义；设计原则 7.3 里 `change_precision` 写的 bf16"`2^-8`"是一次舍入的相对误差界，与这里的 epsilon 是两个量，那句保持，在注释里点明区别。
