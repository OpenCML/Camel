### growable-array-vs-tensor-in-the-onnx-exporter

## cml-read-of-a-write-and-the-write-valued-body

**裁定 1：赋值被当作值用时，取的就是写进去的那个值节点，经数据边直接用。不新建读，不新建锚点。三个候选都不选**。

- var-version-node 裁定的原话是"它的值仍是写入的值，与'版本'是两个输出"。写入的值在图里本来就有一个节点，就是写操作的右边，直接用它就行，不用回头从 cell 再读一遍。所以 SSA 转换没有读可以擦掉，出口、输出、返回值也不会指向被删掉的节点。43 条红用例和那次段错误，都出在"新建一个读"这一步上。

**裁定 2：函数体末尾写 `return e` 和直接写 `e`，建出来必须是同一张图。打印形式不变，不需要负责人拍板**。

## tensor-elementwise-comparison-vs-array-equality（负责人 2026-10-25 定）

**裁定（负责人）：逐元素相等引入 `===`、`!==`；整体比较就是逐元素比较再归约成一个 `bool`**。设计原则 4.1、4.2 已写入。

- `a === b`、`a !== b`：两个数组逐个元素比较，结果是同形状的 `bool` 数组。形状规则与其他逐元素运算相同，对任何元素类型能比较的数组都成立（数组只有一套语义）。标量上 `===` 就是 `==`。重载 `===` 即得到 `!==`。
- `a == b`、`a != b`：永远返回 `bool`，意思是"形状相同且 `a === b` 处处为真"，对数字数组也一样。今天"元素类型没写落到逐元素、写了落到整体比较"的隐式分派删掉，比较的含义不再随类型写没写而变。
- `<`、`>`、`<=`、`>=`：在数字数组上逐元素比较，返回 `bool` 数组。数组整体没有大小顺序，这几个运算符在数组上不会和别的含义冲突。
- **实施**：
  - 词法里已经保留了 `===`、`!==`，删掉 `ConstructNotSupported` 那条拒绝，接到逐元素相等上；
  - 张量模块的 `__eq__`、`__neq__` 改成 `===`、`!==` 的实现，`==`、`!=` 只剩核心的整体比较一种；库里的 `eq`、`ne` 函数删掉，不留兼容；
  - `numeric_contract.cml` 这类"逐元素统计 NaN"的写法改成 `s !== s`；
  - 规则库可以加一条恒等式：`a == b` 等于"形状相同且 `all(a === b)`"；
  - 语言参考（`02_lexical`、`03_data_model`、`06_expressions`）和给 AI 的参考，随实现一起改，写成现在的语言，不写"以前不支持"。

## subscript-operator-choice-and-the-rank-two-refusal

## `#gpu` 作用域里的效应：结果对，修法错，返工

读数对了：`#gpu` 函数体里的 `println` 打印出来，取值处有一次下载，`--devices cpu` 下也打印。但修法是把"声明为有效应的算子"全部当成执行计划的根（`graph_runtime_support.cpp` 的 `observesOnItsOwn`），注释还引了设计原则 3.1。这改变的是整门语言的语义，而不是修 `tiles::compile` 的一个错误：
- 设计原则 2.x 写明"**同步块之外、结果没有被使用的带效应的调用不会执行**。这是按依赖求值的自然结果，是合法的预期行为"；设计原则第 14 节"已经发生过的误读"第 1 条，正是"把'同步块之外未被使用的效应不执行'当成缺陷去修"。

**真正的错误在改写，不在执行计划**：效应在同步函数体里，本来有一条同步边接到出口，是这条边让它执行。`tiles::compile` 把作用域切成段时，用段的调用替换了原来的语句，却没有把这条同步边接到替换上去的节点。H242 早就定过"改写保留顺序与同步输入"。所以：
1. 撤掉 `observesOnItsOwn` 以及执行计划把效应当根的那段，执行计划只从出口与同步边、顺序边出发。
2. 在 `tiles::compile` 的切段里修：被替换的语句带的同步输入、顺序输入，原样接到替换它的节点上；段里的计算与效应之间的数据依赖照常转成传输。
3. 用例保留现在的两条读数（两种运行方式都打印、取值处一次下载），再加两条防回退：同步块之外没人用的 `println` 在加不加 `tiles::compile` 时都不执行（并有 `EffectNotExecuted` 警告）；分支没选中的臂里的 `println` 不执行。

## open-rank-round-type-and-the-value-a-round-hands-over

**C 是终局，不是权宜**。规则是"一个值在运行期的表示，跟着它声明的类型走"：
- `f32[..]` 是秩未知的数组，少一维以后仍然是秩未知的数组，所以 `for v in x` 里 `v: f32[..]`（类型侧不动）。运行期 `x` 恰好是秩 1 时，每一轮交出的是一个 0 维数组（与元素共享数据块的视图），因为声明说它是数组。

**补上状态机的形状**（路线二，流的值是步进函数加状态）：
- 生成器 `func g(args): T.. { body }` 被调用时只求实参，返回 `(step, s0)`，函数体一句都不执行。
- `step(s): (T, S)?`：从 `s` 记录的恢复点接着跑，跑到下一个 `yield e` 时交出 `(e, s')`，`return` 或跑完时交出 `null`。
- **状态 `S`** 是一个结构体，包括：恢复点编号 `pc`；所有活过某个 `yield` 的局部变量（含实参、`var`）；每个包含 `yield` 的循环的状态（循环状态、`for` 的序列与当前位置）。只活在两个 `yield` 之间的局部变量不进状态。
- **含 `yield` 的循环**在步进函数里拆开成状态加分支；不含 `yield` 的循环照旧是普通的 `LOOP`，整个放在某一段里。
- 步进函数体就是函数体：生成器头上写的 `sync` 就是步进函数体的 `sync`，按每次拉取生效。步进函数的资源集就是这个流的资源集，拉取就是一次调用，前面"资源随实例化可见"的规则照样适用。
- **`throw e`**：只有元素类型可错（`T!..`）时可以写，含义是交出这个错误作为最后一个元素，然后结束。元素类型不可错时写 `throw` 是编译错误，与在非可错函数里写 `throw` 是同一条规则。
- 只用 `BRCH`、`LOOP` 和结构体，不加新的节点种类。循环收集槽不是底座：它是急切地收集，生成器是惰性的。

1. **`->` 自动传递**：`x -> f` 中 `x` 是 `T?`/`T!`、`f` 的参数只接受 `T` 时，降低成和现在 `?->` 一样的分支，结果是 `U?`/`U!`。参数能接受包着的值（参数类型就是 `T?`/`T!`，或者是泛型 `T`）时原样传进去。两层标记由外往里，需要几层拆几层。由签名在编译期决定。
2. **删除 `?->`**：词法、文法、AST、格式化器、编辑器高亮一起删。现有代码里的 `x ?-> f` 机械改成 `x -> f`，语义不变，因为它们的 `f` 本来就只接受 `T`。
3. **`attempt(f)` 改成函数变换**：返回参数与 `f` 相同、结果类型带 `!` 的新函数，可以放进尖括号（`rows->map<attempt(parse_row)>`）。三条边界语义按 3.9：结果在边界内完整求值；流的每次拉取各自隔离，元素类型变成 `T!..`；效应不回滚。`attempt(f, x)` 的写法删除。
4. 语言参考 6.6、教程第 9 章（缺失与失败）、给 AI 的参考同步改写。标准库草稿里的 `?->`、`!->` 一律改成 `->`。
5. 与"删除 `throw`、加 `fail`/`never`"同批做，都在错误系统这一片。

## 2026-10-26-indexing-a-position-on-an-open-rank-array

**乙，一条规则管所有秩**：写位置的那一维从结果里去掉，所以开秩 `t: f32[..]` 上的 `t[0]` 是 `f32[..]`（少一维，秩仍未知）。今天给出 `f32` 是在猜秩为 1。

## 代码审查：资源度量 `builder_resources.cpp`（返工）

红线 8 的检查本身成立，但有三处让承诺**静默地不被检查**，与"承诺由编译器检查"相悖：

1. **递归函数永远量不出来**（高）：`footprintOf` 遇到还没量过的被调者就返回 `nullopt`（`Func` 一支），`measureInferredResources` 从"不在表里"开始迭代。一个调用自己的函数（或互相调用的一组）每一轮都量不出来，永远不在表里。于是 `func f(n: int): int pure { println(n); return f(n - 1) }` 不会被拒。正确的不动点要从底开始：所有函数体先记为空集，每一轮按被调者当前的集合重算并取并，直到不变。资源集只增不减，一定收敛。这和类型推断的递归处理是同一个做法。报告里那个"递归 `countdown` 仍是 `unknown`"就是它。
2. **量不出来的函数体，子句被跳过**（高）：`checkInferredResources` 里 `measured == end()` 时直接 `continue`。写了 `pure` 或 `uses` 的函数，只要度量在某处放弃（捕获、递归、参数超过 255 个、算子 `operTarget` 为空），它的承诺就不被检查，也没有任何提示。改法：写了子句却量不出来，就报一条诊断，说明哪一步无法确定（比如"经由第 N 个捕获的资源无法确定"）；或者在那一步按保守的读法记入（`anyOf` 全部类别），让 `covers` 去判。不能什么都不说。
3. **`addParam` 里 `index > 0xFF` 时静默丢弃**：第 256 个以后的参数上的资源使用被丢掉，度量结果偏小，会让 `pure` 错误地通过。要么放宽索引的位宽，要么在这里放弃度量，再由第 2 条报出。不能丢。

小处：
- `measureInferredResources` 每一轮重算所有函数体。改成工作表：一个函数体的结果变了，只重算调用它的函数体。
- `Call` 一支的注释说"没写子句的函数值什么都不承诺，按保守读"。按已经定的规则，没写子句的函数值带的是推断出的资源集，只有对资源泛型的**形参**才是 `Generic`。如果这里处理的只是形参，注释照此改准确；如果函数值也走到这里，就是第 1 节"函数值带推断集"没有落到这一支。
- `footprintOf` 一百多行、四个内嵌 lambda。把"端口编号""读一条签名""一个节点的资源"拆成具名的私有函数，读者才能逐段核对。

## 2026-10-26-attempt-never-overload-and-error-arm

1. **`attempt`**（原则 3.9 已定）：`attempt(f)` 是函数变换，返回一个参数与 `f` 相同、结果类型是 `f` 的结果加上 `!` 的函数；调用写 `attempt(f)(x)`，可以当值传递、放进尖括号（`rows->map<attempt(parse_row)>`）。成功那一臂是 `f` 的返回值，失败那一臂是一个错误值，种类就是故障的种类（`InvalidArgument`、`IndexOutOfRange`……），消息与位置照故障报告。旧的 `attempt(f, x)` 直接删除，写了就是普通的实参个数不匹配，不留专门的诊断。三条边界语义照原则 3.9 实现。
2. **`never` 实参**：一个实参是 `never` 的调用永远不会执行（实参先于调用求值，这个实参永远交不出值），所以这个调用本身的类型就是 `never`，不需要选重载。给一条警告，指出这个调用永远不会执行、是哪个实参导致的。
3. **`return if c then error("…") else v`**：在声明返回 `T!` 的函数里应当接受。返回位置是有期望类型的位置，期望类型是 `T!`，按"`if` 的各臂取整个表达式的期望类型"，`error(...)` 进入失败那一臂、`v` 进入成功那一臂。没有期望类型的地方（`let x = if c then error(…) else v` 不写类型）两臂合不起来，报类型错误是对的。你们"`error` 只在 `T!` 的位置成为失败臂"的读法对，只是 `return` 处正是这样的位置。语言参考 7.3 的两种写法都保留。
4. **单独一行的 `fail`**：它的类型是 `never`，不适用"结果未使用"那条规则（"changes nothing"的措辞也不对）。在同步块里它照常执行；在非同步的函数体里没人需要它，按效应的规则不执行，给 `EffectNotExecuted` 那一类警告，提示放进 `sync` 块或写在数据经过的路径上（原则 3.9）。

## 标准库阻塞表（`docs/handover/reports/stdlib-blockers.md`）的裁定

1. **C++ 模块提供的不透明类型，在声明模块里不写右边地声明**：`export type Graph`、`export type Txn<F>`。这与"不写函数体的 `func` 由 C++ 提供"是同一条规则。类型的身份与资源一样，是模块加名字，C++ 侧按这个名字登记。语法里旧的 `type X = '...'` 形式，若只有语法测试在用就删掉，不留两种写法。
2. **模块类型的类型参数可以是任何类型表达式**，包括泛型声明里的类型变量（`Txn<F>`）。每个类型构造器都是这一条规则。
3. **声明尾部的顺序以文法为准**：`: T uses r when g`。资源子句跟着类型走，与函数类型一致；守卫写在最后。草稿里的 `when ... pure`、`when ... uses` 是草稿写错了，改草稿。
4. **维度**：
   - 维度表里最多一个 `..`，位置不限（开头、中间、末尾），`T[..s, i]` 合法。
   - 只出现在结果里的维度名（`conv2d` 的 `o`、`c`）是草稿写错了：这些维度不是参数维度的线性式，写成 `?`。
5. **`with` 参数的默认值是一个位置，字面量按它取类型**（原则 5.1）：`eps: T = 1e-5` 在 `T` 是浮点时成立。编译器缺这一处，补上。
6. **`uses rng` 是草稿漏了声明**：`random` 要 `export resource rng`。
7. **`ckpt.cml` 的草稿由决策者补写。**
8. **顺序**：前奏先接（它带 `fail`/`never`），然后是四项核心能力（决策者这边正在做）、`array` 的核函数、`math` 的核函数。
