# 现象：同一份构建，同一个程序，`std::gir` 的输出顺序会变（约 10 次 1 次）

单独记一笔，**别和语料结论混在一起**：这是 GGIR 打印器（`src/passes/trans/dot/graphviz.cpp`）
的稳定性问题，不是去函数化车间的结论。它与「`random-red` 那条指针键悬空」不是同一个缺陷，
但建议一起排，因为两者都指向「按指针遍历」。

## ① 同一构建连跑 10 次的哈希

文件：`test/cases/linear/byref/var_capture_reference.cml`（472 行 `std::gir` 输出）。
构建：车道 tip `5bcb8eb53`，主机 `out/latest`，同一条命令，10 次连续运行（2026-10-30）。

| 次数 | 哈希（前 12 位） | 行数 |
|-----:|---|---:|
| 1–9 | `aab89fd55b51` | 472 |
| 10 | `51cf56416c7f` | 472 |

即 **10 次里 1 次不同**；此前在同一份构建上另跑 5 次，得到 `51cf…` 两次、`aab8…` 三次。
两组的比例都是「少数派约 1/5 ~ 1/10」，所以它多数时候能混过闸门，偶尔红一次。

## ② 两次之间差在哪：**顺序，不是内容**

- 两次输出各 472 行；`sort` 之后**逐字节相同**（行多重集哈希两次都是 `c42d27efb81e`）。
- 未排序逐行 diff 只有 5 行移动，全是同一个节点的 ORDER 边：

```
395a396
>         N74 -> N7C [label="ORDER", type="ORDER"];
399d399
<         N74 -> N7C [label="ORDER", type="ORDER"];
...
```

  受影响的边是 `N74 -> {N7C, N7D, N7E, N83, N85}`，label 与端点都不变，**只是这 5 条边在同组
  里的相对位置不同**。

所以：**这不是行序抖动意义上的「无意义差异」，但也不是内容差异**——图本身是同一张图（节点、
边、类型、id 全同），变的是**同一个节点的多条 order 前置被存储/打印的顺序**。

这个不一致的源头不在打印器：`graphviz.cpp:817` 是顺序遍历 `graph->orderPredsOf(nodeIndex)`，
而 `orderPredsOf` 的定义（`include/camel/runtime/graph.h:895`）是「**the order they are stored
(the source order they were written in)**」——也就是说**存储顺序本身**在两次运行里不同。
要查的是：一个节点有多条 order 前置时，这些前置是按什么容器收集进 draft 的
（`draft.orderInputsOf` 的填充处，以及 `appendOrderDependency` 的调用者）。

## ③ 是否与「指针键悬空」同源

**没有证据说同源，形态也不同**，但两者都符合「按指针/按哈希遍历」的指纹：

| | 指针键悬空（`random-red`） | 本页 |
|---|---|---|
| 表现 | 编译失败，诊断指向错误位置 | 输出成功，哈希变 |
| 后果 | 错的诊断（把死体最后一句当未使用值） | 图相同，只有 5 条 ORDER 边的存储顺序不同 |
| 位置每次不同？ | 是（131:58 / 169:30） | 是（同一条边在不同邻接位置） |
| 已定性？ | 是（`lane-flake` 的最小复现） | **未定性**，只到「存储顺序不稳定」这一层 |

要判定同源，得看 `orderInputsOf` 的填充是否也用了裸指针做键的容器；如果用的是同一类容器，
那两条就是同一个根因的两个出口。**在此之前请按「两件事」处理。**

## 为什么这条比去函数化本身更要紧

任何**逐字节**比对 `std::gir` 的断言（快照、golden、语料基线）对这类文件都是**概率不稳**的：
- 我的 3,359 份语料基线里，`var_params.cml` 与 `var_capture_reference.cml` 各出现过一次，
  都是这个原因；因此那份比对按**行集合**放行，并单独说明了这一点。
- 任何人拿「同一输入两次输出必须逐字节相同」当闸门，都会随机红。

## 默认建议

1. **打印端先按 `pred` 排序**（或存储时就排好），让 `std::gir` 对同一张图稳定输出。这一改
   只动输出顺序，不动图，风险很小；由 `graphviz` 的归属方裁决。
2. 在改之前，**语料类闸门一律按行多重集比对**，并在记录里写明放行了哪些文件、为什么。
3. 把「输出顺序不稳定」与「指针键悬空」当成**待查的两个条目**挂在一起，谁先修容器谁就顺手
   把另一个也看了。
