# H151 — `tensor` 的声明迁移：64 个公开算子里 10 个可声明、已迁移，54 个（56 条签名）留在 C++

分支 `handover/H151-tensor-declarations`，起点 `origin/develop` `4122a4ce0`。任务书是 H19 第 10 步的
下一批模块声明化，模块是标准库里最大的 `tensor`。结论：**可声明的名字全部迁出（10 个名字 13 条声明），
其余 54 个名字 56 条签名逐条写明为什么写不进声明，2 条进阻塞名单**（`range` 与 `sum`/`mean` 的轴形式，
第 3.4 节），没有把任何一个计算签名写成 `float[]` 之类的近似，也没有给声明新增语法。

一句话结论：**`tensor` 的声明面是 13 条规则；`Tensor.shape` 这类别名不靠新语法，而是靠"模块写下这个
名字的算子组时，同 URI 的限定名指向同一个实体"这条通用规则解决**（第 4 节）。

## 1 现状：一模块两半

`tensor` 是 H19 里唯一一个"类型本身就带参数"的模块：`Tensor<元素类型, 形状>`。它的算子分两半：

- 一半的名字，结果签名和参数无关：`shape(t) => int[]`、`numel(t) => int`、`to_bytes(t) => Bytes`、
  `num_threads() => int`、`gemm_backend() => string`、`load_npy(path) => Tensor`（元素类型与形状是
  文件的，声明只能写"未知"，这比 C++ 的推断**更粗但不假**）、`save_npy`、`set_num_threads`、`seed`。
- 另一半的名字，结果类型跟着参数或类型实参走：逐元素算子的元素类型是"两个操作数里更宽的那个"、形状是
  广播结果；`reshape`/`transpose`/`permute`/`slice` 的形状是参数算出来的；`sum(t, axis)` 的形状与秩
  跟着 `axis` 和 `keepdims`；`from_bytes::<f32>` 的元素类型来自**显式类型实参**。

声明（无函数体的 `export func`）能表达的是"一个名字一组固定签名、每个参数一个类型"；它不能表达联合
类型（`Tensor | number`）、`TensorLike`/`TensorOrScalar` 这类伞形参数、可选参数（`axis?: int`）、
显式类型实参、以及 `Tensor.shape` 这样的限定名。所以这一半只能留在 C++，`stdlib/signatures/tensor.cml`
保留给参考页与 `--verify-ops`。

`inspect --ops` 数出来的账：80 个 C++ 名字（64 公开 + 16 内部），86 条普通记录，68 条别名记录，154
条描述，79 个 URI。别名记录比公开名字多 4 条，因为 `from_bytes`（3 条 URI）、`sum`、`mean` 各有一个
名字多条规则。

## 2 判据：什么算"可声明"

沿用 H135/H113 的判据，落到 `tensor` 上就是三条：

1. **结果类型不取自任何参数或类型实参**：`int[]`、`int`、`string`、`void`、`Bytes`、`Tensor`（未知
   元素类型与形状）。
2. **每个参数都能写成一个类型**：没有 `Tensor | number` 这种联合，没有"张量或数字数组"的伞形，没有
   可选参数（`?` 只出现在**参考文件**里，照抄 C++ 签名字面；编译的声明里没有先例）。
3. **一个名字只需要一个来源**：名字的每条规则都能写进同一组声明。名字里混着一条写不出的规则，整个名字
   留在 C++（`sum`、`mean` 就是这样）。

按这三条，"元素类型跟着参数走"和"形状跟着参数走"都算计算——即使写 `=> Tensor`（完全未知）在类型上
不算说谎，那也会把编译器已经知道的元素类型和秩丢掉，等于用宽化换迁移数量；本轮一条也没有这样写。

### 3.3 内部名字（16 个，不在公开面上，也没有声明）

`__add__`、`__sub__`、`__mul__`、`__div__`、`__pow__`、`__mat__`、`__neg__`、`__eq__`、`__neq__`、
`__lt__`、`__le__`、`__gt__`、`__ge__`、`__idx__`、`__slice__`、`__iter__`。它们是运算符语法
（`a + b`、`a[i]`、`a[i:j]`、`a @ b`、`for x in a`）背后的名字，由编译器直接按名字发出，不是导入面；

### 3.4 阻塞名单（2 条，逐条给理由）

1. **`range`**：`(start: int, stop?: int, step?: int) => Tensor<int64>`。结果元素类型固定（`int64`），
   形状由参数决定——按判据是可声明的，但三个位置在 C++ 都是 `ParamKind::Int`（`int` 或 `i32` 都接受），
   而声明里写 `int` 只表示 `Int64`。精确写出来需要 1 / 2 / 3 参数 × 每个位置两种整数 = **14 条规则**；
   写 3 条会拒绝 C++ 接受的 `range(0, i32(5))`（收窄接受面＝说谎）。另外编译的声明里"可选参数"
   （`stop?: int`）没有先例，参考文件里的 `?:` 只是照抄 C++ 签名字面，未经编译器验证。所以这一条
   **一个字也没写**，留在 C++。
2. **`sum` / `mean` 的轴形式**：名字里同时有 `(t) => float`（固定，可声明）和
   `(t, axis, keepdims?) => Tensor`（`keepdims` 可选，`axis` 两种整数拼写）。一个名字只能有一个
   来源；只声明一半会把同一个名字拆到 C++ 与声明两处，检查脚本也会判红（"a computed signature is
   also declared"）。所以两个名字整体留在 C++，参考文件里各写两条 `#op` 条目。

`from_bytes` 不算阻塞：它明确是"计算"（元素类型来自类型实参），申请的是新语法（声明看得见类型实参），
属于 H103 的范围。

## 4 迁移：文件、C++ 侧与别名

### 4.1 两个文件

- `stdlib/tensor.cml`（新建，80 行）：13 条声明，按 `// ---- shape and reshaping ----`、
  `// ---- binary form ----`、`// ---- module state ----` 三节分组，每条带 `@pure`/`@effect`、
  失败与例子。`dim`/`set_num_threads`/`seed` 的两条整数规则写在一起（同一 URI，默认 URI 由名字
  决定，不需要 `#op`）。
- `stdlib/signatures/tensor.cml`（重写，359 行）：54 个名字 56 条，按 10 节分组（`creation`、
  `random`、`elementwise`、`shape and reshaping`、`reduction`、`linear algebra`、`gradient`、
  `conversion and display`、`binary form`），每条写明参数、效果、失败与例子；联合与可选参数照 C++
  签名字面写（`Tensor | number`、`axis?: int`），`sum`/`mean`/`max`/`min`/`argmax`/`argmin`
  的轴形式用 `#op<'tensor:sum_axis'>` 一类标签绑定 URI，`from_bytes` 的三条用
  `#op<'tensor:from_bytes_*'>`。
- 68 条参考条目的参数名、元数、可选性逐条与 C++ 签名字面一致（脚本比对：68/68 相符，只有
  `from_bytes` 的通配条目对不上具体 URI）。

### 4.2 C++ 侧交出什么

`modules/tensor/module.cpp` 只改了一处：注册循环里 `if (!isDeclaredOperator(group->name()))` 才
`exportEntity(group->name(), group)`，`kDeclaredOperators` 是同文件里的 10 个名字的 `constexpr`
数组。别的都没动：执行器（`TensorExecutor`）、内核、`OpDef` 的 `traits`/`semantics`/`resources`、
`foldFromTypes`、`vjp`。`from_bytes` 仍显式导出普通名与别名（它是计算签名，声明里没有它）。

### 4.3 别名：为什么需要一条新规则，规则为什么是通用的

C++ 对每个算子（声明的与计算的都算）发布两个名字：`shape` 与 `Tensor.shape`。声明只能写前者。
迁移后实测：`inspect --ops` 里 10 个声明名字的普通名是精确的（`0 with / 1 parameter`），但
`Tensor.shape` 一类的 10 条别名仍然指向 C++ 的旧组（`-2 / -2`，即"这个解析器不知道"），
`--verify-ops` 因此报 10 条"一个算子有两个签名"——正是任务书要求"不许粉饰"的那类不一致。

根因（用临时调试打印在同机构建上读出，未提交）：声明模块的 `.cml` 编译**在** `inheritExportsFrom`
**之后**。C++ 模块先 `load()`（发布 86 个普通名 + 68 个别名，但声明的 10 个名字只有别名），随后
`Context::loadModuleFrom` 建声明模块并 `inheritExportsFrom`（此刻声明模块里没有任何实体），然后才编译
`.cml`、`exportEntity` 每个声明。于是声明写普通名、继承带来的别名先落、声明的普通名后落，别名就成了
"最后一次写"。

修复选择的是"最后写的那个赢，而且声明是签名"：

- `Module::replaceTypeQualifiedAliases(ident, ent)`：遍历本模块实体表，找**标识符相同**、**是算子组**、
  且与 `ent` 的组**共享至少一个 URI** 的限定名，把它们指向 `ent`。共享 URI 是判定"同一个算子"的
  依据，所以同名但不同算子的限定名不会被误改。
- 调用点两处，覆盖两种写序：`exportEntity`/`replaceEntity`（普通名后写）与 `inheritExportsFrom`
  末尾（别名后写）。两处都调同一个函数，规则只有一条。
- 通用性：函数只认"普通名 + 同 URI 的限定名"，不认模块名、不认 `tensor`；`<builtin>` 的
  `std::mem::blocks` 这类限定名走同一条路径（它与普通名同组，守卫直接跳过，无副作用）。

没有采用的两个方案：在声明里加"别名"语法（任务书的停手条件：机制要改加载器/第二个命名空间），
以及让 C++ 继续导出声明名字的普通组再靠 `replaceEntity` 覆盖（那样 C++ 仍在"写签名"，H137 第 4 条
会红，检查脚本也会报"注册循环没有跳过声明名字"）。

## 6 参考页：怎么排、别名怎么处理

`docs/stdlib-reference.md` 由 `scripts/stdlib-reference.mjs --write` 生成（327 条，`tensor` 64 条）。
本轮的改动只有两处，都是让页面"装得下 tensor 的 64 条"：

- **按小节分组**：`renderDoc` 以前按文件的书写顺序平铺条目；tensor 的声明与计算分在两个文件，直接拼
  会得到"声明 13 条 → 全部计算 56 条"的两段，`binary form`、`shape and reshaping` 这类同名小节被拆
  成两处。现在按 `// ---- <小节> ----` 分节、按小节首次出现的顺序输出，两个文件的同名小节合并，
  节内保持书写顺序（重载合并成一条，带 `(+1 overload)`）。tensor 一节因此是 10 节：Creation、
  Random、Elementwise、Shape and reshaping（`reshape`…`one_hot`、`shape`、`numel`、`dim`）、
  Reduction、Linear algebra、Gradient、Conversion and display、Binary form（`from_bytes`、
  `to_bytes`、`load_npy`、`save_npy`）、Module state（`num_threads`、`set_num_threads`、
  `gemm_backend`、`seed`）。起因段落改成"这个模块是什么、哪一半写在哪个文件"，不再从"固定签名"开头。
- **别名不进页面**：`Tensor.shape` 这类名字只存在于 C++ 的实体表，两个 `.cml` 里都没有 `::` 名字，
  所以页面既不会多出一节同名条目，也不需要"别名"小节。读者看到的每个算子一条（重载合并），
  与 `import { ... } from tensor` 得到的名字集合一致。`--verify-ops` 单独守住别名与声明的对应
  关系（每个声明名字必须有一条同 URI 的别名，且别名的 `with`/`norm` 必须与声明相等）。

其余 21 个小节逐字节未变（diff 只有引言、模块表的计数 2→64 与 tensor 一节）。

## 10 留下的

- **H118 的交换律**：`tensor` 的加法/乘法交换律没有动，声明化不改变算子语义，H118 的板行状态不变。
- **`range` 的 14 条规则**：要么声明语法支持可选参数且能写"整数多拼写"，要么等作者裁定"声明接受
  `int` 即接受所有整数宽度"；在那之前它留在 C++。
- **`sum`/`mean` 的 `keepdims`**：同上，取决于可选参数。
- **`from_bytes` 的类型实参**：H103 的缺口，声明看得见 `::<T>` 才能迁。
- **别名的语言层入口**：`Tensor.shape` 在页面上不单列（第 6 节）；它由声明实体承载，补全/hover 走
  H145 的 `declareEntities()` 路径，本轮没有改语言服务器。
- **`empty` 的语义**：C++ 用清零的分配（`zerosKernel`），参考条目照实写"分配是清零的"，没有写成
  "未初始化"。
