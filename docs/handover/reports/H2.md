## 2. 这次补完的部分

### 2.1 `#reads<...>`：Camel 遍声明它读哪些标签

`reads` 成为核心的标准标签（`on func`，`names = true`，`variadic = true`）：

```cml
#[reads<reassociate, contract>]
export func apply(p: Program): Program! sync { return p }
```

- **实参是名字，不是值**。AST 把 `<...>` 里的标识符原样变成字符串字面量（`tagUsesOf` 对 `decl->names` 的特例），GIR 把它变成 `attr::tuple` 的一串 `attr::symbol`；一个名字也仍是元组，形状不随个数变。
- **至少一个名字**：`#reads<>` 是 `TagArgumentCount`（“takes 1 or more parameter(s), but 0 argument(s) are written”），而不是零个事实。
- **名字必须是已声明的标签**：GIR 用 `tagNamed` 解析，不是就报 `TagUndeclared` 并定位到该次使用。这样拼错不会静默变成“读了不存在的标签”。
- **读者登记**：`registerCamelPass` 读函数声明上的 `reads` 事实，把 `模块::函数` 记到每个标签的限定名下（`tag::declareTagReader`），`tag::readersOfTag` 可查。
- **警告**：`TagHasNoReader` 在 CLI 里于程序编译后、遍构建前计算（`tools/camel-cli/main.cpp`），那时 `registerCamelPass` 还没跑，所以 `tagsNeverReadWarnings` 自己按流水线里的遍加载模块、读声明上的 `reads`（`std::` 前缀的核心遍跳过，读不到就忽略，遍自己稍后会报原因）；没有写任何标签时直接返回，不为没有标签的程序加载模块。标签声明的 `read_by` 与 Camel 遍的 `#reads` 取并集，`read_by` 仍按“只有声明自己是读者的遍”过滤，`#reads` 则直接算数。

文档：语言参考 CN/EN 的 6.2 节补了这段与“不得遮蔽核心许可名”；`docs/technical/46_rules.md` 与 7.2 的说明同步。

### 2.2 程序声明的许可组可以写进 `#requires`

```cml
tag fast = [reassociate, contract]

#requires<fast>
rule mul_one(x: float) { x * 1.0 => x }
```

AST 在建规则之前先扫一遍本模块顶层的 `tag g = [...]`，按成员递归展开（用 `sem::parsePermission` 换算，带环检测），`#requires<fast>` 得到两个许可的并集。只收本模块、只收顶层；导入的组、嵌套命名空间里的组还展开不了（见 §5）。普通的非许可标签仍是 `TagNotAPermission`，没有变成“组里没东西所以放过”。

### 2.3 程序不得遮蔽核心许可名（`SemanticDiag::TagShadowsPermission`，0x16E）

```cml
tag reassociate on func   // 定位到声明，拒绝
```

`#reassociate` 在程序里始终指核心许可，声明了也读不到，所以在 GCT 的 `visitTagDecl` 里拒绝。名单是核心的九个许可名加组名 `finite_math`。这条按设计原则日志 2026-10-21 的裁定做，没有替作者扩大成“所有核心标签名”。

### 2.4 `nondeterministic` 与 16 位许可列

- `nondeterministic` 是第 9 个许可（`1 << 8`），标准标签 `on func, nodes`，`PermissionMask` 为 `uint16_t`、`kAllPermissions = 0xFFFF`，`@numeric` 的报错名单也包含它。设计原则 7.2/7.3 已列它，没有改设计文本。
- 按 H2b 检查意见“增长这一列，不另设一列”，没有新增存储列，只把已有列加宽；`graph.h`、`draft.h`、`writings`、`rules`、Tiles、tensor 的许可类型全部走 `sem::PermissionMask`。
- 修掉三处仍按 8 位处理的真实缺陷：GIR `buildFuncBody` 与块作用域的 `static_cast<uint8_t>`、`DraftWritings::contextOf`/`WritingStore` 的 context 键、`reorderFreedom` 的 `uint8_t granted` 参数。前两处会让 `#nondeterministic` 既不进节点许可、也不满足 `#requires`；第三处在索引语义读取处丢位。修完后 `std::gir` 在 `drifting` 的节点上显示 `numeric="nondeterministic"`，要求它的规则只在授予它的函数体上应用。

### 2.5 NaN 的打印

属性的 real 值按位驻留，两个 NaN 可以是两个不同的事实。`attr::valueText` 对 NaN 打印 `nan(0x%016x)` 而不是 `nan`，dump 与 `inspect --tags` 能分辨。

`docs/language/07_statements.md` 与 `en/07_statements.md`（`#reads`、`nondeterministic`、程序许可组、遮蔽诊断）、`docs/technical/46_rules.md`（组、16 位、`nondeterministic`）、`docs/diagnostics.md`（由 `node scripts/diagnostics-catalog.mjs --write` 重新生成，182 个诊断）已更新。设计原则没有改：这次实现的都是 6.2/6.6/7.2/7.3 已经写下的内容，`#reads` 属于 6.2 的“库声明读取者”，`#requires` 的语义按 7.2 的“只在许可满足处应用”。

## 4. 判断与决定

1. **许可列加宽而不是另设一列**（H2b 检查意见）。这一列是持久化的节点数据，宽度改了 `chunkHolds`、`draft_session` 的逐元素比较都按元素大小走，没有别处假设 1 字节。
2. **`#reads` 的名字在 GIR 校验**，不在 AST：AST 阶段标签还没登记齐（规则要求是例外，它只认核心许可），GIR 阶段模块、导入、声明都已知，报错能定位到标签上。
3. **读者记在限定名下**（`reads_pass::marked`），程序的标签使用也用限定名；遍里写的短名在 `registerCamelPass` 里先在本模块解析，再查核心。
4. **警告阶段自己读声明**：`TagHasNoReader` 是 CLI 在遍构建前算的，这是既有顺序；没有改顺序去迁就 `#reads`，而是在警告函数里按需加载遍模块。跳过 `std::` 前缀，读失败只当没有读者。
5. **程序组只展开本模块顶层**：`#requires` 在 AST 阶段就要成为常量，跨模块组需要先加载并解析那个模块的标签声明，属于“解析推到标签声明之后”的改动，没有在代码里替作者决定。
6. **遮蔽名单含 `finite_math`**：它是核心的组名，程序声明同名标签同样永远读不到。
7. **`#reads` 至少一个名字**：空列表没有意义，且让“写了但没读”的警告无法成立。

## 5. 没有做的部分与原因

- **`#strict`（H2 第 4 项）未实现。** 设计 7.4 要求“不使用任何许可，包括默认许可”，而现在的节点只存“授予了哪些许可”，`NumericPolicy` 再把默认值加上；表达“一个许可都不用”需要决定它是许可掩码里的第 10 位、还是节点上的另一个布尔事实、还是每个节点带自己的策略。这会改到所有读许可的引擎，属于设计判断，写在 §6。
- **`@numeric(...)` 没有删除。** H2 第 4 项要求删掉前端分支，但仓库里还有约 380 处用例/示例在用；删它要么批量改写成标签（量大且会掩盖“两种写法等价”的对照测试），要么先保留并标记废弃。现在的状态是：两种写法都工作，`tag_permissions` 计划证明它们落在同一列、结果逐字节一致。需要作者定迁移方式。
- **`#macro`（H2 第 6 项）未开始。** `macro func` 的迁移与 `Modifier::Macro` 的删除是另一项成规模的前端改动。
- **`#vjp<rule>`（H2 第 5 项）未做。** 标签参数目前只能是 int/float/bool/string（`TagParameterType` 会拒绝函数类型），函数值作为标签事实要先有“函数值的图引用”这一层；`@vjp` 保持原样。
- **`on param`** 仍只是声明里保留的位置，没有语义。
- **导入的/嵌套命名空间的许可组**不能用在 `#requires`（§4.5）。
- **`inspect --tags` 只列程序自己声明的标签**，核心的 `reads`、九个许可标签不在列表里；写在声明上的事实仍会打印。要列核心标签需要改 `tag::dump` 的入口（它按模块的 `declaredTags` 走），这次没有动。
- **H2 第 4 项“删除一字节许可列”字面上没有照做**：列还在，宽度按检查意见改为 16 位。理由是评审明确“不另设一列”。

## 6. 待决问题（只应由语言作者定）

1. **`#requires` 的语义是“跳过”还是“拒绝”？** 现在的实现按设计 7.2：规则的要求不满足时，引擎在该函数上跳过这条规则，程序照常运行，没有诊断。任务书里的说法是“缺少许可的程序被拒绝，并给出指出要求及其来源的诊断”。两者不同；如果作者要后者，需要为“程序里没有任何节点满足某条规则的要求”定义一条诊断（位置在规则声明），以及它和“规则本来就可能不匹配”的区分。
2. **`#strict` 怎么表示？** 许可掩码里加一位（`permissionsText` 会打印 `strict`，但“strict”不是许可）；还是节点上另存一个策略标志（`NumericPolicy` 的 effective 对该节点返回 0）；还是每个节点带自己的 `NumericPolicy`。这决定所有引擎、`factsOf`、持久化格式和 dump 的写法。
3. **程序声明的许可组是否允许导入？** 例如 `tiles` 声明 `tag fast`，程序写 `#requires<tiles::fast>`。现在只展开本模块顶层，且 `#requires` 的其他名字仍报 `TagNotAPermission`；如果允许，AST 阶段要先解析被导入模块的标签声明。
4. **`#reads` 是否要求函数确实是一个遍？** 现在只校验名字是已声明的标签，不校验函数签名/是否注册为遍；一个普通函数写 `#reads` 会被接受，只是没人调用它。是否需要 `TagNotAPass` 一类的诊断？
5. **`@numeric` 何时删、怎么迁？** 约 380 处。设计说标签取代它；删之前是否要保留一个过渡期（例如 `-Wdeprecated`），还是直接删并批量改写？
6. **旧计划里的 `expect_stdout_exact`。** 当前 runner 不支持这个字段（见 §3），仓库里不少旧计划因此没有真正比较 stdout。这是测试基础设施的缺陷，不属于 H2，但会影响“测试通过”的可信度；是否单独开一项修 runner 或批量改成 `verify_script`？
7. **遮蔽名单的边界。** 现在只挡核心许可名与 `finite_math`；核心的 `reads`、将来 `#strict`、`#macro` 等同名程序标签是否也应拒绝？
