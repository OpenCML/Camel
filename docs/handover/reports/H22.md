## 1. 数组的切向量（第 2 项）

### 1.1 规则

`tangentTypeOf(T[])` 是"元素切向量的数组"（设计原则 9.9、5.4）：`float[]` 的切向量是
`float[]`，`{x: f32, y: f32}[]` 的是同型的结构体数组；元素没有切向量（`string[]` 等）时数组
也没有。`computeTangentType` 在 `develop` 上本来就把 `TypeCode::Array` 映射为
`ArrayType::create(tangentTypeOf(elem))`，本次没有改它；缺的是算子、规则和活跃性判断。

### 1.2 实现

- `include/camel/core/derivative.h`：`VjpCall` 增加
  `std::span<const vjp_node_t> withInputs;`，位于 `inputs` 与 `output` 之间，注释说明它是
  With 实参；`append` 的被追加值从 With 入边读，不在 Norm 入边里。
- `src/builtin/operators/struct.h/.cpp`：新增内部算子
  - `__tangent_add_arr__`（`tangent/add_arr`）：逐元素结构相加；
  - `__tangent_zeros_arr__`（`tangent/zeros_arr`）：按原数组形状造零，元素零由
    `zeroTangent` 递归给出；
  - `__tangent_scatter_add_arr__`（`tangent/scatter_add_arr`）：把 `dy` 加到 `dx[index]`，
    是 `xs[i]` 的反向；
  - `__tangent_init_arr__`（`tangent/init_arr`）：去掉末尾元素，是 `append` 反向的前半；
  - `__tangent_last_arr__`（`tangent/last_arr`）：末尾元素，是 `append` 反向的后半。
  递归辅助 `zeroTangent` / `addTangent` 支持 `Float64`、`Float32`、`Struct`、`Tuple`、
  `Array`；其他切向量类型报 `RuntimeDiag::RuntimeError`（`noStructuralTangent`）。结构体/元组
  的零按原字段顺序、用 `tangentTypeOf` 映射，丢掉没有可求导性的字段。
- `src/builtin/executors/builtin.cpp`：登记上述五个 kernel，并把它们加入 `kPureHelpers`。
- `src/builtin/operators/derivative.cpp`：
  - `:op/idx_arr` 的规则：`zeros_arr(xs)` 后 `scatter_add_arr(zero, index, dy)`，累加到数组
    入参；
  - `:struct/append_arr` 的规则：`requireInputs(call, 1)`；`init_arr(dy)` 给数组入参，
    `last_arr(dy)` 给 `call.withInputs[0]`；
  - 登记 `TypeCode::Array` 的 `TangentSpace`：`addUri = ":tangent/add_arr"`、
    `zerosLikeUri = ":tangent/zeros_arr"`，没有常量零。
- `modules/autodiff/pullback.cpp`：
  - `carriesGradient` 对数组递归到元素；
  - `visitFill` 支持数组字面量：`dy` 是数组切向量，每个活跃元素按自己的静态下标读回
    `dy[i]`（`slots[i]`，即 FILL 的洞位置）并累加。这修掉了此前捕获 `[w, 2.0]` 时
    "cannot differentiate through an array literal yet"（无位置）的洞；
  - `visitOper` 填 `VjpCall.withInputs`；
  - `visitCallSite` 的数组拒绝收窄：只有**被迭代**且活跃的数组拒绝；被捕获的数组允许，
    其元素梯度由 `idx_arr` 散射加回。

### 1.3 循环中的数组梯度

- 捕获的活跃数组按下标读取：`f(xs) = xs[0] + xs[2]`，`grad(f)([1,2,3]) = [1,0,1]`；结构体
  数组给同型结构体数组，非可微字段为零（`y: 0.0`）。
- 数组循环状态经 `append` 生长（初值用带类型的空数组，如 `let empty: float[] = []`）：
  `f(w) = loop acc = empty for x in [1,2,3] do acc->append<x*w>` 的值是 `[2,4,6]`，
  `grad(f)(2.0) = 6.0`；结构体数组同样成立（值 6.0、梯度 3.0）。
- 被迭代的活跃数组仍拒绝（见 3.2）：反向循环没有把每轮元素梯度散射回被迭代数组的路径。
- 数组字面量从活跃值构造也可以求导（见 1.2 的 `visitFill`）。

## 2. 循环值没有梯度通道时带位置拒绝（第 1 项前半）

`modules/autodiff/pullback.cpp` 的 `Backward::run` 在"节点没有切向量、且不是函数值载体"的
分支里，对 `GCNodeKind::Loop` 检查 Norm/With 入边；只要有一个入边活跃，就 `failAt` 循环节点的
位置，而不是像以前那样让 `rewriteLoop` 因 `dyType == nullptr` 静默返回。诊断原文（`{}` 处是
类型、`whereIs` 处是位置）：

```
autodiff: a 'loop' depends on a differentiated parameter, but its value of type '{}' has no
gradient channel. Gradients cannot flow through a loop whose value has no tangent{}; make the
loop's value, or the value it reads, something that can carry a gradient
```

实测（`test/cases/loops/refuse_loop_no_channel.cml`，第 7 行第 13 列）：

```
error[RuntimeDiag::RuntimeError]: An error has occurred: autodiff: a 'loop' depends on a
differentiated parameter, but its value of type 'int' has no gradient channel. ...
(at test/cases/loops/refuse_loop_no_channel.cml:7:13); make the loop's value, ...
```

`std::macro` 把它包在 `RuntimeDiag::MacroEvaluationFailed` 下，位置仍在循环处（`7:13`）。
没有活跃入边的无切向量循环不会被误拒（`f(w)` 里一个常量 `int` 循环仍给出正确梯度）。

## 3. 其余诊断

### 3.1 迭代活跃数组

`visitCallSite` 只对 `read.iterated && active_.contains(read.array)` 拒绝，位置在循环节点：

```
autodiff: a 'loop' iterates over an array that depends on a differentiated parameter: an array
of type {}. The gradient of each round's element would have to be scattered back into the array
at that round's index, which the loop's reverse pass does not do. Capture the array and read its
elements by index inside the loop instead
```

它仍然拒绝，是因为反向循环没有"按轮把元素梯度散射回被迭代数组"的表示；这不是"数组没有
切向量"的老规则，诊断也改成说明这一点并给出替代写法。**与评审要求的"拒绝收窄为没有切向量的
数组"相比，这一条仍是缺口**（见第 5 节）。

### 3.2 数组元素类型没有切向量

`string[]` 等数组没有切向量；循环值或捕获是这种数组、且依赖被微分参数时，走 2 节的
"has no gradient channel" 拒绝，不是静默跳过。

## 4. 第 1 项未完成：追加识别为收集输出

### 4.1 现状

- 源码里 `loop losses = [] ...` 仍在建图前被 `SemanticDiag::LoopStateWithoutType` 拒绝：
  `[]` 没有自己的元素类型，循环状态的类型来自第一个值；诊断建议先写
  `let none: T[] = []` 再以它为初值。实测位置在 `[]`（第 3 行第 27 列），不是静默跳过。
- 用带类型的空数组作初值、循环体返回 `acc->append<v>` 时，前端把它当普通状态更新
  （`:struct/append_arr`），不是收集槽；整个数组是每轮结束时的状态值。数组状态现在有梯度
  通道（第 1 节），所以不再被静默丢梯度，但**没有**"每轮追加进收集槽、`FILL` 还原用户可见
  元组"的表示，分配行为也不是收集槽的 O(n)（每轮 append 的复制语义取决于
  `rebindingAppendOf` 是否把该次追加认成再绑定；循环体的表达式形式不走那条路径）。

### 4.2 为什么没有落

收集输出要同时改三处，缺一不可：

1. **类型**：`loop losses = []` 的元素类型只能从循环体的 `append` 结果推出，或按上下文给
   `[]` 一个类型。后者属于第 3 项/ H23，按指示没有动；前者是一个尚未决定的类型规则
   （空字面量的类型来自何处），不能由实现擅自定。
2. **建图**：在自动微分和 `std::opt` 之前的规范化改写里，把"初值为空数组、下一值为追加一个
   值、循环体其他处不读该状态"的状态改成收集槽；`LOOP` 的值变成
   `(states..., collected...)`，再用 `FILL` 把收集数组放回用户可见的元组位置。当前没有这样的
   规范化 pass；`rebindingAppendOf`（`src/compile/gir/builder_operators.cpp:660`）只处理
   变量再绑定，按任务要求不能把识别放在那里。
3. **反向**：用户可见的收集数组一旦参与求导，反向循环必须把该数组的梯度按轮取元素
   （`dy[i]`）送进循环体回传，才能让每轮追加的值拿到自己的梯度。H4d 的反向循环
   （`buildReverseBody`）目前只把状态的 `dy` 和残差的原值送进回传；收集槽是自动微分的磁带，
   没有"用户可见收集数组"的梯度入口。

只做第 2 步会得到一个值正确、非求导执行 O(n)、但一求导就丢收集数组梯度的半成品，违反
"不得静默丢失梯度"；因此本次选择不做，并把缺口写清楚，而不是用静默跳过或改测试期望来掩盖。

### 4.3 建议的下一步

按 4.2 的顺序做：先由语言作者裁定 `loop losses = []` 的元素类型来源（这是第 3 项/H23 的
同一类问题）；再做规范化改写与 `FILL`；最后扩展 `LoopBodyPlan`/反向循环，使收集输出参与
`dy`。第 3 步可以复用本次的 `scatter_add_arr` / `idx_arr`，把收集数组的 `dy` 按轮取出。

1. **`loop losses = []` 的元素类型从哪里来**：从循环体的 `append` 推，还是要求写
   `let empty: T[] = []`？与第 3 项/ H23 的空字面量上下文类型是同一类语言规则，留给语言作者。
2. **收集输出参与求导的表示**：反向循环怎样把用户可见收集数组的 `dy` 按轮取出并送进循环体
   回传？这需要 `LoopBodyPlan`/`GCLoopBody` 区分"残差磁带"和"用户可见收集"，是 H4d 之上的
   一步，不是本次能顺手改的。
3. **被迭代的可微数组**：评审要求"拒绝收窄为没有切向量的数组"，但反向没有按轮散射回被迭代
   数组的路径；本次仍拒绝。要么补反向散射，要么与语言作者确认这一条是否可接受。
4. **元素是张量/自定义切向量的数组**：`tangentTypeOf` 有值，但 `tangent/zeros_arr` /
   `add_arr` 的结构化零与加法只支持标量、结构体、元组、数组；这类数组要等 H17 的表示/算子。
5. **`append` 的写法**：本分支是 `acc->append<v>`（尖括号是 With 实参），任务文字里的
   `losses->append(l)` 会得到 `NoMatchingFunction`。这是既有语法，不是本次改的；若以括号形式
   为准，需要语言作者确认后另做。
