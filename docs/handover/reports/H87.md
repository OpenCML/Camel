## 1. 定律表

"必须不触发"只列**数值/类型上真会改变答案**的情形；权限不足而门控不触发的情形单列。
`algebra.cpp` 一列写它对应的实现位置（`src/passes/opt/generic/algebra.cpp`，张量走的是同一个
`simplify<T>` 模板，`T` 是元素类型）。

### 1.1 张量（`Tensor<f32>` 元素；15 条）

这些规则的模式类型是 `Tensor<f32>`：**算符 id 不携带元素类型**（`tensor:add` 对 f32/i64/bool
是同一个 id），所以每条规则还要用类型说"它是关于哪个类型的"。匹配器要求模式项的类型接受被匹配
节点的类型（`acceptsType`，`src/runtime/writings.cpp`）：`Tensor<i64>` 永远不匹配这些规则，而
`Tensor<f32, [3]>` 匹配（更少的类型信息可从更多的赋值）。系数是**普通数**（算符接受任意
`TensorOrScalar`），所以 `x * 3.0` 的常数是 f64，而元素类型是 f32；每个守卫都用 `float` 采样读它，
并要求它**在 f32 里恰好可表示**（`exactIn32`）——读一个 f32 会舍入的系数，就等于把 `x * 0.1`
当成 `x * f32(0.1)`，这正是 `algebra.cpp` 用 `constant<float>` 的 `exactIn<float>` 避免的 bug。

| 定律 | 规则 | 触发条件 | 必须不触发 | `algebra.cpp` |
|---|---|---|---|---|
| `t*1`、`1*t` | `tensor_f32_mul_one`、`_one_mul` | 常数为元素中性元 1.0 | 常数不是 1.0 | 中性元，559–566 的 `simplify<T>` |
| `t + -0.0` | `tensor_f32_add_minus_zero` | 常数为 -0.0（f32 加法中性元） | 常数为 +0.0（`x + 0.0` 会把 -0.0 变成 0.0） | 中性元 |
| `t - 0.0` | `tensor_f32_sub_zero` | — | — | 中性元 |
| `t / 1.0` | `tensor_f32_div_one` | — | — | 无（`algebra.cpp` 没有除法；多出，精确） |
| `-(-t)` | `tensor_f32_neg_neg` | — | — | 无（多出，精确） |
| `t + t` → `t * 2.0` | `tensor_f32_add_self` | 任意 t | — | `a == b` 分支，573–575 |
| `t*c1 + t*c2` → `t*(c1+c2)` | `tensor_f32_combine` | 两个系数都 f32 精确、有限、非零、**同号**、f32 和有限 | 异号；任一为 0；任一非 f32 精确（0.1）；和溢出到 inf | 376–393（`T = float`） |
| 同上但异号 | `tensor_f32_combine_mixed` | 再加 `#requires<no_infs, no_signed_zeros>`；`c1 + c2 != 0` | 未授予权限；和为零（`x*3 + x*-3` 得到 -0.0 而不是 +0.0） | 同上 |
| `(t*c1)*c2` → `t*(c1*c2)` | `tensor_f32_fold` | 系数 f32 精确、非零、积有限、积非零 | 积下溢为 0；积溢出；未授予 `no_infs` | 406–417 |
| `t*c + t*c` → `t*(c+c)` | `tensor_f32_double` | 系数 f32 精确、整数、`1 <= abs(c) <= 8388608`（2 的幂附近精确加倍） | 非整数系数（0.1）；abs(c) 为 2 的幂以外的大数（8388609） | 精确加倍分支 |
| `t*c + t` → `t*(c+1)` | `tensor_f32_combine_one` | 系数 f32 精确、有限、非零、正、`c + 1` 有限 | `c <= 0`（零或负，见异号）；非 f32 精确 | 裸项：`term<T>` 返回系数 1，376–393 |
| 同上异号 | `tensor_f32_combine_one_mixed` | 再加 `no_infs, no_signed_zeros`；`c + 1 != 0` | 未授予权限；`c = -1`（和为零） | 同上 |
| `t + t*c` → `t*(1+c)` | `tensor_f32_one_combine`、`_one_combine_mixed` | 同上，两个顺序 | 同上 | 同上 |
| `a*(b+c) <=> a*b + a*c` | `tensor_i64_distribute` | i64 张量（回绕精确） | **不存在 f32 版**：`a*(b+c)` 可为 0 而 `a*b + a*c` 为 `inf + -inf` = NaN，没有任何权限能表达"不溢出" | 无（多出，只在饱和里，因为写法变大） |

不能写的定律（留给 `algebra.cpp`，见 §6）：`t*0 => 0`、`0*t => 0`、`t - t => 0`、`t + 0 => t`、
`0 + t => t`。原因是**规则写不出"匹配形状的零张量"**：规则的替换就是它写的东西，程序里没有
`Tensor<f32>` 的零常量可写（`reshape([0.0,...],[3])` 是调用不是常量）。把它们写成 `t * 0.0 => t`
这样的形状相关断言是不允许的（那是把定律削弱成对某个形状成立），所以按作者的话**作为问题上报**，
不存在 `algebra_tensor.cml` 里，也不影响 §2 的三例。

## 2. 与 `algebra.cpp` 的覆盖对比

### 2.1 三例（作者点名的验收）

`test/cases/opt/generic/algebra_tensor.cml`，同一程序、同一 `std::opt::fold`，只换 `algebra` 为
`rules::simplify`（计划 `tensor.rules_simplify_matches_algebra`）：

| 例 | `rules::simplify` | `std::opt::algebra` | 起作用的是哪条 |
|---|---|---|---|
| merged | 0 add, 1 mul | 0 add, 1 mul | 元素 `x*3 + x*5 => x*8`（`tensor_f32_combine`） |

### 2.3 逐条覆盖

`algebra.cpp` 的张量路径是同一个 `simplify<T>` 模板，它认的中性元、零、`a==b` 加倍、
系数合并/折叠、精确加倍，规则库都有对应；反过来规则库多出 `div one`、`neg-neg`、
`tensor_i64_distribute`（只在饱和里）和元素族的 `x*c + x`。**没有**"`algebra.cpp` 能做而规则库
不能做、且还能写出来的"条目；写不出来的只有 §1.1 末尾那一族零定律。

## 3. 两个待定项

### 3.1 `x*c + x` / `x + x*c`

**加上，并且守卫集合不变。** 论证：`x*c + x` 就是 `x*c + x*1`，即 `combine` 在 `c2 = 1` 时的
特例；`1` 是元素类型的中性元，`x*1` 精确等于 `x`，所以"隐式的 1"不引入任何新的数值行为。
于是守卫集合逐条相同：

- 整数族（int/i32）：`combine` 无守卫（回绕精确，`INT_MIN` 也成立），裸项也无守卫；i32 的
  `2147483647 + 1` 回绕到 `INT_MIN`，规则用 `Compute` 在 i32 里算这个和，与程序一致（测试
  `i32_combine_one_wrap` 钉住）。
- f32/f64：同号 → 只要 `reassociate`；异号 → 再加 `no_infs`、`no_signed_zeros`；`c = -1`（和为零）
  被拒；`c = 0`（`x*0 + x`，在 inf 上程序是 NaN、定律会给出 inf）被拒；f32 又多一条
  `exactIn32`（系数必须 f32 精确）。
- 张量的额外一条：系数是 f64 常数，所以全部经过 `exactIn32`，与 `tensor_f32_combine` 的
  `c2 = 1` 情形逐条一致。

测试：`bare_target.cml` + `rules.element_bare_term_laws`（四个族、两个顺序、回绕、
`c = -1`、异号未授予/已授予的计数）；`bare_boundary.cml` +
`rules.element_bare_term_boundaries`（守住时的 `0.0`/`nan`）与
`rules.element_bare_term_boundaries_are_real`（去掉守卫后的 `-0.0`/`inf`，证明测试能抓到）；
张量侧在 `tensor_target.cml` 的 `one`/`one_other`/`one_mixed`/`one_mixed_granted`/`inexact_one`
与 `tensor_boundary.cml`。

### 3.2 `safe_fp`

**是小参数，做了。** `rewrite` 与 `saturate` 原本把 `NumericPolicy::relaxed()` 写死；现在各多一个
可选的尾部 `strict: bool` 参数（`rewrite` 参数 2 或 3 个，`saturate` 3 或 4 个，解析器用
`{-1, {}}` 变长形参 + 尾部 `Bool` 检查，签名字符串也写明可选 `strict`）。库里的入口是
`rules::simplify(p)` / `rules::simplify_strict(p)`、`rules::saturate_all(p)` /
`rules::saturate_all_strict(p)`（7.5：一遍可以自己选择数值策略）。

`strict_target.cml` 钉住：同一程序在默认策略下 `combine` 从 1 add/2 mul 变成 0 add/1 mul，严格
策略下保持 1/2；`double` 两边都是 0/1（精确加倍不需要权限，7.4）。计划
`rules.strict_policy_refuses_reassociation`、`rules.strict_policy_keeps_exact_laws`、
`rules.strict_saturation_runs`。

## 4. 检查器与采样器

- `check` 的**直接路径**给每个参数造样本；张量样本按 `shapeOfType` 造（未知维度取 2，`dims`
  为空取 `{3}`，元素数上限 1024，超出则全取 2），f32/i64/bool 分别用 `pickFloat`/`pickInt`
  填字节，**在每次 `vm.callGraph` 前**才物化成 `Array`（引擎路径），结果按字节快照
  （后一次调用可能搬动它）。
- 比较：dtype、shape、字节数必须相同；非 f32 元素按字节比较；f32 逐元素 `agreeFloat`
  （无权限规则按位比较，NaN 与 NaN 视为相同；有权限规则按元素值比较）。
- 系数常数采样：常数参数取小整数（`-64..64`，在每种元素类型里都精确），特殊的精确值里补了
  负数；这是混合符号规则能真的在 64 次抽签里触发（17–55/64）的原因。
- 结果：92 条全部 `ok`，张量的 16 条全部触发（`fired 8 of 8` 或 17–55 of 64）。
  **采样器能造出张量**（f32/i64/bool），所以张量定律没有被削弱；`Tensor<i64>` 的
  distribute 需要三个同形状的 i64 张量，采样器给的是 `[2]`/`[3]` 形状，能造。

## 5. 发现

1. **写法类型**（`writingType`，`src/runtime/writings.cpp`）：规则的 RHS 以前无条件用模式的
   类型建节点。张量定律的模式类型是 `Tensor<f32>`，而被替换的节点是 `Tensor<f32, [3]>`，于是
   替换出来的写法类型变浅；`rewrite` 不比较类型所以看不出来，`saturate` 合并两个写法时按类型
   合并，正好抛 `RewriteInvalid: Two writings of a value have the same type, region and
   permissions...`。修法是：模式类型接受节点类型时，写法沿用节点自己的类型（更精确的那个）。
   这是所有规则共享的机制，标量规则上类型相同、行为不变。
2. **`saturate` 在混合上下文里仍会抛**（先于本轮，非 H87 引入）：`typed_target.cml` 与
   `typed_boundary_guards.cml` 这类"一个函数授予 `no_infs`、另一个不授予"的程序，饱和时同一个
   值会得到权限掩码不同的两个写法，`assertEqualDeferred` 拒绝合并。用 64 条库（
   `git show b13008bae:stdlib/rules.cml`）对同一二进制复现同样的失败，且 `float32_fold` 这种
   H65 就有的规则单独就能复现；本轮没有哪个计划饱和这样的程序。**作为问题上报**：这是
   "饱和跨权限上下文"的设计问题（不是定律的守卫问题），修它要动 `assertEqualDeferred` 的语义。
3. 张量的 `x*0`/`x-x`/`x+0` 族写不出来（§1.1），是删 `algebra.cpp` 的唯一剩余语义缺口。
4. `f32` 没有分配律（反例：`a*(b+c)` 为 0 而 `a*b + a*c` 为 `NaN`），元素库也没有 float
   分配律；`tensor_i64_distribute` 只在 `saturate_all` 里，不进 `simplify`（写法变大）。
   `publish` 的记录：这条 i64 定律是"多出"的，`algebra.cpp` 没有。
5. `import { Tensor } from tensor` 让每个 `import rules` 的程序都加载张量模块；这是本轮接受的
   代价（否则张量定律无处安放），若作者不接受，可以把张量定律挪到 `stdlib/rules/tensor.cml`
   之类的独立模块，代价是 `rules::simplify` 需要 `import` 两个。
6. 元素语料 `algebra.cml` 的等价性复核：`std::opt::fold rules::simplify` 给出与
   `std::opt::fold std::opt::algebra` **相同的多重集**（8 `mul_d`、2 `add_d`、2 `mul_l`、
   1 `mul_i`、1 `mul_f`、1 `dtof`），与 H65 报告一致；只跑 `rules::simplify`（不带 `fold`）时，
   `integer32` 的 `i32(3)` 显式转换留成 `ltoi` 节点、`strict32` 的 `t+t` 变 `t*2` 而不是
   `x*6`，所以 `algebra.cml` 上的对比必须在 `fold` 之后做（H65 的数字就是这么来的；用
   `b13008bae` 的库和 `verify` 检出的旧二进制都能复现，不是本轮引入）。

## 6. 离删除 `algebra.cpp` 的剩余距离

已经等价的：元素族（H65）与张量族（本轮）的中性元、零、`a==b` 加倍、系数合并/折叠、精确加倍、
裸项系数读取；`algebra_tensor.cml` 的三例多重集相同、值在四个后端相同。

还差的：

1. **零定律**：`t*0 => 0`、`0*t => 0`、`t - t => 0`、`t + 0 => t`、`0 + t => t`。要写就必须能写
   "匹配形状的零张量"；这需要规则语言/张量模块给出常量零张量，或者一个新的机制
   （例如按类型构造常量的规则内建）。这是作者要决定的设计问题，报告在此提出，不擅自削弱定律。
2. **工程**：把 `rules::simplify` 注册成 `std::opt::algebra` 的替代（同样的 pass 名/参数
   `safe_fp`），并删掉 `src/passes/opt/generic/algebra.cpp` 与它的计划条目；
   `safe_fp=true` 的加倍行为会从"保留 `t+t`"变成"做精确加倍"（§2.2），这是 7.4 允许且要求的，
   但要在变更说明里写清楚。
3. 已经有的对照：`tensor.graph.default`/`tensor.graph.safe`/`tensor.execution`（algebra 侧）、
   `tensor.rules_simplify_matches_algebra`/`_execution`/`_strict`（规则侧）、
   `rules.tensor_*`、`rules.strict_*`、`rules.element_bare_term_*`；`check_library` 的 92 条。
