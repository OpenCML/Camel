## 2 约定

### 2.1 哪些片段被检查

扫描根 `README.md` 与 `docs/**/*.md`。以下不扫描，理由写在脚本的允许名单里：

- `docs/handover/`、`docs/reviews/`：任务报告与日期化审查是**记录**，不是面向读者的页面；
- `docs/stdlib-reference.md`、`docs/diagnostics.md`：生成的参考页（签名行、故意失败的诊断示例）；
- `docs/design-principles-log.cn.md`：日期化的设计原则旧文与裁定记录。

`docs/design/**` 与 `docs/technical/**` 的**非入口**片段按“节选”处理：这些页在讲设计或测量，片段常是上下文的一部分。策略只有一条，理由在脚本的 `EXCERPTS` 里；**带 `func main` 的完整程序仍然检查**，所以提案里能编译成完整程序的片段不会被放过。节选数在汇总行里报出（当前 102 个），不会静默消失。

### 2.2 片段怎么组成一个程序

- 相邻的 `cml`/`camel` 围栏，如果每个围栏第一行是 `// name.cml`，算同一个多文件程序（标准库模块、入口模块各一个文件）。
- 有 `func main` 的围栏是入口；没有入口的围栏按模块编译，检查器在末尾补一个 `func main(): int sync { return 0 }`，所以“只有声明”的片段也会经过 GCT/GIR。
- 紧接着的 `bash`/`sh` 围栏是运行命令；命令之后的 `text` 围栏是期望输出。片段内部第一行 `// camel ...` 也可以给出命令（如 `--arg name=Camel`），这时直接用它。
- 没有命令时，运行 `camel <入口文件>`（默认后端）；编译检查始终是 `camel <入口文件> std::gir`，即解析、GCT、GIR 都走到。

### 2.3 怎么比对

- 先编译；编译失败就报 `file:line: does not compile: <第一条诊断>`。
- 有 `text` 块时运行：比较 **stdout**、**退出码**（期望错误是 1，否则 0）和**诊断名**。警告在 stderr，仍按文本块里写的 `warning[...]` 断言。
- 路径归一化：`.../snippet.cml:4:15` 与页面上的 `fault.cml:4:15` 都变成 `<file>:4:15`，所以临时目录不影响比较；源码摘录行逐字比较。
- 错误块带 `-->` 位置时比较整段（含帮助行）；页面故意截断、只留诊断名时，只比较诊断之前的 stdout 并断言诊断名。

### 2.4 标记

标记是紧挨围栏的 HTML 注释（页面上不可见），格式：

```text
<!-- camel-snippet: fragment: <理由> -->
<!-- camel-snippet: counter-example: <理由> -->
<!-- camel-snippet: compile-only: <理由> -->
<!-- camel-snippet: graph-dump: <理由> -->
```

- `fragment`：不完整的节选，不编译（例如只展示签名、省略号、上下文里的变量）。
- `counter-example`：**故意错误**的片段，不编译；同时在围栏前 8 行内要有可见标签（`反例`、`错误`、`wrong`、`counter-example` 等）。日期化缺陷记录里的四条都加了 `反例（本条记录的行为）：`。
- `compile-only`：片段本身能编译，但后面的文本块是**另一个文件**的输出（教程 6.2 的 `greet` 只改了函数体，输出属于 `examples/06_sync_block.cml`）。
- `graph-dump`：只编译、不运行（当前没有使用）。

没有标记、又不在节选策略/允许名单里的片段，就是被检查的片段；检查器不会按语言或按“看起来像伪代码”静默跳过。
