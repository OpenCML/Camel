## 2. `graph` 是声明模块

`modules/graph/module.cpp` 的 `GraphModule : BuiltinModule("graph", ctx)` 与 `stdlib/graph.cml`
的 `module graph` 同名，`stdlib/graph.cml` 里没有 `import`，声明模块因此继承 C++ 的导出与类型
（H94 裁定 1）。句柄类型 `Program`、`Graph`、`Node`、`Region`、`TypeRef`、`Op`、`Tag`、`Txn`、
`NodeKind`、`RegionKind` 与别名 `Value = Node` 仍由 C++ `exportType` 导出——声明只*命名*它们，
类型本身不是声明能写的东西。

声明文件 45 条 `export func`：37 条具名（`id` 的 3 个重载各一条）加 8 条 `operator ==`；另有
6 条 `// dynamic func` 注释（C++ 计算签名，见第 5 节）。每条固定签名都带 `///` 文档、`@pure`
或 `@effect` 与 `@example`，参考页从这些声明生成。

## 3. C++ 侧删掉了什么

- `read.cpp`：`ReadOp` 只剩 `{name, kernel}`，25 条读算子的表不再写参数与结果类型；
  `readGroups()` 只剩 `constant` 一组（那是计算签名）。
- `txn.cpp`：`TxnOp` 只剩 `{name, kernel}`；`txnGroups()` 只剩 5 组计算签名
  （`open_function`、`to_function`、`program_of`、`graph_of`、`add_constant`）。
- `facts.cpp`：`FactOp` 只剩 `{name, kernel}`，`factGroups()` 整个删除；`effectsType()` 移出
  匿名命名空间，供构造器导出 `Effects`。
- `module.cpp`：删掉 `current`、`id`、`__eq__` 三组 `StaticFuncTypeResolver` 与 `exportEntity`，
  以及 `factGroups()` 循环；`__eq__` 只保留 `exportDefaultImportRef`。保留的是执行器注册、
  纯度（`load()` 里 43 个名字的一张平表）、资源、原地形式，以及 `__neq__` 的 8 条静态规则
  （见第 4 节）。
- `facts.h`/`read.h`/`txn.h`：去掉 `factGroups()` 与表的类型字段，注释说明签名在声明文件里。

## 4. 编译器的一处修正：无体算子声明的导出

`export func operator ==(...)` 是以保留名 `__eq__` 收集的（`parse/ast/builder.cpp` 用
`overloadableOperatorGroup("==", 2)`），声明模块的导出表里也是 `__eq__`。但声明阶段
（`gir/program.cpp` 的 `declareModule`）先调用 `exportNativeOperators`，再调
`exportDeclarations`；后者对 `ref.plain() && isOverloadableOperatorGroup(ref.ident())` 走
`exportOperatorOverloads`，而这条路径只认本模块的**图或模板**：无体声明两者都没有，于是报
`UnresolvedReference: 'operator =='`（位置在模块头）。`exportNativeOperators` 其实已经把该组
导出好了，缺的只是这条路不要把它当缺失。

修法是 `gir/builder_operators.cpp` 的 `exportOperatorOverloads`：在没有图也没有模板时，若模块
已有同名算子组（`module_->getNativeEntity(Reference(group))` 且 `isOperGroup()`），直接返回；
否则照旧报错。这条检查只影响“声明已经成立、导出已在别处完成”的情形，不影响真正的未解析引用。

## 5. 声明里写不下的东西，以及 `!=`

- **6 条计算签名留在 C++**，用 `// dynamic func` 记录：`constant`、`add_constant`（结果取
  `sample` 的类型），`open_function`、`to_function`、`program_of`、`graph_of`（取函数值的类型）。
  声明写 `(typeas T)` 会接受所有类型，本该拒绝的调用会通过检查（标准库约定 2）。
- **`operator !=` 不能声明**：设计原则 4.3 规定 `!=` 由 `==` 的重载给出，`operator !=` 是
  `SemanticDiag::OperatorNotOverloadable`（`docs/language/07_statements.md`）。但编译器只对
  **Camel 的** `==` 重载做否定（`negatedEqualities_`），原生 `set.ops` 不否定，所以
  `modules/graph` 必须自己注册 `__neq__`，否则 `p != current()` 找不到算子。实际做法是：
  声明 `==`（8 条），C++ 保留 `__neq__`（8 条），H137 检查器给 `__neq__` 一条例外
  （`UNDERIVABLE_OPERATORS`，脚本头注明原因）。这是本任务唯一的检查器改动。
- **`Effects` 结构类型**：`effects` 的结果是匿名结构类型，声明要写它的字段；C++ 用
  `exportType(Reference("Effects"), effectsType())` 给这个类型一个名字，声明里写 `Effects`。
  这不改变类型对象，只给参考页与诊断一个可读的名字。

## 7. `globals`：不是可导入的模块，不能按普通模块声明

任务是“调查 `globals`，声明不了就报告并原样留下”。调查结论是**声明不了**，`stdlib/signatures/globals.cml`
一个字没动。证据：

1. **它不是一个可导入的模块**。`src/builtin/modules/globals.cpp:2144` 的构造是
   `BuiltinModule("", ctx)`——名字为空；内建模块工厂表里没有 `globals` 这一项。`import globals`
   因此是 `SemanticDiag::ModuleNotFound`（起点实测 exit 1）。声明模块的机制要求
   `stdlib/<m>.cml` 与 `BuiltinModule("<m>")` 同名（H137 的识别规则），空名字的全局模块没有
   这个名字，写了 `module globals` 也只是另一个、什么也不继承的模块。
2. **93 条签名里有 43 条是通配 URI**（`#op<':op/*tol'>` 之类，一个 URI 覆盖一组重载）。
   前缀检查（H94 裁定 5）本身允许空协议，所以**不是**前缀问题；问题是通配 URI 表达的是
   “一组算子的共同协议”，不是一条声明能绑定的单个算子。
3. **变参与特殊 `with` 形态**：`print`/`println` 是可变参数，`with <...args: T...>`、
   `with <sep: string>` 是语言全局的调用形态；声明语法没有与它们对应的写法。
4. **非标识符名字**：`std::mem::blocks` 是一个带 `::` 的名字，声明模块的 `export func` 只能写
   标识符（限定名是另一回事），快照里这个文件本身就是 `no`——解析器不接受，与文件头“For
   reference only: these declarations are not compiled”一致。
5. **`sleep`/`exit` 的 URI 是 `process:`**（H114），在 `globals` 里声明它们是
   `NativeDeclarationForeignOperator`（H94 裁定 5：一个模块不能替另一个模块写承诺）。

所以 `globals` 的“声明化”前提不成立：它不是模块，而是语言内建名字的集合，URI 在 `:op/` 协议下
（核心已占）。**建议**（留给作者裁定，不在本任务实施）：要么在 H19 的约定页里明确“语言全局不入
声明文件、参考页从 C++ 注册表生成”，要么给“全局”一个与模块不同的声明宿主（例如
`stdlib/globals.cml` 用不带 `module` 的 `builtin` 头，或允许 `#op` 通配 URI 组），两种都要先有
裁定与语法，不能由本批临时发明。
