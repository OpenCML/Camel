# H113 — 标准库声明化的下一批：`math`

分支 `handover/H113-math-declarations`，起点 `origin/develop` `f492a4d07`。任务书是 H19
计划的第 10 步：固定签名模块逐个声明化。前两批是 `bytes`（H76/H94）与 `str`（H104），本批
按顺序取 `math`。一个模块一个提交；`tree`、`rules`/`rewrite` 未动。

## 1. 选中的模块与不能写成声明的条目

`math` 的 99 个注册算子分成三类：

1. **96 条固定签名**：每个类型一个执行器 URI（`abs_i`、`abs_l`、…），可以逐条写成
   `export func` + 确切的 `#op<'math:...'>`。这是本批迁移的部分。
2. **3 个计算签名**：`sqrt`（`i32`→`f32`、`int`→`float`、`f32`→`f32`、`float`→`float`）、
   `shl`/`shr`（结果取第一个参数的类型，计数可接受另一种整数类型）。它们的类型由 C++
   的 `DynamicFuncTypeResolver` 计算，声明语法表达不了；按任务书"不能表达就停在该条并报告"
   留在 C++。声明模块用 `// dynamic func 名字(...): 类型` 记录参考页条目与文档，共 8 行
   （`sqrt` 4 个重载、`shl` 2 个、`shr` 2 个），这 8 行不是声明、不参与编译。
3. **4 个值**：`pi`、`e`、`inf`、`nan` 由 C++ `exportValue` 导出。`export let` 必须有初始值，
   写出来就是第二份值，因此声明模块用 `// value 名字: 类型` 记录参考页条目，值仍由 C++
   导出；`one_module` 依赖 `math::pi` 是 C++ 常量。

所以没有"整模块跳过"的条目；`sqrt`/`shl`/`shr` 与四个值按上面的边界保留，其余 96 条全部
迁移。任务书提到的 `uses`/资源、原地形式、核心 `:op/...` 前缀在 `math` 里都不存在；`math`
也没有泛型声明。

## 2. 声明模块 `stdlib/math.cml`

`stdlib/signatures/math.cml` 移到 `stdlib/math.cml`，成为与 `stdlib/math.cmo`（C++ 模块）
同名的声明模块，也是这 96 条签名的唯一来源。文件头说明照旧，正文结构：

| 部分 | 内容 |
|---|---|
| 常量 | 4 条 `// value`，`///` 说明与 `@example` 照常在上方 |
| 初等函数 | `abs`(6)、`exp`(4)、`sqrt` 的 4 条 `// dynamic func` 等 |
| 取整/转换 | `round`、`ceil`、`floor`、`trunc`、`bin`、`oct`、`hex` |
| 复数 | `re`、`im`、`conj`、`abs` 的 `c64`/`c128` 重载 |
| 位运算 | `bit_and`、`bit_or`、`bit_xor`、`bit_not`、`shl`/`shr` 的 4 条注释 |
| 数论/比较 | `gcd`、`lcm`、`min`、`max`、`clamp`、`sign`、`is_inf`、`is_nan` |
| 三角/对数 | `sin`、`cos`、`tan`、`asin`、`acos`、`atan`、`atan2`、`sinh`、`cosh`、`tanh`、`log`、`log2`、`log10`、`log1p`、`expm1`、`hypot`、`pow` |

规模：**96 条 `export func`、41 个名字、96 个 `#op<'math:...'>` 标签**；每个标签都是
`ExecutorManager` 与 `OperatorTable` 能查到的确切 URI，没有一个 `*` 通配。`abs`/`min`/
`max`/`clamp`/`sign` 这类"每个类型一个执行器"的名字逐条声明，不能用 `(typeas T)` 的泛型
声明代替：泛型声明仍只绑定一个 URI，而执行器是按类型分名的。

## 3. C++ 侧删掉了什么

`modules/math/module.cpp`：

- 删掉 11 个固定签名组（28 条 `StaticFuncTypeResolver` 规则）：`abs` 6、`re` 2、`im` 2、
  `conj` 2、`exp` 4、`round` 2、`ceil` 2、`floor` 2、`bin` 2、`oct` 2、`hex` 2；
- 删掉构造函数里这些组的 `exportEntity` 循环：导出组现在来自 `.cml` 的声明；
- **留下** `sqrt` 的 `DynamicFuncTypeResolver` 组与它的 `exportEntity`；
- **留下**执行器工厂、`sqrtVjp`/`DerivativeRegistry`、`declareMathOperatorSemantics()`、
  纯度表，以及 `pi`/`e`/`inf`/`nan` 的 `exportValue`。

`modules/math/numeric.cpp`：

- 删掉固定签名辅助（`sig`、`floatUnary`、`floatBinary`、`floatTest`、`sameType`）与
  **68 条**静态规则；
- **留下** `shift()` 与 `getMathNumericGroups()`，后者只返回 `shl`、`shr` 两个动态组；
- 内核与 `getMathNumericOpsMap()` 全保留。

96 = 28 + 68，正好是 `.cml` 的 96 条声明。`numeric.h` 只保留 `getMathNumericGroups()`
的声明，并注明固定签名在 `stdlib/math.cml`。`git grep '"math:'` 在 `src/`、`modules/`、
`include/`、`tools/` 里已无固定签名的 C++ 文本；`sqrt`/`shl`/`shr` 的 URI 仍在动态组里。

## 4. 生成器与约定页

`scripts/stdlib-reference.mjs`：

- `math` 条目改为 `source: 'math.cml'`、`declaration: true`，与 `bytes`/`str` 相同；
- 新增 `// dynamic func 名字(...): 类型` 分支：按默认 URI `<module>:<name>` 生成条目，
  读取上方的 `///`、`@pure`、`@fails`、`@example`；
- 新增 `// value 名字: 类型` 分支：生成值条目，`@example` 照读；`docs/stdlib-reference.md`
  的渲染与旧签名文件里的 `export let` 完全相同，所以**参考页没有 diff**。

`docs/stdlib-conventions.cn.md` 补三条：

1. 一个名字按类型有各自的执行器 URI 时逐条声明、各带确切 `#op`；`*` 通配只在不编译的
   签名文件里作参考，声明里不能写；
2. 计算签名（`DynamicFuncTypeResolver`）留在 C++，声明文件用 `// dynamic func` 记录参考页；
3. C++ 导出的值用 `// value` 记录参考页，值本身仍由 C++ 导出。

`docs/stdlib-reference.md`：265 条，无 diff。`node scripts/stdlib-reference.mjs --verify-ops`：
**343 条**已注册签名一致（与 H104 相同）；`--verify-doc`：最新生成物。`camel inspect --ops`
的 `math` 仍是 **99** 条（96 固定 + `sqrt`/`shl`/`shr` 三个动态算子）。

## 5. 用例

`test/cases/compile/native/` 新增三条，挂在 `feat.compile.native_declarations`（计划 24 条）：

## 8. 测试夹具改名：`tags/graph.cml` → `tags/tags_nodes.cml`

这是本批唯一一处 math 之外的改动，必须说明。

`stdlib/rules.cml` 有 `import { Program, Node, constant } from graph`，它要的是标准库的
`graph` 模块；`test/cases/compile/tags/graph.cml` 是一个**同名**的用户模块（文件名叫
`graph`，`module tags_nodes`）。当 `math` 从 C++ 模块变成声明模块后，`rules` 的 GCT 构建
时机变化，模块加载器把 `rules` 的 `graph` 解析到用例目录里的 `graph.cml`，于是 `Node`
类型在 `rules` 里找不到，`std::opt` 的 pass 加载失败（`read_by.present` 与
`strict_algebra` 都先报 `got undefined`）。把用例文件改名为 `tags_nodes.cml` 后，标准库
`graph` 不再被同名文件遮蔽：

- `feat/compile/tags`：**30/30**，`read_by.present` 由红转绿；
- `feat/compile/tag_permissions`：5/6，剩下的 `strict_algebra` 回到 §7.1 的基线红。

改名只动 `test/cases/compile/tags/graph.cml` → `tags_nodes.cml` 与
`test/plans/feat/compile/tags.plan.toml` 的 2 个 `case` 路径；用例内容与 `main` 模块名
`tags_nodes` 不变。核心加载器的"导入优先在入口目录找"是更深的原因，但修它会改变模块解析
优先级，超出本批范围；这里用测试夹具改名消除冲突，报告留给后续。
