# H62：无 JIT 构建（`linux-x64-nojit`）不能编译

**结论：`FastVMSchedPass::apply` 在 `#if ENABLE_FASTVM_JIT` 之外读了 `jitConfig_`。已修，无 JIT 构建现在通过整个 fast 层。**

## 缺陷

H57 在给 v0.2.24 验证 CI 时发现：`linux-x64-nojit` 这条腿在 `Build (Release)` 就红，`fastvm.cpp:538` 报

```
use of undeclared identifier 'jitConfig_'
```

原因在 `src/passes/sched/fastvm/fastvm.h`：`jitConfig_`（以及 `tierPolicy_`、`jitBackend_`、JIT 图缓存）声明在 `#if ENABLE_FASTVM_JIT` 内，而 `#else` 分支只补了 `currentJitCtx_` 和 `jitEnabled()`——那是给两个解释器循环用的，因为它们在 `#if` 之外的名字只有这两个。`apply()` 里的

```cpp
if (camel::profile::enabled()) {
    camel::profile::setBackend(
        jitConfig_.policy == jit::JitPolicy::Disabled ? "std::fvm" : "std::jit");
}
```

比第一个 `#if ENABLE_FASTVM_JIT` 早十几行，因此无 JIT 时这个标识符不存在。同一文件 565 行起的其余用法本来就在 `#if` 内，所以只有这一处。

这是 `std::profile`（H48）与 JIT 策略（H43）接触面新增后留下的，只在非 x86-64 或显式关掉 JIT 时暴露，CI 的普通腿跑不到。

## 修法

不是给 `#else` 补一个假的 `jitConfig_`（那要连 `jit::JitConfig`、`jit::TierPolicy` 一起补，等于把 JIT 类型拖进无 JIT 构建），而是把这一处按构建分开：

```cpp
if (camel::profile::enabled()) {
#if ENABLE_FASTVM_JIT
    camel::profile::setBackend(jitConfig_.policy == jit::JitPolicy::Disabled ? "std::fvm"
                                                                            : "std::jit");
#else
    // A build without the JIT runs this pass as `std::fvm`, whichever name it was given.
    camel::profile::setBackend("std::fvm");
#endif
}
```

语义上没有选择余地：无 JIT 构建里没有 `std::jit` 这个后端，`jitEnabled()` 恒为 `false`，剖析出来的后端名只能是 `std::fvm`——即使命令行写的是 `std::jit`（那时它按 `std::fvm` 跑，与 `jitEnabled()` 的既有约定一致）。

## 验证

在 Linux 主机上，用 CI 同一条配置（`.camel-opts.json` 写 `{"ENABLE_FASTVM_JIT": "OFF"}`）全量重建后跑 fast 层：

```
camel-remote.ps1 -Path D:\Projects\Camel-wt\h62-nojit -Plan smoke,test/plans/feat -Jobs 8
BUILD_EXIT=0   （构建 163 s）
[SUMMARY] total: 4769, pass: 4757, fail: 0, skip: 12
RUN_EXIT=0
```

与同时刻 JIT 构建的闸门（`4769 / 4757 / 0 / 12`）逐条相同：无 JIT 构建下 `*.jit` 那些用例走的是 `std::fvm`，行为一致，skip 数也一样。

**遗留**：CI 里没有"无 JIT 构建"的本地入口——要复现必须自己写 `.camel-opts.json` 并全量重建（163 s）。这条腿只在 CI 上跑，所以这次的缺陷是 H57 给发布做验证时撞上的，而不是开发时。若以后还想更早发现，可以让 `npm run build` 支持一个 `--nojit` 开关，但那会把构建矩阵带进脚本层，暂不做。
