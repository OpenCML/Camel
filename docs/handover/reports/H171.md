# H171 — 文档里的数字：盘点、修正与数字闸门

分支：`handover/H171-doc-counts`（起点 `origin/develop` `72c421872`）。修正、接线与闸门的提交是 `8f949a2`、`b041589`、`a27445a`、`c0798381`；本文件所在的提交记录本报告与看板。

任务：面向读者的页面里有一类断言是数字。已有的三道文档闸门都不读数字：`check-doc-links` 只看链接，`check-retired-names` 只看旧名字，`check-doc-snippets` 只看代码片段。数字因此可以一直过期，迁移一次就悄悄错一次（H162 修过 `docs/technical/38_compile_pipeline_cost.md` 的两个数，H164 发现发布说明把声明模块写成 11 个而实际是 16 个）。这次要：盘点可核对的数字，逐条核对并改错，给“有唯一来源”的那部分加一道闸门，接入 `feat/docs_links`，并给出红证与成本。

## 1 结论

- 新增 `scripts/check-doc-counts.mjs`，接入 `test/plans/feat/docs_links.plan.toml` 的 `docs.counts_current`，与另外三道并列。
- 扫描 **145 篇**面向读者的文档。**13 条**在用断言逐条与真值比较，**8 条**日期化快照在允许名单里（每条带理由）；干净树 0 失败。规则覆盖：CMake 最低版本、导出矩阵、`RuntimeDiag::RuntimeError` 引用数、`SyntaxDiag` 错误码数、签名文件数、内建遍别名数、`.cml` 文件数、AST 快照文件数、模块子目录数、发布闸门的三组计划数、`modules/tiles/**` 的选计划结果。
- 修正 **6 条断言、10 个数字**，涉及 **5 个文件**：4 处 CMake `3.20`→`3.25`，导出矩阵 `106/66`→`119/65`，兜底码引用 `81`→`89`（并把 `147` 标成“原本”），语法错误码 `12`→`16`，签名文件 `十五`→`11`，遍别名 `35`→`37`。没有改生成的页面，没有碰 `changes.log` 或版本文件。

## 2 范围与方法

扫描根：`README.md`、`CONTRIBUTING.md`、`ROADMAP.md`、`docs/**/*.md`。

不扫描，理由与既有闸门一致：

- `docs/handover/`、`docs/reviews/`：任务报告与日期化审查是**记录**，不是面向读者的页面；
- `docs/stdlib-reference.md`、`docs/diagnostics.md`：生成页。它们的数字由 `scripts/stdlib-reference.mjs --verify-doc` 和 `scripts/diagnostics-catalog.mjs --verify-doc` 管；页面写错说明生成器或生成流程错了，改页面不是修法。

方法：先按“数字 + 单位/名词”的方式把页面上的断言分堆（模块数、声明数、算子重载数、诊断码数、测试数、文件数、计划数、版本号、计时），再逐条找**唯一**来源。能找到唯一来源的，进闸门；找不到的，写清楚为什么（见第 9 节）。日期化页面在页眉/状态行里明确写了“实测于某提交”的，进允许名单，不强制跟随今天。

## 4 闸门

### 4.1 契约

```
node scripts/check-doc-counts.mjs            # 检查，0 通过 / 1 有错 / 2 真值算不出来
node scripts/check-doc-counts.mjs --list     # 打印规则与允许名单
```

失败时每条一行：

```
<file>:<line>: <rule>: <claim> says <值>, truth is <真值> (<来源>)
```

最后一行是汇总：

```
N stale count(s) in M reader-facing document(s): C claim(s) checked, A allowlisted (dated snapshot)
```

“真值算不出来”（文件被移走、`git` 不可用、`release-gate --dry-run` 的输出格式变了）是退出码 2，不伪装成文档错误；计划因此会红，提示修闸门而不是改页面。

规则、模式与真值：

| 规则 | 页面上的写法（正则的要点） | 真值 |
|---|---|---|
| `cmake-minimum` | 表格行 `\| CMake \| x.y \|` | `CMakeLists.txt` 的 `cmake_minimum_required(VERSION x.y)` |
| `export-matrix` | `N 个算子中 N 个前向算子、N 个梯度算子`，且同一行提到 `export_matrix.md` | 生成页 `export_matrix.md` 的表头 |
| `runtime-error-refs` | `RuntimeDiag::RuntimeError` … `仍被引用 N 次`，可带 `其中 python 模块 N 次` | `src/`、`include/`、`modules/`、`tools/` 里子串出现次数；python 子树单独数 |
| `syntax-codes` | 提到 `syntax.h` 的行里的 `N 个错误码` / `N 个码` | `syntax.h` 中 severity 为 Error 的枚举值个数 |
| `signature-files` | `N 个签名文件`、`签名文件 … N 个模块`、提到 `stdlib/signatures` 的 `N 个文件` | `stdlib/signatures/*.cml` 的个数 |
| `pass-aliases` | `另有 N 个别名` | `src/execute/pass.cpp` 的 `passAliases` 表项数 |
| `cml-files` | `N 个 .cml` | `git ls-files '*.cml'` |
| `snapshot-files` | 提到“AST 快照”的行里的 `N 个文件` | `test/plans/feat/parse/golden/ast_hashes.txt` 的非空非注释行 |
| `module-subdirs` | 含 `modules` 的行里的 `N 个子目录` | `CMakeLists.txt` 的 `add_subdirectory(modules/...)` 条数 |
| `gate-counts` | `eleven explicit plan files`、`eight static checks`、`nineteen plan files … forbids` | `scripts/release-gate.mjs --dry-run` 的 slow / 静态检查 / skipped 三组数；英文数词映射到 0–20 |
| `tiles-selection` | `selects six plan files and the 88 GPU tests`（整段，可跨行） | `test/plan-selection.json` 的 `modules/tiles/` 规则的计划数；这些计划里 `tier = "slow"` 的测试数 |
| `declaration-modules` | `N 个声明模块` / `N declaration modules` | `scripts/stdlib-declarations.mjs` 的 `declarationModules()`；当前页面上没有这条断言，规则保留给下一篇写它的页面 |

没有第二条真值，也没有“差不多就行”的容差：数就是数。日期化快照靠整页允许名单解决，不靠模糊匹配。

### 4.2 为什么这些规则、不是别的

- 每条规则的真值都能在**一次读文件或一次不建编译器的命令**里得到。`release-gate --dry-run` 和 `git ls-files` 是例外，各一次进程，0.7 s 的总成本里已经包含。
- 规则的匹配都带上下文（提到 `export_matrix.md`、`syntax.h`、`stdlib/signatures`、`快照`），避免把普通句子里的数字误当断言。`gate-counts` 只认阈值内的英文数词，`declaration-modules` 只认“声明模块”，都不会去碰“3 个后端”这类无关数字。
- 生成页不扫：它们的数字由各自的 `--verify-doc` 管，重复检查只会制造第二个真值。

## 6 顺带修好：三道既有用例此前是空跑

计划运行器只展开 `args`，**不会**把 `case` 自动加到命令行。`tool = "node"` 需要脚本路径作为第一个参数，所以原来的写法是：

```toml
case = "../../../scripts/check-doc-links.mjs"
args = ["${case}"]
```

实际命令是 `node .../check-doc-links.mjs .../check-doc-links.mjs`。三道脚本都把非 `--` 开头的参数当“要扫描的文档/目录”，而 `.mjs` 不是 `.md`，于是：

```
no broken links in 0 document(s)
no retired spelling in 0 reader-facing file(s)
no stale snippet in 0 reader-facing document(s)
```

0 篇、0 个片段，全部“通过”。这不是三道脚本的错，是接线把脚本路径当成了文档。

第一次修（`b031792`）直接把 `args` 删掉，以为脚本会用自己的默认根；主机上一跑，四个用例都在 33 ms 内失败——`node` 没有脚本可执行，读空 stdin 后退出。正确的修法（`b041589`）是保留 `${case}`，再加一个显式开关：

```toml
args = ["${case}", "--default-roots"]
```

三道脚本都认这个开关：它表示“前面的路径只是要执行的脚本，不是文档，按自己的根扫描”。这比在脚本里特判“参数是不是我自己”更清楚，也不会把“参数写错”悄悄变成“扫描全库”。修好后同一台主机上：

```
no broken links in 31 document(s)
no retired spelling in 409 reader-facing file(s) (2 dated snapshot(s) allowed; 2 record directories not scanned)
no stale snippet in 142 reader-facing document(s): 211 snippet(s) ...
```

片段页的数字与 H155 报告一致（142 篇、211 个片段）。
