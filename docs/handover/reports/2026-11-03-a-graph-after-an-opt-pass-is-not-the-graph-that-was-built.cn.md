# 一张过了 opt 的图，不是建图时的那张图

**日期**：2026-11-03。**结论**：`std::gir` 与 `std::rgir` 是同一条边的两种画法，可以互换；**任何 opt pass 之后是另一张图**。拿它当"建图时的边"来用，是同一晚两处误读的共同形状。

## 实测（同一程序三种跑法）

程序是 `sync { g(1); g(2); }`，两个调用都有外部效应。

| 跑法 | 那两个调用之间 |
|---|---|
| `std::gir` | `CTRL` + **`SYNC`（在）** |
| `std::rgir` | 同一条边，只加 style/arrowhead ⇒ `SYNC` **在**（与 `gir` 逐条同边） |
| `std::opt::inline std::gir` | **没有 `SYNC`**：两次调用被内联体替换，链边改挂到 `N04 -> N03`（那里仍是 `SYNC`），并出现 `ORDER` |

⇒ **"零条 `SYNC`"只可能来自跑过 opt 之后的图**，不是建图，也不是渲染层。建图写了 `SYNC`，`gir` 与 `rgir` 都看得到。

## 因此撤回

我们据此立的那一页（"`sync` 块里两条副作用语句之间该不该有链边"）**撤回**：它把一个 pass 之后的状态当成了建图时的状态，于是把一个没有的问题写成了"建图缺陷"。**不是建图缺陷，是读数取错了图。**

## 仍然成立、与这次误读无关的两件

- `generic.cpp:342` 的标记是**有条件的例外**：若链边处处存在，它可由形状推导而退役；这件事与本次读错无关，仍待办。
- 封口检查读的是同一批边，因此它对"图是哪一张"同样敏感。
