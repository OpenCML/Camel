# H133 — 标准库声明化的下一批：`time`

分支 `handover/H133-time-declarations`，起点 `origin/develop` `6a0ff112d`。任务书是 H19 计划的
第 10 步（其余固定签名模块声明化）；前面几批是 `bytes`（H76/H94）、`str`（H104）、`math`
（H113）、`json`（H115）、`random`（H128），`re` 由并行的 H126 完成。一个模块一个提交；
`tree`、`ckpt`、`rules`/`rewrite` 未动。

## 1. 选中的模块与边界

`modules/time` 只注册三个算子，全部是固定签名：

| 名字 | 签名 | 效果 | 资源 | 说明 |
|---|---|---|---|---|
| `now` | `(): float` | effectful | `time:clock` 读 | 读系统时钟 |
| `strftime` | `(timestamp: float, format: string): string` | effectful | `process:environment` 读 | 按 UTC 写文本 |
| `strptime` | `(text: string, format: string): float` | effectful | `process:environment` 读 | 按进程时区读文本 |

逐条对照 H94 结尾留下的限制：

1. **计算签名**：`time` 没有 `DynamicFuncTypeResolver`，三条都是固定签名。不受限。
2. **值/类型**：没有 `exportValue`、没有 C++ 导出的类型，`stdlib/time.cml` 里也没有 `export
   let` 可写。不受限。
3. **泛型/原地/核心前缀**：没有泛型声明、没有 `uses`、没有 `setInPlaceForm`、没有 `:op/...`
   形式的算子。不受限。
4. **URI**：三个算子都答在 `time:` 上，与模块名相同，所以声明不需要 `#op` 标签。

`time` 也没有 `Duration`/`Instant` 这类单位命名的类型：接口上的时间就是 `float`（自 epoch
起的秒），格式化与解析用 `string`，所以不存在"声明写不出的结构体类型"这一项；三条签名都能
逐字写成声明。

所以三条全部迁走，没有"停在 C++ 并逐条报告"的条目；这与 `math` 的 `sqrt`/`shl`/`shr`、
`json` 的 `encode`/`decode_as`、`random` 的 `choice`/`sample`/`shuffle` 不同。
`strftime` 的内核里有一个可选的第三个形参 `as_local`（`norm.size() > 2`），但注册的
`StaticFuncTypeResolver` 一直只接受两个参数；声明照注册的两参数写，调用行为与本批之前逐字
相同。这个不可达的分支是既有事实，本批不改，记在第 9 节。

## 2. 声明模块 `stdlib/time.cml`

`stdlib/signatures/time.cml` 移到 `stdlib/time.cml`，成为与 `time.cmo` 同名的声明模块，也是
三条签名的唯一来源。正文：

```camel
module time

/// The current time in seconds since 1970-01-01 00:00 UTC, with a fraction.
/// @effect reads the clock
/// @example now()    // 1791806400.25
export func now(): float

/// The time `timestamp` (seconds since the epoch) written with a strftime format, in UTC.
/// @effect declared with effects together with the rest of the module
/// @fails fault `TimeFormatFailed` when the time or the format cannot be used
/// @example strftime(0.0, '%Y-%m-%d')    // '1970-01-01'
export func strftime(timestamp: float, format: string): string

/// The time, in seconds since the epoch, that text gives when read with a strptime format; the
/// fields are taken as local time.
/// @effect reads the time zone
/// @fails fault `TimeFormatFailed` when text does not have the format
/// @example strptime('1970-01-02', '%Y-%m-%d')    // 86400 in UTC
export func strptime(text: string, format: string): float
```

- 描述、`@effect`、`@fails`、`@example` 从原签名文件逐字搬来；
- 没有 `#op`：默认 URI 就是 `time:now` / `time:strftime` / `time:strptime`；
- 文件头保留了原签名文件里唯一的模块介绍段落（"All three are declared with effects…"），
  换成了与 `random.cml` 相同的 `/** ... */` 形式；`scripts/stdlib-reference.mjs` 的
  `parseHeader` 读到的仍是这两行，因此参考页的 `time` 一节**没有 diff**；
- 文件头的注释改成与 `str`/`math`/`random` 相同的"这是 C++ 模块的声明、C++ 只留实现、本模块
  的 URI 与模块同名所以不需要 `#op`"说明。文件 29 行。

## 3. C++ 侧删掉了什么

`modules/time/module.cpp`：

- 删掉 `getOperatorGroups()`：三个 `OperatorGroup::create` 与三条 `StaticFuncTypeResolver`
  规则（`now`、`strftime`、`strptime`）；
- 删掉构造函数里把这些组 `exportEntity` 的循环；构造函数变成空的
  `TimeModule(context_ptr_t ctx) : BuiltinModule("time", ctx) {}`；
- 删掉只服务签名的 include（`camel/compile/gir.h`、`camel/core/type.h`、
  `camel/core/type/resolver.h`、`operators.h`）与 `using namespace camel::core::type;`；
- 文件从 99 行降到 75 行，补一段文件头注释写明签名在 `stdlib/time.cml`。

**留下**的是"一个事实只写一处"里 C++ 该留的：

- `load()` 里的 `registerExecutorFactory("time", …)` 与 `loaded_`；
- `operators.cpp` 的三个内核 `__time_now__`/`__time_strftime__`/`__time_strptime__` 与
  `getTimeOpsMap()`；
- `OperatorTable::instance().declare("time", …)` 的三条纯度（`@effect` 的事实来源）；
- `declareResources` 的三条资源，逐字未动（见第 4 节）。

`git grep 'StaticFuncTypeResolver' -- modules/time` 已无结果。`git grep '"time:'` 在
`src/`、`modules/`、`include/`、`tools/` 里剩下几处，都不是签名：

- `modules/time/module.cpp` 与 `modules/process/module.cpp` 的 `time:clock` 是**资源名**
  （`now` 与 `sleep` 读时钟），按第 9 步的改名计划原样保留；
- `src/passes/trans/cpp/operator_rules.cpp` 的 `r["time:now"]` 是 C++ 转译遍的运行时函数
  映射，不是签名。

`operators.cpp` 里的 `"time.strftime"`/`"time.strptime"` 是 `TimeFormatFailed` 故障消息里的
算子位置，按原样保留。

## 4. 资源与效果

| 算子 | 资源 | 访问 |
|---|---|---|
| `now` | `time:clock` | `externalAmbient(..., Read)` |
| `strftime` | `process:environment` | `externalAmbient(..., Read)` |
| `strptime` | `process:environment` | `externalAmbient(..., Read)` |

是同一类债务；本批按"不改无关事实"留下，改名时 `modules/time/module.cpp` 的三条资源与相关
计划一起改。

## 6. 用例

`test/cases/compile/native/` 新增三个，挂在 `feat.compile.native_declarations`：

| 用例 | 证明什么 |
|---|---|
| `native.time_declaration_import`（behavior） | 导入方看到声明：`now` 的 `float` 结果、`strftime` 的两个参数与 `string` 结果、`strptime` 的两个 `string` 参数与 `float` 结果；三次调用都到达 C++ 执行器，输出 `true` / `1970-01-01` / `true`（`strptime` 的时区相关结果只断言为正，不写死时间戳）。 |
| `native.time_wrong_arity`（negative） | `strftime(0.0)` 在调用处拒绝；`NoMatchingFunction` `0x0300000F`，位置 `time_arity.cml:10:21`，消息给出 `(float)` 与 `<time:strftime>: (timestamp: float, format: string) => string`。 |
| `native.time_wrong_type`（negative） | `strptime(42, '%Y')` 在声明类型处拒绝；位置 `time_type.cml:11:21`，消息带 `argument types: <> (int, string)` 与声明自己的参数名 `text`、`format`。 |

这正是约定页要求的两条："导入方看到声明的类型；错误个数或错误类型在声明的类型处诊断"，且
消息里的参数名来自 `stdlib/time.cml`，不是 C++。诊断位置是调用的左括号（`strftime(` /
`strptime(` 的 `(`），不是第一个实参；`time_type` 的行号是 11，因为它的文件头是 5 行。

## 9. 留下的

1. **H19 第 7b 步的 `strptime: float!`**：本批按现状声明 `float`；第 7b 步把
   `TimeFormatFailed` 改成错误值时，改的是同一条声明与调用点，声明仍是唯一来源。
2. **资源名 `time:clock` / `process:environment`**：H19 第 9 步改成 `clock` / `env`；本批按
   "不改无关事实"原样保留，改名时三条资源与 `process` 的 `sleep` 一起改。
3. **`strftime` 的纯度**：它按 UTC 写文本，理论上可以是 pure，但现状是 effectful；本批不改
   纯度（声明只携带类型，不携带效果）。
4. **`strftime` 内核的第三个形参 `as_local`**：注册签名与声明都是两个参数，这条分支当前
   不可达；是把第三个参数纳入签名，还是删掉内核分支，需要单独裁定。
5. 第 10 步剩下的固定签名模块（`fs`、`hash`、`env`、`process` 等）可以照本批与 H113/H115/
   H128 的做法继续；`re` 已由 H126 完成。
