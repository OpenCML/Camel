### B1、B2、B3、B4（新增 §9.11 “规则与事实”）

在 §9.10 之后新增：

> ### 9.11 规则与事实
>
> - **`rule` 声明一个类型为 `Rule` 的值**；规则集是 `Rule[]`，调度是普通的函数（`f->rewrite<rules>`、`f->saturate<rules, rounds: 8>`、`f->std::opt<rules: [negate]>`）。写下一条规则不会改变任何遍的行为，规则集一律显式交给遍。
> - **规则与事实的形参 `x: T` 的类型是 `Node<T>`**：改写只看得到图，形参必然是节点，节点有它的值类型。`Node<T>` 是可以写的类型，Camel 写的遍里可以写 `n: Node<int>`；不带实参的 `Node` 是值类型未知的节点，在它上面查询要写 `range::<int>(n)`。模式里把 `x` 当值用的地方（`x * 1`）按它的值类型检查。`const c: T` 的形参是一个类型为 `T` 的常量，条件与右边里拿到的是它的值；每个 `const` 形参另带一个隐藏的节点形参，`node_of(c)` 取它；左边没有给某个 `const` 形参绑定节点的规则在定义处被拒。
> - **事实的查询实参是节点**：事实描述图上一个值怎么得来，查询只能写在规则条件、事实主体或拿到 `Node` 的遍里；在普通函数体里传一个值给查询，报的是说出这条规则的诊断。查询的类型实参照 5.9 推出，推不出就写 `::<T>`。

> - **泛型规则在匹配处实例化**：被匹配的节点的类型解出类型参数，以类型元组为键缓存；某个类型元组做不出实例（条件为假，或模式在该类型上没有算子）是安静的，`why_not` 报告原因。规则可以有多个类型参数。规则的类型实参与 `with` 实参走同一个实例化通道，实例的键是“规则 + 类型实参 + `with` 值”（5.5）。`when` 里的名字按声明处解析。

7.3 同一处**新增**：

> - **epsilon 一律是机器 epsilon**（相邻两值的相对间距 `2^(1−p)`）：bf16 `2^-7`、f16 `2^-10`、f32 `2^-23`、f64 `2^-52`。它与 `change_precision` 里一次舍入的相对误差界（bf16 `2^-8`）是两个量。

### B12、B13（3.3 补全）

把 L145–146 两条（`pure`、函数类型的参数默认对资源泛型）替换为：

> - **`pure`** 承诺函数不使用任何资源，由编译器检查；可以写在函数声明与函数类型上（如要求回调是纯函数：`f: (x: T) => U pure`）。标准库不用 `/// @pure` 一类注释表达纯度。
> - **一个函数的资源集在它的类型里只有一种读法**：写了 `uses` 子句就是子句（对外的契约，调用者按它算，被调者以后在子句之内改函数体不牵动调用者），没写就是推断的结果；直接调用与经函数值调用读同一个类型。显式的 `uses` 是上界，`pure` 要求空集，函数体超出时报 `UsesPromiseViolated`，点出第一个超出的使用点。`stdout`、`fs` 这类程序外的资源，写出它们就承诺了它们带来的外部效应。
> - **没写资源子句的函数类型，在任何位置都对资源泛型**，按实例化确定：形参（`f: (x: int) => int`）、结构体字段、`Map` 的值类型一样。资源不同的实例效应不同（同步链、执行与否都不一样），所以资源分量进入特化键。实参推断出的资源集须包含于形参要求的：资源少的函数可以用在要求资源多的地方，反之不行；一个不碰资源的 lambda、一个没写子句却不碰资源的具名函数，都能传给 `pure` 形参。值的类型打印推断出的子句。
> - **`sync` 是块的性质，不是类型的性质**：`f<w>` 绑定 `var` 上下文参数后得到的值，它的资源集里有“写这个格子”；经资源泛型的形参调用它，与直接调用一样——在非同步体里丢掉结果不执行并给 `EffectNotExecuted`，在同步体里照常执行。

### B14（3.4 新增一条）

> - **同步链的拼接**：被内联的函数如果是同步函数，它自己的同步链随函数体一起拼进来，调用在调用者链上原有的进出同步边保留；函数体里的效应与可能出故障的节点另有顺序边排在前一条语句之后、后一条之前。含效应或可能出故障的分支是链上的一条语句（前一条 →同步→ 分支，汇合 →同步→ 后一条）。没有表示“一段有效应的工作”的占位节点：顺序边只连真实的效应或可能出故障的节点。

### B15、B16（3.5 新增）

> - **赋值表达式被当作值用时，它的值就是写进去的那个值节点**，经数据边直接使用，不新建读；`x op= e` 就是 `x = x op e`，被当作值用时取的是 `x op e`。函数体末尾写 `return e` 与直接写 `e` 建成同一张图。
> - **`var` 的读与写**：只在自己的图里读写的 `var` 化成 SSA（读用最近一次写的值，写与写之间是顺序边）；被闭包捕获、作为 `var` 实参交出、或是本图 `var` 形参的 `var` 保留一个单元，读和读了捕获变量的调用有一个“捕获”角色的数据端口，接到最近一次写的产出。

### B17（10.5 “计数为 1”一句之后）

> 计数必须如实：值多出一个仍然活着的持有者（存进 `var` 单元而源绑定之后还要读、被闭包捕获、存进收集槽）时，由编译器在内存规划里插入“加一”，在最后一次使用之后插入“减一”（Perceus 的做法），于是“计数为 1”恰好等于“没有别的观察者”。是否原地分三层：编译期规划证明（图上这是旧值的最后一次使用，其他只读使用者排在更新之前）、运行时数组计数为 1、都证明不了就拷贝；决定只在内存规划阶段做并写进执行计划。

### B18（3.7 新增）

> - **`match` 的守卫**（`case p when c =>`）：守卫为假就试下一个 `case`；守卫在该 `case` 的作用域里求值，可以读模式绑定的名字；`|` 备选模式只能用每个备选里都绑定了的名字；`case` 按书写顺序试，第一个模式匹配且守卫为真的胜出；带守卫的 `case` 不计入穷尽性检查；守卫可能出故障时按 3.4，它是那条 `case` 的一部分。`T?`、`T!` 的 `match` 两侧各恰好一条不带守卫的 `case`，带守卫的同侧 `case` 写在它前面；同侧开口之后的 `case` 永远走不到，是警告。

### B19、B20（4.4 新增，紧接 `when` 条之后）

> - **重载选择把 `with` 参数算进去**：`with` 形参的个数与名字和普通形参一样参与选择（不是它们的值）。于是同一个名字可以有 `xs->sum` 与 `xs->sum<0>` 两个形式。按名字给实参时，名字写在持有它的那张表里：普通形参在圆括号，`with` 形参在尖括号（`j->get<key: 'port'>`）。
> - 同名声明按 `when` 互斥分臂就是重载；声明处的互斥检查只能抽样已登记的类型，调用处的判断才是权威的。

### B21、B22、B23、B24（5.1 新增）

> - **类型名作用于数组是逐元素转换**：`f32(xs)`、`T(xs)`、`float(xs)`；没有另外的 `cast`。数组元素类型之间同样没有隐式转换（整数、`bool` 也一样）：两个元素类型不同的数组没有匹配的臂，由签名拒绝；`bool` 变成数是一次转换，掩码用 `where` 或显式转换；`if c then xs else ys` 两支元素类型不同是类型错误。
> - **期望类型沿类型变量传进调用**：先把被调函数的返回类型与期望类型对齐，解出类型变量；实参里提到这些类型变量的位置代入后成为该实参的期望类型，字面量据此取类型；已经取好类型的值不转换。字面量一次舍入到目标类型。泛型函数体里的字面量在实例化时取类型，放不下就在实例化处报 `LiteralNotRepresentable`。
> - **空数组字面量 `[]` 的元素类型只取自它所在的位置**：没有这样的位置（作循环初值、作泛型形参 `T[..]` 的实参）是编译错误，要写类型（`let e: f32[] = []`、`show::<f32>([])`）。`void` 不是元素类型。

### B26、B27（5.4 新增，放在“下标与切片”条之后）

> - **秩 0 就是元素本身**：`T[..]` 包括秩 0，秩为 0 的数组就是那个元素，运行期是同一个值，类型上也没有单独的“秩 0 数组”。开秩数组上写位置，结果少一维、秩仍未知（`t: f32[..]` 的 `t[0]` 是 `f32[..]`）；要元素写 `t[0] as f32`，秩不为 0 时在转换处故障。`for` 遍历 `f32[..]` 每轮交出 `f32[..]`，遍历 `f32[]`（秩已知为 1）每轮交出 `f32`；对标量 `for` 是编译期错误。
> - **声明写下的形状就是值的类型**：数组字面量的长度静态已知，`let x: f32[4] = [1.0, 2.0, 3.0]` 是 `DimensionMismatch`；平铺的字面量配二维注解同样是错误，嵌套的字面量在 `f32[2, 2]` 的位置上就是一个二维数组，没有注解时 `[[1.0, 2.0], [3.0, 4.0]]` 是 `f32[][]`；`f32[3]` 不可追加，要可追加写 `f32[]`。字面量、维度名、`constas` 值参数各种写出 extent 的方式走同一个检查。步长为常量 0 的切片、常量下标或常量切片端点越出已知 extent，都是编译期错误。

### B28（新增 §5.11 “特化与递归”）

> ### 5.11 特化与递归
>
> - **声明里未定的 extent 不参与按类型特化**：形参写 `int[]`、`T[?]`、`T[..]`，实例的形参类型就是声明的类型代入类型变量之后的结果；实参的精确长度是值的性质，不进实例的键。命名维度不产生新的实例（5.4）。

### B31、B32、B33（5.4 流的几条补全）

在“流 `T..`”条之后**新增**：

> - **流的值是步进函数加当前状态**：一个普通的函数值，没有新的运行期表示，也没有新的节点种类。流是一等的值，可以写进签名（`func pass(s: int..): int..`）、作参数、被返回。`for` 遍历流在图上展开成已有的 `while` 循环：每轮先问条件，条件成立才调用步进函数拉取下一个元素，拉空就结束；生产者与消费者同时可见时把步进函数内联进循环体是优化，两条路结果相同。
> - **类型的写法**：后缀一律从左到右读：`T?..` 是 `(T?)..`，`T!..` 是元素可错的流，`T[3]..` 是数组的流，`T[..]..` 是开秩数组的流，`T..?` 是可能没有的流；流不能作数组、映射、集合的元素（元素可以被多次读取，与只消费一次冲突），元组可以。

在“一个流只消费一次”条末尾**新增**：

> 判据是图上的：每个流值（`var` 的每个版本各算一个，`tee` 的结果各算一个，互斥的臂合计一次）数据出度至多为 1。在循环体里消费一个循环外定义的流是错误，要逐轮消费就把流作为循环状态，或用 `for x in s`。第二次使用时诊断同时指出两处，并给出 `tee` 的写法。`tee(s, n)` 的 `n` 默认 8，`n < 1` 是编译期诊断，过大静默夹取到实现上限。

把“生成器”条替换为：

> - **生成器**：函数体里写 `yield` 的函数产生一个流，它的返回类型必须在函数头部写成流类型（`func pairs(n: int): (int, int).. { … yield (i, j) … }`）；简单的生成器可以用库函数 `unfold(初始状态, 步进函数)`。一轮可以 `yield` 多次，恢复点就是 `yield` 所在的位置，任意层嵌套，`match` 的臂里和 `sync` 块里可以；`yield` 之后的语句等消费者再拉时才执行，块里效应的先后照 3.4；故障发生在产生那个元素的那次拉取处；产出的流是线性的，生成器函数可以多次调用，每次得到一个流；不做委托（写 `for x in inner do yield x`）；`return` 结束流、不带值，空流合法；要交出错误元素写 `yield error(...)` 然后 `return`。生成器在图上是一个步进函数：被调用时只求实参并交出 `(step, s0)`，函数体一句都不执行；`step(s): (T, S)?` 从 `s` 记录的恢复点接着跑，跑到下一个 `yield e` 时交出 `(e, s')`，`return` 或跑完时交出 `null`；状态 `S` 是含恢复点编号、所有活过某个 `yield` 的局部变量、以及每个含 `yield` 的循环的状态的结构体，只用 `BRCH`、`LOOP` 和结构体。

> ### 10.7 宿主边界
>
> - 宿主（如 Python）调用 Camel 的泛型 `export func` 时，按宿主传来的实参类型实例化并缓存实例；只出现在返回类型里的类型变量才需要宿主显式给出。数组按元素类型传入，不转换（也保住零拷贝）；宿主的标量（Python 的 `int`、`float`）按字面量处理：进入形参时取形参类型，放不下报错。错误值统一成 `FaultError` 加种类名，不把错误里的字符串提升成宿主的类名。执行 Camel 期间释放 GIL，Camel 回调 Python 时再取得。

### B46、B47（§1 在“内测阶段不考虑兼容成本”条之后新增）

> - **不留过渡，也不记录已经删掉的东西。** 过渡只存在于分支上，合入主线时已经删干净；文档按目标语言写，不标注“目标”“尚未实现”；诊断、注释、文档不写任务编号、裁定日期或指向裁定记录的引用，面向用户的诊断可以引用设计原则或语言参考的小节；编译器里没有“等以后”的拒绝——要么实现，要么变成普通的语法错误，要么换成说出语言规则本身的具名诊断。
