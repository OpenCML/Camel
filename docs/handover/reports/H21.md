## H21-3 对第一个参数求导（丁车道）

### 1. 新规则

- `grad(f)` / `with_grad(f)` 对 `f` 的**第一个普通参数**求导（设计原则 9.9，与 JAX
  相同）。其余普通参数是数据，不扰动；`f` 的 `with` 参数是配置，永远不求导。
- 梯度与第一个普通参数同型：`float -> float`、`Tensor -> Tensor`、结构体/元组 -> 同构的
  结构体/元组（逐成员映射，去掉没有切空间的成员）；`int`、`bool`、`string`、函数值没有
  切空间。
- `with_grad(f)` 返回 `(值, 梯度)`，梯度形状同上，不再是“每个参数一个梯度”的元组。
- 梯度函数保留 `f` 的全部 `with` 参数和普通参数（以及各参数的 `var` 标记），因此
  `grad(f)<cfg>(...)` 仍然可用：`<cfg>` 只是把配置传给梯度函数，不参与求导。尖括号只用于
  配置（4.4）。
- 微分形式**不**给任何参数加 `var`：被求导的第一个普通参数必须非 `var`；其余 `var` 参数
  保持 `var`，函数的写入仍到达调用者的变量（`var_through_with_grad` 等测试）。

### 2. 实现

- `modules/autodiff/pullback.h`：`GradientSignature` 去掉 `withPorts`/`normPorts`，只剩
  `gradientType` 与 `functionType`；新增
  `std::string differentiationRefusal(type::FunctionType *)`。
- `modules/autodiff/pullback.cpp`：`differentiationRefusal` 依次检查：
  1. 返回类型不是 `float`/`f32` → “it returns X, not a float”；
  2. 没有普通参数 → “it has no normal parameter, and grad differentiates the first normal
     parameter”；
  3. 第一个普通参数是 `var` → “its first normal parameter is a `var` of type X; gradients do
     not flow through variables (design principles 3.5)”；
  4. `tangentTypeOf(第一个普通参数) == nullptr` → “its first normal parameter has type X, which
     has no gradient (a float, a tensor, or a struct or tuple of them)”。

  `gradientSignature` 在 `differentiationRefusal` 非空时返回 `nullopt`，否则
  `gradientType = tangentTypeOf(normTypeAt(0))`，并按原样复制全部 with/norm 参数。
  `Engine::gradient` 只收集 `backward.gradient(draft->normPorts().front())`，不再拼元组。
- `modules/autodiff/operators.cpp`：类型解析器的拒绝信息复用同一段 `differentiationRefusal`，
  `signature()` 的说明改为 “gradient of N0”。`grad` 的类型仍是
  `<W...>(N...) => 梯度`，`with_grad` 是 `<W...>(N...) => (float, 梯度)`。
- `modules/autodiff/operators.h`：文件头注释改为“求导第一个普通参数”。

实现是编译期的：`std::macro` 展开与不展开（运行时构造梯度图）走同一套签名检查。拒绝发生在
`grad(f)` 的签名解析（`SemanticDiag::ArgumentsRejected`，指向 `grad` 的实参）；若绕过类型
解析直接调用引擎，则得到同一段文字的 `RuntimeDiag::RuntimeError`。

### 3. 边界情况

| 第一个普通参数 / 函数 | 结果 |
| --- | --- |
| `float` / `f32` | 标量梯度 |
| `Tensor` | 同形状张量 |
| 结构体/元组（有可微成员） | 同构结构体/元组；不可微成员被去掉 |
| 结构体/元组（无可微成员） | 拒绝（`tangentTypeOf` 为空） |
| `int` / `bool` / `string` | 拒绝，说明“has no gradient” |
| 函数值 | 拒绝，说明“has no gradient” |
| `var`（任意类型） | 拒绝，说明 3.5 |
| 函数没有普通参数 | 拒绝，说明“no normal parameter” |
| 返回类型不是 float | 拒绝，说明实际返回类型 |
| 只有 `with` 参数的旧式模型函数 | 拒绝：没有普通参数（旧写法不再是指定求导对象的方式） |

`with` 参数里有 `var` 时按参数原样保留；它不参与求导。

### 4. 旧写法现在是什么

没有兼容层。旧的

```camel
with <m: Mlp>
func loss(x: Tensor): float { ... }
with_grad(loss)<m>(x)
```

现在仍然能编译，但含义已变：`<m>` 只是给 `loss` 的配置，求导对象是 `loss` 的第一个普通
参数 `x`，得到的是 `x` 形状的梯度。**旧写法不会“继续对 m 求导”**；仓库里的测试、示例、
exemplar、showcase 和 nn/onnx/tiles 用例已经全部改成新写法：

```camel
func loss(m: Mlp, x: Tensor): float { ... }
with_grad(loss)(m, x)          // (loss, m 形状的梯度)
```

## H25 撤回 H21-3：对第一个 `with` 参数求导

### 1. 规则

- `grad(f)` / `with_grad(f)` 对 `f` 的**第一个 `with` 参数**求导（设计原则 9.9）。其余
  `with` 参数是常量；普通参数是数据（4.4），既不求导也不是配置。`grad(f)<w>(x, y)` 因此
  仍然可用：`<w>` 选定被求导的值，`(x, y)` 原样传给 `f`。
- 推荐写法是把变换绑定一次：循环外 `let loss_with_grad = with_grad(loss)`，循环内
  `let (l, g) = loss_with_grad<m>(x, y)`。直接 `grad(loss)<m>(x, y)` 同样可用。
- 以下情况在编译期拒绝，统一报 `SemanticDiag::NotDifferentiable`（0x000150），消息
  `The function cannot be differentiated: {0}.`，位置在 `grad`/`with_grad` 调用处，help
  指向 9.9：
  1. 返回类型不是 `float`/`f32`；
  2. 函数没有 `with` 参数（`grad` 不退回普通参数）；
  3. 第一个 `with` 参数没有已知类型；
  4. 第一个 `with` 参数是 `var`（3.5：梯度不流过变量）；
  5. `tangentTypeOf` 为 null：`int`、`bool`、`string`、函数值、没有可微成员的结构体/元组。
- 运行时 `Engine::gradient` 不再重复检查：`ASSERT(signature.has_value())`；发布构建
  （`NDEBUG`）保留一个返回拒绝的兜底，绝不静默给错梯度或崩溃。
- `value_and_grad` 改名为 **`with_grad`**。旧名**删除**：没有别名，也没有“已改名，请用 X”
  的迁移诊断；它就是一个普通的未知名字（`UnresolvedReference`）。
