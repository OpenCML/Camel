# A/B 之前先证明“改的是被读的那一份”

日期：2026-10-31　车道：`lane-recheck`

这一页记一次**假绿**，以及从那一次里长出来的、可以直接执行的规矩。它比被验的那笔代码值钱：
那笔代码已经对了，而假绿的方法下一次还会骗人。

## 假绿发生了什么

第 1 笔（`294c95d73`，前向规则只记“键”、名字从规则集索引读）要做的 A/B 是：**把
`rulesets.jvp` 里某条规则删掉，看读数是否在“那个原语”处变得说不出名字。** 我做了两次，两次读数
都没变，我差点当成“索引被用上了”。

第一次：**改了源树的 `stdlib/`，但二进制读的是 `out/latest/stdlib/`。** 改的对象不是被使用的那个
对象——今晚这类“改没改到”已经第五次。

第二次：`grep -v '^rule jvp_neg'` **一条都没删掉**，因为声明写的是 `export rule jvp_neg`：匹配串
不对，删了零条，读数当然不变。

第三次才做成：先往两份里各塞一个语法错，看哪一份让运行报错——于是知道读的是 `out/latest`；再按整块
（文档注释 + 声明 + 函数体 + 收尾 `}`）删除，并**在脚本里断言 `'jvp_neg' not in text`**。真读数：

```
删掉 jvp_neg 整块（二进制加载的那份）：
RULESET rulesets.jvp -/1            ← 这行没了
FORWARD :op/neg_d rulesets.jvp -/1 -> no rule
FORWARD :op/neg_f rulesets.jvp -/1 -> no rule
还原：
FORWARD :op/neg_d rulesets.jvp -/1 -> jvp_neg
```

## 规矩（两句话，都跑得起来）

1. **A/B 之前先证明“改的是被读的那一份”：往两份里各塞一个语法错，看哪一份让构建或运行报错。**
   这条定位法比 A/B 本身值钱：它把“我以为我改了”变成“我看到它报了”。
2. **删除之后要断言删掉了。** `grep -v` 一条没匹配上是**静默成功**，读数不变量恰好等于“什么都没删”：
   脚本里必须有一行 `assert '被删的东西' not in 文本`，否则这次 A/B 什么也没证明。

同一类错误在读数上的样子是**读数完全不变**。真 A/B 的红必须有一处可见变化（一行消失、一个词变成
`no rule`），看不见变化就不是绿，是没验。

## 反方向的那一类：读数全红，红的不是代码

同一天晚些时候，同一个毛病从另一头来了一次：一份计划**十一个用例齐红**，`stdout` 全空、退出码 1，
看着像我把索引改坏了。实际是**直接 ssh 跑 `node scripts/test.js` 时缺 libstdc++ 覆盖**（
`camel-remote.ps1` 的 `-LibStdCxxDir` 才把它放到 `LD_LIBRARY_PATH` 首位），补上那个路径，11/11 全绿。

所以第三条规矩，与第一条互补：

3. **读数全红时，先证明红的不是环境。** 一次一个用例红，可能是代码；一次全部用例红、而且 `stdout`
   一个字符都没有，先怀疑“二进制在这个环境里起不来”，再怀疑代码。

“改的不是被读的那一份”与“红的不是代码”是同一类错的两个方向：**都在读一个不是被验对象的读数**。
