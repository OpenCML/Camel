## 结论：不是槽放反，是这类 JOIN 不做值选取

一个语句形分支的 JOIN 是**没有值**的合并点：它的 `WITH` 输入是"每条臂的区域给什么"，
运行时按 `BRCH` 选臂是为了决定**控制**走哪条，不是选一个值。把一个 `int` 塞进它的 WITH 槽，
不会让它变成"按条件选值"——它照样按 void 语义走，数据槽里留下的是构造时写进去的那个
（也就是我放的 `7` 那一槽）。所以：

- **槽位用下标还是用类型，都救不了**——问题不在挑哪一格；
- 正确的形状是**另建一个值合并点**，也就是"一个带值的 `if` 会建的那种"：自己的 JOIN +
  每条臂一条 GATE，由 `BRCH` 选出那条臂的值。这正是 `x = if c then 1 else x` 在 Cameron
  里本来的样子，而它**不是**把现有那个语句合并点改造一下就能得到的。
