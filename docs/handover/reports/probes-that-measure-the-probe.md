# 量错方向比不量更贵：两个探针陷阱

**这是给下一个要量"模块级行为"的人的纪律，不是任务。今晚它为这一条付了两次代价。**

## 陷阱一：`CAMEL_STD_LIB` 指向 stdlib 副本，副本本身是坏的

把 `stdlib/` 拷到别处、用 `CAMEL_STD_LIB` 指过去，然后改副本里的模块来量它的行为——**这条路不成立**：

- **一字未改的副本**（只做 `cp -r`，一个字节都没动），只要程序 `import` 了任何 stdlib 模块，就报
  `SemanticDiag::ImportedModuleHasErrors: Cannot import module 'graph': it has errors (…/graph.cml)`，
  锚点固定落在 `autodiff.cml:91:1`（那里是第一条 `export rule add_jvp`）。
- 于是"加一行标签"、"加一个函数"、"只加一行注释"、"删掉那行标签"、"什么都不改"——**五种改动的读数完全一样**。
  2026-10-31 就是靠"什么都不改也报同样的错"这一次对照才发现的。

**能干什么**：副本只能用来跑**不导入任何模块**的程序（`func main()` 里只有字面量的那种）。
**不能干什么**：任何要观察模块级行为（标签、规则、导入、诊断归属）的量法。

## 陷阱二（同一晚的更早一次）：把失败当成"目标不可行"

上面的读数一度被读成"跨模块挂标签今天不可行"，还写进了问题页。**它量的是探针，不是语言**，
后来靠"一字未改的副本也失败"撤回。代价是：一条本来不存在的结论被写进文档、又撤回来。

## 纪律

> **要量模块级行为，只能在工作树里改、构建一次、量完改回去。**
> 副本 + `CAMEL_STD_LIB` 只能跑不导入模块的程序。
> 每次量之前先取一次**对照读数**（同样的程序、未改的树）；**对照和实验读数一样，就先怀疑探针。**

**"早量比晚量便宜"只在量对了方向时成立；量错方向比不量更贵**——这一条今晚付了两次。
