## 任务与实现

任务：784 → 128 → 10 的全连接网络，ReLU、Adam（lr 0.001）、softmax 交叉熵，batch 100，
训练若干步后在 2000 行验证集上报告损失与准确率，保存并读回检查点。

- **Camel**：模型是一个 `type Mlp = { w1, b1, w2, b2: Tensor }`；`with <m: Mlp>` 的 `logits`
  与 `loss` 让 `value_and_grad(loss)<m>(x, y)` 直接给出同形状的梯度树，`adam(m, g, state,
  lr)` 消费这棵树；训练是 `loop m = model, opt = adam_state(model), step = 0`，循环体在
  `sync` 里；`save_tree`/`load_tree` 保存并核对参数树与数据身份，`tree_map` + `tree_reduce`
  算读回漂移。没有按名字数叶子，没有优化器对象。
- **PyTorch**：`nn.Linear` 两层、`F.cross_entropy`、`torch.optim.Adam`、`for` 循环 +
  `zero_grad/backward/step`、`no_grad` 评估、`state_dict` 检查点。按社区惯用写法，没有为了
  让 Camel 好看而写差（例如保留了 `nn.Module` 的层次、逐层 `copy_` 载入同一份初始权重）。

两边读同一份 `.npy` 数据与初始权重、同样的超参数、都设为单线程（`set_num_threads(1)` /
`torch.set_num_threads(1)`），因此差异只来自实现。

## 度量方式（脚本如何产出数字）

`compare.py` 是唯一产出数字的地方，`RESULTS.md` 由它生成，README 不手工抄数字。

1. **准备**：调用 `make_data.py` 写数据与初始权重（`--reuse-data` 可跳过）；删除上次的
   `checkpoint/` 与 `checkpoint-torch.pt`。
2. **编译时间**：`camel train.cml --arg ... std::macro std::stats std::null` 跑三次取中位数。
   这条流水线完成解析、类型检查、宏展开与建图，不执行程序；`std::stats` 顺带给出图规模
   （本次：18 个图、300 个节点、397 条边、95 个算子、1 个循环）。PyTorch 是 eager，无此项。
3. **训练与度量**：分别启动两个进程，循环体内部各自用 `now()` / `time.perf_counter()` 计时，
   只包住训练循环（数据加载、评估、检查点都不计），所以两边的秒数口径相同。进程的峰值工作集
   由 psutil 每 20 ms 采样一次进程树（Windows 上 venv 的 `python.exe` 是启动器，真正的解释器
   是子进程；只测启动器会得到 4 MB 的假数字）。吞吐 = `steps × batch / 秒`。整进程墙钟时间
   另列，含启动与读数据（PyTorch 一侧主要是 `import torch`），不用于吞吐比较。
4. **代码行数**：两个文件用同一套 `// == section ==` / `# == section ==` 标记分段，脚本统计
   每段的 SLOC（空行、整行注释、Python docstring、C 块注释不计；带行尾注释的代码行计一次），
   并给出总物理行。这是一个写明的启发式，不是解析器。
5. **比较**：解析两边共同的机器可读行（`c2 config/init/step/trained/checkpoint`），断言配置
   一致、记录步一致，然后比较初始损失、每个记录步的训练损失（取相对差最大的一步）、最终验证
   损失、最终验证准确率，以及两边各自的检查点往返漂移；任何一项超界则退出码为 1，`RESULTS.md`
   仍会写出并标 FAIL。
6. **环境记录**：机器、操作系统、Camel 版本（同一二进制 `--version`）、PyTorch/Python/NumPy
   版本、日期、完整命令行、数据来源与 `dataset.id` 都写进 `RESULTS.md` 的首部。

## 与 PyTorch 的对照结论

- **数值**：同一份权重、同一份数据下，初始损失差 4.6e-08；训练 1000 步后最终验证损失差
  4.8e-04（相对 2.8e-03）、准确率差 0.05 个百分点；训练曲线最坏一步相对差 5.5e-03，为
  容差的 0.55 倍。差异随步数增长（第 0 步 ~1e-8，第 700 步 ~5e-3），与“矩阵乘累加顺序不同、
  Adam 逐步复合”的解释一致，没有出现跳变或发散。检查点各自原样读回。
- **性能**：这份实现单线程下 Camel 的吞吐是 PyTorch 的 0.83 倍（空载时 0.79 倍，即慢
  17–21%），峰值内存是 0.35 倍（111 MB 级 vs 316 MB 级，含运行时与权重），编译约 0.07 s。
  **没有达到计划里“齐平或更好”的目标**；这是示例当前暴露的真实结果，没有为此调整口径或隐藏。
  MLP 的两个矩阵乘是主要开销，说明张量内核/调度还有优化空间（本任务范围内不改核心）。
- **写法**：Camel 短的段是检查点、评估、初始化，长的是 imports 与 data（类型标注、逐文件
  `load_npy`）；PyTorch 短的段是 model 与 loss（`nn.Linear` 藏起偏置与形状）。总 SLOC
  80 vs 94，但行数只能说明一部分：Camel 把“参数、梯度、优化器状态同型”这件事表达成了一个
  类型，PyTorch 用三套对象表达同一事实；代价是循环体必须写 `sync`，日志/副作用的显式性对
  训练循环是噪声。

### C1：线性回归与逻辑回归

任务：二维输入上的两个小模型——线性回归（MSE）与二分类逻辑回归（稳定 BCE）——用 SGD 训练，
同一份数据、同一套打印协议。Camel 的模型是 `type Model = { w, b: Tensor }`，损失按
`kind` 选 MSE 或 `relu(z) - z*y + log(exp(-abs(z)) + 1.0)`；训练循环是
`loop m, step`，每步 `let (value, gradient) = value_and_grad(loss)<m>(x, y, kind)`，再用
`sgd(m, gradient, lr)`。PyTorch 用 `nn.Linear(2,1)` 与 `F.mse_loss` /
`F.binary_cross_entropy_with_logits`，逐行对应。

standard（1000 步，batch 128，lr：线性 0.1、逻辑 0.05）：

| 指标 | 线性 | 逻辑 |
|---|---|---|
| 初始损失相对差 | 5.8e-8 | 0 |
| 记录步最坏相对差 | 1.1e-6 | 1.151e-2（第 100 步） |
| 最终验证损失相对差 | 3.4e-7 | 6.5e-4 |
| 最终指标 | MAE 0.043818284 vs 0.043818295 | 准确率 0.9921875 vs 0.9921875 |
| 吞吐（样本/s，Camel / PyTorch） | 5.93M / 269k | 3.89M / 249k |
| 峰值内存（MiB） | 8.0 / 273 | 11.0 / 274 |
| 编译（s） | 0.034 | 0.034 |

逻辑回归的记录步差最大 1.151e-2，是 200 步内 lr 0.05 的复合误差在 logistic 饱和区被放大，
容差因此写 2e-2 相对（README 给了推导与“不是为通过而放宽”的说明：先按第 7 节定 1e-2，实测
发现饱和区超界后改成 2e-2，并保留最坏一步的数字；线性仍是 1e-2）。小模型吞吐是 PyTorch 的

README 明确说这不是内核速度结论，不能外推到 C2。

### C6：二维 VAE

### D5：递归 Tree-LSTM

任务：四叶句法树的情感分类，`type Tree = enum { Leaf(Tensor), Node(Tree, Tree) }`，
`forward` 在 `enum` 上递归，五个门的手写公式，根隐状态过线性层。标签是**左子树与右子树的
极性异或**，所以词袋模型做不对，必须按树组合。Camel 的递归调用是
`forward<p>(left)`/`forward<p>(right)`，`value_and_grad(loss)<p>(tree, target)` 对整个参数树
求导——这是 D5 要验证的核心，没有阻塞。每步一句（树是变长的，批处理要 H20-2 的 `take` 或
H21-1 的按索引切片）；词向量用 one-hot 乘嵌入表，没有按行取词。

|---|---|---|---|
| 初始验证准确率 | 0.609375 | 0.609375 | 0 |
| 记录步最坏损失（第 800 步） | 0.000076483 | 0.000076529 | 6.0e-4 相对 |
| 最终验证准确率 | 1.0 | 1.0 | 0 |
| 训练时间（s） | 0.264 | 2.759 | — |
| 峰值内存（MiB） | 19.5 | 274.6 | — |
| 编译（s） | 0.032 | eager | — |

0.096 的时间比同样是小模型 + Python 递归开销的结论，README 与 `RESULTS.md` 写明。三处
Camel 写法都按检查意见标注了将来的形态：H21-3 的 `value_and_grad(loss)(params, ...)` 落地前
保留 `with <p: Params>`；H20-2/H21-1 落地后再补批处理。

### D4：AlphaZero 简化版——未实现（阻塞）

D4 要求 MCTS + 策略-价值网络，用 `enum` 树、回溯、交互-更新循环。当前语言写不出**不绕行**的
MCTS 更新循环，原因不是某一处语法，而是三处叠加（Q6、Q7）：

1. **没有可变元素写回**：数组/记录是值语义，`a[i] = v` 被诊断为
   `AssignmentTargetNotVariable`；`var` 只能整体重绑。MCTS 每次模拟都要更新路径上每个节点的
   `visits`/`value`，只能把整棵 arena 用 `loop`/`apply` 重建一遍。能在“示例”里写，但它是
   明确的绕行，且会把回溯写成 O(节点数 × 模拟数) 的复制——按检查意见“不要 workaround，
   写目标的写法”，这里应当等语言裁定。
2. **递归结构的字段受限**：`type Node = { children: Node[] }` 不可递归；`enum` 递归可以，
   但 `[] as Node[]` 对递归类型静态转换失败，空子节点数组没有直接写法。MCTS 节点的子表
   是天然的递归容器，这条限制让 arena 只能靠“父存 first/count 索引”绕开。
3. **没有运行期数组 → 张量的构造**：`reshape` 只接字面量，`from_bytes` 要 `Bytes`，没有
   `tensor(values: f32[])`。棋面可以在循环里用 one-hot 基向量累加成张量，但自对弈样本
   （棋面 + 访问分布）无法从运行期数组变成张量，也就无法实现“对局结束→用结果更新网络”的
   交互-更新循环；只能把样本落盘再读回，或改成每步在线蒸馏，两者都不是 D4 的目标形态。

**问题（Q6）**：是否给局部数组/记录一个受控的可变写回（例如 `set(a, i, v)` 返回值语义的
新数组，或 `var` 字段赋值），并允许递归 `struct` 的 `children: Node[]`（含空数组字面量）？
**问题（Q7）**：是否提供 `tensor(values: f32[])`（或 `Tensor::of`）？没有它，任何在语言内
生成训练样本的强化学习示例都写不出来，D4 只能等这两个能力。

D4 没有留下半成品目录；等 Q6/Q7 有结论后按目标形态补。C1、C6、D5 不依赖这两项，已经完成。

## 设计上的选择

- **参数树即模型类型**：`Mlp` 同时是初始值、梯度、优化器状态的类型，`value_and_grad` 与
  `adam` 都按树工作，程序里不出现叶子名字的枚举。这是 C2 要展示的语言能力，不是为短而短：
  加上一层 `Mlp` 辅助函数会重复类型信息。
- **初始权重由数据脚本生成，两边从文件载入**，而不是各自 `randn`。两边的随机数发生器不同，
  要让“同一任务、同一起点”成立，只能共享初始值；文件是唯一中立的载体。代价是 Camel 端少了
  “语言内初始化”的展示，README 写明了这一点。另一种做法是 Camel 用 `randn` 生成、存成 npy
  给 PyTorch 读，但那样 PyTorch 的初始值依赖 Camel 的 RNG，比较不再对称；没有采用。
- **数据只打乱一次，训练取连续切片**：因为张量没有按行收集/重排的算子（见问题 2），
  “每个 epoch 重新打乱”在语言里写不出来。数据脚本用固定种子打乱一次，训练循环取连续小批；
  这让比较可复现，也把缺口暴露在 README 里，而不是假装数据管线已经完整。
- **合成替身**：每类固定的一组亮矩形（粗笔画）+ 整体平移几个像素 + 高斯噪声，固定种子；
  不追求像 MNIST，只要求可复现、有可学的信号、两边读同一份。CI 固定用它，所以小规模结果
  跨机器一致；standard 配置优先用真实 MNIST，`manifest.json` 记录实际来源，`RESULTS.md`
  的首部把它写出来。没有网络下载。
- **one-hot 与类别下标都写**：`nn.softmax_cross_entropy` 要 one-hot，`F.cross_entropy` 要
  下标；为了同一份数据两边都能用，数据目录同时有两份（标签数据约为只用下标的 6 倍，其中
  one-hot 本身是下标的 5 倍）。这是问题 3 的绕行，README 里写明了。
- **比较口径**：只比较训练循环内部的时间；峰值内存取进程树（含解释器/运行时）；编译时间取
  三次的中位数（首次冷启动 0.1–0.29 s 不进入中位数，但仍在样本里）；吞吐用
  `steps × batch / 训练秒数`。容差与依据见 README 和 `RESULTS.md`：初始 1e-5 相对、记录步
  1e-2 相对、最终损失 1e-2 相对、准确率 1e-2 绝对，恰好覆盖“同一公式、不同累加顺序、1000 步
  复合”的误差（实测最坏一步为容差的 0.55 倍），又能在小规模配置上留出三个数量级的余量
  （实际 4e-6）。
- **代码行数用共享的分段标记**：两个文件都写 `== imports ==`、`== model ==` 等注释段，
  `compare.py` 按段统计 SLOC 并给出并排表；段标记同时起导航作用。SLOC 是启发式（说明写在
  `RESULTS.md`），注释与空行不计，避免文风影响数字；它仍比“物理行数”更接近可读性，但只
  说明一部分问题。
- **测试放 `slow` 层**：H10 的分层已经落地，四个示例的计划都写 `tier = "slow"`；默认
  `npm run test` 跳过，`--tier all` 才跑。小规模配置都控制在 13 s 以内，整批串行 26 s，
  没有把“几分钟”的配置塞进快速层。
- **`RESULTS.md` 入库、`artifacts/` 不入库**：结果表是审阅对象（几十行文本），数据与检查点
  是生成物（本次 37 MB）。`.gitignore` 只忽略生成物。

## 遇到的问题

写作过程中真正别扭的地方，按第 4 节格式提问。详细版在示例 README 中，这里给出结论性问题。

### Q1：`save_tree` 应当拒绝覆盖还是整体替换？Camel 需要删除目录的能力吗？

例子：

```camel
save_tree(dir, model, dataset_id)   // 第一次运行：成功
save_tree(dir, model, dataset_id)   // 第二次运行：
// [RuntimeDiag::FileSystemError]: 'tree.save_tree' failed for '.../checkpoint': checkpoint already exists
```

`stdlib/signatures/tree.cml` 的注释说“The directory is replaced as a whole or not at all”，
`modules/tree/src/checkpoint_io.cpp` 的实现是原子发布且**不覆盖**。`fs` 有 `exists`、
`mkdir`、覆盖写文件的 `replace`，但没有删除。于是纯 Camel 的训练程序第二次运行一定失败，
只能靠外部脚本删目录（`compare.py` 就是这么做的）。

建议：先让注释与实现一致。若保留“拒绝覆盖”，给 `save_tree` 一个 `replace` 变体（对齐
`fs.replace`）或给 `fs` 补删除操作；若按注释“整体替换”，失败时保留旧目录。倾向后者，因为
训练脚本重复运行是常态，而“整体替换”本来就是注释承诺的语义。

影响：所有训练类示例（C1、C6、C4、I1……）都会遇到；没有它，示例的“重跑”必须依赖外部清理，
与“程序自己就是展示品”的目标冲突。

**检查意见**：H20-4 采用“整体替换 + `fs` 删除”，落地前示例仍从 Python 删目录；C2 README
与本节都标注了这一点。

### Q2：张量是否要加按索引取行（gather/take）？训练数据管线怎么打乱？

例子：

```camel
let order = ...            // 想每 epoch 打乱：没有 shuffle
let x = train_x[order]     // t[i] 取的是单个 float；没有按索引数组取行
let batch = slice(train_x, 0, start, start + batch)   // 只有连续切片
```

现在只能让 `make_data.py` 预先打乱一次，训练循环取连续切片。batch sampler、sequence
packing、数据增强、按长度分桶都写不出来。

建议：加 `gather(t, axis, indices)`（或 `take`），作为普通算子声明纯度/语义并在所有后端实现，
ONNX 有直接对应。它是数据管线的地基，越早越好。

影响：本示例只能“数据脚本预打乱”；README 已写明。第一批其余示例里 C6（VAE）也会需要按
索引取批。

**检查意见**：H20-2 加 `take`，H21-1 加下标/切片；落地后 C2 用 `take` 打乱，D5 用按索引
切片拼批。

### Q3：`nn.softmax_cross_entropy` 是否接受类别下标，或提供 `one_hot`？

例子：

```camel
softmax_cross_entropy(logits, targets)   // targets 必须是 (N, 10) one-hot
```

MNIST 的原生标注是 `(N,)` 整数。为了同一份数据两边都能用，`make_data.py` 同时写 one-hot 与
下标；Camel 里从下标造 one-hot 要逐行 `range(0, 10) == label` 再 `reshape`/`concat`（旧
`test/cases/modules/nn/mnist.cml` 的写法），又长又慢。

建议：让交叉熵接受 `(N,)` 的整数目标（像 `F.cross_entropy`），或提供 `one_hot(labels, classes)`
算子；前者更贴近数据管线，后者更通用。若 `nn` 有意只做 one-hot，请在签名注释里写明，并由
数据管线负责转换。

影响：当前多写一份约 6 倍于下标的标签文件（one-hot 本身是下标的 5 倍）；任何用原生标注的
示例都要绕行。

**检查意见**：H20-2 同时加 `take`、`one_hot` 与接受类别下标的交叉熵；落地后 C2 改为读整数
标签，C6/D5 也少一份 one-hot。

### Q4：循环里的“收集”应当怎么表达（损失曲线）？

例子：

```camel
let (trained, state) = loop m = model, opt = adam_state(model), step = 0
    while step < steps do sync { ... return (next.0, next.1, step + 1) }
```

循环只返回最终状态。想把每个记录步的损失带出来，要么把 `float[]` 加进状态元组并在循环里
追加，要么在循环体里 `println`、由外部解析（本示例选了后者，`compare.py` 解析 stdout）。

建议：明确这是预期用法（日志是副作用，曲线由外部工具读）；若希望语言内收集，需要
`scan`/`collect` 一类的一等写法，属于语义改动，应先定设计再实现。

影响：训练类示例的“训练曲线”目前靠 stdout；如果协调者认为示例应当返回历史而不是打印，
需要先给写法。

### Q5：小规模配置原先放哪一层（H10 落地前）？

例子：`test/plans` 的 `tier` 现在有 `smoke`、`feat`、`slow`、`gpu` 等；本计划原先用
`tier = "benchmark"` + `tags = ["slow", ...]`。

结论：H10 的 fast/slow 分层已经落地，四个计划都已改成 `tier = "slow"`；默认 `npm run test`
跳过，`--tier all` 跑。这是流程问题，已解决，不再是待决项。

### Q6：MCTS 需要的可变节点统计怎么写？

例子：

```camel
nodes[i].visits = nodes[i].visits + 1   // AssignmentTargetNotVariable
type Node = { children: Node[] }         // 递归 struct 不允许
```

MCTS 每次模拟都要回填路径上的访问数与价值。值语义数组 + `var` 整体重绑可以做到，但要把
arena 整个复制一遍，属于绕行；检查意见要求写目标写法，不要 workaround。`enum` 递归可以，
但 `[] as Node[]` 对递归类型会静态转换失败，空子数组没有字面量。

建议：给局部数组/记录一个受控的写回形式（`set` 返回值语义，或允许 `var` 字段赋值），并允许
递归 `struct` 的 `children: Node[]` 与空数组字面量。影响：没有它，D4 的 MCTS 只能写成
O(节点数) 复制的形式，示例失去示范价值。

### Q7：运行期数组怎么变成张量？

例子：

```camel
let board = Tensor::of(values)   // 不存在；reshape 只接字面量，from_bytes 要 Bytes
```

棋面可以在循环里用 one-hot 基向量累加成张量，但自对弈样本（棋面 + 访问分布）是从运行期数组
产生的；没有 `tensor(values: f32[])`，就只能落盘再读回，或放弃“对局结束→用结果更新网络”的
交互-更新循环。影响：D4 的目标形态写不出来；这也是所有语言内生成训练样本的强化学习示例的
共同前提。
