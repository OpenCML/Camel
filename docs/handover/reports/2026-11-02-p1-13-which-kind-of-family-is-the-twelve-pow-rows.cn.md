# `__pow__` 那 12 行是哪一种

## 答：(a)，而且比 (a) 更强——它不是"一个签名 × N 个类型"，是 **12 个不同的签名**

先答你的四选一：

| 选项 | 是否符合 | 依据 |
|---|---|---|
| (b) 有通配、一处活一处死 | **不是** | `git grep "\\*pow\|pow_\\*" stdlib/prelude.cml` **无命中**：12 条声明各写各的 URI，没有任何 `#op(':op/pow_*')` |
| (c) 重复声明 | **不是** | 每条 URI 在 `prelude.cml` 各出现一次；注册表里也各一条（`globals.cpp:1914–1980`） |
| (a) 每类型一条 kernel + 一条规则、无通配 | **是** | 12 条 `#op(':op/pow_*')`、注册表 12 条规则 |
| (d) 其它 | **也是**：见下 | 这 12 条**签名互不相同**，不是同一签名的 N 个类型 |

**"更强"在这里**：`from_bytes_*` 是**同一个签名**（`(bytes, shape) => T[..]`）配 8 个 TypeCode，合并只差一个"读类型实参"的机制；`__pow__` 的 12 条是**12 个不同的签名**：

```
pow_i   (int, int) => int          pow_f    (f32, f32) => f32
pow_l   (int, int) => int          pow_d    (f64, f64) => f64
pow_f6  (f16, f16) => f16          pow_bf   (bf16, bf16) => bf16
pow_c   (c64, c64) => c64          pow_z    (c128, c128) => c128
pow_c_i (c64, int) => c64          pow_c_l  (c64, int) => c64
pow_z_i (c128, int) => c128        pow_z_l  (c128, int) => c128
```

**"复数底数、整数指数"这四条与"同类型底数与指数"那八条不是一类**：它们的**结果类型规则不同**（一个按底数取复型，一个要求两侧同型）。所以这里没有"一个泛型算子 + 按类型选 kernel"可做——**合并它们不是类型问题，是语义问题**：`c64 ^ int` 与 `c64 ^ c64` 是两条不同的运算。

## 处置：不合并，记为整洁债（与 `from_bytes_*` 同一处置，但理由不同）

- **不是缺陷**：`^` 的符号在语言里有（`operator_names.cpp` 的 `kForms`：`{"^", 2, 2, "__pow__"}`），打印器按所有权规则印 `^`，不印组名；
- **不是通配**：一条通配都没有，作者 00:10 那个病在这里不存在；
- **不能合并**：12 条签名两两不同（见上表），"合并"会造出一个需要按两个位置同时分派的重载解析问题。

**所以处置与 `from_bytes_*` 相同——不合并、写进页、不进缺陷表**，区别只在理由：那边是"缺一个读类型实参的机制"，这边是"**根本没有同一个签名可以合**"。

## 下一个人会问的那句话

> "`*tos` 能合，为什么 `pow` 不能？"

因为 `*tos` 的 8 条**签名相同**（`(T) => string`），只差 kernel；`pow` 的 12 条**签名不同**（上表），差的是语义。**合并的前提是"同一个签名、多个实现"，不是"同一族名字、多个 URI"。**

## 语义用例（没跑，说明原因）

`^` 的语义用例（不同指数、负数、零、整数指数）**本轮没有手工跑**——因为**这一轮没有改任何代码**，只做了分类。若下一步要动 `^`（例如给它补声明或改 kernel），那份输出是必需的，不能拿"能跑完"当"数值对"。
