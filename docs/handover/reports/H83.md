# H83：H21 第 1 项前半——下标与切片的语法与类型

**任务**：H21 第 1 项的**前半**——下标与切片的语法、类型检查与下界（lowering）；运行时的
多维视图属于 H17 的数组表示，不在本轮。分支 `handover/H83-subscript`（自 `origin/develop` 的
`ee325146`），只动解析、AST/GCT 建图、`__idx__`/新 `__slice__` 算子组、张量模块的对应算子、
格式化器与语言参考；不改语义，越界与负数的规则按设计原则 3.9、5.4。

范围按任务书写：`t[a:b]`、`t[a:b:s]`、省略端点、多维 `t[:, 0]`/`t[a:b, c]`、按整数数组下标
`t[idx]`（降低为 `take`）、`last(t)`；负数是故障而不是 Python 式回绕；越界按 3.9；格式化器、
语言服务器、语言参考。**H17 的表示没到之前不实现 rank>1 的视图**：这些写法照样解析、照样类型
检查，但下界时给一条**点名 H17** 的带位置诊断，而不是悄悄退化成一份语义不同的拷贝。

## 1 语法

文法（`docs/language/08_top_level_and_grammar.md` 由 `scripts/check-grammar.mjs` 从解析器函数上
方的 `///` 产生式生成，中英两份同时更新）：

```
indices            : '[' (sliceIndices | dataExpr) (',' (sliceIndices | dataExpr))* ']'
sliceIndices       : dataExpr? ':' dataExpr? (':' dataExpr?)?
```

- `indices` 的每个维度是一个 `sliceIndices`（带冒号）或一个普通表达式（元素下标）。逗号分隔
  多维，允许尾逗号（沿用原来的宽容）。
- `sliceIndices` 的**子节点就是写出来的那串**：表达式与冒号记号按书写顺序排列（`a:b` 是
  `[a, ':', b]`，`[:b]` 是 `[':', b]`，`[::s]` 是 `[':', ':', s]`）。哪一段被省略因此直接从树里
  读得出来，不需要额外的“空节点”种类，也不靠 token 位置反推。**没有新增 `OmittedIndex` 之类
  的节点种类**：每种节点都要有对应的产生式，凭空造一个 ε 节点会让文法表与解析器对不上。
- AST（`src/parse/ast/`）：每个维度不变仍是 `DataLoad`；切片那一维是新的
  `SliceLoad`（`DataType::Slice`），**正好三个子节点**——start、end、step；没写的那段是
  `NullLoad`。三个槽的落位由冒号的个数决定（第一个冒号前是 start，两个冒号之间是 end，第二个
  冒号之后是 step），所以 `t[a::s]` 的 end 是 `NullLoad`，语义是“到底”，与 `t[a:]` 相同。
- 与 `t.[n]` 不混淆：`t.[n]` 是编译期字段访问（`memberAccess`，H51b 的 `StaticAccessLoad`，
  `ACCS`），走的是另一条产生式，本轮完全没动；`t[n]`、`t[a:b]` 是运行时下标（`indices` +
  `AnnoExpr`），两者在 CST 上就不同。`t[]` 仍然是语法错误（数组字面量由
  `peek(1) != ']'` 区分，行为不变）。

## 2 类型与下界：设计原则 3.9、5.4 落到实现

内部算子组：`t[i]` 一直走 `__idx__`（`t[i]` 的符号在 `operator_names.cpp` 里就指向它）。本轮
新增：

| 组 / URI | 签名 | 说明 |
|---|---|---|
| `__slice__` / `:op/slice_sub` | `(arr: T[], start: int, end: int, step: int, endWritten: int) => T[]` | 切片下标；`endWritten` 说明 end 是否写了（`t[a:]` 到底） |
| `__idx__` / `:op/idx_take` | `(arr: T[], indices: int[]) => T[]` | `t[idx]`，与 `take` 同一实现 |
| `last` / `:struct/last_arr` | `(arr: T[]) => T` | `last(t)`，全局内建 |

张量模块（`modules/tensor/ops/layout_ops.cpp`）：`slice_sub`（`__slice__` 导出，视图
`viewTensor`）与 `idx_take`（`__idx__` 导出，复用 `takeKernel`/`takeInfer`）。

`t[idx]` 是否本来就降低为 `take`？**不是**：原来 `__idx__` 的下标重载只接受 `int`，`t[idx]`
（`idx: int[]`）在 group 里没有接受它的重载，报 `NoMatchingFunction`。本轮加的就是这个重载；
`t[idx]` 现在是 `take` 的语义——按 `idx` 的顺序取、重复的下标重复取、结果是新数组（行被复制，
块被共用），张量上是 `takeInfer` 的 `[len(idx)] + shape(t)[1:]`。

越界与负数（3.9）：

| 情况 | 诊断 | 位置 |
|---|---|---|
| 元素下标越界或为负（`xs[i]`，`t[i]`） | `RuntimeDiag::IndexOutOfRange`（不变） | 下标表达式 |
| `t[idx]` 里某个下标越界或为负 | `RuntimeDiag::IndexOutOfRange`，`index as written` | `[`（算子节点） |
| 切片端点越界或为负 | `RuntimeDiag::SliceOutOfRange`，消息带两端与长度 | `[`（算子节点） |
| 切片端点编译期已知越界（张量静态形状） | 编译期 `SemanticDiag::ArgumentsRejected`（`ShapeError` 文本，`slice bounds a..b are outside the first dimension of extent n`） | `[` |
| `b < a` | 空结果，不是故障（3.9） | — |
| `b == len` | 合法（右开端点） | — |
| `last([])` | `RuntimeDiag::IndexOutOfRange`（与 `xs[0]` 同一诊断） | 调用处 |
| 数组长度未知（槽数组、运行时才知道） | 越界留给运行时故障；没有编译期检查 | — |

**负数是故障，不是回绕**：`xs[-1]` / `xs[-1:2]` 都报错；`last(xs)` 是取末尾元素的写法。特意
**没有**复用 `modules/tensor/kernels/layout.cpp` 的 `normalizeSliceBound`——那里的负数按 Python
回绕，是函数式 `slice(xs, 0, a, b, s)` 的既定语义，两种写法在 5.4 里就是不同的东西。

## 3 今天能下界的写法 / 等 H17 的写法

| 写法 | 现在的行为 |
|---|---|
| `xs[i]`、`t[i]`（`int` 下标） | 下界，行为不变 |
| `t[idx]`（`int[]`，数组与 rank-1 张量） | **下界**（`take`，拷贝行） |
| `t[a:b]`、`t[:b]`、`t[a:]`、`t[:]`（rank-1 数组与 rank-1 张量） | **下界**：共用数据块的视图（`Array::view` / `viewTensor`） |
| `t[a:b:1]` | **下界**，与 `t[a:b]` 相同 |
| `t[a:b:s]`，`s != 1`（数组） | 运行时 `RuntimeDiag::InvalidArgument`：`a slice step must be 1 for now; … needs the multidimensional array representation of H17` |
| `t[a:b:s]`，`s` 不是常量或 `!= 1`（张量） | 编译期 `SemanticDiag::ArgumentsRejected`（`ShapeError` 文本，点名 H17） |
| `t[a:b]`，`t` 是 rank≥2 的张量 | 编译期 `SemanticDiag::ArgumentsRejected`（`ShapeError` 文本，点名 H17） |
| `t[:, 0]`、`t[a:b, c]`（多维下标里有一维切片） | 编译期 `SemanticDiag::ConstructNotSupported`：`'a subscript that slices a dimension other than the first' is not supported: it is a view with strides, which needs the multidimensional array representation of H17; until then take the rows with the function 'take', or index one dimension at a time.` |
| 槽数组（元素是对象）的切片 | 下界，但是**复制**（槽数组没有可共用的数据块）；文档写明随 H17 改成视图 |
| `last(xs)` | 下界 |

多维切片与步长是“语法与类型先做、视图等 H17”的部分：**解析、类型检查、AST/GCT 都通过**，只是
在 GCT 的 `Index` 分支（多维）或算子里（步长）明确拒绝，并且**点名 H17**、给出替代写法（`take`、
逐维取、`slice(xs, 0, a, b, s)`），不会静默产生一份“看起来像视图、其实不共用块”的拷贝。

`std::cpp`、四个调度器、`std::opt`、自动微分、ONNX 侧没有新节点种类：`__slice__` 与
`__idx__` 都是普通的算子组调用，四个调度器按现有机制执行（测试覆盖 nvm/fvm/jit/prl）。

## 4 语言服务器

- **格式化**：`tools/format/fmt.cpp` 增加 `visitSliceIndices`，`visitIndices` 改成逐项输出并用
  `, ` 连接。规则：冒号照写出来的样子保留，冒号后面**跟着一段才有空格**——`xs[a: b]`、
  `xs[: b]`、`xs[:]`、`xs[a: 4: 1]`、`xs[idx]`。格式化器是 CST 驱动的，所以 `t.[n]`（成员访问）
  仍走原来的规则，不受影响。
- **补全**：`[...]` 内部与切片的各段都是普通表达式位置，语义层的补全查询本来就按“位置上的
  名字”工作，不需要新的位置种类；`: ` 已经是补全的触发字符，`[` 不需要新的触发字符。`test/
  cases/tools/lsp/basics.test.mjs`（格式化）与 `editing.test.mjs`（`[...]` 内、冒号两侧的补全）
  加了覆盖。

## 6 没有做、留待后续

   求导会在“没有梯度通道”的检查处拒绝（不会静默丢梯度），但正式的散射要在 H17 之后按 9.9 做
   （H22 第 2 项）。

   机制拒绝。ONNX 侧按任务书在视图表示之后统一做。
4. 函数式的 `slice(xs, 0, a, b, s)` 保持原语义（负数回绕、端点截断），与下标切片的两套规则
