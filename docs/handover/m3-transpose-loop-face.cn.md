# 循环的转置：先量清楚 `LOOP` 节点长什么样，再说哪一步能落地

作者 06:30 催办的那句是「循环按轮次倒序执行」。这一页只做一件被要求过的事：**把 `LOOP` 节点量清楚**，然后说清「轮次倒序」在什么条件下是一条同长度循环、在什么条件下必须先把每一轮的状态存下来。**这一笔没有实现，也就没有数**——原因写在第 4 节。

## 一、`LOOP` 节点实测

`thrice(x) = loop s = x for i in 0..3 do s * 2.0` 的 GIR（`std::gir`）：

```
N00  x                      PORT   float
N01  0 / N02 3 / N03 FILL   (int,int)   区间
N04  (0,0)                  DATA   (int,int)   区间的初值
N05  2.0                    DATA   float
N06  :op/mul_d              OPER   float      ← 循环体
N07  LOOP for               LOOP   float      ← 循环本身
N06 -> N07 [0|0 WITH]   循环体算出来的值
N09 -> N07 [0|1 WITH]   （循环的另一个 with，体里那个 s 的自变量）
N03 -> N07 [0|0 NORM]   区间
N00 -> N07 [0|1 NORM]   初值 x
N07 -> O02 EXIT
```

要点三条：

1. **状态不是节点，是端口。** 循环体里的 `s` 是一个由 `LOOP` 自己引出的 with（`N09`），不是原图上某个 id；所以「第 k 轮的 s」在图里没有名字。
2. **轮数不是常数节点，是数据。** `0..3` 变成一个 `FILL` 和一个 `(0,0)`，`LOOP` 的 norm 输入拿的是它。**任何按「恰好两轮」写的实现都是错的**，而且按「恰好 k 轮」写也错——轮数在图里是值。
3. **循环体是区域。** 和分支的臂一样，体里的节点带自己的 region；从外面只看得到 `LOOP` 的 with 与 norm。

## 二、「轮次倒序」的两种情形

| 情形 | 倒序要什么 | 能不能不建 tape |
|---|---|---|
| **体里的法则只用常数**（`s = s * 2.0`、`s = s * 3.0 + 1.0` 这类仿射体） | 每轮乘同一个常数，倒着走与正着走**乘的是同一串常数**，只是次序相反——乘法可交换，所以倒序的结果等于「同长度的一次正向循环，每轮把法则反过来用」 | **能**。转置图里一条同轮数的循环，体的每条法则取 `transposeRuleOf` 的版本即可 |
| **体里的法则要用那一轮的状态**（`s = s * s`、`s = (s + a) * b` 里 `b` 是上一轮的值、任何非线性） | 倒到第 k 轮时得知道第 k 轮的 `s`，而它只存在于那次已经跑完的执行里 | **不能**。必须先把每轮的状态（或每条需要残差的中间值）**收进一个集合槽**（`GCLoopBody::collectionCount` 就是为这个准备的），再建第二条循环倒着读这个集合 |

设计页 §4.3 写的「逐轮取 `split` 留下的残差」就是第二行。**第一行是可以先做的**：它不改三个模块接口，只用现成的 `addRegion` + `setInsertRegion` 和已有的法则表，和分支那一笔同一套路子。

## 三、这一笔如果只做第一行，要落成什么

- 转置图里建一条 `LOOP`，**轮数取原节点的区间**（原样复制区间，不写死）；
- 体的每条法则按 `transposeRuleOf` 取转置版，常数原样；
- 体的入口是余切、出口是「上一轮的余切」——即每次迭代把余切往前推一轮；
- 循环的 exit 就是参数的余切。
- 体里一旦出现**要用当轮状态**的法则，`skip=state`（指到那条节点的 origin），不返回错余切。

## 四、第一行已经落地，数在第五节

这一笔按第三节做了**第一行（仿射体）**：`thrice(x) = loop s = x for i in 0..3 do s * 2.0` 的转置在 `ȳ = 1.0` 上得 `8.0`、在 `ȳ = 2.0` 上得 `16.0`；四轮的 `quad` 得 `16.0`（轮数取循环自己的区间，不是写死三轮）。四个后端一致（`test/cases/compile/transforms/transpose_loop.cml`）。

- 转置图里的循环**轮数取原节点的区间**：把 `FILL` 的**整个 payload**（`makeFillPayload(kind, slots)`，槽位在头部之后，只拷头部等于没有分量）连同它的 norm 模板与两个定界值一起复制，并且**给这个 `FILL` 分配自己的 slot**（`allocateRuntimeSlot`）——不分配的话它会从 slot 0 读别人的值。
- 体的每条法则按 `transposeRuleOf` 取转置版，常数原样。
- 体里一旦出现要用当轮状态的法则，`skip=state node=<id> origin=<origin>`——指到那一轮写在哪，绝不返回错余切。

**这一笔最贵的一课，写在这里省下一个人两小时**：`LOOP` 的两个 with 输入是「**体的结果**」和「**轮次**」，**不是**体和状态端口。状态是隐式的（`with[0]` 就是下一轮的 `s`），体的状态端口自己从第一轮的值开始。我一开始把状态端口当 `with[1]` 传进去，图的校验全过、也跑得出来，**只是每一轮读的都是同一个初值**——四轮、三轮、两轮的转置全都答 `2.0`。判据是「轮数变、答案不变」，这正是那个 bug 的样子。

**第二行（要用当轮状态的体）仍然要等 `split`**：那些值只存在于已经跑完的那次执行里，得先按轮收进集合槽（`GCLoopBody::collectionCount`）。第三节里那两条事实留着，它们是那一笔的地基。

## 五、口径：协调者给的数也要能被程序复算

作者 06:50 的验收原文是「`s = s * 2` 三轮、`x = 1` → 值 8，转置在 `ȳ = 1` 上得 12」。**前一半对，后一半是错的数**：`d(2³x)/dx = 2³ = 8`，余切 1 拉回去就是 **8**。作者 07:0x 已确认作废 `12`，验收按 `8`。

留给后来的一句：**协调者给的数也要能被程序复算——拿程序（或纸笔）算一遍，算不出来就是数错的，不是“以作者为准”。** 这条不是客气话：`12` 没有任何程序对应它（「三轮各贡献一份」是累加型，那是 `2+4+8 = 14`，也不是 12）。若当时照 `12` 去“凑”，凑法一定是错的，而错的那一下会被后面的测试当成正确基线。
