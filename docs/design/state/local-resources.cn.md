# 局部可变资源：不可变语言怎样线性地改一个可变对象

> **设计稿（2026-11-27，负责人与决策者讨论所得）**：第 2、3 节是已经成立的分析，第 5 节是待定的取舍。本页与同目录 `README.cn.md`（`var` 只是写法、语言里没有可变单元）是一个主题的两半：那一页讲"值上的写法"，这一页讲"必须原地改的对象"。

## 1. 为什么

Camel 的值都不可变：图是值，遍可以随意复制、共享，事实可以缓存，规范形式可以当身份（原则 9.1）。可有些对象天然要原地改，最典型的是 `edit` 块里的草稿：把一张图改上几十步，每步复制一份图代价太高。

可变对象真正的麻烦是**别名**：同一个可变的东西被两处持有，一处改了另一处看得见；或者旧版本在改动之后还被拿来用。值语义的一切推理都建立在"没有别名可见"之上。

别的语言各付出一套机制来管它：Haskell 用 `ST` 单子在语句间传一个状态令牌，再用 rank-2 类型的 `runST` 把它关进作用域；Clean 用唯一性类型、Rust 用借用检查，在类型里证明只有一个持有者；Lean 4、Koka 在运行时看引用计数，只有一个持有者就原地改，被共享了就先复制。

Camel 用图本身已有的东西就够了：资源与顺序边。

## 2. 模式：解冻、局部资源、冻结

1. **身份变成资源**：可变对象不作为值交给用户，而是一个资源名；对它的每次操作都是对这个资源的读或写。
2. **顺序代替传值**：同一资源上的冲突访问按书写顺序排（原则 3.3）。图上的顺序边，就是函数式写法里"把新版本传给下一步"的那条链，只是不用写出来。
3. **作用域给出纯**：资源在一个作用域里新建、出不了作用域，在出口按效应遮蔽掉（原则 3.4，与 `sync` 块的时间线是同一条规则），所以从外面看整段是纯的。

**线性从哪来**：用户手里从来只有资源名，没有"某个版本"，所以根本无从"对同一个中间状态改两次"。线性类型、唯一性类型是把线性写进值的类型里；资源化让版本根本不出现在用户的词汇里，线性是自然的结果，不需要类型系统去证明。也正因为只有一个活着的版本，原地修改和"每步交回新值"在外面区分不出来：实现可以原地改，语义仍是值。

**能不能出作用域**决定最后的样子：出不了的，整段是纯的；出得了的，效应留在函数类型上，外面看得见。

## 3. 已经在用这个模式的地方

| 构造 | 局部资源 | 出得了作用域吗 | 对外 |
|---|---|---|---|
| `sync` 块（原则 3.4） | 一条匿名的时间线 | 否 | 时间线在出口遮蔽，不进函数的效应 |
| `edit d = f { … }`（`docs/design/graph-editing` 第 5、6 节） | 草稿：把 `f` 解冻成可编辑的副本 | 否（句柄由块的标签关住） | `commit` 冻结回函数值；`edit` 对外是纯的 |
| `var`（原则 3.5） | 无：重新绑定就是那条版本链，链在名字上而不在资源上 | — | 值上的写法 |
| `Ref` 与外部资源 | `Ref`、文件、控制台 | 是 | 效应留在函数类型上 |

规律是：**解冻成局部资源 → 按资源规则顺序修改 → 冻结回值**，中间的可变性整个被作用域吞掉。

## 4. 由此得到的两点

- **并行是白送的**：资源规则区分读和写，不冲突的访问不排序，所以解冻后的对象天然"多读并行、写有先后"。
- **在图原生语言里这是自然产物**：版本链本来就是图上的顺序边，资源化不需要新机制。近邻各为可变性付出一套额外机制（单子、唯一性类型、借用检查、引用计数），Camel 直接用图本身就有的东西。

## 5. 待定

1. **`edit` 的草稿：块，还是值。**
   - 块（现状）：草稿不以值出现，编译器在块内逐句隐式地传"当前草稿"，线性由构造保证，永远原地改；拿一张图的节点去改另一张图在编译期报错。
   - 值加共享时复制（像数组那样，数据块带计数）：草稿是普通的值，可以与 `->`、`map`、`reduce` 自由组合，不需要块；正常原地改，不小心留着旧草稿再用会悄悄复制一整张图；节点混用改成运行时检查。
2. **编辑一步失败报成什么。**
   - 现状（设计页第 5 节）：产生故障，沿草稿上的顺序边传播，到块体外那层 `attempt` 变成错误值；块体里的普通故障（比如除零）也变成块的错误值（11-17 的规则）。
   - 另一种：编辑交回 `Draft!`，失败给错误值 `InvalidEdit`，后面的编辑把它原样传下去，`commit` 拿到错误就交回错误；块体里的普通故障照常是故障，和语言别处一条规则；不需要隔离边界。
3. **是否推广成通用构造并写进原则**：今后再有局部的可变对象（例如循环里原地累积的缓冲区），是否都套"解冻、局部资源、冻结"这一个构造，而不为它单独发明机制。
