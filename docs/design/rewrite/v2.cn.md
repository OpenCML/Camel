状态：已定（决策者 2026-10-22，负责人："都加上吧，越强越好"）。第一版见同目录 [README.cn.md](README.cn.md) 与 `docs/technical/46_rules.md`。

目标：规则库从"逐类型、逐算子罗列定律"变成"少量通用定律加 ML 专用的图替换"，并且每条规则都能被 `check` 检验。**不加保留关键字**：只扩展 `rule`、`when` 能写什么，`analysis` 改为 `fact`（7.5），全部是上下文关键字，复用元组、函数类型、Camel 函数调用。

## 1. 类型泛型与值语义

- **规则的形参按设计原则 5.5 自动绑定类型变量**：`rule sub_self(x: T) { x - x => 0 }` 对所有类型实例化；字面量在实例里取 `T`。只对部分类型成立的写在条件或要求里（`#requires<no_nans, no_infs>`、`when is_integer::<T>()`），不复制规则。
- **`const c` 在 `when` 与右边里是常量的值**，类型是形参的类型：`when c1 != 0 && sign(c1) == sign(c2)`。需要节点本身（读事实、形状）时写 `node_of(c)`。
- **形参的类型由匹配器检查**：`const c: T` 只匹配类型为 `T` 的常量，规则不再写 `isI32` 一类的守卫。
- **`fact` 的子句同理**（7.5）：模式变量在子句里是节点（事实挂在节点上），常量变量是值。

## 2. 算子变量

- 形参可以是函数类型：`op: (T, T) => T` 在模式里匹配任意二元算子，在右边原样使用。
- **算子的性质由 `when` 读取**：`commutative(op)`、`associative(op)`、`identity::<T>(op)`（单位元，没有时为 null）、`distributes(mul, add)`。这些性质来自算子的语义声明（10.4 要求每个原子算子声明定律）；Camel 定义的函数由其定义推出或用标签声明。
- 例：
  ```camel
  rule neutral(x: T, op: (T, T) => T) { op(x, e) => x } when e == identity::<T>(op)
  rule distribute(a: T, b: T, c: T, mul: (T, T) => T, add: (T, T) => T) {
      mul(a, add(b, c)) => add(mul(a, b), mul(a, c))
  } when distributes(mul, add)
  ```

## 3. 多根模式

- 左边是元组时，元组的各项是**同一张图里同时存在**的几个值，共用形参：
  ```camel
  rule divmod(x: T, y: T) { (x / y, x % y) => divmod(x, y) }
  rule qkv(x, wq, wk, wv) { (x @ wq, x @ wk, x @ wv) => split3(x @ concat(wq, wk, wv)) }
      when same_shape(wq, wk, wv)
  ```
- 右边是同样元数的元组，各项依次替换左边各项。匹配按共享的形参连接（先匹配含最少变量的一项，再按共享变量找其余项）。
- 只有左边各项都存在才触发；它们之间不要求相邻，也不要求在同一区域之外的任何关系，除了**都不依赖彼此的结果**（否则替换会成环，匹配器拒绝）。

## 4. 条件与右边可以调用 Camel 函数

- `when` 与右边都可以调用任意纯的 Camel 函数，在改写时求值，参数是常量变量的值、属性与形状：
  ```camel
  rule perm2(x: T, const p: int[], const q: int[]) {
      x->permute<p>->permute<q> => x->permute<compose(p, q)>
  } when !is_identity(compose(p, q))
  rule perm_id(x: T, const p: int[]) { x->permute<p> => x } when is_identity(p)
  ```
- 读形状：`shape(x)`（形状已知时是值，未知时条件为假）；读属性：`attr(x)` 一类。
- 右边调用的函数结果成为新节点的常量或属性；调用失败（故障）时该次改写不发生。

## 5. 代价是 Camel 函数

- `extract<cost>(p)`：`cost` 是 `(op: Op, args: Shape[]) => float` 一类的 Camel 函数（具体签名随 `graph` 模块定），给出一个写法的代价；抽取取总代价最小的写法。
- 标准库给出 `rules::nodes`（节点数）、`rules::flops`（按形状估算）等；Tiles 给出自己的代价模型。字符串形式 `extract(p, 'nodes')` 删除。

## 6. 结合交换匹配

- 声明了结合律与交换律的算子（第 2 节的性质），匹配器把一串同一算子的项看作**多重集**：`a + b + c` 不展开成各种括号与顺序，模式 `x + 0` 在多重集里找 `0`。
- 交换律、结合律不再写成规则（它们是匹配器的语义），饱和不再因此爆炸（H118 的超时）。
- 这一节不改语法，只改匹配器与抽取。

## 7. 控制区域上的模式

- 模式可以写分支与循环：
  ```camel
  rule same_arms(c: bool, a: T) { (if c then a else a) => a }
  rule const_cond(a: T, b: T)   { (if true then a else b) => a }
  ```
- 循环上的变换（不变量外提、相邻循环融合）属于本节的第二步：模式能匹配 `loop` 的头与体，条件能问"这个值是否依赖循环状态"（由 `fact` 或内建事实回答）。
- 区域按图内区域（图存储设计稿第 5 步）匹配，替换保持区域结构合法，由校验器检查。

## 7.5 事实：`fact` 取代 `analysis`

第一版的 `analysis` 名字说的是动作，没说出产物；子句 `initial`/`join`/`on` 是格论术语，输入又是隐含的。第二版改为声明**图上每个值的一项事实**（与图存储的"事实"同一个概念），写法像函数、分情况像 `match`：

```camel
fact range(v: T): Interval {
    case const c => Interval(c, c)
    case x + y   => range(x) + range(y)
    case abs(x)  => range(x).abs()
    case _       => Interval::of_type::<T>()
    join (a, b)   => a.union(b)
    meet (a, b)   => a.intersect(b)
    widen (a, b)  => a.widen(b)
    narrow (a, b) => a.narrow(b)
}

rule abs_nonneg(x: T) { abs(x) => x } when range(x).lo >= 0
```

- **`fact 名字(参数): 事实类型`**：输入显式写出；`T` 可在 `case _` 等处使用（如按类型给出范围）。多个参数时是"这几个值之间"的事实。规则的 `when` 与其他事实里按函数调用查询。
- **`case 模式 => 事实`**：按值的构造方式分情况，模式与 `rule` 左边同一种写法；`case _` 是没有一条匹配时的事实（必需）。
- **`join`**（必需）：分支汇合，"两者之一"，最小上界。
- **`meet`**（可选）：同一个值的等价写法，"两者都成立"，最大下界；省略时等价写法也用 `join`（正确但不精确）。
- **`widen`**（可选）：循环中迭代时加速收敛；省略时，迭代到上限退回 `case _` 的事实。
- **`narrow`**（可选）：`widen` 收敛之后再收紧一轮或几轮，找回被 `widen` 丢掉的精度（如循环条件 `i < n` 给出的上界）。
- `fact`、`join`、`meet`、`widen`、`narrow` 是上下文关键字（`fact` 在声明开头，其余只在 `fact` 的块内）；`case`、`_` 沿用 `match` 的含义。第一版的 `analysis`、`initial`、`on` 删除，不保留旧写法。
- 理论对应：`join`/`meet`/`widen`/`narrow` 即抽象解释的 ⊔/⊓/∇/Δ；egg 的 `Analysis::merge` 合并的是等价写法，对应这里的 `meet`。

## 8. `check` 的覆盖

- 第 1 节之后，常量变量是值，条件能在采样值上求值：带 `when` 的规则也做采样对照（今天只能走引擎路径）。
- 多根规则对每一项分别对照；带算子变量的规则对每个满足条件的已登记算子各检验一次；带结合交换的规则按多重集采样。
- 规则库进入标准库之前必须通过 `check`，不变。
