# 官方示例计划：经典、高难、工业规模

状态：计划（2026-10-20，语言作者提出）。现有的 `examples/` 是"每个程序做一件事"的短示例；本计划是另一套：**完整的 AI 程序**，用来证明 Camel 的主张，也用来逼出语言与实现的不足。

## 1. 要证明什么

语言作者的判断：**性能上限与 Python 技术栈（PyTorch、JAX，含 `torch.compile`、XLA）齐平，同时写法更可读、更清爽，就是胜利**；生态不是障碍（AI 时代软件开发成本大幅下降）。控制流复杂、动态性强的工作负载尤其重要，因为那里 Python 技术栈确实吃力：`torch.compile` 遇到依赖数据的控制流会断图，JAX 的 `while_loop` 不能反向求导。

所以每个示例都要同时给出四样东西：

1. **Camel 实现**：按当前的设计原则写，代码就是展示品，追求清楚、可读。
2. **对照实现**：同一任务的 PyTorch 实现（必要时加 JAX），按各自社区的惯用写法，不故意写差。
3. **结果一致**：两边的数值结果按数值契约（设计原则第 7 节）比较：严格模式下逐位或在误差界内，默认模式下在合理的容差内；训练类示例比较训练曲线与最终指标。
4. **度量**：代码行数与并排对照（可读性）、吞吐与峰值内存（性能）、编译时间；工业规模的示例另报 MFU（模型浮点利用率）。

## 2. 示例清单

### 第一层：经典（入门与回归测试）

| # | 示例 | 展示的 Camel 能力 | 依赖 |
|---|---|---|---|
| C1 | 线性回归、逻辑回归 | 张量、`grad`、`do` 循环训练 | 已具备 |
| C2 | MLP 训练 MNIST（含评估与检查点） | 参数树即类型、`tree_map`、`value_and_grad`、资源推导、`save_tree` | 已具备 |
| C3 | CNN：LeNet、ResNet-18 训练 CIFAR-10 | 卷积、BN、数据管线、`@gpu` | GPU 路径（Tiles） |
| C4 | 字符级 RNN、LSTM 语言模型 | **穿过循环的反向传播**（按时间展开） | 循环求导（H4d） |
| C5 | Transformer（nanoGPT 规模）训练 TinyShakespeare | 注意力、混合精度标签、`#strict` 对照 | GPU 路径 |
| C6 | VAE、自编码器 | 随机数（键式）、重参数化 | 已具备或接近 |

### 第二层：高难（控制流与动态性，Camel 的主场）

| # | 示例 | 难点 | 展示的 Camel 能力 |
|---|---|---|---|
| D1 | **自适应步长的 Neural ODE** | 步数由误差估计决定（数据相关的 `while`），要穿过求解器求导 | 条件决定轮数的循环可以求导（JAX 的 `while_loop` 做不到） |
| D2 | **可微物理仿真**：质点-弹簧、布料、刚体或稳定流体，长时间推演并用梯度做控制或参数辨识 | 上千步的循环、每步有分支（碰撞） | 循环与分支是一等结构；每轮残差 O(n)；可选检查点 |
| D3 | **强化学习**：PPO 训练 CartPole、Pendulum，环境也用 Camel 写，整个"交互-更新"循环在一张图里 | 环境步进的控制流、片段长度不定 | 整程序编译，没有 Python 与环境之间的往返 |
| D4 | **AlphaZero 简化版**：蒙特卡洛树搜索 + 策略价值网络（井字棋或四子棋） | 递归的树搜索、可变的树结构 | `enum` 表示的树、递归、按需执行的副作用 |
| D5 | **Tree-LSTM**：在句法树上做情感分类 | 每个样本的计算图形状不同 | `enum` 树、对树结构的递归、批处理 |
| D6 | **动态网络**：混合专家（按数据路由）、提前退出网络、束搜索解码 | 依赖数据的分派与提前终止 | 分支与循环在编译后的图中保留 |
| D7 | **HMC / NUTS 采样** | 蛙跳积分的循环、NUTS 动态建树 | 循环、递归、可复现的随机数 |
| D8 | **图神经网络**：消息传递（稀疏邻接） | 不规则的稀疏结构 | 收集与散射、按声明的性质并行 |

### 第三层：工业规模

| # | 示例 | 规模与要求 | 展示的 Camel 能力 |
|---|---|---|---|
| I1 | **GPT 类语言模型预训练**：1 亿到 10 亿参数，多卡 | 数据并行与张量并行、混合精度、检查点、数据管线；对照 nanoGPT 或 Megatron 的简化版，报吞吐与 MFU | `#shard` 切分、调度文件注入、`@gpu`、资源与副作用 |
| I2 | **扩散模型训练**：DDPM、UNet | 大张量、长时间训练（核心已有扩散所需的 GPU 算子） | Tiles 融合、BF16 许可 |
| I3 | **推荐模型**（DLRM 类）：大规模稀疏嵌入 | 稀疏查找、混合并行 | 切分、收集与散射 |
| I4 | **推理部署**：把训练好的模型导出为 C++ 或 ONNX，在没有 Python 的 CPU 设备上运行；以及带 KV 缓存的自回归推理 | 冻结、导出、动态长度的解码循环 | `#macro` 冻结参数、`std::cpp`、`std::cml` |

## 3. 组织方式

- 放在仓库顶层 `showcase/` 下，每个示例一个目录：Camel 实现、对照实现（`baseline/`）、数据获取脚本、运行与比较脚本、`README.cn.md`（说明任务、运行方法、结果表格与并排对照的要点）。
- 每个示例都有一个**小规模配置**（几秒到一分钟，进测试的 `slow` 层，保证示例不会悄悄坏掉）和一个**完整配置**（产出 README 中的结果）。
- 结果表格由脚本生成，注明机器、版本、日期；不手工抄数字。
- 示例暴露的语言或实现问题，记入示例 README 的"遇到的问题"一节，并按交接任务书的格式提问或立项。
