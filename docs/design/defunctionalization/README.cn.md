# 去函数化：标签与环境

函数值在程序里只有一个写法：**一个标签加它的环境**。这条页面写这个写法的表示、调用怎么落到已知函数，以及求导的磁带为什么存标签。图上的对应关系以[设计原则](../../design-principles.cn.md) 2.1、5.2、5.3、9.9 为准。

## 1. 表示

- **每个函数类型一个 `enum` 类型**。程序里被取作值的每个函数（具名函数、lambda）是这个 `enum` 的一个变体，变体的数据是这个函数捕获的值，也就是它的环境。变体没有捕获就没有数据。
- **构造就是装一个标签**：`enum` 的构造算子的输入是变体的标号与环境，结果是一个值；图上不增加节点种类（原则 2.1）。环境的字段类型就是这个函数捕获的值各自的类型，随变体不同而不同。
- **标签在值的类型里，不在值的外面**：一个函数类型的值就是这一个 `enum` 类型的值，所以两条臂、两个调用点、一个循环的状态交出同一个类型的值，JOIN 与循环头不需要额外约定。
- **闭包只在一个地方留下**：函数值离开程序的边界（交给宿主语言、导出接口）。程序内部的函数值都是上面这个 `enum` 的值。

不用 `{ tag: int, env: T }` 这类结构体：环境随变体不同，而 Camel 没有 `any`、没有通用联合类型（原则 5.10），标签与数据必须是同一个和类型的值。`enum` 是已有的机制：构造与 `match` 的图形状、把它作键与排序都已在规范里（原则 5.3、11.3）。递归也只能经由 `enum` 表示（原则 5.2）——回传的"下一步的回传"就是同一类型里的另一个值。

## 2. 调用

经过函数值的调用是三步：取标签、按标签 `match`、每臂直接调用那个函数。

- 每臂拿到的是这个变体的环境字段，它们作为那个函数的**尾部参数**传入：去函数化之后，被调函数的捕获是它的普通参数，调用是直接调用（图上是一条 `FUNC` 边）。
- **标签在编译期已知时，`match` 由折叠去掉**，只剩那条直接调用，再由内联展平。所以 `std::opt` 之后不会剩下对标签的分支，除非标签真的只有运行期才知道（一条臂在运行期才选定、循环的轮次决定它）。
- 一条调用点能到达哪些变体是**从类型**得出的，不是从猜得出：这个 `enum` 的变体就是它的臂。程序里说不出标签的调用不存在了——那正是"每个 lambda 一个标签"的意思。

- 所以磁带里没有闭包，也没有经过函数值的调用：每一步调用的目标在编译期就是已知的，运行期只在标签上分支。

## 4. 施工顺序

降级的次序由"类型先定"决定，不能倒过来：

1. **先定变体集合**：一个函数类型的 `enum` 有哪些变体，要在任何用到这个类型的图被编码之前定下。求导这一侧的回传图与它们的残差是随改写逐步发现的，所以先把全部计划与残差算出来，再建类型，再编码图；编码之后再补一个变体就是另一个类型，JOIN 的两臂会因此对不上。
2. **整程序换类型**：值、端口、元组与结构体的字段、数组元素、函数的签名一起换成这个 `enum` 类型。只换一处（例如只换构造点）会让调用处的签名、`match` 各臂的类型与 JOIN 的结果三者不一致。
3. **换节点**：构造点换成 `enum` 的构造，经过函数值的调用换成"取标签、分支、每臂直接调用"。这两步都保持值，不改变哪些效应执行（原则 9.7）。
4. **特化不是等价的替代**：按调用点复制被调函数可以把一次调用变直，但被复制的函数里还有它自己的函数值，副本只会更多；标签的做法不复制，规模随程序线性增长，因此它是流水线里固定的一步，不是可选优化。
