# 参数树实现

2026-10-18，按设计稿 3.2、3.5 的修订实现。所有操作在 GIR 建图时展开，交给原有的字段访问、调用、构造及后续自动微分处理，不增加运行时树遍历。

- `tree_map<f>(t1, ..., tn)` 只按 `t1` 的结构体和普通元组递归。其他实参在对应内部节点必须有同样的字段顺序和结构；在第一棵树的叶子位置整体传入，即使该位置是结构体或元组。
- 回调调用复用普通调用的泛型实例化、重载选择、闭包捕获、可变参数检查和效应记录。不会根据回调的参数类型改变叶子边界。
- `tree_unzip(r, like)` 根据 `like` 的边界取出各叶子的元组分量，再构造结果树。各叶子元组的元数必须一致；空参照树不能确定元数，给出明确诊断。
- `tree_reduce<op>(t, init)` 依字段声明顺序深度优先展开为有数据依赖的左折叠；回调必须保持累加器的类型。
- `tree_leaves(t)` 返回规范顺序的叶子元组；`tree_paths(t)` 返回同构的路径字符串树。根本身为叶子时路径为空字符串。
- 数组、映射和其他模块类型作为叶子；可空、可失败包装与可变单元不按普通元组展开。

服务器手动运行 `tree_operations.cml`，覆盖多树映射、泛型与重载回调、回调元组返回、以第一棵树为准停止展开、数组叶子、路径和叶子顺序，以及浮点 `((0 + 1e16) + -1e16) + 1 = 1` 的左折叠。`tree_shape_error.cml` 在编译期指出第一个不匹配位置 `block`。

`tree_training.cml` 在物理 GPU 2 上以 `std::macro std::fvm` 手动执行：含树操作的损失完成自动微分；通用更新函数通过 `tree_map` 返回元组，再以 `tree_unzip` 拆成设备参数树。五项 CPU/GPU 损失、梯度及更新误差都是零。

这些手动结果随后登记为计划条目，没有运行全量回归。DDPM 的通用优化器和实际训练验收见实现进度文档；原生检查点与其他训练基础设施仍按设计稿继续推进。
