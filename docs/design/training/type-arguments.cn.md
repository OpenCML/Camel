# 显式类型实参与训练二进制接口

2026-10-19。实现设计原则 2.13 的两层调用类型推断，不引入类型值，也不改变 with 参数含义。

- `id::<int>(7)` 在编译期选择泛型实例；顺序为签名中类型变量首次出现的顺序。
- `repeat::<int><3>(5)` 的类型实参是 `int`，值上下文参数是 `3`。
- `let f = id::<int>` 得到普通函数值；同一组类型仍复用既有实例缓存。
- 返回位置允许声明 `typeas T`。例如 `empty(): (typeas T)[]` 可由 `let xs: int[] = empty()`、已知形参类型、声明的返回类型确定 `T`；缺少上下文时须写 `empty::<int>()`。

解析器将 `::<...>` 记为独立 CST/AST 构造，GCT 中为 `TAPP(callee, TYPE...)`。GIR 建图时消费它，仍只产生既有的具体函数图、函数值或算子节点，没有新的运行时节点种类。期望类型只在编译器的词法访问范围中生效，进入另一个函数体时清除；调用的实参分别取已知形参的类型，不把调用结果的期望类型误传给每个实参。

原生算子类型解析增加 `resolveForCall`，接收显式类型与期望结果。默认解析器拒绝不属于它的显式类型实参，普通调用继续走既有规则。此项扩展 C++ 虚接口，因此模块 ABI 从 1 升至 2；旧 `.cmo` 必须用新 SDK 重建，载入器不能将旧虚表当新接口使用。

`tensor::from_bytes::<f32/int/bool>(bytes, shape)` 在编译期选择具体 dtype 的算子 URI。内核运行时只接收 Bytes 和形状，不接收类型值。tensor 注册表保留算子定义与纯度/精确语义，原生解码不经过 double，不进行数值降精度。

服务器独立运行时 `.camel-explicit-types-v6` 验证显式实例、with 组合、函数值、返回类型推断、命名空间限定调用以及张量二进制往返。类型实参数目错误在编译期诊断；payload 长度、bool 非规范值和尺寸溢出在运行期诊断。原有泛型字面量、高阶函数、嵌套与跨模块调用也手动复核。未跑全量测试。

`.camel-explicit-types-v7` 将推断调用、函数值和显式调用的实例类型合法性检查统一到实例化入口；重复可空标记等规则不能被 `::<T>` 绕过。有效用例重新执行通过，`optional::<int?>(null)` 在编译期正确报告 `int??`。

当前期望类型覆盖直接声明、已知形参及声明的返回位置。结构字面量字段、需要其他实参才能确定类型的嵌套泛型调用等更复杂位置，尚需进一步完善双向类型传播，不能仅以直接调用用例声称所有推断位置已经完成。

构建源必须以更新后的时间戳同步。曾在服务器构建旧源期间修改本机文件，保留 tar 时间戳会令后续增量构建复用较新的旧对象；这些混合产物不计为验收。使用 `tar --touch` 重新同步并标准构建，安装到新的运行时目录后再验证。
