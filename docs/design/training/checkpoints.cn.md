# 原生训练状态检查点

接口遵循训练设计稿 8.2：`tree::save_tree(dir, state)`、`tree::load_tree::<State>(dir): State!`（2026-10-19 起属于 `tree` 模块，原在 `nn`；设计原则 13.5）。载入目标也可由直接的期望类型推出，如 `let state: State! = load_tree(dir)`。类型参数在编译期解析，运行时没有类型值参数。

原生库的服务器验收已通过，尚未接替 DDPM 的旧检查点入口。

结构体按字段声明顺序、普通元组按下标递归。当前叶子支持主机 `Tensor<f32/int/bool>`、`f32/float/i32/int/bool/string/Bytes`；设备值须先显式下载。数组、映射、可空或错误包装、函数和外部对象不支持。`Key` 待无状态随机数阶段实现后接入。

每个张量写精确存储 dtype 的 NPY，Bytes 写 `.bin`，其余写 `.txt`，文件名来自树路径：与 `tree_paths` 的结果逐字一致，写作 `blocks.0.w`，根的路径为空（设计原则 13.5）。浮点标量使用固定长度的 IEEE 位模式十六进制文本，避免十进制解析丢失 NaN 载荷和负零；整数用十进制，布尔为 `true/false`，文本是 `string`，按设计原则 13.5 本来就是合法的 UTF-8。树本身就是一个叶子时，路径为空，其文件名固定为 `_root`（清单里记录的路径仍为空）。叶子类型不受支持（数组、映射、函数等）是编译期错误，信息里带路径；`T?`/`T!` 是叶子，不会被当作内部节点展开。

`manifest.json` 记录 schema、Camel 包版本、树结构、各叶子的文件名、字节数、SHA-256 和张量 dtype/shape。`save_tree(dir, state, dataset_manifest_sha256)` 可记录数据清单版本；`load_tree::<State>(dir, expected_dataset_manifest_sha256)` 不匹配时按设计稿警告，实际训练入口仍须执行自己的数据版本准入规则。

保存先把值复制成原生持有的字节，不在文件 IO 期间保留 Camel 堆的裸指针。新检查点整体写入同一父目录下的独占临时目录（`dir.pending-<pid>-<序号>`）并逐文件刷盘。发布是同一卷上的两步改名：已有目标先改名为 `dir.previous`，再把临时目录以不覆盖的改名发布为目标（Linux `renameat2(RENAME_NOREPLACE)`，Windows 用不带替换标记的目录移动；缺少对应原语的平台明确失败）。第二步失败时把 `dir.previous` 改回目标，旧检查点原样保留；成功后删除 `dir.previous`，删不掉则留到下次保存清理。目标不存在时直接发布；目标已存在时被整体替换，不会出现新旧叶子混合的状态。目标是符号链接、junction 或其他重解析点时，在动任何东西之前拒绝：改名只会移动该条目本身，而清理不能跟随链接。三个名字同父目录，因而总在同一卷；只有目标是挂载点或指向另一卷的链接时才跨卷，此时明确失败（`EXDEV`/`ERROR_NOT_SAME_DEVICE`），不做复制——复制会破坏“要么旧、要么新”的原子性。进程在两次改名之间死亡时，目标缺失而 `dir.previous` 是完整的旧检查点：下次保存先把它改回目标再替换，载入则读取 `dir.previous` 并在标准错误上警告。第二次改名成功后死亡只留下过期的 `dir.previous`，下次保存清除；被杀死时留下的未用 `.pending-*` 目录从不被读取，可手工删除。任何失败只清理本次创建的临时目录和文件，不递归删除其他目录。

载入先读入原生字节，检查完整结构、各文件长度/校验和、NPY 存储格式及目标类型的 dtype/已知形状；全部通过后才重建 Camel 对象。未知维度允许从清单取得实际尺寸。失败返回带路径的 `CheckpointError`，不向调用方发布半棵状态树。原生调用通过 `ArgsView::resultType()` 接收单态调用的静态结果布局；这改变了 C++ SDK 布局，模块 ABI 升至 3，核心与模块必须一起重建。设计原则 5.5 规定原生算子的内核不在运行时读取静态类型；`load_tree` 按树的类型递归解码，需要等泛型的设计（编译期按结构体、元组的字段展开）才能不读，现在仍读，是已知的遗留。

验收要求包括：各调度器往返一致、分代 GC 压力、IEEE/大整数精确性、损坏/截断/类型与形状错误、失败时旧检查点逐字节不变、成功时整体替换（无旧的残留叶子）、连续更新与跨进程恢复逐位一致。完整训练的随机恢复验收仍依赖后续 `Key` 和设备常驻训练步，不能由此处的小规模优化器状态样例代替。

## 实测（2026-10-19）

88 上使用标准构建安装独立运行时 `.camel-checkpoint-v2`。先观察 CML 的命令行输出，再补 `checkpoint_verify.mjs` 和对应计划；未跑全量测试。NVM、FVM、JIT、并行调度器的保存与显式/期望类型载入一致；NVM/FVM/JIT 的分代搬移与安全点压力验证通过。10 次连续更新与 3 次更新后保存、退出、重启再更新 7 次的参数、Adam 两组动量、EMA、步数、种子和游标完全一致。大于 2^53 的整数、浮点负零、NaN 载荷、无穷、次正规数、空张量、Bytes 和中文文本均保留。

损坏的叶子校验和、dtype、已知形状、缺失清单、校验和正确但存储 dtype 不支持的 NPY 均被拒绝；当时覆盖已有目录也被拒绝，H20 起改为整体替换（协议、Windows 规则与验证见 `docs/handover/reports/H20.md`）。原有自动微分/SGD 示例仍得到 `1.0 -> 0.9215999841690063` 的损失，二进制张量往返用例通过。

另在 64 MiB 张量写入临时目录后强制 `SIGKILL`：只留下 `.pending-...`，正式目标目录不存在，没有发布半个检查点。若被杀时目标已被移走，剩下的 `dir.previous` 是完整旧检查点，载入会读它、下次保存会先恢复。该手动探针为 `checkpoint_interrupted.cml`，不放进有时序依赖的默认 CI 检查。

服务器 v2 源码归档 SHA-256 为 `eeee7fc82a381f4ea467d5fba3f109814f570217438b69f9f3e6b871e3bc5d38`；独立运行时的 `bin/camel` 为 `006552d51a0054cc3cce00e48e3e09bc20cd5f69c90d8974bbc995af91198451`，`stdlib/nn.cmo` 为 `4997942f0beb11965be75dc8654f1f8d7cf740fb6ba084ce6567e575ce1725ef`。这些是提交前源码快照的产物标识，不等同于随后格式化提交的逐文件哈希。
