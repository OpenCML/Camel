# 重复：`EACH` 与 `LOOP`

## 初心

程序里的"重复"在图上本来只有一种写法：要么是 `LOOP` 节点，要么是一个把元素函数当参数的高阶算子（`map`、`filter`、`reduce`）。后一种是黑盒。"怎样逐个元素跑"写在每个后端各自的内核里，于是有四个后果：

1. **算子反过来调后端**：要回调当前后端去执行元素函数，算子不再是值到值的函数。
2. **每个后端各写一遍循环**：在字节码虚拟机里，这个循环是一段 C++ 代码，每个元素都要付一次完整的调用入口，JIT 也没有循环可编。
3. **图上没有"各轮互不依赖"这条性质**：并行调度器只能按算子名去认它。
4. **遍看不见结构**：融合、求导、批处理都只能为每个算子单写规则。

把它们在前端编成 `LOOP` 也不行。`LOOP` 带状态，下一轮依赖上一轮，"各轮互不依赖"同样丢了。

所以图上要有两种重复，各对应一种节点。语义只说结果是什么，怎么调度由后端决定。这正是"算什么与怎么跑分开"在重复上的落点。

## 两种重复

- **`LOOP`：有状态的重复**。下一轮用上一轮的结果，或者各轮产生必须按顺序发生的效应。`fold`、`while`、计数，以及各轮效应会冲突的 `foreach`，都属于这一种（原则 3.10）。
- **`EACH`：无依赖的重复**。每一轮各算各的。`map`、`filter`、`find`、`any`、`all`、`reduce`，以及各轮效应互不冲突的 `foreach`，都属于这一种（原则 3.6）。

划分有理论依据，就是列表同态（Bird–Meertens 形式化与"第三同态定理"）：能在列表上并行计算的函数，恰好可以写成"先 `map`、再用一个结合运算归约"；一般的从左到右折叠只能顺序算。

## `EACH` 节点

`EACH` 由三样组成：

- **迭代空间**：一个或几个等长的数组或范围，决定有几轮。长度不等时，与 `zip` 一样产生故障。范围直接按下标迭代，不先转成数组。
- **体区域**：一个区域，输入这一轮的元素（以及下标），输出这一轮的结果。它与分支的臂、循环的条件与体是同一套区域机制，由同一个"拥有区域的节点"编辑原语建造。
- **汇合方式**：每一轮的结果怎样合成节点的值，见下一节。

`EACH` 的各轮之间没有先后。由此直接得出两条规则，都不是新加的：

- **体里写共享资源，提交拒绝**。提交检查本来就要求"冲突的访问有先后"，`EACH` 的各轮之间没有先后，所以体里一旦出现与另一轮冲突的写，就被拒绝。"冲突"按资源效应系统的四条等式判断：一对访问同在一个资源上、至少一方是写、又不满足交换，就是冲突（见 [`../effects/README.cn.md`](../effects/README.cn.md)）。
- **体里给外面的 `var` 赋值是编译错误**。原则 3.5 说循环体里给外面的 `var` 赋值会成为循环携带的状态；`EACH` 没有携带的状态，所以不允许。这与"闭包不能给捕获的名字赋值"是同一个道理。

## 汇合方式

一共四种。每一种的结果都完全由语义规定，所以在所有后端上都相同。

| 汇合方式 | 库函数 | 结果 |
|---|---|---|
| 按位置收集 | `map(xs, f)` | 第 i 位是 `f(xs[i])` |
| 按位置保留 | `filter(xs, p)` | 保留 `p` 为真的元素，保持原来的顺序 |
| 按下标取第一个 | `find`、`any`、`all` | 下标最小的命中，以及它决定的真假 |
| 树形归约 | `reduce(xs, op, unit)` | 按一棵由元素个数唯一决定的平衡二叉树两两合并；空数组得 `unit` |

### 按下标取第一个：乱序执行，按下标定输赢

`find` 要的是下标最小的命中。并行时可以切块同时找：某一块在下标 i 找到命中后，完全落在 i 之后的块可以停下或不再开始；i 之前的块还要跑完，因为它们可能有更靠前的命中。最后取最小的下标，结果与顺序执行相同。

把命中与故障放在一起，规则只有一条：**下标最小的那一件事胜出**。

- 下标 3 故障、下标 7 命中：结果是故障。这和顺序执行时先碰到故障一样。
- 下标 2 命中、下标 5 故障：结果是命中，下标 5 可以根本不算。

这和原则 3.6 已有的并行故障规则（"下标大于已知最小故障、还没开始的元素不再开始"）是同一条。

### 树形归约：合并树是语义的一部分

`reduce` 的语义不是"合并顺序不确定"，而是"按一棵固定的平衡二叉树合并"。树的形状由元素个数唯一决定，所有后端都算同一棵树。由此得到三点：

- **确定**：结果在所有后端上逐位相同，浮点数也是。
- **天然可并行**：左右子树互不依赖，并行调度器把它们分给不同线程，顺序后端按同一棵树依次算。
- **数值更好**：两两合并求和的误差随 log n 增长，从左到右累加的误差随 n 增长。

`op` 不必声明满足结合律。语义已经完整定义，`op` 不满足结合律时结果照样确定，只是不再等于从左到右折叠。想要从左到右，就用 `fold`。编译器改变合并树的形状，属于 `reassociate` 许可（原则 7.2）。

### 以后加的：前缀和

`scan(xs, op, unit)` 的第 i 位是前 i+1 个元素按 `op` 合并的结果，例如 `[1, 2, 3, 4]` 用加法得 `[1, 3, 6, 10]`。它同样按固定的合并树定义，所以确定、可并行。用处有三类：

- **累计量**：累加和、累计最大值。
- **并行的 `filter` 自己要用**：先对"保留与否"做前缀和，才能并行算出每个保留元素在结果里的位置。
- **线性递推的并行求解**：状态空间模型一类的递推可以写成结合运算的前缀和（JAX 的 `lax.associative_scan`）。

它是第五种汇合方式，排在前四种落地之后。

## `foreach`

`foreach(xs, f)` 的语义是按下标顺序执行 `f` 的效应。

- **各轮效应会冲突**，例如都往控制台打印：就按这个顺序执行，落成 `LOOP`。
- **互不冲突**，例如各写各的资源，或写的是可交换的资源（效应系统里的 `unordered` 修饰词）：顺序看不出来，后端可以并发，落成 `EACH`。

是哪一种，由 `f` 声明的足迹在降低时决定；判断不了就按 `LOOP`。所以不需要另设一个"无序的 `foreach`"。真想并行做事，就让效应落在不冲突的资源上，或者先用纯的 `map` 并行算好，再按顺序输出。

## 名字只说结果，不说调度

能否乱序、能否并行，由性质决定，不由名字决定。这些性质是：元素函数纯、各轮效应不冲突、合并树固定。这是原则 3.6"并行来自声明的性质，不来自名字"在库函数命名上的直接推论。所以库里没有 `unordered_` 一类的名字。

## 各后端怎样调度同一个 `EACH`

| 后端 | 调度方式 |
|---|---|
| `std::nvm` | 下标从 0 走到 n−1，每轮执行一次体区域 |
| `std::fvm` | 字节码生成时把体区域降成一个字节码循环，体内联，不再每个元素调用一次 |
| `std::jit` | 编译同一个循环 |
| `std::prl` | 按原则 3.6 的粒度，用节点的相对代价把下标范围切块并发；嵌套的 `EACH` 先只并行外层 |
| `std::cpp` | 翻译成一个 `for` |
| GPU 与 ONNX | 体是逐元素运算时，借批处理规则集提升成张量运算；否则用 ONNX 的 `Loop` |

调试器单步时按下标 0 到 n−1 的顺序走。

## 和其他部分的关系

- **资源效应系统**：`EACH` 节点的足迹是体的足迹，"可能故障"也由体推出。这与分支、循环取区域内的合取是同一套（见 [`../effects/derived-properties.cn.md`](../effects/derived-properties.cn.md)）。
- **求导**：
  - `map` 的反向是对体求反向的 `EACH`。
  - 被所有元素共享的输入（例如捕获的权重），各元素的余切要用确定的顺序相加，不用无序归约，否则梯度不可复现。
  - `filter` 的反向把梯度散回保留下来的位置。
  - 带效应的 `foreach` 里，效应只在正向执行，反向是纯的（原则 9.9）。
- **批处理**：体是逐元素运算的 `EACH`，与 `rulesets/vmap.cml` 的批处理规则互相转换。
- **优化遍**：
  - `cse`、`fold`、`dce`、`inline` 都要认得 `EACH` 的体，C++ 版与 Camel 版两套都要。
  - 新的优化机会是把每一轮都相同的计算提到体外。
  - `map` 接 `map`、`map` 接 `reduce` 的融合，是 `EACH` 套 `EACH` 的图重写，用 Camel 写成一个遍。
- **图编辑 API**：`graph` 模块的查询（`kind`、`region_of`）、规则匹配与提交检查都认得 `EACH`。
- **流**：`EACH` 只用于长度已知的有限集合，也就是数组与范围。惰性的流只能消费一次，走自己的路，不并进来。
