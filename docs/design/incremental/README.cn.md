# 增量计算（设计稿）

状态：方向已定（负责人 2026-10-24），中期，排在流与驻留执行（H248）之后；暂不施工。

## 1. 是什么

程序跑完一次之后，输入只变了一点，只重算受影响的部分，其余复用上次的结果。典型场景：电子表格（改一个格子只重算引用它的格子）、构建系统（改一个源文件只重编依赖它的部分）、响应式界面、IDE 分析、数据库的增量视图。

## 2. 定位：用户主动用的遍，不是默认优化

- 增量计算是一个**遍** `std::incremental`：用户需要时放进流水线（`camel report.cml std::incremental std::fvm`）；能从源码调用遍之后，也可以只对一个函数用（`costs_updates->map<incremental((c) => report(sales, c))>`）——吃进一个函数，交回一个记住上次结果的函数。
- 不默认开启：它多占内存（每处记住一份上次的结果）、多做判断（每次比较输入），只在输入一版一版地来、相邻版本大部分相同时才划算。
- **语法不变，语义不变**：用与不用结果完全相同，程序代码不改。输入随时间变化用流 `T..` 表达（设计原则 5.4）。剖析报告哪些地方复用、哪些重算。

## 3. 前提

- **纯计算是确定的**（设计原则 3.2）：同样的输入一定得到同样的结果；结果会变的操作是效应或在声明里写明不确定。这是复用结果安全的前提。
- 值语义：没变的输入就是同一个对象，判断"变没变"是一次指针比较。
- 效应照常执行，不因为"上次做过"而跳过。

## 4. 实现（遍的内部，用户不需要关心）

1. **挑存档点**：值得记住结果的地方——耗时的纯函数调用与区域（分支臂、循环体）。编译时顺带算出"每个输入影响哪些存档点"（依赖就是图本身，不需要像 Salsa 那样在运行时记录）。
2. **改写**：每个存档点改写成"输入与上次相同就用上次的结果，否则重算并记下"的分支；改写后是一张普通的图，执行器不需要新机制。
3. **存在哪**：驻留执行时图的实例一直活着，每个存档点在帧上多两个槽位——上次的输入（对象引用）与上次的结果；只保留上一个版本，旧值由 GC 回收。被调函数内部按调用位置各留一份，先做第一层。
4. **提前截断**：重算出的结果与上次相同，下游看到输入没变，继续复用。

## 5. 分阶段

1. 单进程内的增量（本稿）。
2. 集合级的增量：一个大数组只变一行时只更新受影响的汇总（参照差分数据流 / Materialize），与流模型衔接。
3. 跨进程、存到磁盘的结果缓存（参照 Bazel、Nix），按内容哈希。
