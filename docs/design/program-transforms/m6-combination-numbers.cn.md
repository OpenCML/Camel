- 状态：**准备件**。只给数，不给实现：三组组合在库层 `grad` / `vmap` / `jvp` / `vjp` 能跑之前，先把期望值钉死。
- 基于：`origin/develop` 的 `357cdcddd`（72 小时冲刺计划，M6 一行），和 `docs/design/program-transforms/README.cn.md` 第 5 节"求导的验收对照三样"。
- 用途：M6 的验收是"三组组合有数"（T+48）。这一页是"数"的那一半：解析导数与有限差分各算一遍，两条独立的路，谁先到都能对。
- 判据：**先写期望值，再写实现——反过来的话，期望值就成了实现的复印件。**

## 1. 两个函数与它们的导数

| 函数 | 定义 | 一阶 | 二阶 |
|---|---|---|---|
| `f` | `f(x) = x*x`，`f: R → R` | `f'(x) = 2x` | `f''(x) = 2` |
| `g` | `g(v) = sum(v*v)`，`g: R² → R` | `∇g(v) = 2v` | `H_g = 2I` |

手推一行就够：`d/dx (x²) = 2x`；`∂/∂v_i Σ_j v_j² = 2v_i`。两个都是二次，二阶导是常数——这是选它们的原因：期望值不用近似，误差只来自求导实现本身，不来自题目。

## 2. 三组组合的期望值

每个组合要报清四件事：哪个函数、在哪一点、余切/方向是多少、期望输出逐位是多少。三个组合用同一对 `f`、`g`，因为组合的差别只在**顺序**，不在数学。

### 2.1 `grad(vmap(f))`

约定写清：`vmap(f)` 逐元素，`grad` 要标量，所以这个组合是 `grad(x ↦ sum(vmap(f)(x)))`。点 `x = [1, 2, 3]`。

`d/dx_i Σ_j x_j² = 2x_i`：

| | x = 1 | x = 2 | x = 3 |
|---|---|---|---|
| 期望 | 2.000 | 4.000 | 6.000 |

### 2.2 `vmap(grad(f))`

`grad(f)(x) = 2x`，逐元素套在同一个批上：

| | x = 1 | x = 2 | x = 3 |
|---|---|---|---|
| 期望 | 2.000 | 4.000 | 6.000 |

**这两组必须逐位相等。** 顺序不同、答案相同，是这一对组合唯一的意义；不相等就说明其中一条路把"批的维度"和"点的维度"搞混了——这是 `vmap` 与 `grad` 一起用最容易犯的错，也是这条对照存在的理由。

### 2.3 `jvp(vjp(f))`

`vjp(f)(x, v) = v·f'(x) = 2vx`（`v` 是余切，标量）；它对 `x` 的导函数还是 `2v`，再乘方向 `ẋ`：

`jvp(vjp(f))(x, v, ẋ) = 2v·ẋ`

取 `v = 1`、`ẋ = [0.5, 1.0, 1.5]`：

| | 第 1 位 | 第 2 位 | 第 3 位 |
|---|---|---|---|
| 期望 | 1.000 | 2.000 | 3.000 |

### 2.4 `g` 的三组（批是两个 `R²` 行：`M = [[1, 2], [3, 4]]`）

`grad(vmap(g))` = `grad(M ↦ Σ_rows g(row))`，`∂/∂M_ij = 2M_ij`：

| | 列 0 | 列 1 |
|---|---|---|
| 行 0 | 2.000 | 4.000 |
| 行 1 | 6.000 | 8.000 |

`vmap(grad(g))`：同一张表，**2.000 / 4.000 / 6.000 / 8.000**，逐位相等（理由同 2.2）。

`jvp(vjp(g))`：`vjp(g)(M, v) = v·2M`，它对 `M` 是线性的，所以方向导数是 `2v·Ṁ`；取 `v = 1`、`Ṁ = I₂`：

| | 列 0 | 列 1 |
|---|---|---|
| 行 0 | 2.000 | 0.000 |
| 行 1 | 0.000 | 2.000 |

附带一条一眼判死的：`grad(vjp(g))(M, v)` 必须是**全 0**（`vjp` 对 `M` 线性，二阶导为 0）。这条抓的是"把 `vjp` 的余切又当成变量求了一次导"。

## 3. 有限差分：步长与误差界

中心差分 `D_h f(x) = (f(x + h) − f(x − h)) / (2h)`。

误差两项：截断 `(h²/6)·|f'''|`，舍入 `≈ ε·(|f(x+h)| + |f(x−h)|) / (2h)`，`ε = 2⁻⁵³ ≈ 1.11e-16`。

- 两个函数都是二次，**三阶导数恒为 0**，所以截断项**恰好是 0**：它们的中心差分只有舍入误差。
- 取 **`h = 1e-5`**：舍入界在 `f` 上 `≤ 2.0e-10`（`|f| ≤ 9`），在 `g` 上 `≤ 3.6e-10`（`|g| ≤ 16`）。这个步长离中心差分的理论最优 `h* = ε^{1/3} ≈ 6.1e-6` 只差不到一倍，取它不会因为 `h` 太小而放大舍入、也不会因为太大而引入截断。
- 验收取 **`|FD − 解析| ≤ 1e-9`**：比上面的界宽 2.5 倍以上，但不至于宽到看不出实现的错。
- 实测（本地算术，不经任何实现）：`f` 的最大偏差 **3.9e-11**，`g` 的最大偏差 **1.3e-10**，都在界内。
- 将来对照三次以上的函数时截断项不再是 0：`h = 1e-5` 时它约 `(h²/6)·|f'''| = 1.7e-11·|f'''|`，仍是同一套界，只是不能再宣称"截断为 0"。

## 4. `remat` 的期望：数不变，残差数下降

`remat` 只改"存不存"，不改"算得对不对"：反向时把一段子图重算一遍，不保存残差。

| 项 | 期望 |
|---|---|
| 数值 | 与不加 `remat` **逐位相同**（同一函数、同一点、同一方向） |
| 残差数（保存的张量数） | **严格下降**；极端情形（整段都重算）下，该段只留入口值 |
| 时间 / 内存 | 只记不追 |

验证方式：同一组期望值跑两遍（加 / 不加 `remat`），逐位比数值；残差数比引擎报的计数。数值这一半可以直接复用第 2 节的表——`remat` 不该让任何一个数变化，所以它不需要自己的期望值。
