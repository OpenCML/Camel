# 工作路线与待办

本文件记录已经裁定、尚未完成的工作，以及等待语言作者回答的问题。裁定本身写在 [设计原则](design-principles.cn.md)（规范性文件），各项设计写在 `docs/design/` 下；尚未决定的语义问题列在设计原则第 6 节。这里只记"要做什么、做到哪、按什么顺序"。完成的条目直接删去，历史见提交记录。

更新：2026-10-19。

## 1. 已排定的顺序

**地基（进行中，由语言作者的协作 AI 完成）：**

1. **装饰器的通用机制**：节点属性由库注册并随节点保留；装饰器可以修饰代码块，被修饰的块与不加修饰时行为完全相同；装饰器可以改写函数的图。
2. **遍参数与模块流水线**（2.17）：`name(key=value)` 是通用写法；设置不放在环境变量里；模块自己登记遍名与默认流水线。
3. **效应与优化统一**（2.17）：效应以资源声明为准；算式优化读算子语义；2.15、2.16 的默认放宽落到语义层；高阶函数由声明的性质驱动；循环驱动只有一份。
4. **前端清理**（2.17）：`string` 保证 UTF-8，`Bytes` 内建；参数树路径与叶子规则统一；类型实参可按名字写；审查前端报告中的其余条目。
5. **泛型按结构体、元组字段递归的设计稿**（待讨论，见第 5 节）。

**地基之后、可交给其他开发者的：**

- **`enum`**：`type Shape = enum { Circle(float), Rect { w: float, h: float }, Empty }`，`Shape::Rect { ... }` 构造，`match` 列全成员时不需要 `case _`。只有一种封闭的 `enum`。退役 `T ? U` 与 `A | B`。旧的半成品在 `lane/enum`（只有头文件），应基于最新代码重做。
- **数值许可改为库装饰器**（在 `enum` 之后）：`@numeric<Reassociate, Contract>`，许可是标准库 `numeric` 中的封闭 `enum`；编译器中不再有专为 `numeric` 写的代码；取消 `@name(...)` 写法，不做兼容过渡。其他模块需要自己的放宽时，定义自己的 `enum` 与装饰器。
- **依赖通用节点属性的后续**：融合与库实现记为节点属性、图上保留原算子（2.17）；记录内联来源，调试器据此显示内联函数的帧（2.14）；`@gpu` 改为编译期标注（归 Tiles，见 Tiles 路线第 11 节）。
- 审查报告中其余不需要裁定的条目（见第 4 节与各报告）。

## 4. 审查发现（2026-10-19）

审查不分作者，覆盖 2026-10-08 以来的提交，只问"是否符合长期设计"，不问"能否运行"。完整报告（每条带位置、现状引文、理由、优雅的形式、严重度）：[前端与标准库](reviews/2026-10-19/frontend.cn.md)、[运行时与优化器](reviews/2026-10-19/runtime.cn.md)、[模块](reviews/2026-10-19/modules.cn.md)。共 42 条，归为四类：

**甲、核心按名字认具体的模块或算子（与 `@numeric` 同类）**
- 参数树 `tree_map` 等在核心建图器里按 URI 展开，`tree` 模块是空壳（三份报告都指出）。
- 遍参数只为 `std::opt` 的 `safe_fp` 写了一段专门解析；其余设置散在环境变量里。
- 核心的遍别名表写死了 `std::tiles`。
- `std::opt::algebra` 写死 12 个算子，不读算子语义。
- `append` 的就地改写按名字写死（`sort` 走通用机制）；`error` 的调用位置、`foreach` 的丢弃检查按名字判断。
- `:mark/` 高阶算子是封闭名单，每个后端各写一遍。

**乙、同一事实有多个来源**
- 效应与写入：资源声明、签名里的 `var`、按 URI 前缀猜测，三者并存，优化遍不读资源声明。
- "什么是树、什么是叶子"写了五到七份，已经不一致。
- 算子的签名、纯度、效应写在 C++ 注册、算子表、`stdlib/signatures` 三处。
- Tiles 直接读张量模块的内部注册表；Tiles 内部有四五张按名字的封闭算子清单，彼此不一致。
- 循环的轮次驱动写了三遍半；FastVM 是否降级循环取决于环境变量和调试器在不在。
- 原生算子拿到类型实参有四种做法。

**丙、缺少通用机制**
- 通用节点属性（许可列只是特例；内联来源也应记在这里，调试器才能按 2.14 显示内联函数的帧）。
- 通用的遍参数。
- 模块注册的编译期展开。
- 梯度与融合产生的算子没有语义声明与定义图；`expandDefinition` 没有调用者，Tiles 只好照 CPU 内核复刻。

**丁、语义缺口**
- `string` 与 `Bytes` 的分界未定。
- `std::tiles` 插入的节点被声明为外部效应，与"纯性能遍"矛盾。
- 2.15、2.16 的默认放宽没有落到语义层，各模块各写一份"许可对应哪种实现"。
- 设备故障按算子名判断，报告没有故障种类与位置。

不需要裁定的条目由核心或 Tiles 按报告中的"优雅的形式"修复；归属见各报告。需要裁定的列入第 5 节。
