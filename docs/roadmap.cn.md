本文件记录已经裁定、尚未完成的工作，以及等待语言作者回答的问题。裁定本身写在 [设计原则](design-principles.cn.md)（规范性文件），各项设计写在 `docs/design/` 下；尚未决定的语义问题列在设计原则第 6 节。这里只记"要做什么、做到哪、按什么顺序"。完成的条目直接删去，历史见提交记录。

更新：2026-10-19。

## 1. 已排定的顺序

1. **装饰器的通用机制**（进行中）：节点属性由库注册并随节点保留；装饰器可以修饰代码块，被修饰的块与不加修饰时行为完全相同；装饰器可以改写函数的图，而不只是包一层。
2. **`enum`**：`type Shape = enum { Circle(float), Rect { w: float, h: float }, Empty }`，`Shape::Rect { ... }` 构造，`match` 列全成员时不需要 `case _`。只有一种封闭的 `enum`。退役 `T ? U` 与 `A | B`。
3. **数值许可改为库装饰器**：`@numeric<Reassociate, Contract>`，许可是标准库 `numeric` 中的封闭 `enum`；编译器中不再有专为 `numeric` 写的代码；取消 `@name(...)` 写法，不做兼容过渡。其他模块需要自己的放宽时，定义自己的 `enum` 与装饰器。
4. **审查近期实现**：逐项检查 2026-10-08 以来各方提交的实现是否符合设计原则的长期方向（不只是能否运行），结果补入本文件第 4 节。
