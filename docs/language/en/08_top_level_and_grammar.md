# 8. Program and grammar

English | [中文](../08_top_level_and_grammar.md)

This chapter describes the top-level structure of a program, gives a summary of the grammar, and collects the constructs that the grammar accepts but that are not implemented. The complete grammar is in [8.5](#85-the-complete-grammar); it is generated from the source of the parser.

---

## 8.1 Program

```
program : (decl ';'?)* EOF
decl    : moduleDecl | importDecl | exportDecl | namespaceDecl | usingNamespaceDecl
        | dataDecl | funcDecl | typeDecl
```

The module top level contains only declarations and no executable statements; execution starts from `main` ([4.1](04_execution_model.md#41-program-and-entry)).

| Declaration | Grammar | Section |
|---|---|---|
| Module | `module name` | [5.1](05_modules.md#51-module-declaration) |
| Import | `import (module \| (name \| { name, ... }) from module)` | [5.2](05_modules.md#52-imports) |
| Export | `export (dataDecl \| typeDecl \| { name, ... })`; the `export` of a function is written before `func` | [5.3](05_modules.md#53-exports) |
| Namespace | `namespace qualified-name { ... }` | [5.4](05_modules.md#54-namespaces) |
| Opening a namespace | `using namespace qualified-name` | [5.2](05_modules.md#52-imports) |
| Data | `(let \| var) name (: type)? = expression` | [7.2](07_statements.md#72-let-and-var) |
| Function | `annotation* (with <parameters>)? export? modifier* func name(parameters) (: type)? block` | [7.4](07_statements.md#74-functions) |
| Type | `type name (<parameter, ...>)? = type` | [7.7](07_statements.md#77-type-declarations) |

## 8.2 Statements and blocks

```
stmt      : dataDecl | funcDecl | typeDecl | dataExpr | usingNamespaceDecl | retStmt | blockStmt
retStmt   : (return | throw) dataList
stmtBlock : sync? '{' (stmt ';'?)* '}'
blockExpr : stmtBlock | dataExpr            // branch arm, lambda body
```

## 8.3 Expressions

From low precedence to high (see [6.12](06_expressions.md#612-operator-precedence)):

```
dataExpr   : waitExpr | ctrlExpr
ctrlExpr   : if logicalOr then blockExpr (else blockExpr)?
           | match name '{' (case pattern ('|' pattern)* '=>' blockExpr)+ '}'
waitExpr   : wait? assignExpr
assignExpr : logicalOr (('=' | '+=' | '-=' | '*=' | '/=' | '%=' | '^=' | '@=' | '&=' | '|=') logicalOr)?
logicalOr  : logicalAnd ('||' logicalAnd)*
logicalAnd : or ('&&' or)*
or         : and ('|' and)*
and        : equality ('&' equality)*
equality   : relational (('===' | '!==' | '==' | '!=') relational)*
relational : additive (('<' | '>' | '<=' | '>=') additive)*
additive   : multiplicative (('+' | '-') multiplicative)*
multiplicative : power (('*' | '/' | '@' | '%') power)*
power      : nullable ('^' power)?
nullable   : unary (('??' | '!!') dataExpr)?
unary      : link (as type)?
link       : neg (('->' | '?->') comp)*
neg        : ('-' | '!' | '~') negPower | comp
negPower   : ('-' | '!' | '~') negPower | comp ('^' negPower)?
comp       : anno ('..' anno)*
anno       : primary ( '.'field | '[' subscript ']' | '(' arguments ')' | '<' with arguments '>' )*
primary    : name | literal | '[' element, ... ']' | '{' key: value, ... '}' | '(' expression, ... ')' | lambda
lambda     : modifier* ('<' parameters '>')? '(' parameters ')' (':' type)? '=>' blockExpr
pattern    : literal | '_' | null | error name | name
```

Subscripts, arguments and `with` arguments must directly follow the expression before them. `(e)` is a parenthesised expression, `(e,)` a one-element tuple.

## 8.4 Types

```
typeExpr : unionType ('?' | '!')*
unionType: arrayType ('|' arrayType)*
arrayType: specType ('[' ']')*
specType : primaryType ('<' (type | const data), ... '>')?
primaryType : name | '(' type ')' | '(' type, ... ')' | '{' name: type, ... '}'
            | modifier* '(' parameters ')' '=>' type | typeas name
```

- `T?`, `T!`: [3.4](03_data_model.md#34-may-be-null-t-and-may-fail-t).
- `typeas T`: [7.5](07_statements.md#75-generic-functions).
- Angle brackets: the arguments of a type function ([7.7](07_statements.md#77-type-declarations)) or the arguments of a module type.

## 8.5 The complete grammar

Every production of the language, one for one with the parser: each production is written above the function that implements it (`src/parse/syntax/parser*.cpp`), this section is generated from there by `node scripts/check-grammar.mjs --write`, and the test `grammar.reference_in_step` keeps the two in step. Notation: `'x'` is a literal token; `IDENTIFIER`, `INTEGER`, `REAL`, `STRING`, `MULTI_STR`, `FSTRING` are token classes (see [chapter 2](02_lexical.md)); `OPERATOR` is any operator token (used only in `operatorName`, whose `IDENTIFIER` is the name `operator`); `SEP` is `;`; `*` `+` `?` `|` and parentheses have their usual meaning.

<!-- grammar:begin (generated by scripts/check-grammar.mjs --write) -->

```
program            : SEP? (decl SEP?)* EOF
decl               : moduleDecl | importDecl | exportDecl | namespaceDecl | usingNamespaceDecl
                     | dataDecl | funcDecl | typeDecl
stmt               : dataDecl | funcDecl | typeDecl | dataExpr | usingNamespaceDecl | retStmt
                     | blockStmt
blockStmt          : 'wait'? stmtBlock | funcAnno+ stmtBlock
stmtList           : stmt (SEP? stmt)* SEP?
stmtBlock          : 'sync'? '{' stmtList? '}'
blockExpr          : stmtBlock | dataExpr
moduleName         : ('.' | '..' | '...')? IDENTIFIER ('.' IDENTIFIER)* ('::' IDENTIFIER)*
moduleDecl         : 'module' identDef
importDecl         : 'import' (moduleName ('as' identDef)? | (importItem | bracedImports) 'from' moduleName)
bracedImports      : '{' (importItem (',' importItem)*)? ','? '}'
importItem         : identDef ('as' identDef)?
exportDecl         : 'export' (dataDecl | typeDecl | bracedIdents)
usingNamespaceDecl : 'using' 'namespace' identRef
namespaceDecl      : 'namespace' identRef '{' SEP? (namespaceItem SEP?)* '}'
namespaceItem      : namespaceDecl | importDecl | exportDecl | usingNamespaceDecl | funcDecl
                     | typeDecl | dataDecl
funcAnno           : '@' identRef (angledValues | parentIdents)?
funcDecl           : funcAnno* ('with' angledParams)? 'export'? implMark? modifiers?
                     'func' (identRef | operatorName) parentParams (':' typeExpr)? stmtBlock
operatorName       : IDENTIFIER (OPERATOR | '[' ']')
dataDecl           : ('let' | 'var') carrier (':' typeList)? '=' dataList
                     | 'let' '_' (':' typeList)? '=' dataList
carrier            : identList | parentIdents | bracedIdents | bracketIdents
typeDecl           : implMark? 'type' identRef
                     ('=' | '<' identDef (',' identDef)* ','? ('>' '=' | '>='))
                     (typeExpr | STRING)
retStmt            : ('return' | 'throw') dataList
implMark           : 'inner' | 'outer'
modifiers          : ('atomic' | 'shared' | 'sync' | 'macro')+
identDef           : IDENTIFIER
identRef           : (IDENTIFIER '::')* IDENTIFIER
identList          : identDef (',' identDef)*
parentIdents       : '(' identList? ','? ')'
bracedIdents       : '{' identList? ','? '}'
bracketIdents      : '[' identList? ','? ']'
keyParamPair       : 'var'? identDef ':' typeExpr ('=' dataExpr)?
pairedParams       : keyParamPair (',' keyParamPair)*
parentParams       : '(' pairedParams? ','? ')'
angledParams       : '<' pairedParams? ','? '>'
dataExpr           : waitExpr | ctrlExpr | loopExpr
waitExpr           : 'wait'? assignExpr
ctrlExpr           : 'if' logicalOrExpr 'then' blockExpr ('else' blockExpr)?
                     | 'match' identRef '{' matchCase+ '}'
                     | 'try' stmtBlock catchClause+ ('finally' stmtBlock)?
assignExpr         : logicalOrExpr (('=' | '+=' | '-=' | '*=' | '/=' | '%=' | '^=' | '@=' | '&='
                     | '|=') logicalOrExpr)?
logicalOrExpr      : logicalAndExpr ('||' logicalAndExpr)*
logicalAndExpr     : orExpr ('&&' orExpr)*
orExpr             : andExpr ('|' andExpr)*
andExpr            : equalityExpr ('&' equalityExpr)*
equalityExpr       : relationalExpr (('===' | '!==' | '==' | '!=') relationalExpr)*
relationalExpr     : additiveExpr (('<' | '>' | '<=' | '>=') additiveExpr)*
additiveExpr       : multiplicativeExpr (('+' | '-') multiplicativeExpr)*
multiplicativeExpr : powerExpr (('*' | '/' | '@' | '%') powerExpr)*
powerExpr          : nullableExpr ('^' powerExpr)?
nullableExpr       : unaryExpr (('??' | '!!') dataExpr)?
unaryExpr          : linkExpr (('as' | 'is') typeExpr)?
linkExpr           : negExpr (('->' | '?->') compExpr)*
negExpr            : ('-' | '!' | '~') negPower | compExpr
negPower           : ('-' | '!' | '~') negPower | compExpr ('^' negPower)?
compExpr           : annoExpr (('..' | '?..') annoExpr)*
annoExpr           : accessExpr (indices | parentArgues | angledValues | '!' | memberAccess)*
memberAccess       : '.' (IDENTIFIER | INTEGER | REAL)
accessExpr         : primaryData ('.' (IDENTIFIER | INTEGER | REAL))*
primaryData        : identRef | literal | arrayData | structData | tupleData | funcData
literal            : ('+' | '-')? INTEGER | ('+' | '-')? REAL | STRING | MULTI_STR | FSTRING
                     | 'true' | 'false' | 'null'
indexValue         : '...'? dataExpr
keyValuePair       : identDef ':' dataExpr | '...' dataExpr
pairedValues       : keyValuePair (',' keyValuePair)*
dataList           : dataExpr (',' dataExpr)*
argumentList       : indexValues (',' pairedValues)? | pairedValues
indexValues        : indexValue (',' indexValue)*
indices            : '[' dataExpr (':' dataExpr (':' dataExpr)?)? ']'
parentArgues       : '(' argumentList? ','? ')'
angledValues       : '<' argumentList? ','? '>'
arrayData          : '[' ((indexValues ','?) | dataExpr 'for' identRef 'in' dataExpr ('if' dataExpr)?)?
                     ']'
structData         : '{' (pairedValues ','?)? '}'
tupleData          : '(' dataList? ','? ')'
funcData           : modifiers? angledParams? parentParams (':' typeExpr)? '=>' blockExpr
matchCase          : 'case' pattern ('|' pattern)* '=>' blockExpr
pattern            : identRef identDef? | literal | '(' (dataList | identList)? ','? ')'
                     | '{' (pairedValues | identList)? ','? '}' | '_'
loopExpr           : 'loop' loopState (',' loopState)* loopFor? loopWhile? 'do' blockExpr
loopState          : identDef '=' logicalOrExpr
loopFor            : 'for' identDef 'in' logicalOrExpr
loopWhile          : 'while' logicalOrExpr
catchClause        : 'catch' identDef ':' typeExpr stmtBlock
typeExpr           : unionType (('?' | '!')+ | '?' unionType)?
unionType          : interType ('|' interType)*
interType          : diffType ('&' diffType)*
diffType           : keyUnionDiffType ('\\' keyUnionDiffType)*
keyUnionDiffType   : keyInterType (('+' | '-') keyInterType)*
keyInterType       : typeUnit ('^' typeUnit)*
typeUnit           : (identDef 'of')? arrayType
arrayType          : specType ('[' ']')*
specType           : primaryType ('<' typeOrData (',' typeOrData)* '>')?
typeOrData         : typeExpr | 'const' dataExpr
primaryType        : structType | identRef | '(' typeExpr ')' | tupleType | funcType
                     | 'typeof' dataExpr | 'typeas' identDef
tupleType          : '(' typeList? ','? ')'
structType         : '{' (keyTypePair (',' keyTypePair)*)? ','? '}'
keyTypePair        : identDef ':' typeExpr
funcType           : modifiers? angledParams? parentParams '=>' typeExpr
typeList           : typeExpr (',' typeExpr)*
```

Two layout rules outside the grammar ([2.1](02_lexical.md#21-lines-whitespace-and-separators)) decide where a production applies:

- The `indices`, `parentArgues`, `angledValues` and postfix `!` of `annoExpr`, and the `<` of `specType`, touch the token before them; the `<` of `relationalExpr` follows white space. Inside an angle-bracket list a `>` that touches the token before it, or starts its line, closes the list.
- An expression does not go on across a line break unless the operator after the break can only be binary; inside round, square and angle brackets and the braces of a struct a line break means nothing.

Where there is more than one reading, the following rules decide, each on a bounded number of tokens:

| Place | Decision |
|---|---|
| `(`: lambda, or tuple / parenthesized expression | a lambda for `(name:`, `(var`, or an empty list followed by `=>` or `:` |
| `(` in a type | a function type for `(name:`, `(var`, an empty list followed by `=>`; `(T)` is the parenthesized type; anything else a tuple type |
| `{`: struct or block | a struct for `{ name :` and `{ ...`; `{}` is the empty block as a branch arm or a lambda body and the empty struct as a statement |
| Arguments: positional or named | named from the first `name :` on |
| `T ?` | the reserved form `T ? U` when a type can start after the `?` on the same line, the nullable mark otherwise |
| `+` `-` `^` after a type | part of the type when a type can start after it (`x as T + U` casts to the type `T + U`) |
| Unary `-` | always an operator; looser than `^`, tighter than `->`; applied directly to a number it gives the negative literal |

## 8.6 Constructs reserved but not implemented

The following constructs are accepted by the grammar (or their keywords are reserved) and explicitly rejected by the compiler. For most of them the meaning is not yet decided; do not rely on them.

| Construct | Diagnostic given | Alternative today |
|---|---|---|
| Spread `[...xs, y]`, `{ ...p, x: 1 }`, `f(...args)` | `ConstructNotSupported` | `concat(xs, [y])`; write out the fields one by one |
| Format string `` `x = {x}` `` | `ConstructNotSupported` | `'x = {}'->format<x>` |
| `e is T` | `ConstructNotSupported` | None (there is no type information at run time) |
| Non-null assertion `x!` | `ConstructNotSupported` | `x ?? default`, `match` |
| `f ?.. g` | `ConstructNotSupported` | None |
| `f..g` | The result of the composition cannot be called (`ArgumentsMismatch`) | `(x: T) => g(f(x))` |
| `wait { ... }`, and `wait` before a name, a literal or a lambda | `ConstructNotSupported` | `sync { ... }` |
| `try { } catch e: T { } finally { }` | `SemanticDiag::TryCatchNotInLanguage` (not part of the language) | `T!` with `!!`, `?->`, `case error e` |
| Tuple patterns, struct patterns; identifier patterns on ordinary types | `ConstructNotSupported` | `if` chain; take the members first |
| Struct destructuring `let { x, y } = p`, array destructuring `let [a, b] = xs` | `SemanticDiag::FeatureNotSupported` | `p.x`, `xs[0]` (tuple destructuring is available) |
| Keyword arguments `f(a: 1)` | `FeatureNotSupported` | Pass by position |
| Parameter default values `b: int = 5` | `FeatureNotSupported` | Overloading; `with` parameters |
| Slice subscripts `xs[a:b]`, `xs[a:b:c]` | `SemanticDiag::NoMatchingFunction` (there is no dedicated diagnostic: it is reported as "the subscript operator has no overload that accepts these arguments") | `xs->slice<a, b>` |
| Type operations `A & B`, `A \ B`, `A + B`, `A - B`, `A ^ B` | `FeatureNotSupported` | None |
| `typeof e`, `T ? U`, `name of T` | `FeatureNotSupported` | None |
| `keyof`, `enum` | Syntax error | None |
| Modifiers `atomic`, `shared`, `inner`, `outer` | No diagnostic; no semantics | Do not write them |

In addition there are a few things that "can be written but cannot be used at present": the union type `A | B` (values of the member types cannot enter it), and a declaration with a function type `let f: (x: int) => int = g`.
