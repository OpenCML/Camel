# The programs of test/tools/cppexec/expect.txt that still link the Camel runtime when std::cpp
# writes them, and why. The check (run.py --standalone --expect=... --baseline=...) asks the whole
# list and requires exactly this set: a new name is red, and so is a name here that stops linking
# it -- in that case the line is deleted, because a list that can only grow says nothing.
#
# Every line says whether it is a GAP (a rule the writer is missing, so the next person should
# write it and then delete the line) or an EXCEPTION (the bridge is the answer, and the next
# person should not). "known" alone tells neither.
#
# EXCEPTION: a regex engine is not in the standalone header set and is not meant to be -- the
# bridge is how a program that needs one runs.
test/cases/compile/diag_render/runtime_regex.cml   # re:test -- exception, not a gap
# EXCEPTION: a tensor crosses the bridge as a handle (rt::Foreign); standalone operators over
# tensors are a different piece of work, and the bridge is what makes them work today.
test/cases/trans/cpp/tensor_ones.cml               # tensor:ones -- exception, not a gap
# GAP: the f64 square root has no rule yet; the next commit writes it and deletes this line.
test/cases/trans/cpp/exec/scalars.cml              # math:sqrt_d -- gap
# GAP: creating a tensor by the module's operator still crosses the bridge; the standalone rule
# that builds the array directly is not written yet, so the next commit writes it and deletes these.
test/cases/trans/cpp/tensor_zeros.cml             # tensor:zeros -- gap
test/cases/trans/cpp/tensor_ones_element.cml      # tensor:ones -- gap
